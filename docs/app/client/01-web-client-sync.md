# Web 客户端同步方式

> 范围：`tools/openapi-codegen` 与 `apps/web-app/src/lib/api`
> 状态：基于当前代码的静态整理

## 1. 生成工具

生成工具为独立小包，不进入前端工作区，仅在需要重新生成时安装运行。设计意图是隔离编译器版本冲突：生成器依赖旧版编译器，而前端已升级，目录隔离可避免依赖树污染与版本协商。

工作方式为单命令式：读取后端快照，直接写出前端类型文件。目录内不保留中间产物，日常校验不运行生成，仅在注解或文档结构变更后按刷新快照再生成的顺序执行。

另有一条只读检查命令：比较快照与类型产物的修改时间，产物落后时直接失败，用于在持续集成中发现忘记重新生成的情形。

## 2. 类型产物

产物为纯类型声明文件，只包含路径与构件命名空间，供运行时客户端做泛型约束。文件规模大但只参与类型检查，日常构建跳过其内部检查以控制开销。

产物提交入库，因此存在落后风险，依靠上述只读检查命令兜底。产物不描述流式语义，流式类型在前端侧独立维护。

## 3. 运行时封装

运行时以类型化请求库为底座，按快照路径发起调用。共四层：

* 传输与身份：基础地址解析、请求头注入、原始请求与文件下载通道、工作区目录状态复用、目录错误分类、服务端目录拉取。
* 信封拆包：统一拆开成功与数据两层信封，统一分页与截断视图提取，统一错误映射与缺载保护。
* 领域服务：按域划分的封装，将传输结果映射为界面模型，承担命名风格转换与字段归一。
* 流式传输：订阅与推送通道独立维护，不由生成产物覆盖。

原始请求通道绕过类型约束，专供二进制与附件等非信封响应使用。目录头与查询参数双通道分别服务可设请求头与不可设请求头的通道。

## 4. 预览替换

预览模式经构建别名将客户端整体替换为固件实现，服务层无需分支。替换面与正式面保持同名导出，使上层调用保持不变。

固件内部由路由内核、按域注册的路由表、线缆适配与固件事件流组成。路由分发结果经同一内部处理统一为成功或错误信封，模拟错误标记在此处转为真正的错误信封。

目录错误分类在预览与正式实现中保持同一纯函数行为，目录拉取在预览中返回空集合。传输键解析同样保持一致，使地址栏与标签行为在预览中可用。
