# 07 工作流节点覆盖补齐方案

> 范围：工作流各场景与各类节点在 `e2e/` 壳层与 `wf-workflow` 集成层的覆盖补齐
> 关系：`05` 回答壳层实际跑了什么，`06` 规定管理面补齐顺序，本篇只规定节点执行语义如何补齐；`04` 清单保持命令面口径，本篇不再重复管理命令

## 目标与原则

目标是在不引入外部大模型依赖的前提下，让默认门禁真实执行主流节点类型，而不仅是管理面的创建展示删除。原则延续现有线束：内存存储加临时端口加隔离工作区保证确定性，每次调用显式传入远端与目录并固定结构化输出，每类用例使用唯一标识并遵循建后即清。新增固件遵循最小可用与具名登记，不复用已有文件的副作用。断言先看退出码，再看终态是否为完成态，最后看节点历史是否含预期节点。

## 现状盘点

壳层真实执行仅两种固件：最小起止流程承担管理链路占位，单脚本流程承担唯一的执行闭环。其余节点在壳层均无执行用例。库内集成层已覆盖变量、路由、分支汇聚、循环、子图、内嵌图、模拟大模型、代理循环、工具可见性、上下文处理、消息压缩、错误分支等，但走的是库内直调，不经过服务端路由装配与无头包络，字段漂移与错误映射退化无法被壳层感知。决策节点与交互式脚本、用户交互节点在两层均为空白，其中决策节点的纯配置错误路径无需外部服务即可验证，交互节点的完整等待恢复闭环仍需受控环境。

## 壳层补充设计

### 固件规划

新增五个自包含固件，全部复用已注册的回显脚本与内联脚本语义，不新增脚本注册形态，不依赖外部模型：

- 变量链固件承载多变量串联求值，验证表达式与类型转换的端到端语义
- 路由固件承载首匹配与默认回退，分支体使用记录型脚本占位
- 分支汇聚固件承载分支并发与汇聚等待，验证双分支均运行且汇聚后继续
- 循环固件承载计数迭代，验证循环体按次数运行后正常退出
- 可见性固件承载工具屏蔽标记与上下文变换串联，验证标记写入与后续节点可见

子图与内嵌图暂不进入壳层默认门禁，原因在于子图涉及跨定义注册顺序，内嵌图涉及预处理展开，两者在库内集成层已有覆盖，壳层接入需先验证服务端注册表装配语义，列为后续受控项。

### 执行层规划

在本地执行层内新增工作流节点执行分组，复用已有的条件跳过约定：当前置脚本注册失败或任一流程创建失败时明确跳过并报告原因，不记为通过亦不记为失败。分组内对每个新固件执行统一四步：校验定义文件、创建定义、后台触发执行并等待终态、断言终态为完成。清理沿用建后即清，每个新定义的删除与删后不可见断言紧随其执行之后，避免残留影响后续用例。否定路径复用现有校验失败与未知引用用例，不新增独立的非法定义文件。

### 判定规划

成功路径判定统一为退出码为零加业务包络可解析，再加终态完成断言。变量链追加执行检视中变量可解析，路由与分支汇聚追加执行历史中含预期分支节点，循环追加执行日志中循环体多次运行痕迹。只读检视类断言保持宽松，不对条目数量做精确断言，避免与本机状态耦合。

## 集成层补充设计

新增决策配置集成用例，覆盖两层空白中的可确定性部分：空问题集被拦截、缺连接信息被拦截、引用档案但无注册表被拦截。以上均为同步配置错误，无需网络与凭证，失败信息需携带节点标识以便定位。交互式脚本与用户交互的完整等待恢复闭环因涉及运行中暂停与外部输入，放在受控环境验证，不进入本次默认门禁。

## 固件与文档登记

所有新增固件在输入固件说明表中登记用途与使用层级，新增壳层分组在用例文档中登记意图与判定，新增集成用例在测试文件头注释中说明覆盖意图。黄金目录仍保持归一化投影口径，新增执行用例的实际输出先人工确认再提升为黄金，存量黄金变更视为行为变更。

## 验收标准

设计文档入库且索引可达，五个新固件版本化入库且说明表可查，验证脚本新增节点执行分组且跳过语义与清理约定完整，决策配置集成用例覆盖三条可确定性失败路径。全量验证在单次编译检查内通过，默认门禁在支持本地执行的環境下新增用例全部转正，手工层范围不扩大。
