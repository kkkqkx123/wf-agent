# 阶段 4：通用化（触发式，不排期）

本阶段没有排期。触发条件是第二个真实旁路用途立项（候选：todo 提案、上下文水位提示）。
在触发之前，任何「先抽原语」的重构都不做：recap 实例本身就是模式的载体。

## 触发时做什么

- 在 `wf-execution-shared` 新增 `aside` 模块：`Aside` trait（名称、节奏、模型槽、超时、
  投影、清洗与去向判定）+ 注册表（与工具注册表同形，可逐个启停）。不引入新插件框架。
- 调度行订阅 `EventBus` 上已有的回合/迭代完成事件，只做计数与发起，从不 await 主流程；
  每个（用途、会话）最多一个在途，过期（切会话、新回合、行卸载）结果丢弃。
- 去向只保留三种语义：屏幕注记（请求-响应，不广播、不落日志）、白名单事实（白名单在用途立项时
  随协议评审确定，在此之前不定义）、既有决策缝的内容（压缩仍由现有触发权拥有，旁路最多复用「问」的一半）。
- recap 迁移：提示词正文与清洗规则进 `wf-resource` 注册表成为 `aside-recap` 的资源，
  节奏、模型槽、超时、上限由 Rust 侧结构携带；迁移判据是阶段 1 的旧测试不改断言通过，
  任一断言需改即语义漂移，停下先修语义。

## 两个候选用途的边界

- todo 提案：每 N 步问一次计划是否过期，产出屏幕注记与给模型的提醒式内容，写入仍由主 agent 的
  工具调用完成。不合成 `AssistantMessage`（日志不得声称模型做过它没做过的事）。
  真正由旁路写入 todo 需要新事实变体并加宽所有折叠点，另立 ADR，本计划不含。
- 上下文水位提示：只产出屏幕注记（例如建议执行压缩），不得回调压缩、不得改写压缩触发条件。

## 非目标

不新增 kernel 命令与回合终态；不新增第二压缩状态机与回合末补丁；提示词不进可打印配置；
无宿主消费能力的屏幕注记直接丢弃，不写日志。
