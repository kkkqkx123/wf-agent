# Dify 与 n8n 前端可视化能力分析 · 总览

> 本文档是 Dify（`langgenius/dify` 前端 `web/`）与 n8n（`n8n-io/n8n` 前端 `packages/frontend/editor-ui/`）两个项目**前端可视化能力**的对比分析总纲。
> 针对用户关注的五个维度分别成篇：**执行过程可视化、工作流可视化编辑、页面布局、组件设计、UI 风格**。
> 每篇均给出两项目的具体实现、关键代码文件与行号、横向对比表与设计启示。

---

## 1. 分析对象与版本

| 项目 | 仓库 | 前端根目录 | 镜像范围 | 文件数 |
| --- | --- | --- | --- | --- |
| Dify | `github.com/langgenius/dify` | `web/` | `web/app/components/workflow/`（工作流模块）+ 运行日志 + 聊天过程 + 样式 | 541 个文件 |
| n8n | `github.com/n8n-io/n8n` | `packages/frontend/editor-ui/` | `features/{workflows,execution,ndv}` + `app/{views,layouts,components}` + 设计令牌 | 80 个精选文件 |

> 注：因沙箱网络对 `github.com` 直连 TLS 被拦截，源码通过 GitHub Contents API（WebFetch）+ jsDelivr CDN（`-L` 跟随重定向）镜像至本地 `dify-src/`、`n8n-src/`。n8n 仓库体积超过 jsDelivr 单包 50MB 限制，故按路径逐个文件拉取，前端根目录为 `packages/frontend/editor-ui/`（非 `packages/frontend/`）。

## 2. 技术栈总览（直接影响后续各维度的实现形态）

| 维度 | Dify | n8n |
| --- | --- | --- |
| 框架 | React + Next.js（App Router） | Vue 3 + TypeScript（`<script setup lang="ts">`） |
| 画布引擎 | `reactflow`（React Flow） | `@vue-flow/core`（VueFlow） |
| 状态管理 | Zustand（`useStore` / `useWorkflowStore`）+ `immer` | Pinia（`@n8n/stores` / `@n8n/composables`）、依赖注入 `inject/provide` |
| 组件库 | `@langgenius/dify-ui`（Tabs、CodeEditor 等共享组件） | `@n8n/design-system`（`N8nButton`、`N8nText`、`N8nIcon`、`N8nSpinner`、`N8nTags`、`N8nActionDropdown`、`N8nScrollArea`、`N8nResizeWrapper`、`N8nCallout`…） |
| 样式方案 | Tailwind 原子类 + 语义化 CSS 变量（`bg-components-panel-bg`、`system-sm-semibold-uppercase`） | SCSS Module（`useCssModule` / `$style`）+ 语义化 CSS 变量令牌（`--color--primary`、`--spacing--md`、`--font-size--xs`） |
| 图标 | Remix Icons（`@remixicon/react`，如 `RiCheckboxCircleFill`） | 内联 SVG / `N8nIcon`（如 `redo-2`、`thumbs-up`、`flask-conical`） |
| 国际化 | `react-i18next`（`useTranslation`） | `@n8n/i18n`（`useI18n` + `baseText`） |
| 事件/通信 | Zustand store、`useEventEmitterContextContext` | 事件总线 `@n8n/utils/event-bus`（`createEventBus`），`canvasEventBus` / `nodeViewEventBus` |
| 深色模式 | Tailwind 暗色类 + CSS 变量覆盖 | `[data-theme="dark"]` 选择器（见 `tailwind.config.js` 仅声明 dark mode 策略，主题扩展为空，样式主力是 SCSS Module） |

**关键差异一句话**：Dify 是「React + Tailwind 原子类 + 语义 CSS 变量」的声明式 UI；n8n 是「Vue 3 + SCSS Module + 设计令牌 + 组件库」的强类型、样式模块化 UI。两者都把画布选择为 `reactflow` / `vue-flow` 这一同宗（fork 关系）的引擎。

## 4. 分析方法说明

- **以代码为据**：每一条结论均附 `文件:行号` 引述（如 Dify `web/app/components/workflow/run/index.tsx:104`、n8n `…/features/workflows/canvas/components/elements/nodes/CanvasNode.vue:109`）。
- **同维度对比**：每个维度先讲 Dify 实现、再讲 n8n 实现，最后以对比表收口，便于直接对照。
- **聚焦前端**：仅分析前端可观测的视觉与交互实现，不展开后端执行引擎细节（n8n 的 `n8n-workflow` 与 Dify 的后端 API 仅作为数据源提及）。
- **版本局限**：分析基于镜像时的 `main`/`master` 分支快照，具体行号随上游演进会变动，引用时请以实际分支为准。
