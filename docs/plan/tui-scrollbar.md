# TUI 滚动条设计

对照对象为 `ref/opencode` 的滚动条能力，目标是判断当前项目 TUI 是否引入同类能力，并给出最小可用落地范围。

## 现状事实

### opencode 的做法

滚动条是画布内单列覆盖层，不是终端原生滚动条。承载体是统一滚动容器，滚动条以外观选项挂载其上，含轨道与滑块颜色、是否可见、右侧预留一列边距。主会话默认关闭，由配置项与切换命令控制；侧栏与补丁查看器常开；迷你表单类在内容超出视口且非单色模式时条件显示；其余大量可滚区域隐藏滚动条但保留滚动能力。滚动位置来自容器自身状态，键盘翻页与鼠标滚轮驱动，另有吸底与滚动加速度配置。主题侧只定义一个滑块语义色，轨道色复用所在表面色。

### 当前项目的做法

全仓无滚动条组件。位置反馈依赖文字：主会话右下浮动回尾徽标携带隐藏行数，详情窗格用尾行附加剩余行数与按键提示，历史浮层用底状态行说明加载与按键。滚动状态本身已完备：主会话以距尾行数记录偏移并在绘制时钳制，历史浮层同理，设置与详情以顶部偏移记录，文件与补丁查看器共享顶部偏移结构。渲染后端为 `ratatui`，经 `crossterm` 输出，具备增量重绘与预排缓存。

### ratatui 的支持情况

经 `ctx7` 文档查询与本地 `registry` 源码核对，当前工作区 `ratatui` 版本提供有状态滚动条组件：状态含内容总长度、当前位置与视口内容长度，支持右置竖向、隐藏首尾箭头、自定义轨道与滑块符号及样式，以有状态方式渲染进同一缓冲。该能力与现有滚动状态可直接换算，技术上可行；交互仍需复用现有键盘与滚轮通路，组件本身不处理拖拽。

## 可借鉴的设计

### 共享位置与职责

在 `tui-components` 新增独立滚动条模块，`tui-render` 复用。模块只做三件事：按总行数与视口行数判断是否显示，按窄终端阈值隐藏，以及把顶部起始位置换算为组件状态并画到预留单列。调用方在绘制边框后把内容区拆出一列给滚动条，内容绘制宽度相应减一。顶部偏移与距尾偏移两种语义由换算函数统一，调用方无需理解组件细节。

### 可见性与布局规则

仅当内容超出视口且视口高度满足最小值时显示；终端过窄时一律隐藏，避免挤压内容。详情与设置等无宽度相关预排的区域采用单遍绘制，内容被裁一列。历史浮层内容行需按宽度换行，采用两遍换行以避免文字丢失：先按全宽换行判断，显示时再按减一列宽度重新换行。主会话因预排缓存以宽度为键，预留边距会引起全量重排，本次不纳入改造，继续沿用回尾徽标，留作二期可选。

### 主题与样式选择

本次不新增主题语义色，滑块复用柔和次级文本色，轨道使用默认弱化样式。理由是新增语义色需改动主题结构体、派生、覆盖与所有穷举匹配， blast 半径大，而现有次级色对比度已满足装饰性指示需求；后续如需精调再立项扩展主题。

### 各调用点改造

只读查看器共享渲染函数统一加条；执行与工作流详情窗格在渲染边框后拆分内容区与滚动条区；设置屏同理；历史浮层在重算窗口后绘制。管理列表使用选择高亮定位，暂不加条。所有改动不改变按键与滚轮行为，不新增配置项与快捷键。

## 落地顺序与验收

先落共享模块与单测，再依次接入查看器、详情窗格、设置屏与历史浮层。验收以单元测试覆盖可见性判断与两种偏移语义换算，渲染测试保证有条与无条两种布局不断言崩溃，全量校验收敛为一次完整编译检查。主会话滚动条、主题语义色扩展与鼠标拖拽明确不在本次范围。
