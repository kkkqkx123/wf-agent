## 逐文件职责分析与拆分建议

拆分原则：只按职责拆分，不创建替代性新模块；原模块名保留并转为门面重导出；新模块名描述其承担的职责。

### 1. `checkpoint-state/src/state/storage.rs`：职责最多，优先拆分

现状职责：

- 通用结构体构造与配置：结构体定义、若干构造器、时钟与指标注入、底层存储访问器
- 清理水位元数据：键构造、水位读取、水位写入项构造
- 索引元数据文档构造：参数聚合体、元数据文档组装
- 链信息计算：快照链归属推导
- 查询：按实体查最新、按父实体查最新
- 清理与回收：单实体清理执行、通用清理、策略清理、并发锁表
- 压缩：增量链合并与后继修复
- 持久化特征实现：保存、加载、批量加载、删除、按实体分页列举、计数、取最新、元数据加载
- 载荷解析辅助：一组自由函数负责字段提取、类型推断、标签与自定义字段解析、存储元数据解析
- 加载器特征实现：单点数据加载与元数据加载
- 测试：二十余个异步单测覆盖保存加载、清理水位、并发、压缩、指标

判断：必须拆分。生产代码超千行，且持久化、查询、清理、压缩、元数据解析五类职责耦合在同一泛型结构体上。

建议拆分方向：

- 保留 `storage.rs` 为门面，仅保留结构体定义、构造器与重导出
- 按职责新建同级子模块：元数据文档构造与解析、链信息与压缩、查询、清理水位与回收、加载器实现
- 测试按职责随模块迁移，或统一移入集成测试目录，避免单个文件尾部堆积千行测试

### 2. `wf-checkpoint/src/coordinator/workflow.rs` 与 `agent.rs`：重复度最高，优先拆分

两个文件体量相近，结构几乎镜像：

- 进度坐标：坐标结构体、坐标渲染为字段、从存储元数据解析坐标、从快照计算坐标、哈希与指纹辅助
- 协调器装配：结构体定义、十余个链式配置方法、时钟与策略访问器
- 内容策略：写前过滤逻辑
- 版本迁移：旧格式加载、基线查找
- 子层级恢复：子恢复结果类型、层级发现与恢复、单子恢复辅助
- 协调器特征实现：准备、构建、持久化、校验、恢复、删除、类型判定、默认策略、事件总线
- 文件快照与异步持久化队列：快照保存、入队、等待排空、开关判断
- 扩展操作：带父关联准备、带层级准备、描述回写、重复复用
- 时间线：代理侧时间线查询与标签推导，工作流侧坐标往返逻辑
- 测试：三十个左右单测覆盖准备构建持久化恢复全链路

判断：两个文件都必须拆分，且应联合治理。两协调器的大部分逻辑同构，长期各自演进会放大分歧。

建议拆分方向：

- 将两协调器公共部分下沉到已有的 `coordinator/base.rs`：异步持久化队列、文件快照保存、子层级恢复、版本迁移、重复复用与描述回写
- 各协调器目录下按职责分离：进度坐标、内容策略、特征实现主体、扩展操作
- 保留 `workflow.rs` 与 `agent.rs` 为薄编排层，仅保留结构体装配与特征委托
- 时间线查询单独成模块，避免与持久化主路径耦合

### 3. `checkpoint-base/src/delta/calculator.rs`：双计算器耦合，建議拆分

现状职责：

- 共享基础：消息差异三元组类型、变量删除标记常量与判定辅助
- 工作流差异计算器：差异计算、增量应用、消息差异、变量差异、消息上下文差异、节点结果差异、其他字段差异
- 代理差异计算器：差异计算、增量应用、追加式消息差异、其他字段差异
- 测试：工作流与代理各一组往返测试

判断：需要拆分。两个计算器面向不同快照类型，仅共享少量标记语义，放在同一文件导致各自的差异分支互相干扰。

建议拆分方向：

- 保留 `calculator.rs` 为重导出门面
- 新建工作流计算器模块与代理计算器模块，各自收拢其差异分支
- 变量删除标记与消息差异公共语义独立为基础模块，供两者共享

### 4. `checkpoint-file/src/git_store.rs`：底层存储大单体，建议拆分

该文件测试仅百余行，超标几乎全部来自生产代码，是最纯粹的大单体。现状职责：

- 冻结规则与常量：仓库目录名、五类引用前缀、提交附注键、系统提交者身份、重试上限、文件模式
- 错误类型：存储错误枚举与标准输入输出错误转换
- 数据类型：树条目、提交解析结构及其附注访问器
- 纯辅助函数：附注解析、十六进制判定、二进制判定、文件内容合并、文件映射合并、引用名构造
- 底层对象操作：初始化、引用路径换算、引用存储访问、过期锁清理、引用事务编辑、引用读写、比较交换、删除复制列举、对象库访问、数据查找、_blob_ 与树读写、树扁平化、从父树构建树、提交读写、基于引用的提交、日志遍历、全量遍历、祖先判定、合并基点、冲突列举
- 提交消息构造：消息组装辅助
- 测试：引用往返、并发比较交换、空提交跳过、树往返、合并语义、祖先判定

判断：需要拆分。引用管理、对象读写、合并语义三类逻辑交织，引用命名策略与底层对象操作耦合。

建议拆分方向：

- 保留 `git_store.rs` 为门面，重导出核心类型与常用函数
- 按职责分离：引用管理、对象读写、合并与冲突、提交消息与附注、错误类型
- 常量策略集中一处，避免引用前缀散落在读写逻辑中

### 5. `checkpoint-file/src/provenance.rs`：只读查询大单体，建议拆分

测试仅二十余行，超标全部来自生产代码。现状职责：

- 视图模型：变更摘要、分区视图、工作区文件、文件差异种类与视图、冲突文件、文件时间线条目与时间线
- 提交扫描辅助：路径过滤、意图行提取、单提交展开、按执行者归集、全量引用列举、引用分类
- 查询接口：一组自由函数负责分区列举、按执行者查变更、按路径查变更、工作区获取、主线与协作目标获取
- 差异：工作区比较、文本差异、执行者间比较、与主线比较、相似度与行数辅助
- 冲突：标记冲突解析、冲突列举
- 时间线：单文件时间线
- 索引：来源索引重建、未解决合并查询、工作区条目转换
- 门面：只读器结构体委托上述全部自由函数

判断：需要拆分。查询、差异、冲突、时间线、索引五类只读能力共用同一文件，新增一种查询即扩大该文件。

建议拆分方向：

- 视图模型独立为模型模块
- 扫描辅助、查询接口、差异、冲突、时间线、索引各自成模块
- 保留 `provenance.rs` 与只读器为门面，仅做委托

### 6. `checkpoint-file/src/file/manager.rs`：测试推高，暂缓生产拆分

生产代码约五百余行，未超标；尾部六百余行测试将其推过阈值。现状职责：

- 数据模型：文件状态、文件检查点投影及其别名、检查点元数据、文件内容条目、选项、恢复结果
- 管理器装配：结构体定义、克隆实现、时钟与事件总线注入、指标挂载、存储打开、配置打开、工作区绑定、内存模式构造
- 检查点主路径：创建与恢复
- 哈希与差异小工具
- 来源查询委托：一组薄委托方法转发到来源查询模块
- 测试：二十余个单测覆盖创建恢复、哈希差异、分区隔离、审批合并、冲突流程

判断：暂不做生产代码拆分，优先做测试分流。若硬按生产职责拆分，会制造过度碎片。

建议方向：

- 数据模型独立为模型模块，管理器仅保留装配与主路径
- 测试移入集成测试或按主题拆分为多个测试模块
- 来源查询委托保持现状，避免为薄转发新建模块

### 7. `checkpoint-state/src/restore/hierarchy.rs`：概念混装，中长期拆分

生产代码约四百余行，未超标；测试约四百行将其推过阈值。但生产部分装入三个正交概念：

- 子解析：解析特征、内存实现、缓存装饰器与缓存清理辅助
- 子发现：发现器、发现加载器特征、发现结果与汇总
- 恢复事务：事务主体、事务结果与状态、恢复操作与类型、操作状态、回滚策略

判断：总量未超标但内聚性差，建议中长期拆分。三个概念各自有独立演进轴，混装会导致修改互相影响。

建议拆分方向：

- 按上述三概念分为三个模块，保留 `hierarchy.rs` 为重导出门面
- 事务执行与回滚逻辑独立，避免与发现广度遍历耦合
- 测试随模块迁移

## 拆分优先级

1. 高优先级：两个协调器与存储管理器。三者生产代码均超千行，且处于写路径核心，改动风险最大，收益也最大。建议先抽公共异步持久化与子层级恢复，再瘦身各自特征实现。
2. 高优先级：底层对象存储与差异计算器。前者是文件历史的唯一真相来源，后者是增量链正确性的核心，两处逻辑错误影响面大，拆分后更易单测。
3. 中优先级：来源查询模块。纯只读但生产代码超八百行，拆分风险低，可作为拆分手感的起点。
4. 低优先级：文件管理器与层级恢复。当前超标主要由测试贡献，先做测试分流与概念分层即可，不必立即动生产路径。
5. 观察对象：清理策略文件接近阈值，本次不拆分，后续若继续增长再评估。

## 通用注意事项

- 拆分只按职责进行，不引入替代性实现；原文件名保留为门面并重导出，保持外部引用稳定。
- 新模块名描述其承担的职责，避免比较性命名。
- 拆分过程中保持包依赖有向无环，内部模块不得回指门面。
- 测试迁移与生产拆分同批次完成，避免门面文件尾部继续堆积。
- 每批拆分后运行全量编译检查，集中验证，减少重复编译次数。
