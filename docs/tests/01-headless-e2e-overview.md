# 01 无头集成测试总览

## 目标

以最贴近生产调用的方式验证服务端与客户端的集成：启动真实 `wf-server` 进程，以 `wf-headless` 二进制作为唯一客户端驱动，覆盖建连、鉴权、目录作用域、业务调用、输出渲染与退出码。测试不关心大模型回答质量，只关心链路正确性与行为可重复。

## 为何选用无头形态

无头形态是面向脚本与自动化的单次语义：一次调用执行一条命令后即退出，不保留跨调用状态，提示词与管理命令均走同一套参数解析与连接探活。管理类命令直接分发，单次会话走无头会话管线，全屏探针明确拒绝并指引全屏二进制。该形态与生产脚本共用同一实现，因此测试结论可直接迁移到真实使用。

关键性质包括：纯客户端定位，所有能力经 `wf-client` 访问服务端；先解析远端地址与凭证并探活健康端点，失败时给出可操作的启动提示；业务内容走标准输出，诊断走标准错误，管道下自动关闭颜色；四档输出格式中结构化档位适合机器断言。

## 测试边界

覆盖范围为传输与装配层：路由挂载、信封封装、中间件、目录中间件、客户端连接解析、命令分发、输出包络渲染、退出码映射。不覆盖全屏与行式会话的交互外壳，不覆盖引擎内部语义，不覆盖前端页面。引擎语义由各 crate 单测与离线调试器覆盖，交互外壳由演示示例与黄金输出覆盖。

## 分层策略

用例按外部依赖程度分层，默认只运行无外部依赖的层级：

- 健康与元信息层：健康探针、服务信息、模式诊断。无状态，总是可运行。
- 只读管理层：工作流与执行体的列表与展示、图结构检视、工具与技能与模板的列表展示、统一检索与指标快照、存储健康透传。只读，无外部依赖。
- 有状态管理层：工作流定义的校验、创建、展示、更新、删除、克隆、导入导出。依赖本地存储，不依赖外部服务，通过内存存储实现隔离。
- 本地执行层：仅含无模型节点的流程执行与等终态观察。依赖本地脚本执行能力，不依赖外部大模型。
- 真模型会话层：单次智能体会话。依赖外部大模型配置，仅手工触发，不进入默认门禁。

默认门禁包含前四层中的确定性子集，真模型层始终手工运行。

## 与离线调试器的分工

离线调试器回答流程语义是否正确，输入是追踪文件，判据是维度分析与断言。集成测试回答服务是否可达与调用是否正确，输入是真实命令，判据是退出码与输出包络。新增调试维度时扩展调试器视图与断言；新增服务端端点时扩展集成测试用例。两者共享固件与黄金输出的组织习惯：输入版本化入库，输出可检视，实际运行产物与期望分离存放。

## 确定性原则

服务端以内存存储启动，监听临时端口，业务目录指向隔离的临时工作区，不读取开发机全局配置。客户端每次调用显式传入远端地址、业务目录、结构化输出格式与颜色关闭，不依赖环境默认值。断言只针对包络中的稳定字段，对时间戳与标识符先做归一化再比较。运行顺序固定为串行，单个用例使用唯一标识，用例结束即清理所建数据。
