# 视觉风格与设计令牌对比

本文比较三套前端的视觉系统：色彩模型、主题切换、排版、圆角/阴影/边框、密度、动效，以及当前项目中的规范漂移。

## 1. 样式方案总览

| 项目 | 方案 | 令牌载体 | 主题切换 |
| --- | --- | --- | --- |
| 当前项目 | Tailwind v4 CSS-first + `@wf-agent/ui` tokens | `app.css` 的 `@theme inline` 映射到 HSL 三通道变量；`@wf-agent/ui/styles/tokens.css` 定义原始值 | `.dark` 变体（`app.css:5`），变量级切换 |
| n8n | SCSS Modules + `@n8n/design-system` | `_tokens.scss` 的 `@mixin theme`（light/dark 两套）；`_tokens.legacy.scss` 兼容层 | 主题 mixin + CSS 变量 |
| Dify | Tailwind v4 + `@langgenius/dify-ui` | `tailwind-core.css` 的 `@theme`/`@theme inline`；`themes/manual-light.css`、`manual-dark.css` | `html[data-theme='light'|'dark']` |

三者都采用「原始变量 → 语义变量 → 工具类」的三层结构，差异在语义命名的粒度与主题切换方式。

## 2. 色彩模型

### 2.1 当前项目：HSL 三通道 + 语义映射

- 原始色以 `H S% L%` 三通道存储，使用时拼 `hsl(var(--x) / alpha)`（`docs/design-tokens.md:8`）。
- `app.css` 把每个语义色映射为 Tailwind 颜色工具：`--color-background`、`--color-card`、`--color-primary`、`--color-muted`、`--color-destructive`、`--color-success`、`--color-warning`、`--color-info`、`--color-running`、`--color-brand`、`--color-border`、`--color-sidebar`、`--color-chart-1..5`、`--color-code-*`（`apps/web-app/src/app.css:8-52`）。
- 品牌色 `--brand: 24 95% 53%`，运行态 `--running: 252 56% 54%`（`docs/design-tokens.md:18-19`）。

优点：透明度组合灵活（`hsl(var(--x) / 0.1)`），语义色覆盖完整；风险：所有层都依赖「三通道」格式，接入非 HSL 来源（oklch、十六进制）时需要转换。

### 2.2 n8n：SCSS 主题 mixin + 双横线命名

- `@mixin theme` 内定义 `--background--brand`、`--background--surface`、`--border-color`、`--text-color`、`--icon-color`，以及 success/warning/danger/info 四组 `background/border-color/text-color/icon-color`（`docs/ref/n8n/packages/frontend/@n8n/design-system/src/css/_tokens.scss`）。
- `--border` 是复合令牌：`var(--border-width, 1px) var(--border-style, solid) var(--border-color)`（`:26`）。
- `--color--primary: var(--color--neutral-900)`（`:37`），焦点边框 `--focus--border-width: 2px`（`:67`）。
- 画布专用令牌：`--canvas--color--background`、`--canvas--dot--color`、`--canvas--color--selected-transparent`、`--canvas--label--color--background`（`:78-84`）；节点专用：`--node--color--background`、`--node--color--background--executing`、`--node--border-color--pinned/running`（`:87-91`）。
- 暗色是另一套完整变量（`:683-777`）。

`_tokens.legacy.scss` 解释了双横线命名的迁移策略：`--color--primary` 与旧 `--color-primary` 并存，通过 CSS 变量 fallback 兼容嵌入方（`_tokens.legacy.scss:16`、`:37`、`:45`）；并保留 `--color--primary--h/s/l` 三通道（`:29`）。这说明 n8n 的令牌层同时承担「内部语义」与「外部兼容」两种职责。

### 2.3 Dify：语义工具类 + 渐变主题

- `tailwind-core.css` 用 `@layer theme, base, components, utilities` 明确层序（`:8`），并引入 `@langgenius/dify-ui/styles.css`（`:20`）与 `manual-light/dark.css`（`:23-24`）。
- `@theme` 定义断点与字体：`--breakpoint-mobile: 100px`、`tablet: 640px`、`pc: 769px`、`2k: 2560px`；`--font-sans` 去除 emoji 字体族（`:36-59`）。
- `@theme inline` 把主题文件中的变量映射为 Tailwind 工具（`:67` 起）。
- 主题文件按 `html[data-theme='light']` 定义大量渐变：`--color-workflow-process-bg`、`--color-workflow-process-paused-bg`、`--color-workflow-process-failed-bg`、`--color-workflow-run-failed-bg`、`--color-app-detail-bg` 等（`docs/ref/dify/web/themes/manual-light.css:2-66`）。
- 组件层直接使用语义类：`bg-components-panel-bg`、`border-components-panel-border`、`text-text-primary`、`text-text-tertiary`、`bg-background-section-burn`、`border-divider-subtle`、`system-sm-semibold-uppercase`（`nodes/base.tsx:37-72`、`run/index.tsx:183`、`workflow-log/list.tsx:163`）。

Dify 的特点是「令牌名即用途」：`components-panel-bg`、`divider-subtle`、`text-tertiary` 这类命名让组件代码几乎不需要知道具体颜色；代价是语义类数量膨胀，命名空间较长。

## 3. 主题与暗色模式

| 项目 | 切换方式 | 覆盖范围 |
| --- | --- | --- |
| 当前项目 | `.dark` 类 + `@custom-variant`（`app.css:5`） | 全部语义色与阴影 |
| n8n | 主题 mixin 生成 light/dark 变量集 | 画布、节点、按钮、表格、日志面板均有独立暗色值（`_tokens.scss:683-777`） |
| Dify | `data-theme` 属性 + 两份 manual 主题文件 | 渐变、画布、聊天、应用详情背景 |

当前项目与 Dify 都采用「根元素标记 + 变量切换」，n8n 则是编译期 mixin + 运行时变量。对新增组件的友好度：Dify 最好（写语义类即可），当前项目次之（写 `bg-card` 即可），n8n 需要确认新组件是否引用了主题作用域内的变量。

## 4. 排版

| 项目 | 字号体系 | 字体 |
| --- | --- | --- |
| 当前项目 | 六档：heading/title/body/caption/small/micro，均乘 `--font-scale`（`docs/design-tokens.md:31`） | Inter + 系统中文字体；JetBrains Mono 等宽（`app.css:59-65`） |
| n8n | 以 design-system 文本组件与 SCSS 变量为主，日志/画布有局部字号（画布节点 10/9px 级别） | 系统字体栈 + 局部等宽 |
| Dify | `system-*` 工具类：`system-sm-semibold-uppercase`、`system-xs-medium-uppercase`、`system-2xs-medium-uppercase` | `--font-sans` 去除 emoji 族（`tailwind-core.css:46-59`） |

当前项目的六档字号与密度联动（`--font-scale` 0.94/1/1.06，`docs/design-tokens.md:41`）是三家唯一把「字号缩放」作为一等令牌的实现；Dify 通过组合类（尺寸 + 字重 + 大小写）表达排版，读代码时信息更完整，但组合爆炸；n8n 更依赖组件默认值。

画布字号是例外：当前项目节点 10px、边 9px（`canvas-style.ts:20`、`:114`），n8n/Dify 的节点标题分别为 design-system 文本与 `system-sm-semibold-uppercase`。当前项目的画布字号未接入六档体系，属于硬编码。

## 5. 圆角、阴影、边框

### 5.1 当前项目

- `--radius-sm/md/lg/xl` 由 `--radius` 派生（`app.css:54-57`），`--radius` 本身乘 `--density-scale`（`docs/design-tokens.md:30`）。
- 阴影：`--shadow-frost`、`--shadow-popover`（`app.css:74-75`）。
- 边框：全局 `* { border-color: hsl(var(--border)) }`（`app.css:85-87`）。

### 5.2 n8n

- 圆角：`--radius--xl: 1.125rem`、`--radius--lg: 1rem`、`--radius--sm: 0.75rem`，并支持旧变量 fallback（`_tokens.legacy.scss:108`）。
- 阴影：`--shadow`、`--shadow--dark`、`--shadow--light`、`--shadow--card-hover`（`_tokens.legacy.scss:95-106`）。
- 边框：节点 1.5px，状态态使用 `--spacing--5xs`（`_canvasNodeStyles.scss:4`、`:30-41`）；面板用 `var(--border)` 复合值。

### 5.3 Dify

- 圆角以任意值类为主：`rounded-2xl`、`rounded-[15px]`、`rounded-[10px]`、`rounded-b-xl`（`nodes/base.tsx:26-37`、`run/node.tsx:146`、`run/index.tsx`）。
- 边框常见半像素：`border-[0.5px]`（`workflow-panel/index.tsx:637`、`run/index.tsx:183`）。
- 阴影：`shadow-xs` → hover `shadow-lg` / `shadow-md`（`nodes/base.tsx:36-37`、`run/node.tsx:146`）。

Dify 的「半像素边框 + 大圆角 + 轻阴影」形成明显的浮层质感；当前项目更接近「平面分栏」；n8n 介于两者之间，画布元素用边框与状态环，面板用复合边框令牌。

## 6. 密度

| 项目 | 密度机制 |
| --- | --- |
| 当前项目 | `--font-scale` 与 `--density-scale` 双变量，三档 0.92/1/1.08（`docs/design-tokens.md:41-42`） |
| n8n | `--spacing--*` 阶梯 + 面板固定宽（310px 侧栏、120×200 小地图） |
| Dify | 断点令牌 + 固定面板宽（节点 240px、NodePanel 最小 400px） |

当前项目是唯一提供「全局密度档」的实现；n8n/Dify 通过固定尺寸与局部 padding 控制密度，切换成本更高。

## 7. 动效

| 项目 | 动效 |
| --- | --- |
| 当前项目 | `--ease-out-expo`、`--ease-standard`（`app.css:77-78`）；`animate-panel-in`、`animate-overlay-in`、`animate-toast-in`、`animate-pulse-dot`（`:221-235`）；`prefers-reduced-motion` 降级（`:237`） |
| n8n | 画布 300ms 淡入（`Canvas.vue:2239-2244`）；运行态 `conic-gradient` 旋转，running 1.5s / waiting 4.5s（`_canvasNodeStyles.scss:57-63`）；日志列表 `TransitionGroup`（`WorkflowExecutionsSidebar.vue:231`） |
| Dify | `--animate-spin-slow`（`tailwind-core.css`）；节点 hover 阴影过渡；无统一 reduced-motion 令牌（本次快照未见） |

当前项目在「统一动效令牌 + 可访问性降级」上最完整；n8n 的动效更贴近画布语义（运行/等待）；Dify 的动效最克制。

## 8. 规范漂移与硬编码

当前项目的 `docs/spec/web/style-guide.md` 明确禁止硬编码色值、自创圆角阴影、仅用颜色区分状态。但在画布层存在直接违反：

- `apps/web-app/src/lib/graph/canvas-style.ts:14`：节点背景 `#18181b`。
- `:116`：边标签文字背景 `#18181b`。
- `:166`：分组标题背景 `#52525b`。
- 节点/边字号 10/9 未接入六档字号（`:20`、`:114`）。

这些值不会随 `.dark` 或主题切换，也不会跟随 `--density-scale`。相比之下：

- n8n 的画布色全部走 `--canvas--*` / `--node--*` 令牌，暗色在 `_tokens.scss:765-777` 成对定义。
- Dify 的画布背景/点色走 `bg-workflow-canvas-workflow-bg` 与 `var(--color-workflow-canvas-workflow-dot-color)`（`workflow/index.tsx:799`）。

这是当前项目最值得优先修复的视觉一致性问题。

## 9. 结论

1. **令牌完备度：当前项目 ≈ n8n > Dify。** 当前项目的语义色覆盖最全且带密度档；n8n 的画布/节点专用令牌最细；Dify 的语义类最好用但缺少统一密度机制。
2. **主题一致性：n8n > Dify > 当前项目。** 前两者画布颜色全部令牌化；当前项目画布层存在硬编码，暗色下会出现不协调。
3. **排版一致性：当前项目 > Dify > n8n。** 当前项目有六档字号与缩放；Dify 有完整组合类；n8n 更依赖组件默认值。
4. **视觉质感：Dify 最「浮层化」，n8n 最「工程化」，当前项目最「平面化」。** 这没有绝对优劣，但与当前项目「高信息密度 + 多面板」的定位相比，平面分栏会削弱层级感。

## 10. 建议

1. 把 `canvas-style.ts` 的所有颜色改为读取 CSS 变量（可通过 `getComputedStyle` 或预定义 `var(--...)`），并补暗色值。
2. 画布字号接入 `--text-micro` / `--text-small` 或新增 `--canvas-node-font-size` 令牌，避免 9/10px 游离在体系外。
3. 为选中环、运行态边框引入缩放补偿变量（参考 n8n `--canvas-zoom-compensation-factor`）。
4. 统一面板的「半像素边框 + 圆角 + 阴影」组合，明确哪些面板是分栏、哪些是浮层。
5. 在 `@wf-agent/ui` 中补一组状态语义类（success/warning/danger/running 的 bg/border/text 三件套），减少组件内拼色。
6. 为动效补充 `prefers-reduced-motion` 覆盖到画布动画（当前仅覆盖全局 keyframes）。
