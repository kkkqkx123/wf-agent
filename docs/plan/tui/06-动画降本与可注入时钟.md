# 动画降本与可注入时钟

## 本文参考的 jcode 设计

| jcode 设计 | 位置 | 本文取用的部分 |
| --- | --- | --- |
| 纯数学动画核独立 crate | `jcode-tui-anim`：3D 光线步进采样、字形选择、HSV→RGB，无 UI 依赖 | "先集中纯函数、最后评估拆 crate"的路线参照 |
| 查找表消除每帧超越函数 | 同 crate：固定角度序列的 `cos`/`sin` 预计算，去掉约 99% 每帧调用，且逐位精确 | 指示符查表、相位表的思想来源 |
| 构建级优化隔离 | 工作区 `Cargo.toml` 的 per-package `opt-level = 3`，dev 构建仍完全优化 | wf 若拆 crate 需在根 `Cargo.toml` 登记同类配置的说明 |
| 确定性刻意保证 | 同 crate：查找表精确重放原浮点累加顺序，与优化级别无关 | 查表/三段化改写必须与旧实现逐帧等价的验收依据 |
| 可注入时钟 | `jcode-tui` `tui/test_harness.rs` 的 `TestClock`（`advance` / `set` / `now_ms`）与 `SimulatedInstant` | wf 时钟抽象的接口形态 |
| 时钟全局启用开关 | 同文件：`OnceLock<RwLock<TestClock>>` + `TEST_CLOCK_ENABLED` 原子开关 | 测试形态生效、不污染产品路径的实现方式 |
| 动画帧与区域可断言 | `ui_animations.rs` 的 `IDLE_VARIANTS` 与 `LAST_IDLE_ANIMATION_AREA`（测试态换 `TEST_LAST_IDLE_ANIMATION_AREA`） | 时钟加区域记录组合使"第 N 帧字符"可断言 |
| 动画帧率独立配置 | `jcode-config-types` 的 `display.animation_fps`（1..=120） | 动画时刻分桶的帧率参数来源 |

需要说明的对应关系：wf 的"扫光三段 span"是针对每字符分配问题的直接推导，jcode 无逐条对应物；jcode 对应的通用思想是上表的"预计算与查表复用热点动画计算"。

## 现状

动画相关代码分布在 `crates/app/cli/wf-tui/src/animation.rs` 与 `crates/app/cli/wf-tui/src/motion.rs`。控制器每次查询都读取真实时间，扫光方法每次调用都读取真实时间并为每个字符构造一个文本片段与颜色。指示符方法同样依赖传入的起始时刻做取模，调用方传入真实时间。

这种写法有两个代价。一是每帧分配量与文本长度成正比，流式行越长成本越高。二是时间不可注入，动画帧、通知存续、重绘节奏都无法在测试中确定性复现，只能用睡眠等待或放宽断言。

排版方法在动画激活时会走扫光分支，意味着动画时刻的变化会污染排版缓存的失效判断。若不分离动画时刻与内容版本，准备缓存将因动画而频繁失效。

对照 jcode，差距在于缺少纯数学的动画核与全局可替换时钟。jcode 把热点数学下沉为无依赖的数值逻辑并用查找表消除重复超越函数调用，时间查询走可注入的模拟时钟，测试时推进时钟即可断言具体帧。

## 修改目标

让动画成本与文本长度解耦，让时间相关行为可离线断言，让动画推进不再污染内容缓存。

## 方案

时钟先行，降本随后。新增一个时钟抽象与两种实现：系统时钟基于单调起点换算毫秒，测试时钟基于可推进的计数。改造范围按顺序为动画控制器、扫光方法、通知队列的存续判断、交互控制器的时刻方法、按键双击判断。帧率限制器已经是注入式，保持一致即可。改造后所有动画接口接收时刻参数，不再自行读取真实时间。

扫光方法的降本抓住高亮带宽度固定的特点。高亮带只占文本长度的一小部分，带外字符可共用同一个暗色片段。把按字符分配改为按三段分配：前暗段、带内亮段、后暗段，分配量从与长度成正比降为常数量级。颜色插值保持现有视觉效果不变，扫掠周期与带宽保持不变。

指示符方法改为查表。旋转帧表与脉冲表采用常量数组，帧序号由时刻与帧率换算，避免每次重复计算周期。扫掠相位表可在稳定后引入，当前阶段先完成三段化即可获得主要收益。

动画时刻进入缓存键时必须按桶离散化，避免每帧失效。桶宽度取百毫秒量级，静态内容在桶内保持命中，只有流式行首的装饰段随桶更新。内容版本号与动画时刻分离存储，判定函数区分两者。

是否拆分为独立 crate 放在最后评估。拆分的收益是调试构建下热点数学仍保持高优化级别，代价是新增工作区成员与包级编译配置登记。当前阶段先把纯函数集中在现有动画模块并消除时间依赖，便于后续整体搬迁而不改变接口语义。

## 与现有模块的衔接

动画模式的三档语义保持不变，精简与静态模式继续走无动画路径。排版方法保留动画分支的对外行为，只是时间来源改为参数传入。通知存续的语义保持不变，只是时间来源可注入。

## 验收

动画测试可断言具体帧字符而无需睡眠，通知在推进后的恰当时刻消失。扫光方法的片段分配从与长度成正比降为常数量级，视觉效果与之前一致。静态内容不因动画时刻推进而重排。

## 风险与回退

主要风险是时钟替换遗漏导致新旧时间混用。缓解方式是按模块逐个替换并在编译期禁止直接读取真实时间的关键路径。若视觉出现差异，保留旧扫光路径作为对照实现并做像素级等价测试。
