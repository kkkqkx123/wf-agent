# simvec 过滤加速路径分析与立项说明

本文分析 simvec 过滤加速路径的现状缺口，并回答是否需要补充功能。结论是正确性层面无需补充，加速层面暂不补充；先补可观测性并定死触发条件，出现热点后再按性价比排序立项。与《向量抽象层剩余任务说明》的关系：本文是其中 R1（延后算子）落到 simvec 引擎侧的性能视角，触发式原则与回归约束两边一致。

## 现状：保守预过滤加全量后过滤

simvec 的过滤分两层。预过滤掩码只做候选剪枝，三个检索扫描路径与按过滤删除最终都用全量过滤器求值裁决。后过滤是真值来源，预过滤允许多收、绝不漏排，即使掩码全空，结果依然正确。这是判断一切加速工作的前提。

当前被加速的只有必含位置的等值条件（经等值位图或逐字段映射索引）与已声明数值索引字段上的区间条件。其余一律回退后过滤。计划过程中的记账字段目前只有掩码被实际消费，选择了哪些索引的信息尚无读取方，这是现成的可观测性钩子。

批次 3 新增的语义在求值层已闭环，在加速层全部正确回退：等值位图与两类字段索引对新条件类型走通配分支返回空，任何含分支组的过滤器直接放弃整掩码。加速覆盖缺口真实存在，但不影响正确性。

## 缺口清单

按潜在收益排序。分支组整组放弃加速，组内若含等值分支，本可复用现有掩码做并集。点标识集合检索仍全量扫描，本可短路直取再补剩余过滤。前缀查询受无序哈希键空间所限只能后过滤，有序词典在结构上可行但需新索引结构。长度与存在性尚无对应位图，长度可复数值索引思路，存在性一比特一位图即可，但都是窄收益。通用子串索引代价大收益低，不应考虑。区间落在未声明索引字段上回退是批次 3 之前就有的行为，非新增缺口，不在此立项。

## 现在不补充的理由

过滤新算子刚随批次 3 落地，尚无调用方在规模数据上使用，更无热点证据，提前建索引属于防御式投入。每个新索引结构都要配套持久化、写入增删路径、变容、重启重建与一致性测试，是实打实的正确性负担扩大。最高频场景即命名空间与来源过滤本就是等值，正好落在现有加速内；新算子多为低选择性或临检性质，单点求值廉价，后过滤与端内精确扫描基线同复杂度，可接受。simvec 定位是嵌入式端内引擎，向量侧已有分层索引与量化投入，载荷过滤保持等值尽力加速、其余正确回退是与其定位相称的取舍。

## 触发后再补的排序

第一位是可观测性先行，也是唯一现在值得做的事。把已有的索引选用记账接到度量，辅以过滤选择率与掩码命中率，压测给出选择性过滤下近邻候选放大倍数与分位延迟数据后再动手。这是立项门槛，不是优化本身。

第二位是分支组掩码组合。零新索引结构，复用等值与区间掩码做并集、阈值计数与内层可加速时的补集；内层不可加速则该分支回退，组整体仍正确。

第三位是标识集合短路。纯标识集合为主的查询直接按标识取点再补剩余过滤，改动小，命中标识列表场景收益确定。

第四位是前缀有序词典。仅当前缀成为实测热点时立项，需逐字段有序结构、写入路径与重启重建，中等成本。

第五位是长度与存在性位图，按需立项。通用子串索引与不可加速内部的取反补集明确不做，仍走回退。

## 触发条件

满足任一即立项对应项：选择性过滤查询的分位延迟回归到压测红线；等值分支为主的分支组查询成为实测热点；标识集合查询在目标规模下可测地慢于直取；前缀查询在目标规模下成为热点。立项前必须先有度量数据，不凭推测动手。

## 回归约束

任何加速立项必须保持保守性即永不漏排，后过滤永远是真值来源。新增索引必须走注册、注销、重建三条路径，并通过重启一致性测试。只修改原模块，不新增替代模块。日志与错误信息英文，注释只描述意图。不做旧数据兼容，不更新版本号。每步通过受影响包的编译检查与单测，编译输出先重定向到文件再阅读，集中为最少次数的验证。
