# 集成测试设计

> 范围：使用 `wf-headless` 作为客户端驱动，对 `wf-server` 与 `wf-client` 链路做黑盒集成测试
> 状态：设计方案，验证载体位于 `e2e/` 目录

`wf-headless` 是共享库的薄二进制，自身不内嵌执行引擎与存储，所有子命令经 `wf-client` 以 HTTP 访问运行中的 `wf-server`。该特性使其天然适合担任集成测试的客户端驱动：一次调用对应一次真实传输，退出码与输出包络即断言依据。

## 目录映射

验证相关内容全部位于仓库根 `e2e/` 目录：可执行产物进入 `e2e/bin`，输入数据位于 `e2e/fixtures`，可检视的期望与实际输出位于 `e2e/outputs`，编排脚本位于 `e2e` 根与 `e2e/lib`。构建产物同步方式见线束设计文档，脚本本身只做复制与版本确认，不做版本升级。

## 与现有调试器的关系

`crates/app/debugger` 做离线回放：输入为录制或手写的追踪文件，不启动服务端；其目录按输入示例与断言测试组织。`e2e` 做在线联调：必须先启动真实服务端，再以无头客户端驱动；其目录按输入固件与输出黄金组织。两者互补：调试器覆盖引擎语义，集成测试覆盖传输、装配与客户端渲染。
