# TUI 输入能力设计：焦点 / 鼠标 / 键盘增强（含粘贴补线）

## 背景与现状

`wf-tui` 的策略对象（`perf.rs`）已经有 `enable_focus_change / enable_mouse_capture / enable_keyboard_enhancement` 三个开关，能力探测（`capabilities.rs` / `probe.rs`）也能给出键盘增强与焦点支持的判断，但两者之间是断开的：终端模式（`terminal.rs` 的 `TerminalModes`）只有 raw、alt screen、bracketed paste、光标四档，事件循环（`tui.rs`）只处理按键与尺寸，其余事件一律丢弃。实际后果有三处：键盘增强从未启用（Shift+Enter 换行、Ctrl+Enter 提交等修饰键语义做不了）；焦点报告从未启用（后台标签页的重绘节奏无法区分）；粘贴处于半启用状态——bracketed paste 已打开，但粘贴事件在事件循环里被丢弃，终端包裹的粘贴内容到不了输入框。

本文给出四个输入能力的完整设计，参考实现见下一节。计划文档按仓库约定只用自然语言描述，不贴实现代码。

## 参考实现对照

jcode（`ref/jcode/crates/jcode-tui`，Rust + crossterm，与本仓库同栈，优先参照）：

- 终端模式的生效点唯一且参数化。进入、恢复、重断言三处都走同一个按开关裁剪的序列输出函数，并有字节级测试断言开 mouse 时含对应序列、关 mouse 时不含。键盘增强在进入时用栈式 push，退出时 pop；运行中重断言用 set 形式，避免 push/pop 失衡。
- 键盘增强的标志位刻意不含全键转义上报。原因是某些终端会把可打印键报成基础键加修饰键，而 crossterm 拿不到键盘布局关联文本，非美式布局的移位符号无法还原。这个取舍直接抄。
- 焦点事件的消费分三层：收到获得焦点时重断言终端模式并请求一帧差分重绘，不做后端整体失效（不清屏，避免大终端切标签时闪烁）；收到失去焦点时只记状态不画帧；任何按键/鼠标/粘贴都视为当前聚焦（部分合成器与多路复用器会丢获得焦点事件，只信事件流会把窗口卡在未聚焦态，重绘被节流到约 1Hz，表现为滚不动）。
- 鼠标策略是用户配置显式开启才捕获；移动事件直接忽略不重绘；滚轮与点击按覆盖层分发；捕获会挡住终端原生选中，为此另有一套复制选中机制。本仓库不抄复制选中，只抄“默认不捕获、移动忽略、滚轮分发”的结论。
- 策略构造的关注点分离：鼠标开关来自用户配置，焦点与键盘开关默认开、仅对已知坏的终端家族关闭；档位只钳制帧率与装饰动画，不决定输入能力开闭。这个分离是本文策略接线的直接依据。

codex（`ref/codex/tui`，Rust + crossterm）：

- 进入序列是 bracketed paste（失败即报错）、raw mode、键盘增强（尽力而为）、焦点报告（非 Windows 开、Windows 关）。退出用比进入更强的键盘重置，防止终端漏掉 pop 导致父 shell 继承增强上报。
- 键盘增强另有环境变量总开关，以及 WSL 下 VS Code 终端的特判（含跨到 Windows 侧读环境变量的探测）。
- 焦点状态用于通知门控（仅在未聚焦时弹通知）。
- 粘贴有独立的状态机处理没有 bracketed paste 的终端（Windows 下粘贴到达是连续按键流）：首字暂扣防闪烁、按时间间隔判定突发、Enter 在突发内视为换行而非提交。这是粘贴部分的后续参照。
- 滚轮支持的首选是 alternate scroll 模式（私有模式 1007，把滚轮转成上下键），不需要鼠标捕获，不影响原生选中。

opencode（`ref/opencode`，TypeScript）：渲染器选项显式关闭鼠标。佐证“鼠标捕获默认关”是多家的共同选择。

## 设计总则

策略对象是唯一事实来源。进入、恢复、重断言、事件分发四处只读策略，不在调用点硬编码序列。任一能力关闭时的字节行为与现状完全一致，这是回退线。

## 终端模式管理

`TerminalModes` 增加焦点报告、鼠标捕获、键盘增强三档；控制平面 trait 与生产实现、测试替身同步增加对应开关；守卫的进入与恢复保持现有差量幂等风格，恢复按进入的逆序执行。panic hook 与现有退出路径补上三档的尽力关闭，键盘用“先弹栈、再强重置”的两段式，防止父 shell 继承增强上报。

运行中重断言（获得焦点时、挂起恢复后、外部编辑器调用返回后）走参数化的序列输出函数：bracketed paste 恒开，焦点与鼠标按策略裁剪，键盘增强用 set 形式重写标志位而不碰栈。面向内存写入器的字节级测试覆盖开与关两种组合。

键盘增强标志位取三项组合，不含全键转义上报（jcode 的布局安全结论）。是否启用的三重门：环境变量总开关（默认开，显式设值可强制关）、能力探测启发式、策略开关。三者任一为否则不 push。

鼠标默认关闭。开启需要用户配置显式 opt-in，同时满足策略开关；上报格式用 SGR 扩展模式。另提供 alternate scroll（1007）作为不捕获鼠标的滚轮方案，默认行为保持现状（滚轮事件在未捕获终端里根本到不了应用层）。

焦点报告的开启条件是策略开关与终端支持矩阵同时成立，Windows Terminal 家族默认排除（焦点事件不可靠）。

## 事件处理

事件循环在按键与尺寸之外新增三类分支，其余保持丢弃。

获得焦点：重断言终端模式，置聚焦态，请求一整帧（差分追赶，不做后端失效不清屏）。失去焦点：只置未聚焦态，不请求帧。任何按键、鼠标、粘贴到达都顺手置聚焦态（合成器丢事件的补偿）。

聚焦态参与帧调度：未聚焦且空闲时跳过装饰性重绘，有实时活动（流式输出、通知存续、待处理范围）时仍画；复用既有的空闲退避间隔，不引入新计时器。通知类打扰行为可按聚焦态门控。

鼠标事件：移动类型直接返回，不记交互、不请求帧；滚轮上下映射为滚动区的上滚/下滚各一行页距（复用既有滚动方法与回放分页触发）；按下、抬起、拖拽在首版忽略（保留终端原生选中的前提是不捕获，捕获开启时按下事件同样忽略，不做选中）。

粘贴事件：按当前聚焦的输入框路由。交互屏进会话输入框，搜索屏进搜索草稿，模态框打开时吞掉。粘贴体作为一个整体字符串一次性插入，不触发任何快捷键语义。这是本次必做的补线（当前粘贴内容被丢弃）。无 bracketed paste 终端的突发启发式状态机列为后续项，不在本次范围。

按键处理利用增强上报的增量收益：修饰 Enter（Shift+Enter 在输入框内换行）、Ctrl+Enter 提交、重复事件（Repeat）与单击的区分、Esc 的精确消歧。每项独立门控，终端不支持时行为回退到现状。

## 策略构造

档位选择函数不动。新增策略组装规则：鼠标来自用户配置（默认关）；焦点默认开，终端在不可靠名单或探测不支持时关；键盘默认开，环境变量、特殊终端组合、探测不支持任一命中时关。档位继续只钳制帧率、动画率与装饰动画。底部状态栏的档位标记不动，不新增展示项。

## 分阶段

第一阶段接通粘贴路由（纯 bug 修复性质）。第二阶段键盘增强的模式管理与修饰键消费。第三阶段焦点报告、聚焦态与重绘门控。第四阶段鼠标：先 alternate scroll 滚轮，再配置门控的全量捕获。各阶段独立可验证，任一阶段回退只需把对应策略开关固定为关。

## 验收

字节级测试覆盖三档开关的进入、恢复、重断言序列；焦点真值表测试覆盖获得/失去/事件补偿三种转移；粘贴路由测试覆盖三个输入框目标与模态框吞掉；关闭三档时的快照与现有行为一致；手动矩阵覆盖主流终端与 Windows Terminal、ssh、tmux 下的行为。

## 风险与回退

键盘误判导致按键错乱时，环境变量总开关与策略开关双线可关；终端漏 pop 由退出强重置兜底。焦点误判导致常驻未聚焦时，默认聚焦与事件补偿保证最多一帧延迟自愈。鼠标开启破坏选中时，默认关与配置门控保证不受影响。新增度量只出现在测试与录制形态，正式路径零开销。
