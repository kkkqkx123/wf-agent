# lazygit 交互模型拆解与可迁移性量化

> 本文回答：lazygit 的交互到底由哪几层构成，以及它的 294 条键位在 Web 上有哪些能直接搬、哪些必须重做。
>
> 基线：`lazygit` @ `a3fae72`。

---

## 1. lazygit 交互模型的四层结构

lazygit 不是「一堆快捷键」，而是四层叠加。理解这四层，才能决定 Web 上该保留什么、替换什么。

| 层 | 作用 | 代码依据 | Web 对应物 |
|---|---|---|---|
| **Context（上下文）** | 一个可聚焦的逻辑面板，拥有自己的数据、渲染与键位表 | `pkg/gui/context/setup.go:5-137`（30 个节点） | 侧栏面板 / 主视图窗格；「当前焦点面板」 |
| **Binding（绑定）** | `(ViewName, Key) → Handler`；`ViewName=""` 为全局 | `pkg/gui/keybindings.go:81-296`（全局）、`:298-309`（context 自带） | 动作表项 `actionId + alias[]` |
| **Mode（模式）** | 跨面板的持久状态，改变键位可用性与面板行为 | `pkg/gui/types/modes.go:10-15`（Filtering / CherryPicking / Diffing / MarkedBaseCommit） | 面板级状态位（过滤中、拣选中、比较中） |
| **Popup（弹层）** | confirmation / prompt / menu / suggestions / commit message 等临时输入层 | `setup.go:89-110`（Confirmation / Prompt / CommitMessage / Search 等） | `Dialog` / 行内输入 / 下拉菜单 |

### 1.1 Context 的全部取值

侧栏可配置的 tab 只有 10 种（`pkg/config/side_panel.go:17-30`）：

```
status, files, worktrees, submodules, branches, remotes, tags, commits, reflog, stash
```

默认分成 5 组（`pkg/config/user_config.go:882-888`）：

```
[status]
[files, worktrees, submodules]
[branches, remotes, tags]
[commits, reflog]
[stash]
```

除此之外还有一批**非侧栏** context：主视图（`Normal` / `Staging` / `CustomPatchBuilder` / `MergeConflicts`）、提交文件的子视图（`CommitFiles` / `SubCommits`）、以及弹层类（`Confirmation` / `Prompt` / `CommitMessage` / `Search` / `Menu` / `Suggestions`）。

Context 种类枚举为 6 类（`pkg/gui/types/context.go:16-30`）：`SIDE_CONTEXT` / `MAIN_CONTEXT` / `PERSISTENT_POPUP` / `TEMPORARY_POPUP` / `EXTRAS_CONTEXT` / `GLOBAL_CONTEXT`。

**迁移结论**：Web 上「焦点面板」概念可以完全对齐 Context；弹层类 context 映射为 Dialog/行内输入；主视图的 `Staging` / `PatchBuilding` / `MergeConflicts` 是三态切换而非并列面板，Web 上应做成主视图的**模式切换**（tab 或分段控件），不是三个独立面板。

### 1.2 Mode 的迁移

| Mode | lazygit 行为 | Web 处理 |
|---|---|---|
| Filtering | 侧栏进入过滤态，多数键位被拦截，必须先退出 | 过滤框常驻在面板头部，不拦截其他操作（Web 无需模态） |
| CherryPicking | 提交被标记为「已复制」，之后可粘贴 | 保留为提交行上的标记状态 + 顶部活动条 |
| Diffing | 选中一个 ref 作为比较基准 | 做成主视图顶部的「比较基准」选择器 |
| MarkedBaseCommit | 标记变基的 base commit | 提交行上的标记 + 顶部活动条 |

**关键差异**：lazygit 的 Mode 之所以要拦截键位，是因为单键空间有限、必须靠模态复用。Web 上控件空间充裕，**Mode 应降级为普通状态，不做键位拦截**——这会显著降低实现复杂度，也降低用户困惑。

### 1.3 绑定解析时的守卫

绑定执行前有两道守卫（`pkg/gui/keybindings.go:14-45`）：

- `NoPopupPanel`：弹层聚焦时全局绑定不生效。
- `OutsideFilterMode`：过滤态下多数绑定不生效，先提示退出过滤。

Web 上不做键位拦截，这两道守卫可以简化为：**弹层打开时输入栏禁用**（而非静默失效），过滤态不拦截。

另外绑定支持 `GetDisabledReason`（`keybindings.go:393-412`），可返回三种结果：继续派发 / 面板内报错 / toast 提示。这个机制在 Web 上应当保留——它对应「当前选中项不满足动作前置条件」时的禁用态与提示。

## 2. 294 条键位的三分类量化

对 `docs/keybindings/Keybindings_zh-CN.md` 全部表格行解析，取每条绑定的**主键**（`[<pgup>, K, <ctrl+u>]` 取 `<pgup>`）分类：

| 类别 | 判定规则 | 条数 | 占比 |
|---|---|---|---|
| **A 可打印单字符** | 字母 / 数字 / 标点 / 空格，可直接键入输入框 | 215 | 73.1% |
| **B 浏览器原生键** | `<up>/<down>/<left>/<right>`、`<pgup>/<pgdown>`、`<home>/<end>`、鼠标滚轮 | 12 | 4.1% |
| **C 必须控件化** | `<esc>` / `<enter>` / `<tab>` / `<ctrl+x>` / `<alt+x>` / `<shift+方向>` / 其他控制键 | 67 | 22.8% |

**这个比例是本方案成立的核心依据**：近 3/4 的键位可以直接「输入 + Enter」，输入栏方案不是削足适履。

### 2.1 各面板三分类分布

| 面板段 | 总数 | A 可打印 | B 原生 | C 控件化 |
|---|---|---|---|---|
| 全局键绑定 | 28 | 19 | 2 | 7 |
| 列表面板导航 | 12 | 10 | 0 | 2 |
| 子提交 | 15 | 10 | 0 | 5 |
| 子模块 | 9 | 7 | 0 | 2 |
| 工作区 | 5 | 4 | 0 | 1 |
| 引用日志 | 15 | 10 | 0 | 5 |
| 提交 | 37 | 29 | 0 | 8 |
| 提交信息 | 2 | 0 | 0 | 2 |
| 提交文件 | 15 | 11 | 0 | 4 |
| **文件** | **28** | **22** | **0** | **6** |
| 本地分支 | 26 | 21 | 0 | 5 |
| 构建补丁中 | 11 | 6 | 0 | 5 |
| 标签 | 11 | 7 | 0 | 4 |
| 次要 | 3 | 1 | 0 | 2 |
| 正在合并 | 11 | 5 | 6 | 0 |
| 正在暂存 | 17 | 10 | 0 | 7 |
| 正常 | 5 | 1 | 2 | 2 |
| 状态 | 6 | 5 | 0 | 1 |
| 确认面板 | 3 | 0 | 0 | 3 |
| 菜单 | 3 | 1 | 0 | 2 |
| 贮藏 | 9 | 7 | 0 | 2 |
| 输入提示 | 2 | 0 | 0 | 2 |
| 远程 | 7 | 6 | 0 | 1 |
| 远程分支 | 14 | 10 | 0 | 4 |
| **合计** | **294** | **215** | **12** | **67** |

注意两个面板的 C 类占比异常高：

- **正在合并**（11 条中 6 条是方向键）：冲突解决靠方向键在 hunk 间移动。Web 上这是**纯点击场景**（点选冲突块），原生方向键反而多余，B 类 6 条可直接丢弃。
- **确认面板 / 输入提示 / 提交信息**（C 类 100%）：只有 `<enter>` 确认与 `<esc>` 关闭。Web 上就是 Dialog 的「确定 / 取消」两个按钮，**零设计成本**。

### 2.2 C 类完整清单（按动作去重后 35 项）

| 键 | 动作 | 出现面板数 | Web 替代方案 |
|---|---|---|---|
| `<enter>` | 打开 / 确认 / 进入（查看提交的文件、进入子模块、执行菜单项、暂存块行） | 12 | 双击列表项 + 主按钮「打开」 |
| `<esc>` | 取消 / 关闭 / 返回（取消、关闭弹层、退出逐行模式、返回文件面板） | 8 | 弹层取消按钮 + 面包屑「返回」+ 点击遮罩 |
| `<ctrl+o>` | 复制 X 到剪贴板（哈希 / 路径 / 分支名 / 标签 / 文本） | 6 | **收敛为一个行内复制按钮**（无需按类型分） |
| `<ctrl+t>` | 外部 difftool 打开 | 4 | 首期不支持（服务端无桌面环境），标记不可用 |
| `<tab>` | 切换到其他面板（已暂存/未暂存视图） | 3 | 主视图的 Segmented 分段控件 |
| `<ctrl+r>` | 切换到最近的仓库 / 重置已拣选的提交 | 2 | 前者首期不支持；后者做成「清除拣选标记」按钮 |
| `<ctrl+j>` / `<ctrl+k>` | 下移 / 上移提交 | 2 | 提交列表拖拽重排 + 行内上/下移按钮 |
| `<ctrl+l>` | 打开日志菜单 | 1 | 提交面板头部的下拉菜单 |
| `<ctrl+p>` | 自定义补丁选项 | 1 | 主视图工具条按钮 |
| `<ctrl+s>` | 按路径过滤选项 | 1 | 与过滤框合并 |
| `<ctrl+w>` | 切换是否显示空白字符差异 | 1 | 主视图工具条开关 |
| `<ctrl+z>` | 挂起应用程序 | 1 | **不适用**（Web 无挂起语义），丢弃 |
| `<ctrl+b>` | 按状态过滤文件 | 1 | 文件面板头部筛选下拉 |
| `<ctrl+f>` | 找到用于修复的基准提交 | 1 | 动作菜单项（低频） |
| `<alt+shift+c>` | 编辑配置文件 | 1 | 跳到设置页 |
| `<shift+up>` / `<shift+down>` | 扩展选择范围 | 2 | shift+点击 / 拖拽（浏览器原生） |
| `<ctrl+y>` | 复制 PR URL | 1 | 首期不支持（无托管平台集成） |

**去重后真正需要单独设计的 C 类控件约 12 个**，其余要么天然被 Web 控件取代（enter/esc/tab/复制），要么首期不支持（difftool / PR / 挂起）。

### 2.3 B 类完整清单（12 条，保留原生键）

| 键 | 动作 | 处理 |
|---|---|---|
| `<pgup>` / `<pgdown>` | 滚动主面板 | 保留浏览器原生滚动；不进输入栏 |
| `<up>` / `<down>` | 选择顶部/底部块（合并冲突） | 保留原生方向键做列表导航；冲突块改点击选择 |
| `<left>` / `<right>` | 选择上/下一个区块（staging / patch building） | 保留原生方向键；同时提供「上一块 / 下一块」按钮 |
| `<mouse wheel up/down>` | 滚动 | 天然支持 |
| `<home>` / `<end>` | 滚动到顶/底（与 `<` `>` 别名共存） | 保留原生，且 `<` `>` 是 A 类可进输入栏 |

B 类的处理原则是：**能用原生就用原生，但必须同时有鼠标等价物**。lazygit 的 B 类在 Web 上大多有更自然的表达（滚动条、点击），原生键位只作为加成。

## 3. 单键冲突与歧义分析

同一字符在不同面板含义完全不同，这是 lazygit 靠「焦点面板」消歧的。典型冲突字符：

| 字符 | Files | Branches | Commits | Stash | Submodules |
|---|---|---|---|---|---|
| `<space>` | 切换暂存状态 | 检出 | 检出 | 应用贮藏 | — |
| `d` | 查看「放弃变更」选项 | 删除分支 | 删除提交 | 删除贮藏 | 删除子模块 |
| `n` | — | 新建分支 | 从提交创建分支 | 从贮藏建分支 | 添加子模块 |
| `g` | 查看上游重置选项 | 查看重置选项 | 查看重置选项 | 应用并删除 | — |
| `s` | 贮藏所有变更 | 排序 | 压缩(Squash) | — | — |
| `c` | 提交变更 | 按名称检出 | 设置修复提交信息 | — | — |
| `e` | 编辑文件 | — | 开始交互式变基 | — | 更新子模块 URL |
| `r` | 刷新文件 | 变基 | 改写提交 | 重命名贮藏 | — |
| `f` | 抓取 | 从上游快进 | 修正(fixup) | — | — |
| `M` | 查看合并冲突选项 | 合并到当前分支 | — | — | 批量子模块选项 |

**迁移结论**：

1. 输入栏必须**绑定焦点面板**，否则 `d` 无法消歧——这与 lazygit 完全一致，不是新设计。
2. 输入栏必须**显式显示当前上下文徽标**（如 `Files`），这是 lazygit 用边框高亮表达的信息，Web 上要用文字说清楚，否则用户不知道自己敲的 `d` 会删什么。
3. `d` 类动作多为破坏性，输入栏在命中时应**立即显示完整动作名**（输入 `d` → 显示「放弃变更…」而非只显示 `d`），把歧义在提交前暴露。

## 4. 三个 lazygit 机制在 Web 上的去留

| 机制 | lazygit 原因为存在 | Web 去留 | 说明 |
|---|---|---|---|
| 单键模态 | 键位空间有限，靠模态复用 | **保留但弱化** | 输入栏绑定焦点面板即为模态；Mode 不再拦截键位 |
| 范围选择（`v`） | 无鼠标，需键盘扩展选区 | **替换为原生多选** | shift+点击 / ctrl+点击 / 拖拽 |
| 过滤模式（`/`） | 无空间常驻过滤框 | **改为常驻过滤框** | 面板头部一个输入框，不进入模态 |
| 命令日志（`@`） | 终端无滚动回溯 UI | **保留为操作历史面板** | 可作为 CLI 区域的一个 tab，记录每次动作及其结果 |
| 撤销/重做（`z` / `Z`） | 基于 reflog 撤销上一个 git 命令 | **保留，且增强** | Web 空间充裕，可做显式的「撤销上一操作」按钮 + 历史栈 |
| 剪贴板复制 | TUI 无法选中文本 | **大幅简化** | Web 天然可选中复制；`<ctrl+o>` 退化为便利按钮 |

「范围选择」和「剪贴板」这两项在 Web 上是**纯简化**，不需要设计——lazygit 为终端限制付出的复杂度，在浏览器里本来就不存在。

## 5. 可迁移性结论

| 维度 | 结论 |
|---|---|
| 面板信息架构 | **可直接照搬**。5 组侧栏 tab 是成熟设计，无需重新发明 |
| 键位覆盖 | 73% 直接可搬（输入 + Enter），4% 保留原生键，23% 需控件化但多数有天然 Web 等价物 |
| 交互模态 | **应弱化**。Mode 不做键位拦截，过滤不进模态，范围选择交还鼠标 |
| 弹层 | 100% 对齐 Dialog，且比 TUI 更清晰 |
| 缺失能力 | 外部 difftool、PR 集成、挂起应用、最近仓库切换——首期全部标记不可用，不模拟 |
| 新增需求 | CLI 终端是 lazygit 没有的（lazygit 只有单条 shell 命令 `:`），这是本方案的增量，需独立设计（见 03 文档） |
