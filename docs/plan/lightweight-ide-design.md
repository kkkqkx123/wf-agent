# 轻量 IDE 功能设计：终端执行、文件树查看、文件编辑

> 目标：在 `apps/web-app` 中补充轻量 IDE 能力，复用现有 PTY 终端，新增受控文件系统浏览与代码编辑。只描述结构、职责与边界，不包含完整代码实现。参考分析见 `docs/research/frontend/08-轻量IDE参考项目分析.md`。

## 1. 背景与范围

### 1.1 当前状态

- 终端：后端 `wf-api::pty` 与 `wf-server::api::pty` 已提供 PTY 会话、WebSocket 重连、输出回放；前端已有 `PtyPanel`、`TerminalInstance` 与 xterm.js。
- 文件：当前只有 Git 文件状态、checkpoint 文件视图与 `@mention` 的本地文件扫描，没有通用目录浏览与文件读写 API。
- 编辑器：当前只有 `JsonEditor`，没有通用代码编辑器。

### 1.2 本期范围

包含：

- 终端执行：复用现有 PTY，嵌入 IDE 布局。
- 文件树查看：浏览工作区目录，懒加载子目录，显示文件类型与 Git 状态。
- 文件编辑：打开文本文件、编辑、保存、多标签、脏状态提示。

不包含：

- LSP、调试器、扩展系统、协作光标、二进制文件编辑。
- 独立权限系统；沿用现有 API Key 与用户 Git 配置。

### 1.3 工作区根目录

复用现有 `user_git.repo_root` 作为 IDE 工作区根目录。若未配置，IDE 页面显示未初始化状态，与 Git 页面保持一致。终端默认 `cwd` 使用同一根目录。

## 2. 总体架构

```text
┌──────────────────────────────────────────────────────────────┐
│ AppShell / Nav: 新增 IDE 入口                              │
├──────────────┬──────────────────────────────┬────────────────┤
│ 文件树       │ 编辑器标签页 + Monaco/CM     │ 可选属性面板   │
│ (左)         │ (中)                         │ (右, 后续)     │
├──────────────┴──────────────────────────────┴────────────────┤
│ 终端面板（下，复用 PtyPanel/xterm）                         │
└──────────────────────────────────────────────────────────────┘
```

- 路由：新增 `/ide`，作为独立页面，不改变现有执行/聊天主流程。
- 前端：新增 `IdePage`、`FileTree`、`FileEditor`、`IdeStore`；复用 `PtyPanel`。
- 后端：新增 `wf-api::fs` 与 `wf-server::api::fs`，提供受控文件操作。
- 预览模式：新增 mock 路由，保证 `dev:preview` 可用。

## 3. 后端设计

### 3.1 模块位置

- `crates/app/wf-api/src/fs.rs`（或 `workspace_fs.rs`）：业务逻辑与路径安全。
- `crates/app/wf-server/src/api/fs.rs`：HTTP 路由与 OpenAPI。
- 在 `wf-api::lib` 与 server router 中注册，遵循现有模块注册方式。

### 3.2 核心能力

| 能力 | 说明 |
| --- | --- |
| `workspace_root` | 复用 `user_git.repo_root`，未配置时返回未初始化错误 |
| `list_dir` | 返回目录条目：名称、相对路径、类型、大小、修改时间 |
| `read_file` | 读取文本文件，返回内容、编码、大小、哈希、是否二进制 |
| `write_file` | 写入文本文件，支持可选期望哈希做乐观并发控制 |
| `create_entry` | 创建文件或目录 |
| `delete_entry` | 删除文件或目录 |
| `rename_entry` | 重命名或移动 |
| `stat` | 返回单个路径元数据 |

### 3.3 路径安全

复用 Git 模块的路径校验思想：

- 相对路径，拒绝绝对路径、`..`、空字符、反斜杠。
- 所有路径必须落在工作区根目录内。
- 忽略 `.git`、`node_modules`、`target`、`dist` 等重目录的默认展开，但允许显式访问。
- 符号链接需解析后再次校验根目录归属。

### 3.4 读写限制

- 文本读取设置大小上限（建议 2 MB），超过时返回元数据与截断标记。
- 二进制文件标记为不可编辑，前端只读展示或拒绝打开。
- 写入前校验父目录存在与路径类型。
- 可选哈希冲突返回 409，避免覆盖他人修改。

### 3.5 API 形态

建议采用查询参数承载路径，避免 URL 路径编码复杂度：

- `GET /api/v1/fs/list?path=`
- `GET /api/v1/fs/content?path=`
- `PUT /api/v1/fs/content?path=`
- `POST /api/v1/fs/entries`
- `DELETE /api/v1/fs/entries?path=`
- `PATCH /api/v1/fs/entries`

响应统一使用现有信封格式，类型加入 OpenAPI schema，前端通过代码生成更新 `schema.d.ts`。

## 4. 前端设计

### 4.0 页面布局、样式与 UI/UX

IDE 作为独立页面 `/ide`，采用三区 IDE 布局，视觉上复用现有 Token，不新建色板。

#### 4.0.1 布局

```text
┌──────────────────────────────────────────────────────────────┐
│ 顶栏：工作区根目录、全局搜索、保存状态、面板开关               │
├──────────────┬──────────────────────────────┬────────────────┤
│ 文件树       │ 编辑器标签栏 + Monaco 编辑器  │ 可选检查面板   │
│ 260px        │ 1fr                          │ 320px(可折叠)  │
│ 可折叠       │                              │                │
├──────────────┴──────────────────────────────┴────────────────┤
│ 终端面板：可折叠、可调高度，默认 35vh                         │
└──────────────────────────────────────────────────────────────┘
```

- 宽屏：三区 + 终端同时可见。
- 中屏：右侧检查面板转浮层，终端默认折叠为底栏。
- 窄屏：文件树与终端变为抽屉，编辑器全宽，标签栏横向滚动。
- 移动端：单栏，通过顶部切换「文件 / 编辑器 / 终端」。

#### 4.0.2 视觉风格

- 颜色、圆角、间距、阴影、动效全部复用 `app.css` 语义 Token 与现有组件库。
- 文件树使用低密度列表，选中态用 `accent`，脏文件用警告色点标记。
- 编辑器区域使用等宽字体栈，背景与主题跟随浅/深色模式。
- 终端面板复用现有 xterm 主题映射，避免第二套终端配色。
- 图标与徽标复用现有 Icon 与 Badge，不新增图标体系。

#### 4.0.3 交互与 UI/UX

- 文件树单击预览、双击固定打开为标签。
- 标签支持拖拽排序、中键/关闭按钮关闭、脏文件关闭确认。
- `Ctrl/Cmd+S` 保存当前文件；`Ctrl/Cmd+W` 关闭当前标签；`Ctrl/Cmd+P` 快速打开文件。
- 保存成功显示轻量 toast，失败显示错误详情。
- 二进制或超大文件打开时显示只读提示与「在外部查看」建议。
- 终端面板支持拖拽调整高度、折叠与全屏。
- 所有异步加载使用骨架/占位，不阻塞编辑器首屏。

#### 4.0.4 与参考项目的对比

| 维度 | code-server | File Browser | 本方案 |
| --- | --- | --- | --- |
| 布局 | VS Code 全功能工作台 | 文件管理器单页 | 轻量三区 IDE |
| 文件树 | 编辑器内建 | 资源列表 | 懒加载树 + Git 状态 |
| 编辑器 | Monaco 全量 | 文本编辑 | Monaco 动态加载 |
| 终端 | PTY | 命令执行 | 复用现有 PTY |
| 复杂度 | 高 | 中 | 低 |

### 4.1 路由与导航

- 新增 `src/routes/ide/+page.svelte`。
- 在 `src/lib/config/navigation.ts` 的 workspace 分组增加 IDE 入口。
- 命令面板增加「打开文件」「打开 IDE」动作。

### 4.2 服务层

新增 `src/lib/services/fs.ts`：

- 类型：`FsEntry`、`FsFileContent`、`FsWriteInput`。
- 函数：`listFs`、`readFsFile`、`writeFsFile`、`createFsEntry`、`deleteFsEntry`、`renameFsEntry`。
- 错误处理沿用 `call`/`requireData` 与 toast。

### 4.3 状态管理

新增 `src/lib/stores/ide.svelte.ts`：

- `tree`：目录缓存与展开状态。
- `openFiles`：标签列表，包含路径、内容、原始内容、脏标记、加载状态。
- `activePath`：当前激活文件。
- `terminals`：IDE 内终端会话 id 列表。
- 提供 `openFile`、`saveFile`、`closeFile`、`reloadTree`。

### 4.4 组件

| 组件 | 职责 |
| --- | --- |
| `IdePage.svelte` | 三区布局、终端停靠、快捷键 |
| `FileTree.svelte` | 递归目录树、懒加载、图标、Git 状态徽标、右键菜单 |
| `FileEditor.svelte` | 编辑器封装，支持多标签与保存 |
| `IdeTerminalPanel.svelte` | 复用 `PtyPanel`，cwd 为工作区根 |

### 4.5 编辑器选型

编辑器统一使用 Monaco Editor：

- 一个文件对应一个 `ITextModel`，切换标签时复用 model，避免重复解析。
- 根据扩展名与路径推断 language。
- 通过动态 import 与 worker 配置延迟加载，不阻塞 IDE 首屏。
- 二进制、超大或只读文件使用只读 model/editor。
- 编辑器接口保持 `value`、`language`、`readOnly`、`onSave`，避免 UI 层与 Monaco API 直接耦合。

### 4.6 文件打开与保存

- 打开文件时按扩展名推断语言。
- 二进制或超大文件以只读预览或拒绝打开。
- `Ctrl/Cmd+S` 触发保存；未保存关闭时提示。
- 保存成功后更新原始内容与脏标记。
- 外部变更检测可后续通过哈希/轮询实现，本期不做自动合并。

### 4.7 标签页设计

引入 IDE 后，标签页从「可选便利」变为「核心导航」。建议分两层：

1. **文件标签**：编辑器顶部标签栏，每个文件一个标签，支持固定/预览/脏状态。
2. **终端标签**：终端面板内支持多个 PTY 会话标签，便于切换命令上下文。

标签状态持久化到会话存储，刷新后恢复打开文件与激活标签。关闭脏文件时要求确认；支持「全部保存」「关闭其他」等批量操作。标签数量过多时使用横向滚动与下拉列表，不强制限制，但对内存占用做软提示。

## 5. 终端集成

- IDE 终端复用现有 `PtyPanel` 与 `TerminalInstance`。
- 创建终端时传入工作区根目录作为 `cwd`。
- 终端面板支持折叠、高度记忆，沿用现有偏好存储。
- 多终端标签可后续扩展，本期先支持单终端面板。

## 6. 安全与可靠性

- 路径校验在后端集中执行，前端不承担安全边界。
- 文件大小与类型限制在后端执行。
- 写入采用临时文件 + 原子替换，降低写入中断风险。
- 乐观并发控制避免静默覆盖。
- 所有操作走现有认证中间件。
- 预览模式 mock 不访问真实文件系统。

## 7. 性能与体验

- 目录树按展开懒加载，避免一次性扫描大仓库。
- 大目录使用虚拟列表。
- 编辑器动态 import，不阻塞 IDE 首屏。
- 终端缓冲复用 SerializeAddon，标签切换时保持输出。
- 文件内容缓存按路径 + 哈希失效。

## 8. 与现有功能集成

- Git 页面可增加「在 IDE 中打开」入口，跳转 `/ide?path=...`。
- `@mention` 文件结果可跳转到 IDE 编辑器。
- 检查点文件视图可提供「在 IDE 中打开」。
- 命令面板支持按文件名搜索并打开。

## 10. 验收标准

- 未配置工作区时页面有明确空态。
- 能浏览目录树并懒加载子目录。
- 能打开、编辑、保存文本文件，二进制文件不可编辑。
- Monaco 编辑器按需加载，文件标签可恢复。
- 路径逃逸与超大文件被后端拒绝。
- 终端可在 IDE 中执行命令并保持输出。
- 预览模式可浏览 mock 文件树与终端。
- 类型检查、lint、格式、构建通过。

## 11. 风险与开放问题

- Monaco 与 SvelteKit/Vite 的 worker 配置可能增加构建复杂度。
- 大仓库的目录扫描与文件树渲染需要虚拟化。
- 多标签与外部文件变更的冲突处理本期仅做哈希冲突提示。
- 是否将 IDE 作为聊天侧边面板嵌入，还是独立页面，需根据导航优先级最终确认。
