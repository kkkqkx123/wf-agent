# Web 前端的 RAG 界面

> 范围：`apps/web-app` 的知识库页面、检索服务封装、预览固件与工具调用呈现
> 上游契约：[../client/03-rag-clients.md](../client/03-rag-clients.md) 与 [../api/10-rag-domain.md](../api/10-rag-domain.md)

前端不实现检索逻辑。页面通过统一服务层调用 HTTP 契约，预览模式使用同一服务层加固件路由；模型工具输出的检索命中则在通用工具卡片内做结构化展示。

## 1. 页面结构

知识库页面位于 `/rag`，侧边栏归入“构建”分组。页面顶部是 collection 与 namespace 范围选择，下面按职责分为四个区域：

| 区域 | 内容 |
|---|---|
| 索引统计 | 向量点数、可选关键词点数与当前范围 |
| 数据源管理 | source 列表、状态、分块/点数、重建与删除；另有添加 source 表单 |
| 检索预览 | 问题、top K、摘录长度；展示命中分数、chunk 标识、摘录与来源 |
| 诊断 | 展示服务端给出的可能原因，与检索预览共用问题输入 |

添加 source 支持 URL 与本地文件两种 kind，并可指定转换器、读取器选项 JSON 和强制重建标志。每个动作都有进行中状态；成功与失败分别以提示条反馈。

## 2. 服务层与错误

页面只调用 `services/rag.ts`，不在组件内拼接 API 路径。服务层使用生成的 OpenAPI 类型和统一信封拆包，错误由 `ApiHttpError` 抛出。

服务不可用与空结果是两种不同状态：前者在页面顶部显示配置提示，后者显示空 source 列表或无命中提示。这样未配置 embedding 的服务器不会被误读为知识库为空。

## 3. 预览模式

RAG 固件提供固定统计、三条预览命中与三个 source 状态，其中一个 source 处于失败态用于展示错误行。mock 路由覆盖全部 RAG 操作，source 列表在固件会话内可变，因此添加、重建、删除可以连续演示。

固件客户端的 DELETE 实现透传请求体，使 source 删除在预览模式下可用。固件数据与正式服务层共享 DTO 形状，页面没有环境分支。

## 4. 工具调用呈现

`utils/toolcalls.ts` 负责从工具名推导展示类型。修正后的优先级把 `rag_*` 与检索语义归为 `knowledge`，避免 `rag_search` 被通用 `search` 规则归为网络调用。

同一模块提供命中数组解析：读取 `chunk_id`、source、`score`、内容或摘录字段，忽略非数组结果。`ToolCallCard` 对 `rag_` 工具在展开区域展示紧凑引用列表，包含 chunk 标识、分数、摘录与来源；完整 JSON 仍保留在详情中，不丢失原始证据。

## 5. 文案与测试

新增文案按中英文片段文件维护，再由合并脚本生成运行时消息文件；页面与导航均通过 i18n 入口取文案。新增单测覆盖工具分类与命中解析，前端类型检查和预览类型检查均包含新页面与新服务。
