# RAG 抽象与插件扩展点复核：实现轮问题清单与修改方案

> 背景：本篇承接《RAG 抽象与插件扩展点复核：问题清单与修改方案》与《关键词与向量存储契约对称调整》，记录仓库当前代码相对两篇方案的完整差距，并给出本轮实现范围。两篇前序文档定义的分层与职责不变，本篇不重建模块、不做旧数据兼容。
> 范围：`vector-contracts`、`keyword-contracts`、`wf-rag`，以及持有检索扩展的 `wf-api`、`wf-runtime`、`wf-tools`、`wf-workflow`、`wf-plugin-sdk`、`wf-plugin`。HTTP、CLI 与前端的形态不在本轮改动目标内，但会核对它们是否仍能通过宿主装配访问新抽象。

## 0. 结论

* 存储层搬迁已完成主体：关键词三后端、共享分词核心、打开器均已在契约包；门面只保留薄转发与适配职责。
* 插件实例注册表、统一调用抽象、结构化补全端口只建了骨架，主链路仍依赖进程级全局状态与自由函数。
* 检索建议、快照策略、编解码扩展存在“半清理”状态：`wf-rag` 侧已删，`wf-plugin-sdk` / `wf-plugin` 侧仍可注册但无消费。
* 本轮按“实例贯通、死点删除、提示词装配、门面退出、文档对齐”五条线收尾；每一条都以调用链真实可达为完成标准。

## 1. 完整问题清单

### 1.1 扩展注册与隔离

1. `RetrievalExtensions` 虽已定义，但所有管线与桥接仍调用它的 `global()`；实例本身没有生产消费者。
2. 自由注册函数仍以全局实例为后端，测试仍依赖 `test_registry_guard` 串行化，无法证明多实例并存。
3. 关键词分词器仍由 `keyword-contracts/src/tokenizer.rs` 的静态注册表持有；插件分析器通过 `plugin/analyzer.rs` 写入该全局表，无法随宿主配置隔离。
4. 插件边界仍以可选名字字符串与通用结构化值为载体，模式错误、形状错误只能在运行期暴露。
5. 未知名字早失败与执行失败降级已在摄取、查询、路由、评测路径分别实现，但分散在多处辅助函数中，没有一个统一装配门禁。

### 1.2 重复、死点与半清理

1. `PluginRetrievalAdvisor` 与 `PluginPostprocessor` 曾同做融合后整形，`wf-rag` 已只保留后者；但 SDK、插件管理器、原生/Lua/Wasm 分发、manifest 与 C 头仍保留 advisor 注册入口，运行时桥已不再同步它。
2. 快照策略在 `wf-rag` 侧已删除，但 SDK、插件管理器、原生分发与 manifest 仍保留声明入口，运行时桥已不再同步，注册后无任何消费者。
3. `apply_registered_selector` 与 `router::resolve_selected` 各写一套候选校验与空结果回退，前者除单测外无生产调用。
4. 嵌入与重排编解码的进程级注册表已删除，只留 SDK 特征定义与 `wf-rag` 适配器；插件引擎没有对应 contribution 通道，宿主默认模型构造链也不按名选用，形成不可达扩展点。
5. `wf-rag/Cargo.toml` 中 `once_cell` 已无引用；`keyword-sqlite` 与 `vector` 是搬迁后留下的空特性，`wf-api/keyword` 仍转发到空特性。
6. 门面打开器与重导出仍在，宿主尚未切换到 `keyword-contracts` 直接打开， transitional 代码仍在真实调用链上。

### 1.3 模型端口与调用抽象

1. `CompletionRequest` 区分 system/user 并支持输出上限，但 `CompletionLlm::complete(&str)` 仍是必需方法，`complete_request` 只有默认实现且调用方未使用。
2. 合成、分解、HyDE、反馈改写的提示词仍硬编码在门面私有函数中，配置只暴露策略、预算与零命中提示。
3. `StandardRetriever` 只覆盖 `query` / `query_multi`；`StandardQa` 只覆盖变体重写路径；没有 hybrid、routed、metrics 形态。
4. 工作流节点、工具与预览仍直接调用自由函数，新抽象没有向上传导；仓库内也没有生产环境 `CompletionLlm` 实现。

### 1.4 存储契约对称性收尾

1. 关键词侧 `ensure_collection` 与能力声明已具备调用形状，但摄取管线和宿主装配都没有消费，能力门禁实际不存在。
2. 向量侧缺少“编码指纹变化需显式重建”的契约说明，现有指纹逻辑只在门面配置与重建模块中体现。
3. 宿主仍经门面打开器构造关键词后端，契约包打开器尚未成为唯一入口。
4. 计数近似语义、通用条件复核、候选放大归属、格式戳与只读降级已落地，不作为本轮改动对象。

## 2. 修改方案

### 2.1 扩展实例贯通

* 将 `RetrievalExtensions` 改为宿主持有的 `Arc`，作为运行时、API 上下文与检索句柄的共享字段；删除 `global()` 与所有转发到全局的自由注册/查询函数。
* 管线函数显式接收 `&RetrievalExtensions`，覆盖摄取、查询、混合、路由、评测与合成。未知名字在调用前统一门禁，执行失败按既有策略降级并记诊断。
* 将关键词分析器注册表改为可注入实例，`RetrievalExtensions` 持有该实例；后端构造时接收实例，插件分析器只写入所属实例。无显式注册的实例为空，不再回退到进程级状态。
* 插件桥接改为向所属实例注册与反注册；测试改为每个用例持有独立实例，删除串行守卫。

### 2.2 死点与重复处理

* 删除 `PluginRetrievalAdvisor`、`snapshot-policy`、`apply_registered_selector`，同时清理 SDK 记录入口、插件管理器注册表、原生/Lua/Wasm 分发、manifest 类型与 C 头声明。
* 编解码按“暂无宿主需要则移除不可达选用能力”处理：删除 SDK 中的 embedding/rerank codec 特征、`wf-rag` 适配器与相关测试，保留宿主侧已使用的通用 LLM codec 通路不动。
* 删除 `once_cell` 依赖、空特性及空转发；宿主切换到契约包打开器后删除门面转发函数与重导出模块。

### 2.3 模型与调用抽象

* `CompletionRequest` 成为补全端口的唯一请求类型；提示词模板（系统提示、用户提示、输出上限）作为装配参数进入 `SynthesisConfig` 与变换配置，提示词拼装函数只负责填充模板。
* `StandardRetriever` / `StandardQa` 补齐 hybrid 与 routed 形态，工作流节点与工具改为调用句柄，自由函数只作为句柄的默认实现保留。
* 补全端口不引入流式与结构化输出；宿主按需实现结构化请求方法，默认拼接行为保留但不作为主链路。

### 2.4 存储契约收尾

* 摄取管线在写入前调用关键词侧 `ensure_collection`，宿主装配按关键词能力声明校验分词与分析器选择。
* 在向量存储契约中写明编码指纹变化即需显式重建，不新增格式机制。
* 宿主直接使用 `keyword_contracts` 的打开器；门面只保留向量点与关键词文档的双向适配、命中复核与候选放大。

## 3. 实施顺序与完成标准

1. 先改契约包的分析器实例与打开器签名，再改 `wf-rag` 插件实例与管线参数，最后改宿主装配；保证任一步结束后不存在同时依赖全局与实例的混合路径。
2. 清理 SDK/插件引擎死点时同步清理 manifest 与 C 头，避免插件仍可声明不可达贡献。
3. 提示词模板与句柄收敛放在注册实例之后，因为它们需要复用同一份宿主装配参数。
4. 完成标准：生产链路无 `RetrievalExtensions::global()`、无全局分析器注册表、无 advisor/snapshot 声明入口；测试不依赖串行守卫；工作区全特性编译通过。

## 4. 验证范围

* 远端执行工作区全特性编译与全目标检查，重点覆盖 tantivy/elastic 特性开与关两种形态。
* 定向测试覆盖未知名字早失败、执行失败降级、融合后整形顺序、路由兜底、合成零命中短路、格式戳拒绝与只读降级、多实例并存。
* 在线远端服务测试继续按环境变量门控；无环境时跳过不作为通过依据。
