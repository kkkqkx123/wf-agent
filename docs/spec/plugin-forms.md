# 插件形态全局规范

本文定义项目内插件形态的归属层次、选用边界与实现契约。凡涉及新增扩展点、接入新后端、选择宿主渲染或执行路径之处，均以本文为准。

约定：注释只描述代码意图，不引用本文编号；协议主版本锁定为一，不保留旧分支。

## 0. 源码地图

* 契约层：`crates/foundation/wf-plugin-sdk/src/manifest.rs`（清单、后端类型、权限、限额段）、`src/contributions.rs`（行为与描述载荷）、`src/native.rs`（原生 C ABI 类型）、`src/wasm.rs`（沙箱客户机契约）、`src/plugin.rs`（作者侧包装与导出宏）。
* 原生 C 头：`crates/foundation/wf-plugin-sdk/c-api/wf_plugin.h`，与 `src/native.rs` 同源，供非 Rust 语言直接实现。
* 引擎层：`crates/infra/wf-plugin/src/engine/config.rs`（三后端开关与全局限额）、`src/engine/loader.rs`（类型推断、门控、模块分发）、`src/guard.rs`（外层超时与恐慌隔离）、`src/signing.rs` 与 `src/package.rs`（供应链）、`src/dependency.rs`（版本依赖）、`src/registry.rs`（注册表）。
* 原生后端：`src/native/loader.rs`（路径收敛）、`src/native/abi.rs`（符号解析与版本协商）、`src/native/plugin.rs`（贡献转发与分发），示例见 `examples/native-c/`。
* 脚本后端：`src/lua/loader.rs`、`src/lua/pool.rs`（限额解析）、`src/lua/bridge.rs`（钩子装配）、`src/lua/plugin.rs`，沙箱基座见 `wf-sandbox` 的受限解释器策略。
* 沙箱后端：`src/wasm/loader.rs`、`src/wasm/abi.rs`（核心模块协商）、`src/wasm/component.rs`（组件模型世界）、`src/wasm/policy.rs`（限额与授权解析）、`src/wasm/pool.rs`（会话复用），世界定义见 `wit/plugin.wit`，示例见 `examples/wasm-echo`、`examples/wasm-go`、`examples/wasm-python`。
* 桥接层：`src/contributions/bridge.rs`、`src/contributions/manager.rs`、`src/contributions/registrar.rs`、`src/manifest.rs`（清单工具同步）。

## 1. 形态总览与特性矩阵

同一需求只选一种执行形态。能用数据表达的不用代码，能用清单内联的不用程序化注册。

### 1.1 后端特性矩阵

| 形态 | 载体 | 执行位置 | 隔离强度 | 实现语言 | 默认开关 |
|---|---|---|---|---|---|
| 清单内联声明 | 清单中五段加工具定义 | 不执行代码 | 无代码即无风险 | 无关语言 | 常开 |
| Lua 脚本 | 脚本文件加受限标准库 | 宿主进程内解释器 | 弱，受限库加指令钩子 | Lua | 开 |
| Wasm 客户机 | 核心模块或组件产物 | 沙箱内线性内存 | 强，燃料加 epoch 中断加内存上限加体积上限加授权默认拒绝 | 任意可编译到 Wasm 的语言 | 开 |
| Native 原生库 | 动态库 | 宿主进程同地址空间 | 无，同进程直接装载 | 任意可导出 C ABI 的语言 | 关 |

### 1.2 契约与约束对比

| 维度 | 清单内联 | Lua | Wasm | Native |
|---|---|---|---|---|
| 边界契约 | TOML 字段 | 脚本全局表加宿主桥 | 导出函数名加线性内存 JSON，或组件世界接口 | C ABI 符号加空结尾 JSON，见 `c-api/wf_plugin.h` |
| 版本协商 | 无版本概念 | 无版本概念 | 主版本交集，核心模块按导出校验，组件按世界名主版本 | 主版本交集，插件声明数组与宿主支持数组取最高公共值 |
| 限额表达 | 无需限额 | 超时加内存，上层弱到强三级回落 | 燃料加超时加内存加体积加会话池，上层弱到强三级回落 | 无专属限额，只受外层守卫超时约束 |
| 权限执行力 | 声明即审计输入 | 声明为准入与审计，另有库裁剪 | 声明为运行时强制授权 | 声明为准入与审计，无运行时强制 |
| 失败姿态 | 单条非法按条丢弃并计数 | 超时或超内存按插件错误上报并可重建状态 | 燃料耗尽或 epoch 中断按调用失败上报，会话可复用 | 钩子非零按加载或调用失败上报，恐慌由作者侧先拦截 |

### 1.3 贡献通道矩阵

| 贡献类 | 清单内联 | Lua | Wasm | Native | 说明 |
|---|---|---|---|---|---|
| 节点执行、工具执行 | 否 | 是 | 是 | 是 | 行为类，走统一分发 |
| 模型编解码、认证、镜像、发现 | 否，连接模板除外 | 仅确定性测试桩 | 仅确定性测试桩 | 是 | 需触网的实现只允许原生 |
| 事件处理、中间件 | 否 | 是 | 是 | 是 | 中间件应答统一为布尔或信封 |
| 工具定义、工具描述 | 是 | 否，经清单段同步 | 否，经清单段同步 | 是，经注册器或清单段同步 | 同一注册表方法与冲突策略 |
| 界面五段 | 是 | 否 | 否 | 是，经注册器追加 | 沙箱不新增程序化界面通道 |

## 2. 契约层

* 清单是唯一身份载体，含标识、严格语义化版本、后端类型、入口、版本化入口表、依赖表、贡献声明、权限表、配置模式与配置值、钩子表、模型提供方模板、工具与工具描述、界面五段、沙箱限额。未知字段直接拒绝。来源见 `wf-plugin-sdk/src/manifest.rs`。
* 后端类型显式声明优先，缺省按入口后缀推断，动态库后缀归原生，脚本后缀归脚本，模块后缀归沙箱，推断逻辑见 `engine/loader.rs` 的类型解析。默认入口与全部版本化入口必须同属一个后端，混用即加载失败。
* 权限声明按后端分档，后端差异见特性矩阵。脚本与原生声明仅做准入黑名单匹配与审计输入，脚本另有库裁剪；只有沙箱具备运行时强制。不得把权限声明当作跨后端安全边界，枚举定义见 `PluginPermission`。
* 贡献载荷分两类。行为类含节点执行、工具执行、模型编解码、认证、镜像生成、事件处理、中间件、压缩与检索建议；描述类含界面五段、工具定义、工具描述、资源模板。行为类走分发，描述类走注册表同步，类型定义见 `wf-plugin-sdk/src/contributions.rs`。
* 协议主版本锁定为一。原生主版本常量与宿主支持数组见 `src/native.rs`；沙箱客户机主版本与世界名见 `src/wasm.rs` 与 `wit/plugin.wit`。版本不一致直接拒绝加载，由作者升级后重建。

## 3. 引擎层

* 三后端各走自己的版本门控，上层插件特征行为一致。原生取声明与宿主支持数组交集的最高公共值；核心模块路径先按声明选文件再用客户机导出校验；组件路径编译前扫描内嵌世界名主版本；脚本无版本概念，不参与协商。宿主侧协商见 `src/native/abi.rs` 与 `src/wasm/abi.rs`、`src/wasm/component.rs`。
* 加载门按后端独立开关，配置见 `engine/config.rs` 的三启用标志。脚本与沙箱默认开启，原生默认关闭。原生与宿主同进程、无沙箱，只允许完全受信的第一方构建显式开启。限额数值永不兼任开关语义。
* 准入只做清单合法性、黑名单与名单过滤、签名复核。接口兼容由后端握手决定，属主过滤由调用方决定。批量发现时加载失败跳过并记日志，单文件加载失败大声报错，分发见 `engine/loader.rs`。
* 限额解析优先级由弱到强为内建默认、引擎全局默认、单清单声明。沙箱单次调用超时在两级都缺省时回落到引擎守卫超时。超时类零值表示关闭该层，内存类零值回落内建默认，超大池水位钳制到上限。生效后的限额在加载日志中一次性可见。脚本解析见 `src/lua/pool.rs`，沙箱解析见 `src/wasm/policy.rs`。
* 外层守卫只做稳定性兜底，不做安全隔离。超时阻止无限循环阻塞引擎，恐慌隔离阻止单个钩子拖垮引擎。原生运行时无专属限额，其可配置面即守卫超时、名单与权限拒绝名单，实现见 `src/guard.rs`。
* 注册键全局唯一。单值注册表在默认拒绝策略下重复即失败，无论属主是否相同；多值注册表允许多条并存。静默覆盖视为缺陷，调用方必须先注销再重注册。包管理以标识为唯一键，签名覆盖默认入口加全部版本化入口，完整性在包层解决，加载期只做配置了信任时的复核。

## 4. 后端分述

### 4.1 清单内联声明

不执行代码，风险最低，推荐度最高。界面五段、工具定义、工具描述直接写在清单中，引擎在激活期按与程序化注册相同的校验与冲突策略写入注册表，本机扫描只读清单字节，不启动任何运行时。需要斜线、补全、设置行、摘要模板、改写规则时优先选用。

与程序化注册的对比：同一注册表方法、同一校验、同一冲突判定，区别仅在于前者无代码，后者需经过分发通道。沙箱与脚本的界面需求一律走本形态，不另开通道。

### 4.2 Lua 脚本

受信轻量回调通道。载体为脚本文件，宿主在受限标准库上求值，要求脚本设置约定的全局插件表。保护钩子按固定指令间隔检查超时与内存，超时触发后按插件错误上报；内存超限同样失败，部分实现在失败后重建解释器状态，避免污染后续调用。来源见 `src/lua/loader.rs`、`src/lua/pool.rs`、`src/lua/bridge.rs`。

与沙箱的对比：脚本无版本协商、无能力授权、无燃料计量，隔离弱于沙箱，但启动快、编写轻，适合受信回调。与原生的对比：同进程但受解释器约束，可做超时与内存干预，而原生无运行时干预。

### 4.3 Wasm 客户机

不可信第三方扩展的首选。两种产物形态共享同一贡献语义与限额语义，调用方无需区分。核心模块路径用线性内存字符串传递，客户机导出约定的分配与入口符号；组件模型路径面向版本化世界接口，运行于受限系统接口上下文。来源见 `src/wasm/loader.rs`、`src/wasm/abi.rs`、`src/wasm/component.rs`、`wit/plugin.wit`、`wf-plugin-sdk/src/wasm.rs`。

限额与授权默认拒绝。燃料预算、epoch 中断、内存上限、模块体积上限、会话池水位共同约束单次调用；文件、环境、网络授权未授予即不可用，其中网络在当前阶段恒为拒绝，声明即加载失败。解析见 `src/wasm/policy.rs`，会话复用见 `src/wasm/pool.rs`。

与原生的对比：沙箱可承载不可信代码，原生只能承载完全受信代码；沙箱载荷仍为 JSON 字符串，与原生分发保持同构，便于同插件在不同信任等级间迁移。与脚本的对比：沙箱隔离强度更高，支持多语言分发，但单次调用开销与配置复杂度高于脚本。

### 4.4 Native 原生库与 C ABI 统一

原生是唯一可执行界面程序化注册与触网实现的通道，也是风险最高的形态，必须默认关闭、显式开启。载体为动态库，宿主用动态装载按符号名解析，路径收敛阻止目录逃逸，清单标识与库内清单一致性作为装载前提。来源见 `src/native/loader.rs`、`src/native/abi.rs`、`src/native/plugin.rs`。

边界已经统一为 C ABI，不存在 Rust ABI 跨界问题。证据如下：结构体均为标量加指针的 C 布局，函数均为无名修饰的 C 调用约定，复杂载荷均为 JSON 字符串，变长返回均为两段式尺寸查询，内存归属均为宿主分配、插件读写、调用期有效，恐慌在作者侧先拦截为状态码。Rust 作者侧只经 `export_plugin!` 生成符号，不手写边界；宿主侧只按 C 函数指针类型解析，不过问编译器版本。其他编译语言实现同一符号表即等价，头文件见 `c-api/wf_plugin.h`，最小 C 实现见 `examples/native-c/`。

细化对比：相对 Wasm 的内存字符串加 fuel 模型，原生用空结尾字符串加宿主缓冲，避免两套分配器互释；相对 Lua 的全局表约定，原生用注册器回调表加单分发入口，跨语言时无需绑定解释器；相对清单内联，原生是唯一能追加行为与界面描述的执行形态，但也因此承担同进程崩溃与恶意代码的全部风险，不可用于不可信分发。

演进方向是加固而非另起模块：冻结主版本符号表，补齐头文件与多语言示例，补齐容量不足重试与错误码的契约测试。需要对非受信代码设防时，把插件迁移到沙箱，而不是给动态库套脚本式沙箱仿真。

## 5. 桥接层、命令层、界面层与对话层

* 桥接只同步声明式资源。行为贡献留在执行路径消费，资源模板、工具定义、模型提供方模板在激活期写入资源注册表、工具注册表与模型网关，停用期对称移除。内置装配器经适配器走统一引擎，注册按装配前、组装、注册、装配后顺序执行，任一步失败即激活失败。来源见 `src/contributions/bridge.rs` 与 `manager` 目录。
* 命令声明层只产数据。服务端快照按版本号整体替换，不做逐条差分；本机扫描只读清单字节，全局目录直读，项目目录按内容指纹显式批准；合并优先级为内置大于本机，本机大于快照。清单五段的形状与校验见 `wf-plugin-sdk/src/contributions.rs` 的界面类型。
* 命令程序化层仅原生可追加。注册器尾部字符串入口与清单内联走同一注册表方法与冲突策略，输入为 JSON 字符串，输出按容量不足告知所需尺寸并重试。作者侧只经生成宏导出符号。脚本与沙箱不新增程序化界面通道。
* 界面槽位层只做展示。宿主拥有插件与槽位内容，命名渲染区域按宽算高，零高即隐藏。第三方界面扩展先走命令声明层，确需自绘只允许受信原生通道，且焦点与关闭权归宿主。
* 对话层是向人提问的唯一通道。插件只发确认、单选、输入、编辑四种请求，宿主拥有焦点、渲染与关闭。超时与输入结束一律失败关闭，不挂起轮次。缺失对话框权限即拒绝并指名插件。

## 6. 推荐用法

* 纯界面加斜线加补全加设置加模板加改写，一律用清单内联；本机专属再加本机扫描。无执行代码时不选任何后端。
* 工作流节点与工具执行等轻回调，优先脚本；需要多语言分发或不可信隔离时选沙箱；需要触网的认证与镜像实现、复杂编解码、界面程序化注册时选原生。
* 声明式资源经桥接同步，不手写注册表写入；内置资源用装配器适配，不另起插件类型。
* 界面自绘先判断是否为内置需求。内置用槽位实现；第三方先用命令声明与对话框；确需自绘再走受信原生通道。
* 向人提问一律走对话层，不自建终端读取，不绕过权限门控。

## 7. 禁止事项

* 禁止为旧协议保留兼容分支，禁止提升版本号，禁止新增并行模块，替代一律改原模块。
* 禁止把权限声明当作跨后端安全边界，禁止用宽松开关放行必选冲突，禁止带着残留占位执行命令。
* 禁止在沙箱与脚本侧新增程序化界面通道，禁止插件自带主题与自绘组件（受信通道除外），禁止插件发起连接、直改工具激活集、贡献会话源。
* 禁止在注释中引用本文档的章节编号，注释只描述代码意图。
