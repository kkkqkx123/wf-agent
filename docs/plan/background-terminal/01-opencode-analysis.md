# `ref/opencode` 后台终端实现分析

> 本篇只回答 `opencode` 是怎么做后台终端的，不做评价。评价与取舍见 `03-design.md`。

## 两个正交概念

`opencode` 有两套不要混为一谈的后台机制：

1. **后台任务**：agent 工作的后台化，以任务注册表为中心，shell 命令与子 agent 都是任务的生产者。
2. **终端载体**：承载命令输出的存储与交互层，分为非交互 shell 存储、短暂伪终端、会话级常驻伪终端三类。

另有后台服务（托管服务进程的启停）与本文无关，仅为服务宿主生命周期管理。

## 任务注册表

核心位置为核心包内的任务模块，进程内注册表加键值持久化两部分组成。

数据模型上区分运行态与持久态。运行态记录标识、类型、标题、状态（运行中、完成、失败、已取消）、起止时间与输出摘要；持久态只保留可恢复任务的最小恢复信息（shell 类记录会话标识与命令，子 agent 类记录父子会话标识）。

关键行为：

- 启动时去重并在独立作用域分叉运行，退出时结算状态并落盘（仅可恢复且已分配通知标识的任务）。
- 阻塞等待区分三种返回：已完成直接消费返回；已被后台化返回后台化分支；否则注册阻塞计数并竞速等待完成或后台化信号。
- 后台化仅对运行中任务有效（已完成但可恢复的允许延迟交接），后台化时分配通知标识并持久化，解除阻塞等待者。
- 等待支持可选超时；不可恢复的已完成任务进入小容量最近最少使用队列，可恢复任务保留至通知确认。
- 取消标记状态、解除等待、关闭作用域并消费条目。
- 重启恢复通过扫描持久化键恢复：shell 任务不再复活进程，而是回放输出或取消原因并合成通知；子 agent 任务校验父子会话后重建等待并通知。

容量上有明确上限（已退出条目保留约二十余条），输出文件有按天清理与定时回收。

## 非交互 shell 存储

核心位置为核心包内的 shell 服务，位置作用域（按工作区隔离），内存映射加输出文件两部分组成。

创建流程为解析环境与 shell 二进制、分配递增标识、落输出文件、派生子进程并将字节流泵入文件，同时计数大小与行数、发布创建与退出事件、维护已退出上限、触发超时终结。输出读取按绝对字节游标分页，返回输出片段、当前游标与总大小；结果组装做行数与字节数双截断并提示完整输出的文件位置。

事件通过统一事件清单发布创建、退出、删除三类；超时可清除（后台化时长清零转为无限等待）。

## 支持后台的 shell 工具

输入含命令、工作目录、超时与后台开关。无后台时默认超时约两分钟，有后台时默认不限时。

执行流程为创建 shell 会话并上报进度、注册后台任务、根据后台开关分流。后台路径直接后台化任务并派生完成通知后返回 shell 标识与输出文件位置，附带不要轮询等待的指示。非后台路径阻塞等待任务，等待期间若被会话级后台化动作抢占，则同样转后台（清除超时并派生通知），否则等待结算，失败或取消转为工具失败。

完成通知等待任务结算，组装带状态的通知文本，通过合成会话消息唤醒原会话，再确认并清理后台条目。

## 子 agent 后台

第二类任务生产者。创建或复用子会话并投递提示词，注册子 agent 任务，后台开关分流与 shell 工具同形。后台路径返回子会话标识，前台路径阻塞等待，中断时同时中断子会话并取消任务。通知投递携带子会话状态与来源元数据，同样经合成消息唤醒父会话。

## 会话集成

- 手动后台化：将会话当前阻塞的任务整体转后台，并合成一条列出任务类型与标题的提示，告知不要等待或轮询。
- 用户直发 shell：以不限时创建会话并返回结果句柄，同时发布会话级 shell 起止事件。
- 语言模型降噪：标记为后台的合成消息在转语言模型消息、压缩与更新路径被跳过或压空，避免后台通知污染上下文。
- 配置面：默认 shell、便携扫描开关、子 agent 深度等。

## 协议与事件

- shell 域按位置作用域提供列表（仅运行中）、创建、查询、按游标读输出、删除（含终止与删文件）。
- 伪终端域提供列表、创建、查询、改标题尺寸、删除、连接令牌与套接字连接（含游标续播）。
- 会话级常驻伪终端为实验域，按会话读写屏、启停与交接。
- 会话域提供直发 shell 与整会话后台化两个动作。
- 事件经统一套接字下发 shell 与伪终端的创建更新退出删除，以及会话级 shell 起止。

服务端处理器均包位置上下文，删除幂等，会话后台化对空闲会话为空操作。

## 客户端与界面落点

- 客户端软件包提供 shell 与伪终端的连接构造器与生成式调用，运行中 shell 以映射形式持有。
- 桌面终端界面用会话级常驻伪终端，支持快照恢复后套接字接管、尺寸同步与检查点协议。
- 网页端后台任务视图不直接读任务注册表，而是从时间线派生：筛选运行中的 shell 与子 agent 工具片段，减去已完成的合成通知，加上活跃子会话与按会话过滤的运行中 shell。
- 命令行界面无 shell 任务直达命令，仅有服务启停命令；shell 与伪终端纯经接口与工具驱动。

## 对本方案的提示

`opencode` 的关键分离在于任务注册表只管任务状态与通知闭环，终端存储只管进程与字节流，两者经标识关联而非合一。通知经合成消息唤醒会话而非经终端字节流推送，大输出经文件加游标而非经事件广播。这些分离正是当前项目缺失的部分，详见 `03-design.md`。
