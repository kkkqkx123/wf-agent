# 当前差距与必要性分析

本文基于当前项目前端源码，判断执行页是否需要浮窗式 graph 查看功能。所有结论均给出文件依据，无法确认的内容明确标注。

## 1. 当前执行页结构

- 执行工作台为列表加检查器，支持双栏对比，检查器按执行器类型切换会话检查器与运行检查器，对应 `apps/web-app/src/routes/executions/+page.svelte` 的主区与检查器插槽。
- 执行详情为独立路由，头部展示状态徽标、类型徽标、版本、编号与血缘链接，动作区提供暂停、恢复、取消、重跑与返回，对应 `apps/web-app/src/routes/executions/[id]/+page.svelte`。
- 运行检查器为最重的组件，头部为名称、编号、状态、进度条与四宫格，主体为按类型裁剪的页签集合，对应 `apps/web-app/src/lib/components/domain/ExecutionInspector.svelte` 与 `apps/web-app/src/lib/config/execution-tabs.ts`。
- 工作流类型展示九个页签，智能体类型展示十个，聊天类型展示六个，图只是其中一个页签，默认页签为总览。

## 2. 图与进度的现状

- 图页签已具备叠加管线：从图快照、分析快照与状态快照派生执行叠加，再分别生成节点与边叠加，支持运行脉冲、失败、关键路径、慢节点热力与决策点，对应检查器中的叠加派生与 `apps/web-app/src/lib/graph/execution-projection.ts`。
- 回放游标、倍速、单步与范围选择与同一叠加管线共享，工具与时间线可跟随回放范围过滤。
- 图页签同时承担实时订阅，缓冲服务事件并按固定节拍合并，避免高频节点更新逐帧重渲染。
- 迷你图明确只渲染结构点与分组框，不渲染执行色，避免热更新重绘总览，对应 `GraphCanvas.svelte` 中总览刷新的注释。
- 模板侧的图为可编辑的定义图，执行叠加只存在于工作流图页签，模板草稿图明确不投影运行态，避免把运行态误写到未保存的草稿上。

## 3. 痛点场景

- 实时值守：用户需要一边看实时输出、工具调用与时间线，一边确认当前节点在图中的位置。现状要求切到图页签才能看到脉冲与当前节点，切回其他页签即丢失空间上下文。
- 事后复盘：用户需要一边读调用栈与慢节点分析，一边对照拓扑。现状要求在分析页签与图页签之间往返，选中节点的心智锚点靠记忆维持。
- 跨页签定位：图、调用栈、工具、分析之间已有双向定位，但都以完整图页签为目标，跳转即切换页签，打断当前阅读位置。
- 定义对照：执行基于某个定义版本，快照可能与模板最新版不一致。现状只在图页签提供跳转定义库的文字链接，没有快照与定义的版本对照，也没有基于原始模板的进度表达。
- 列表浏览：工作台检查器默认展示总览页签，同样看不到拓扑，连续查看多次执行时需要逐个进入详情。

## 4. 必要性判定

- 需要做，优先级为高。理由不是图不够强，而是图与进度互斥，信息密度优势被页签切换抵消。
- n8n 与 Dify 的共同选择是图与执行同屏，n8n 用底部常驻日志面板，Dify 用右侧浮动运行面板，两者都不要求用户离开画布去看执行。
- 当前项目不需要改为画布为主，只需要在检查器为主的布局上补一个跨页签的空间锚点，浮窗是改动最小的形态。
- 不做会继续付出上下文切换成本，且回放、热力、关键路径等已有能力的使用率会被页签隔离拉低。

## 5. 非目标

- 不替代完整图页签，完整图的筛选、分组、回放、边标签预算与大图截断策略保持不变。
- 不在浮窗中做编辑、连线、布局保存与版本管理，浮窗为只读。
- 不为聊天类型补拓扑，聊天为无图 transcript，按现有页签集合保持现状。
- 不把执行色画进迷你总览，迷你总览继续保持结构-only，避免热更新重绘。
- 不引入第二套颜色语义，所有色板复用现有状态字典与语气管线。

## 6. 对原始模板叠加进度的影响

- 用户诉求中的在原始模板基础上补充执行进度，应理解为基于定义拓扑的只读进度投影，而不是把执行快照写回模板。
- 需要展示定义标识、版本号、重跑来源与父子血缘，并在快照与定义不一致时给出版本提示，避免把旧拓扑误认为当前定义。
- 工作流执行已有定义标识，具备做模板关联的条件；智能体决策图为 loops 语义，与模板定义图不同源，浮窗首阶段只覆盖工作流类型。
