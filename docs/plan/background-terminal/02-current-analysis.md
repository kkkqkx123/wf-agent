# 当前项目后端、前端、命令行界面现状分析

> 本篇只回答当前项目是如何处理长耗时命令的，结论汇总见末尾差距表。

## 后端：双路径执行模型

### 无状态单发路径

单发命令执行器走阻塞等待加超时钳制（默认约两分钟，上限约十分钟），超时杀进程。参数为命令、工作目录、超时与单发标准输入，返回标准输出、标准错误、退出码、耗时与成功标志合并后的内容。无流式、无交互，调用前走作用域门控、沙箱网关与检查点起止。

### 有状态后台会话路径

后台会话存储是当前承载长耗时命令的主力，位置为基础设施层 shell  crate 的存储、终端会话、会话、后端、输出缓冲、排出、行分发、事件槽与生命周期模块。工具层以有状态工具族暴露：创建后台会话、在会话内阻塞执行、复用空闲会话、读输出、等待、发输入、调尺寸、终止、按任务释放、会话观察。

典型用法分两种：创建即运行（返回会话标识与进程信息，不含输出），或在已有空闲会话内阻塞执行（带超时并返回该命令的输出）。配套操作含全量快照、增量新输出、分页窗口（含窗口末端、总写入量与前缀丢弃信息）、带正则与静默期的等待、标准输入注入、伪终端尺寸调整、优雅终止（先终止进程组，宽限后强制杀）与按任务批量释放。

### 进程跟踪与输出模型

伪终端支持始终编译进，仅由运行时开关与会话级交互标记决定是否走伪终端，否则走管道。管道后端可走沙箱策略，伪终端后端因无法挂载执行前钩子而跳过内核强制，仅走命令安全门。

会话池以并发映射持有终端会话，另有一根延迟启动的监视线程做完成检测（短轮询加读端结束时唤醒）。终端会话记录空闲或忙碌状态、模式、工作目录与环境、累积输出、当前命令句柄、任务绑定与活跃时间。会话上限约六十余个，支持按任务限额与空闲超时回收（仅回收无绑定的空闲会话）。

输出为分段环形缓冲（约两百余 KB 尾部保留，绝对位置在截断后保持稳定），经输出管线（缓冲加行分发加排出）与事件分发（异步单线程逐行）推进。逐行输出事件默认关闭，生命周期事件常开以便检查点收尾。同步执行路径在返回前排空事件，保证调用者返回时推送已达槽。消费者只能轮询（读输出、等待、快照、窗口），没有面向套接字的字节推送。单会话同一时刻只允许一条运行命令，忙时直接报错。伪终端输出合并标准输出与标准错误，前端无转义序列渲染。

### 服务端接口现状

服务端没有直达 shell 的路由。shell 只能经通用工具调用面触达（单发执行、审批执行、事件审计），工作流后台执行与流式执行是整图维度的异步（派生驱动后立即返回执行标识，另起任务排空流），与单条 shell 后台化无关。

另一套独立的 Git 终端（仓库锁定，不走后台会话存储）提供创建、输入、按字节偏移读输出、调尺寸（空操作，仅刷新时间戳）、关闭。输入为同步执行单条命令并拼接到约一 MB 上限的字符串缓冲，前端轮询。

## 前端现状

前端无终端仿真器依赖。工具调用展示以工具调用卡为中心，shell 类工具名映射为终端图标与尾部展示类型，默认折叠显示尾部若干行加 earlier 行数提示，可展开看全量或结构化视图。实时聊天经执行流的事件增量驱动，而非原始 shell 字节流。

Git 终端面板为简易预排文本加输入框，状态机持有终端标识、文本与偏移，发送后按偏移增量追加，清空仅清显示不清服务端缓冲。

## 命令行界面现状

命令行界面不直连本地进程，仅为服务端事件流的渲染端。传输由共享运行器驱动服务端事件流，渲染器分流处理。后台仅存在于工作流维度（后台执行调用）。展示上轻量终端做标准输出与标准错误分流加 Markdown 渲染，完整终端界面做可折叠工具块与查看器弹窗，均无交互式 shell 透传、无伪终端挂件、无输出尾随循环。

## 差距汇总

| 维度 | `opencode` 有 | 当前项目有 | 缺口 |
|---|---|---|---|
| 任务注册与后台化语义 | 任务注册表，阻塞与后台化竞速 | 仅会话忙闲，无任务视图 | 无跨工具调用的后台任务聚合与手动后台化 |
| 完成通知闭环 | 等待结算后合成消息唤醒会话 | 监视线程仅收尾会话，无唤醒 | 后台命令完成后无人通知，需人肉轮询 |
| 大输出翻页 | 文件加绝对游标分页 | 环形缓冲截尾，前缀丢弃 | 长输出早段不可回看 |
| 输出推送 | 事件清单加通知事件 | 逐行槽默认关，生命周期常开 | 后台完成可感知但输出仍需拉 |
| 传输 | shell 与伪终端各有直达接口与套接字 | 无 shell 直达接口，仅工具调用面 | 前端与命令行界面无法独立管理 shell 会话 |
| 前端聚合视图 | 从时间线派生后台工作视图 | 仅单卡尾部展示 | 无运行中后台任务一览 |
| 命令行界面 | 服务启停加后台提示文案 | 事件流渲染 | 无后台任务列表与等待提示 |
| 重启恢复 | 后台键扫描加回放或取消说明 | 进程随进程结束 | 重启后后台任务无交代（预期内，但需明确语义） |

## 约束继承

- 架构规则要求优化只改原模块，不新增替代模块；命名按职责而非新旧。
- 无需向后兼容历史数据，但接口一旦发布即需文档化，不做静默双轨。
- 安全面沿用命令安全与沙箱网关，伪终端仍跳过内核强制的现状不变，需在设计中显式声明而非试图补齐。
