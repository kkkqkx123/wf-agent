# 02-执行器

> 范围：`executor/`（`trait_def`、`base`、`stateless`、`stateful`、`builtin`、`mcp`、`rest`、`cli`、`circuit_breaker`、`builtin_handler`、`builtin_handlers`）
> 定位：工具的实际执行层，按工具类型分派到不同运行时

## 执行上下文与 trait

`ToolExecutionContext` 是每次工具调用的携带结构：执行 id、可选节点 id、元数据，以及上层注入的父链路、general 代理调用器、检查点会话、已解析文件作用域、取消信号。格式化输出只暴露各可选项的有无，避免泄漏句柄细节。`ToolExecutor` trait 只要求异步执行、类型名与可选清理；`ToolExecutorExt` 为全部实现者统一提供带重试与带超时的执行：重试策略来自调用选项，成功判定为返回成功结果；超时走公共执行网关，超时本身转为失败结果而非错误（标记为可重试的瞬态失败）。

## 参数校验

`BaseExecutor` 承担执行前的参数校验：必填字段缺失、未知字段（当 schema 禁止附加属性时）、类型与枚举/格式（日期时间、日期、时间、UUID 等正则）、数值与长度与数组元素约束。校验失败直接返回校验错误，不进入处理器。

## 五类执行器

- 无状态执行器：同步与异步两张处理器表，优先查异步表。处理器为纯函数（参数加上下文），供文件读写、网络检索等无会话工具使用。
- 有状态执行器：按工具 id 存放实例工厂，按执行 id 隔离实例，另有按工具与执行双层键的键值存储。供记忆、后台终端会话等需跨调用保持状态的工具使用。
- 内置执行器：按工具名分派到共享的内置处理器表（六个默认处理器加外部注入），分派前做参数校验，作用域违规错误保持错误类型向上传播（供引擎计数与标注），其余处理器错误转为失败结果。资源（回调、技能加载器、general 调用器）按调用时刻动态解析。
- MCP 执行器：从工具配置解析服务名，可注入共享连接管理与用量分析；无管理时退化行为由连接层决定。
- REST 执行器：基于 HTTP 客户端，支持请求/响应/错误三类拦截器、错误分类（坏请求、鉴权、缺失、限流、服务端、客户端、网络、熔断）与可重试判定，内置熔断器。

内置处理器（`builtin_handlers`）为每个默认内置工具提供类型化参数结构（未知字段拒绝），保证 schema 与实现由类型系统同步：智能体调用（同步等待或异步派生）、工作流执行（同步或异步）、工作流状态查询、执行取消、技能加载、general 代理（委托执行上下文中的调用器）。

## 熔断与 CLI 执行器

`circuit_breaker.rs` 是通用的失败计数熔断器：连续失败达阈值后打开，经复位超时后放行单个半开探测，与 REST 无依赖，可被任何执行器复用。`cli.rs` 是外置二进制执行器：按配置定位可执行文件（自定义路径优先），支持沙箱策略透传、同步命令运行与 ripgrep 专用执行，未找到二进制时报告不可用而非执行失败。
