# 插件形态全局规范

本文定义项目内所有插件形式的归属层次、适用范围与选用边界。凡涉及新增扩展点、接入新后端、选择宿主渲染或执行路径之处，均以本文为准。

## 1. 分层模型

插件按七层依次落地，后一层只能消费前一层的产物，不得跨层直接调用实现：

* 契约层：清单结构、贡献载荷、权限枚举、原生与 Wasm 的接口常量。只做类型与校验，不含宿主逻辑。
* 引擎层：三种后端加载、版本协商、准入校验、贡献注册与冲突判定、包管理与签名。只做加载与注册，不做业务渲染。
* 桥接层：把声明式资源贡献同步进资源注册表、工具注册表与模型网关；把内置资源装配器包装为插件。只做同步与卸载，不执行业务。
* 命令声明层：快照五种界面描述加本机两根目录扫描。只产数据，不执行代码。
* 命令程序化层：仅原生库可通过注册器追加界面描述。只走稳定接口，不暴露内部类型。
* 界面槽位层：进程内槽位内容注册与分帧绘制。只做展示，不承载行为。
* 对话层：宿主代为提问并回传答案。只做呈现与超时失败关闭，不让插件触碰终端。

跨层引用一律无效。例如界面不得直接调用引擎后端模块，沙箱客户机不得构造界面组件，槽位内容不得发起注册表写入。

## 2. 形态总览

| 形态举例 | 归属层次 | 载体 | 是否执行代码 | 推荐度 |
|---|---|---|---|---|
| 清单内联界面描述 | 引擎与命令声明 | 清单中的命令、补全来源、设置行、工具摘要、改写规则五段 | 否 | 最优先，纯数据首选 |
| 本机两根目录扫描 | 命令声明 | 全局目录加项目目录下的清单 | 否 | 本机专属界面首选 |
| 服务端快照合并 | 命令声明 | 快照版本号加五段集合 | 否 | 联机 shells 默认来源 |
| 原生库程序化注册 | 命令程序化 | 稳定接口加空结尾字符串载荷 | 是，同进程 | 可执行界面唯一通道 |
| Lua 脚本贡献 | 引擎 | 脚本文件加受限标准库 | 是，解释器内 | 轻量执行回调可选 |
| Wasm 客户机贡献 | 引擎 | 核心模块或组件模型产物 | 是，沙箱内 | 不可信或多语言分发首选 |
| 桥接同步 | 桥接 | 资源注册表、工具注册表、模型网关 | 否 | 声明式资源唯一落点 |
| 内置装配器适配 | 桥接 | 内置装配器包装 | 是，同进程 | 内置资源首选 |
| 槽位内容 | 界面槽位 | 进程内槽位实现 | 是，同进程 | 内置与受信界面首选 |
| 宿主对话框 | 对话 | 确认、单选、输入、编辑四种请求 | 否 | 向人提问唯一通道 |

同一需求不得同时选用两种执行形态。能用数据表达的一律不用代码，能用清单内联的一律不用程序化注册。

## 3. 契约层规范

* 清单是唯一身份载体，含标识、严格语义化版本、后端类型、入口、版本化入口表、依赖表、贡献声明、权限表、配置模式与配置值、钩子表、模型提供方模板、工具定义、工具描述、界面五段、沙箱限额。未知字段直接拒绝，不做忽略。
* 后端类型显式声明优先，缺省时按入口后缀推断。默认入口与全部版本化入口必须同属一个后端，混用即加载失败。
* 权限声明按后端区分执行力。沙箱客户机运行时强制授权，脚本与原生库仅做准入与审计输入。不得把权限声明当作跨后端安全边界。
* 贡献载荷分两类。行为类含节点执行、工具执行、模型编解码、认证、镜像生成、事件处理、中间件、压缩与检索与向量建议；描述类含界面五段、工具定义、工具描述、资源模板。行为类走分发，描述类走注册表。
* 协议主版本锁定为一，不提供向后兼容，不保留旧分支。版本不一致直接拒绝加载，由作者升级后重建。

## 4. 引擎层规范

* 三种后端各走自己的版本门控，上层插件特征行为一致。原生路径取声明与宿主支持数组的交集选最高公共版本；核心模块路径先按声明选文件再用访客导出校验；组件路径编译前扫描内嵌世界名主版本；脚本路径无版本概念，不参与协商。
* 加载门按后端独立开关。脚本与沙箱默认开启，原生默认关闭。原生与宿主同进程、无沙箱，只允许完全受信的第一方构建显式开启。限额数值永不兼任开关语义。
* 准入只做清单合法性与权限黑名单。接口兼容由后端握手决定，属主过滤由调用方决定。批量发现时加载失败跳过并记日志，单文件加载失败大声报错。
* 注册键全局唯一。单值注册表在默认拒绝策略下重复即失败，无论属主是否相同；多值注册表允许多条并存。静默覆盖一律视为缺陷，调用方必须先注销再重注册。
* 包管理以标识为唯一键，签名校验覆盖默认入口加全部版本化入口。供应链完整性在包层解决，加载期只做配置了信任时的复核。

## 5. 桥接层规范

* 行为贡献留在执行路径消费，桥接只同步声明式资源。同步写入资源注册表与工具注册表，卸载对称移除。网关侧先注册编解码适配再写入提供方定义并淘汰缓存客户端。
* 内置装配器通过适配器走统一插件引擎。注册期按装配前、组装、注册、装配后顺序执行，任一步失败即激活失败；卸载期桥接先移除资源再调卸载钩子。资源模块本身不得依赖插件模块，胶水只出现在运行时。
* 无插件构建走直装回退路径，逐项大声报告但不阻断启动，钩子失败仍大声失败，与引擎桥接语义对齐。

## 6. 命令声明层规范

* 快照是服务端的版本化投影，含指纹版本号加界面五段。外壳比较指纹相等即跳过，不相等即整体替换，不做逐条差分。形状与契约层逐字段对应，漂移时编译失败而非运行时丢弃。
* 本机扫描只读清单字节，从不查入口点，从不启动脚本运行时。全局目录受信直读，项目目录需按内容指纹显式批准，篡改即批准失效。权限缺失整类跳过并提示，单条非法按条丢弃并计数。
* 合并优先级固定为内置大于本机，本机大于快照。本机同键遮蔽快照同键并提示；内置斜线名冲突时插件行保留但不可达。设置值非法时保留旧值或回落。
* 三端消费形态不同。完整终端拉取快照并扇出到全部标签页；轻量终端同样拉取并合并后驱动斜线解析、补全、设置展示与模板渲染；无头模式仅提供管理命令与结构化问答协议，不做斜线注册。无头需要完整界面时应升级形态，而非在无头内重建交互。

## 7. 命令程序化层规范

* 仅原生库可程序化追加界面五段。注册器尾部五个字符串入口与清单内联走同一注册表方法、同一校验与同一冲突策略。解析失败按非法贡献记录并使激活失败。
* 脚本与沙箱客户机不新增程序化界面通道，其界面需求一律走清单内联。沙箱内无法构造界面组件，多走一次边界只增失败点，不增表达力。
* 接口形态与工具注册对称。输入一律为空结尾字符串载荷，输出缓冲按容量不足告知所需尺寸并重试，清单按两阶段尺寸查询。作者侧只经生成宏导出符号，不手写接口符号。
* 结构扩展后旧产物必须重编，新旧混用不做适配。注释只描述代码意图，不引用外部文档编号。

## 8. 界面槽位层规范

* 槽位是命名渲染区域，字符串命名即可扩展，关联常量覆盖外壳实际消费的区域。现有区域含侧栏、作曲器芯片、转录本条目、工具调用与结果、会话分组、设置行、首页提示与页脚、瞬态通知、页眉、页脚主行与扩展行。
* 宿主拥有插件与槽位内容，停用按插件精确移除，会话切换按槽位清空。注册在启动期编译期完成，激活在运行时切换。槽位内容按宽算高，零高即隐藏。
* 当前唯一已接线实现为会话侧栏，属内置插件。槽位层不做动态外部加载，第三方界面扩展应先走命令声明层；确需自绘时只允许受信原生通道，且焦点与关闭权归宿主。

## 9. 对话层规范

* 插件只发问题，宿主拥有焦点、渲染与关闭。四种请求为确认、单选、输入、编辑。空选项拒绝呈现，超时与输入结束一律失败关闭，不挂起轮次。
* 承载映射固定。完整终端用现有浮层组件承载；轻量终端降级为标准错误提问加标准输入读取；无头模式返回取消或默认值并记录。同一请求在三端返回同形结果。
* 权限在运行时准入。缺失对话框权限即拒绝并指名插件。自定义全屏与浮层仅开放受信原生通道，沙箱无此通道。

## 10. 信任与失败姿态规范

* 项目代码先批准后运行。项目插件目录未批准时零加载并提示可执行动作；批准粒度为目录内容摘要。
* 校验失败按条处理，冲突失败按次阻断。渲染与补全类失败回落内置并记录，不阻断会话；命令与设置类冲突阻断激活并指名双方。
* 部分激活失败不自动清理残留，调用方必须显式停用后再重试。重试不做幂等覆盖，避免把半注册状态误认为成功。

## 11. 推荐用法

* 纯界面加斜线加补全加设置加模板加改写，一律用清单内联；本机专属再加本机扫描。无执行代码时不选任何后端。
* 工作流节点与工具执行等轻回调，优先脚本；需要多语言分发或不可信隔离时选沙箱；需要触网的认证与镜像实现、复杂编解码、界面程序化注册时选原生。
* 声明式资源经桥接同步，不手写注册表写入；内置资源用装配器适配，不另起插件类型。
* 界面自绘先判断是否为内置需求。内置用槽位实现；第三方先用命令声明与对话框；确需自绘再走受信原生通道。
* 向人提问一律走对话层，不自建终端读取，不绕过权限门控。

## 12. 禁止事项

* 禁止为旧协议保留兼容分支，禁止提升版本号，禁止新增并行模块，替代一律改原模块。
* 禁止把权限声明当作跨后端安全边界，禁止用宽松开关放行必选冲突，禁止带着残留占位执行命令。
* 禁止在沙箱与脚本侧新增程序化界面通道，禁止插件自带主题与自绘组件（受信通道除外），禁止插件发起连接、直改工具激活集、贡献会话源。
* 禁止在注释中引用本文档的章节编号，注释只描述代码意图。
