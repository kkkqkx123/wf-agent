# 任务一至三细化修改方案

对象为剩余任务总清单的前三节。本方案逐任务给出 n8n 参照、现状锚点与分节点修改步骤。
配套分析：`docs/analysis/n8n-workflow-visualization.md`；n8n 实现位于 `ref/n8n`。

> 落地状态：阶段一（后端节点归属）与任务一至三均已实现。回放作用域只使用精确连接
> （工具按节点标识精确匹配，时间线按时间戳精确截断），未使用名称模糊匹配做数据
> 连接；模糊匹配仅保留为工具卡定位画布这一显式用户手势的兜底。

## 任务一：执行回放联动

### n8n 参照

- 编排层节流：`WorkflowCanvas.vue` 用 `throttledRef(mappedNodes, 200)` 降频执行态高频更新，且只在执行中启用节流版本，静止时用全量映射。含义是游标或流事件只改变映射输入，不改变映射函数本身。
- 单一可视化状态源：`useWorkflowDocumentRenderData` 统一派生执行、校验、标签状态，画布只消费。含义是回放游标应当作同一派生的一路输入，而不是第二套状态。
- 边状态优先级：`useCanvasMapping` 按运行中优先于错误优先于成功派生边色。回放沿用现有优先级，不另起规则。

### 现状锚点

- 回放条与播放节拍：`ExecutionInspector.svelte` 回放控件区约 675-747 行，播放节拍约 353-369 行，速度变量已存在但无选择控件，节拍下限 200 毫秒已符合 n8n 的节流 floor。
- 游标投影：约 149-182 行，游标已作为投影输入，工具列表派生约 250-258 行只认文本过滤，时间线直接渲染全量。
- 分析行：慢节点行约 878-895 行，决策点约 916-929 行，关键路径约 896-915 行，均为静态展示；图选中卡已有跳工具 Tab 的按钮约 773-781 行。

### 分节点修改

执行检查器节点分四步。第一，增加速度选择控件，放在播放暂停按钮旁，选项覆盖慢放、常速、倍速三档，直接绑定已有速度变量，节拍公式与下限保持不变。第二，新增游标作用域派生：由已有游标视图的已执行节点集合得到节点集合；工具列表派生在文本过滤之上叠加该作用域，回放未启动时行为不变，启动后列表只显示已执行节点相关的工具调用，并用一行小字说明正在跟随游标。节点与工具的匹配复用已有的工具到节点匹配函数，反向再写一个节点到工具的归一化匹配，两者共用同一归一化规则。第三，时间线跟随游标：调用栈帧带进入时间戳，时间线条目带发生时间戳，游标时刻取当前帧的进入时间戳，只显示该时刻之前的条目；名称匹配作为兜底。第四，分析行与图双向定位：慢节点行、决策点、关键路径各项增加定位按钮，点击后切到图 Tab 并经现有聚焦通道定位；图选中卡在选中节点属于慢节点或决策点或关键路径时，追加跳分析 Tab 的入口，分析侧三张卡片加可定位的标识以便滚动定位。

图浏览外壳与画布节点无需改动，全部复用现有聚焦、过滤与投影通道。

### 验收

速度切换后步进间隔跟随变化；拖动游标时工具调用与时间线同步收缩；分析行可定位到图节点，图节点可跳回分析对应行；回放退出后列表恢复全量。

## 任务二：热力与决策点悬停说明

### n8n 参照

- 边悬停说明：`CanvasEdgeTooltip.vue` 用设计系统悬停组件包裹边标签，悬停即显示端点与计数说明；`CanvasEdge.vue` 悬停时把边提到顶层，工具栏收起带 600 毫秒延迟，避免误触闪烁。
- 节点信息外露：节点副标题由渲染数据派生并常显，状态图标表达执行结论。含义是结论性标记常驻图上，数值性明细放在悬停与详情卡。

### 现状锚点

- 标签生产：`ExecutionInspector.svelte` 约 219-248 行，耗时标签与分支标签均已派生。
- 传递断点：`GraphExplorer.svelte` 约 80-81 行接收标签，约 889-904 行只在选中卡展示，未转发画布；`GraphCanvas.svelte`  props 区约 40-100 行无标签通道，事件区只有点选与右键约 922 行与 1026 行，无悬停监听。

### 分节点修改

画布节点分三步。第一，增加标签通道，接收按节点标识索引的说明文本，与现有的决策标识集合、热力分档通道并列。第二，在 cytoscape 实例上注册节点悬停与离开监听，与现有点选监听放在同一事件接线区；悬停命中且该节点有说明文本时，在画布容器内显示一个绝对定位的提示浮层，内容即转发的说明文本。显示加短延迟以避免平移经过时闪烁，离开、拖拽、缩放、点选时立即隐藏并清理计时器。定位用事件的渲染坐标换算为容器相对坐标，复用小地图已有的坐标换算思路。组标题单元沿用其已有标签，不叠加说明。第三，浮层样式收敛在画布组件内，对读屏器隐藏，因为同样信息已在选中卡中可达。

图浏览外壳节点只做一件事：把已持有的两份标签转发给画布，合并为一份或分开传递均可，与画布通道命名保持一致。

执行检查器节点无需改动。

### 验收

悬停慢节点可见耗时，悬停决策点可见分支说明；形状尺寸不变；快速划过画布无闪烁残留；选中卡信息与悬停一致。

## 任务三：大图保留规则显性化与失败态强调

### n8n 参照

- 状态视觉语言：`CanvasNode.vue` 按数据计算状态类，选中、悬停、运行中、等待、停用各有独立类别，互不覆盖；边色由状态优先级函数决定，失败优先于成功。
- 大图降载：分组成员折叠隐藏降低渲染量，布局把整组视为一个盒子。含义是保留规则作用于数据进入渲染之前，提示文案说明的是数据侧的取舍。

### 现状锚点

- 计数行：`GraphExplorer.svelte` 约 635-643 行，只显示折叠数与总数；大卡片约 793-811 行已写清保留顺序与采样说明。
- 失败通道：执行检查器约 766 行已传入失败集合，外壳约 206-218 行仅用于保留集合；画布约 481-502 行的节点类别无失败项，约 823-850 行的样式表有运行、关键、决策、热力三档，无失败强调。

### 分节点修改

图浏览外壳节点分两步。第一，计数行在截断或折叠生效时追加保留优先级短语，与大卡片使用同一词汇，顺序为失败、运行中、关键路径、选中；未截断时不显示，避免常态噪音。第二，把已持有的失败集合转发给画布的新增失败通道。

画布节点分两步。第一，节点类别装配处增加失败项，与运行脉冲、关键路径、决策点并列。第二，样式表内新增失败类别，表达为加粗的失败色描边，不改变形状尺寸；选择器顺序保证运行中脉冲优先于失败态，与投影层的优先级一致。

执行检查器节点无需改动，失败集合的传入保持不变。

### 验收

截断时计数行、大卡片、悬停说明三处词汇一致；失败节点在图上有独立强调且与运行脉冲不打架；保留顺序与分析 Tab 数据一致。
