# RAG 抽象与插件扩展点复核：问题清单与修改方案

> 背景：`crates/infra/rag` 现有四包分层与九类插件扩展已可工作，本篇在不重写的前提下收敛已知问题。存储契约对称调整见《关键词与向量存储契约对称调整》。
> 范围：`vector-contracts`、`keyword-contracts`、`source-contracts` 的端口形状，以及 `wf-rag` 的管线、插件注册、模型端口、配置引用方式。不含 HTTP、CLI、前端与工作流节点的集成收敛，那部分另见集成类计划文档。
> 方式：只改原模块，不建替代模块；不做旧数据兼容，已有索引以显式重建恢复。

## 0. 结论速览

* 存储与数据源契约方向正确，管线保持无状态、宿主注入后端与模型，值得保留。
* 插件层存在系统性问题：进程级全局注册表、字符串名字引用、建议型与执行型混杂、两处重排职责重复、一处声明后无消费、一处编解码注册后无调用。
* 模型端口过简，提示词不可定制；检索入口是自由函数群，缺少统一调用抽象，工作流与 Agent 难以多态复用。
* 方案按“收敛注册形态、合并重复职责、删除或接通死点、补齐调用抽象”四条线走，分三批落地，每批可独立验证。

## 1. 现状确认

* 契约层：向量存储、关键词索引、数据源读取与文档转换各有独立中立契约，对象安全，宿主以智能指针持有并按配置切换后端。
* 门面层：`wf-rag` 承担分块、清洗、摄取、查询、融合、重排适配、引用、合成、路由、同步、评测与三类关键词后端实现。
* 模型端口：嵌入与重排复用外部模型套件的提供方特征，文本补全自有极简端口，查询改写自有改写特征，编解码自有请求描述与响应解析特征。
* 插件扩展：文本分析器、向量编码（含命名空间编码）、元数据提取、分块切分、路由选择、检索建议、后处理、评测裁判、快照策略、嵌入与重排编解码，共十余注册入口，配置以可选名字引用。

## 2. 问题清单

* 全局注册表与实例注册表并存。转换器用可组合实例注册，其余插件用进程级静态映射，多配置共存、多租户隔离与测试隔离都受影响，测试需额外串行守卫。
* 插件边界以通用结构化值为载体，模式与种类以字符串声明，错误只能在运行时发现，拼写或形状问题无法在装配期暴露。
* 检索建议与后处理同做融合后重排，输入输出形状一致，仅调用时机一前一后，宿主难以判断何时用哪一个。
* 快照策略只声明不执行，管线无读取方，属于无消费扩展点，保留只会误导宿主。
* 嵌入与重排编解码只有注册与查询能力，默认提供方构造链未按名选用，属于未接通基础能力。
* 文本补全端口只有一个单提示词补全方法，无消息角色、无流式、无结构化输出，分解、假设 passage、反馈改写与合成的提示词全部硬编码在门面内，宿主无法调优。
* 配置以可选字符串引用插件，新增一种扩展就要在摄取、查询、合成三类配置上各加一个可名字段，配置类持续膨胀，且“名字写错”与“插件执行失败”的错误性质被混在一起。
* 检索入口是多个自由函数，参数多为集合、命名空间、文本、配置的重复组合，调用方需手写变体管理与重排装配；缺少统一的检索器与问答引擎调用抽象，上层编排难以统一。
* 分块只有递归实现加预设，语义与代码结构感知切分完全依赖外部切分插件补齐，而插件载荷同样走通用结构化值，调试成本高。

## 3. 修改方案

### 3.1 注册形态收敛

* 将插件持有方式从进程级静态映射改为宿主持有实例。每个宿主装配一个检索扩展注册实例，管线以引用传入，不再经全局查找。转换器注册实例作为形态范本。
* 名字引用保留为过渡形态，但查找失败与执行失败分离表述：未知名字属于装配错误，执行失败属于运行期降级，前者早失败，后者走内置回退并记录诊断。
* 迁移按扩展逐个进行，一次迁一种，存量全局入口在迁移完成前保留为薄转发，全部迁完后移除。

### 3.2 重复与死点处理

* 合并检索建议与后处理为单一融合后整形阶段，保留一个注册名与一个执行点，执行语义为排序与分数调整，输入输出沿用现有命中模型。
* 快照策略二选一：如确认未来由宿主执行，则补齐消费方并明确执行归属；如无消费计划，则移除注册与相关文档，不保留声明式占位。
* 编解码二选一：如宿主要按名选用线协议，则把选用接入默认提供方构造链；如暂无宿主需要，则移除注册表，只保留特征定义与适配器，不保留不可达的选用能力。

### 3.3 模型与调用抽象补齐

* 文本补全端口先补最小可用形态：区分系统提示与用户提示，允许调用方传入候选截断与输出上限，提示词模板下沉为可替换的装配参数而非硬编码常量。流式与结构化输出本次不做。
* 新增统一检索调用抽象与问答调用抽象：检索抽象封装嵌入、召回、融合、整形、扩展与预算裁剪；问答抽象在检索抽象之上封装改写、重排与合成。现有自由函数保留为抽象的默认实现，不删除，只收敛上层调用。
* 路由选择保留两级语义：插件选择器先选候选集合，关键词规则再兜底；两者共用一套候选校验与空结果回退，不再各写一套。

### 3.4 分块与元数据

* 递归分块保留为默认实现，标题路径、表格块、 token 预算等预设语义不变。
* 外部切分插件的输出校验保留内容非空与元数据标量约束，失败回退内置切分并记录诊断，行为不变。
* 元数据提取保留只补缺失键语义，不覆盖调用方显式传入的键。

## 4. 验证范围

* 每批迁移后运行工作区完整编译检查与受影响包的定向测试，重点覆盖未知名字早失败、执行失败回退、融合后整形顺序、路由兜底、合成零命中短路。
* 插件相关测试去掉对进程级串行守卫的依赖，改为每个用例持有独立注册实例，验证多实例可并存。
* 存储契约对称调整的验证见姊妹篇，不在本篇重复。

## 5. 不做事项

* 不引入图检索、多模态、摄取缓存、分布式抓取与后台任务队列。
* 不做旧插件名字兼容与旧索引兼容，需要时以显式重建恢复。
* 不改变向量种类、命名空间、融合算法与引用语义。
* 不改动 HTTP、CLI、前端与工作流节点的消费链路。
