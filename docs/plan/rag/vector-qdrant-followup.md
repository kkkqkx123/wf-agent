> 针对向量抽象层 Qdrant 剩余未实现能力的分批设计。中文撰写、自然语言为主，不贴完整实现。改动点与验收一一对应，顺序即实施顺序。其中第一批至第三批已落地，状态见各批标注；第四批至第六批与第三批延后算子仍为触发式。

## 背景与范围

`vector-qdrant-gaps` 的前三阶段已落地：集合校验、类型一致、确定性标识、单批取数、等待语义、索引最小集、配置拆分、健康版本、错误细分与读重试。在此之后，第一批（滚动列举、召回整定）、第二批（载荷局部更新）、第三批（组合扩展与确定性匹配算子）也已落地。当前契约覆盖创建、写入、稠密检索、滚动列举、按标识取数、按标识与按来源删除、计数、载荷局部更新，以及必含、可选分支、最小满足数、标识集合与相等、区间、前缀、子串、长度、空与 null 过滤。

本文剩余范围为第三批明确延后的算子，以及第四批至第六批：分组、推荐与发现输入、预取融合、排序输入、稀疏与多向量、命名向量、快照、分片与别名、gRPC 后端。所有未落地项均为触发式，不提前实现；无触发时契约保持现状。

## 设计原则

- 契约优先：三后端行为一致才进契约；仅 Qdrant 需要的运维能力保持专有扩展，不进 `VectorStorage`。
- 只加可选字段：查询与配置的扩展一律可选，默认行为不变，旧配置反序列化不变。
- 无后端逃生舱：不引入透传原生过滤或原生请求的旁路。
- 过滤扩展三端同步：过滤算子一旦扩展，内存、simvec、Qdrant 同步实现并补对等用例。
- 错误与重试沿用既有边界：参数错误报非法输入，限流与瞬错报传输错误，仅幂等读自动重试。
- 日志英文且不倾倒载荷与向量。

## 第一批：检索整定与分页扫描（已落地）

触发条件为管线需要全量扫描、维护分页，或召回调优需要整定参数。

- 滚动列举：契约新增滚动接口，参数为过滤加分页游标与上限，返回点列表与下一游标。Qdrant 侧映射为单次滚动请求；内存与 simvec 侧按过滤全量筛选后按游标切片。游标为后端私有的不透明值，不可跨后端使用。验收为分页遍历结果与过滤计数一致，无丢无重。
- 批量查询：契约暂不新增批量接口，调用方循环调用单查询；仅当压测证明往返为瓶颈时再加批量，且批量语义为多次单查询的合并，不改变排序与阈值语义。验收为新增调用方明确。
- 召回整定：查询新增可选的近似开关与召回宽度，默认保持现有精确行为；Qdrant 侧下发对应参数，内存与 simvec 侧忽略但行为不变，零值宽度三端同判非法输入。验收为缺省时行为零变化。

## 第二批：载荷局部更新（已落地）

触发条件为管线需要热修元数据而不重写向量。

- 契约新增按标识设置全量载荷、按标识合并字段、按标识删除指定键三者，均为原子语义，缺失标识报错，口径三端一致。Qdrant 侧分别映射为设置、覆盖与删除键请求，写前验存在以保证同错，保留映射键自动保护；内存与 simvec 侧直接改内存映射。验收为更新后取数可见，且不改变向量。
- 清空载荷暂不提供，确有需求时以设置空对象表达。验收为无需新增接口。

## 第三批：高级过滤（部分落地）

触发条件为检索管线提出新的过滤需求。每加一个算子，三后端同步落地。已落地：可选分支、最小满足数、标识集合、前缀、子串、数组长度、空与 null；排序算子仅匹配数值载荷与数值边界的约定保持不变。验收为组合真值表用例通过，每个已落地算子有三后端对等用例，数值字段用例锁定。

仍延后的算子按需逐个加入，立项要求一并写明：

- 分词类全文与短语、任意词：立项前必须先定分词器口径，服务端分词与端内扫描不一致则三后端行为必然分叉；定不出一致口径宁可继续延后，也不引入透传旁路。验收为分词口径用例锁定。
- 地理半径、包络、多边形：以统一经纬度对象与米制半径、闭合多边形约定为准。验收为跨半球与边界用例锁定。
- 嵌套对象：递归过滤器，组合语义与顶层一致，空过滤仍匹配全体。
- 时间区间：数值区间已落地，时间区间随需求立项，格式与边界语义立项时锁定。
- 向量存在性：随命名向量一并考虑，不单独提前；点标识存在性已落地。
- 切片：id 空间确定性分片语义，仅用于并行扫描场景。

simvec 侧为本批配套新增的两种条件类型与组合语义修正已完整，正确性无缺口；加速覆盖缺口见《simvec 过滤加速路径分析与立项说明》，按触发条件立项，本文不重复展开。

## 第四批：分组推荐发现与融合

触发条件为出现多路召回或分组展示需求。

- 分组检索：契约新增按分组键取每组前若干命中的接口，不改变现有平铺检索的排序语义。验收为组内排序与全局过滤同时成立。
- 推荐与发现输入：契约新增基于正负示例的检索接口，输入为点标识与向量，输出沿用现有命中形状。验收为示例为空时行为可定义且可测，覆盖空示例与纯正例、纯负例。
- 预取融合与排序：统一查询的预取、融合、排序与上下文对仅当融合器需要时引入；引入前调用方在客户端侧做多路合并。验收为默认链路零变化。

对照参考：官方客户端检索组与统一查询组的操作、分组与推荐发现的构造器、预取与融合类型定义，仅作协议形状参考，不引入依赖。

## 第五批：向量形态

触发条件为出现混合稀疏需求或多向量建模需求。

- 稀疏与多向量：契约新增可选的稀疏向量与多向量字段，缺省时稠密路径零变化；Qdrant 侧映射为对应向量类型，内存与 simvec 侧先以精确扫描实现正确性。验收为纯稠密语料行为不变，混合语料三后端排序一致，不比分数绝对值。
- 命名向量：集合配置新增可选命名，缺省为单未命名向量；取数解析已兼容命名对象形态，写入侧按命名下发。验收为新旧集合互不干扰。
- 向量增删：按标识增删单个向量或命名向量的能力随命名向量一同引入，不单独提前。验收为调用方明确。

对照参考：官方客户端向量输入、稀疏向量配置、多向量配置、命名向量与向量增删操作的类型定义。

## 第六批：运维面

触发条件为分布式运维需求或压测证明 REST 为瓶颈。

- 快照：集合与全量快照的创建列表删除与下载作为 Qdrant 专有扩展，不进契约。验收为运维可备份恢复，日常检索不依赖。
- 分片别名与集合更新：别名、分片键、集群信息、集合参数更新作为专有扩展；触发前不支持跨分片语义。验收为日常链路无感知。
- 传输增强：空闲保活、压缩、连接池、连接检查按需加入配置，默认关闭；gRPC 后端仅当压测证明 REST 为瓶颈时立项，且保持契约不变。验收为默认行为不变。
- 索引多类型：关键词之外按需加整数、浮点、文本、布尔、地理、时间索引，缺失时退化为全扫描但行为正确。验收为过滤正确性不受索引有无影响。

对照参考：官方客户端快照组、分片键组、集合更新与传输配置、索引管理操作。
