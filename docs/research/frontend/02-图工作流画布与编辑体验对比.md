# 图工作流画布与编辑体验对比

本文比较当前项目、n8n、Dify 在「图工作流的查看与编辑」上的实现：渲染管线、节点与边的视觉、工具条、快捷键、编辑交互、配置面板、只读/历史/协作状态。

## 1. 技术底座与渲染管线

| 维度 | 当前项目 | n8n | Dify |
| --- | --- | --- | --- |
| 画布引擎 | cytoscape | VueFlow（`@vue-flow/core`） | reactflow |
| 状态模型 | Svelte 5 runes + 页面 controller | Pinia + `CanvasRenderData` | Zustand + React Flow store |
| 渲染入口 | `GraphCanvas.svelte` | `WorkflowCanvas.vue` → `Canvas.vue` | `workflow/index.tsx` → `WorkflowCanvas` |
| 数据流 | props 驱动 + 少量导出方法 | `renderData` 单向映射，`apply-changes=false` | store 驱动，React 组件订阅 |
| 自定义元素 | cytoscape stylesheet + DOM overlay | VueFlow 插槽（node/edge/group/connection/background） | 自定义 node/edge 组件 |

### 1.1 当前项目

`GraphCanvas` 暴露了大量渲染 props（`apps/web-app/src/lib/components/domain/GraphCanvas.svelte:60-91`）：

- 执行态：`pulseIds`、`failedIds`、`criticalIds`、`heatTierById`、`decisionIds`（`:60-73`）。
- 编辑态：`editMode`（`:77`）、`collapsedIds`、`hiddenIds`、`groupTitles`（`:78-80`）。
- 辅助：`tooltipLabels`、`minimap`、`presence`（`:73-91`）。

并通过 `export function` 暴露命令式 API（`:703` 起），例如 `exportPng`、`zoomIn/zoomOut/fit`、`selectedNodeIds` 等。`GraphExplorer` 负责工具栏、过滤器、分组折叠、右键菜单与添加节点抽屉（`GraphExplorer.svelte:22-25`、`:578`、`:1363-1373`）。

渲染与交互事件在 cytoscape 实例上注册：`tap` 节点/边（`GraphCanvas.svelte:762`、`:794`）、`dblclick`（`:865`）、右键 `cxttap`（`:918`），以及编辑态连线拖拽（`:481-505`）。

### 1.2 n8n

`WorkflowCanvas` 用 `effectScope(true)` 建立渲染计算作用域，并按 `documentId` 重建（`docs/ref/n8n/packages/frontend/editor-ui/src/features/workflows/canvas/components/WorkflowCanvas.vue:87`、`:109`）。映射结果只在执行中做 200ms 节流（`:228-229`），避免编辑时抖动。`Canvas.vue` 给 VueFlow 设置 `:apply-changes="false"`（`Canvas.vue:2069`），表示节点位置由外层状态控制，而不是让 VueFlow 直接改数据。

画布通过具名插槽替换 VueFlow 默认元素：节点、节点组、边、连线、背景（`Canvas.vue:2181`、`:2186`、`:2197`、`:2213`）。

### 1.3 Dify

`workflow/index.tsx` 在 `#workflow-container` 中配置 ReactFlow（`docs/ref/dify/web/app/components/workflow/index.tsx:640`、`:779-797`）：

- `multiSelectionKeyCode={null}`、`deleteKeyCode={null}`、`selectionKeyCode={null}`，禁用默认键盘行为，改由自定义快捷键系统处理。
- `panOnScroll={controlMode === Pointer && !workflowReadOnly}`、`panOnDrag={controlMode === Hand || [1]}`，明确区分「指针模式 / 手型模式 / 评论模式」。
- `minZoom={0.25}`、`selectionMode={Partial}`。
- 背景：`<Background gap={[14,14]} size={2} className="bg-workflow-canvas-workflow-bg" color="var(--color-workflow-canvas-workflow-dot-color)" />`（`:799`）。

历史记录通过 `WorkflowHistoryStoreInitializer` 初始化，先 `temporal.pause()`，初始化后再 `resume()`（`:840-879`），避免初始化写入污染撤销栈。

## 2. 画布背景与容器

| 项目 | 表现 |
| --- | --- |
| 当前项目 | cytoscape 容器 + 可选小地图；背景样式在 stylesheet 中 |
| n8n | `CanvasBackground` 支持点阵/条纹，只读时可按 `stripedBackground` 切换（`Canvas.vue:2181`、`NodeView.vue:316`）；容器背景绑定 `--canvas--color--background`（`WorkflowCanvas.vue:341`）；加载完成前 `opacity: 0`，`.ready` 后 300ms 淡入（`Canvas.vue:2239-2244`） |
| Dify | 14×14 间距、2px 点；背景色/点色由语义变量提供（`workflow/index.tsx:799`） |

n8n 的「加载完成再淡入」避免了画布首帧跳动；当前项目未看到等价处理。Dify 把背景参数直接暴露为 `Background` 组件属性，调整成本最低。

## 3. 节点

### 3.1 尺寸与外观

| 维度 | 当前项目 | n8n | Dify |
| --- | --- | --- | --- |
| 节点尺寸 | `width: 120`、`height: 40`（`apps/web-app/src/lib/graph/canvas-style.ts:12-14`） | 由渲染类型与 `nodeViewUtils` 决定，支持配置节点圆形（`CanvasNode.vue` 中 `CONFIGURATION_NODE_RADIUS`） | 普通节点 `240px` 固定宽；Iteration/Loop 使用数据宽高（`workflow-preview/components/nodes/base.tsx:28-47`） |
| 边框 | `border-color: data(color)`，宽度默认（`canvas-style.ts:16-22`） | `1.5px`；success/error/warning 使用 `--spacing--5xs`（`_canvasNodeStyles.scss:4`、`:30-41`） | 外层 `border-2 border-transparent`，内层 `border border-transparent` + `rounded-[15px]`（`base.tsx:26`、`:37`） |
| 圆角 | 由 cytoscape 默认/样式决定 | 由设计系统 token 决定 | `rounded-[15px]`，外层 `rounded-2xl` |
| 背景 | 硬编码 `#18181b`（`canvas-style.ts:14`） | `--node--color--background`，执行态另有 `executing` 变体（`_tokens.scss:87-90`） | `bg-workflow-block-bg` |
| 阴影 | 无明显阴影 | 选中用 6px 外环（`_canvasNodeStyles.scss:24-30`） | `shadow-xs`，hover `shadow-lg`（`base.tsx:36-37`） |

当前节点的 120×40 适合「密集拓扑总览」，但在需要显示端口、状态文本、节点副标题时空间不足；n8n 通过渲染类型区分普通节点/配置节点/触发节点，Dify 直接用 240px 宽卡片承载图标、标题、描述与端口。

### 3.2 执行态表达

- 当前项目：在 stylesheet 中定义 `node.selected / problem / failed / running / critical / decision / heat-1..3 / highlighted / dimmed` 等类（`canvas-style.ts:28-100`），执行时由 `pulseIds`、`failedIds`、`criticalIds`、`heatTierById`、`decisionIds` 映射（`GraphCanvas.svelte:60-73`）。
- n8n：`CanvasNode` 计算 `hovered/highlighted/selected/waiting/running` 等 class，并按 `renderType` 选择渲染器；运行态用 `conic-gradient` 旋转边框，running 1.5s、waiting 4.5s（`_canvasNodeStyles.scss:57-63`），选中环随缩放补偿：`0 0 0 calc(6px * var(--canvas-zoom-compensation-factor, 1))`（`:24-30`）。
- Dify：节点状态主要落在边与运行面板；节点本体保持稳定外观，仅 hover 提升阴影（`base.tsx:36-37`）。

当前项目的状态类数量多，语义丰富（热力、关键路径、决策点三家独有），但视觉实现是「换色/换边框」，缺少 n8n 那种与缩放无关的选中环和持续动画，因此在缩小视图时状态辨识度会下降。

### 3.3 端口与连线锚点

- 当前项目：编辑态在节点上渲染 4 个 12px 圆形连接点（`GraphCanvas.svelte:1023-1029`）。
- n8n：`CanvasNode` 通过 `createCanvasConnectionHandleString({ mode, type, index })` 生成 handleId，输入/输出句柄按模式与索引区分（`CanvasNode.vue`）。
- Dify：输入/输出句柄内嵌在节点头部，`NodeTargetHandle` 位于 `top-4 -left-[9px]`、`NodeSourceHandle` 位于 `top-4 -right-[9px]`；部分节点（IfElse/QuestionClassifier/HumanInput/agent-v2 输出路由）不渲染 source handle（`workflow-preview/components/nodes/base.tsx:52-67`）。

n8n/Dify 都把「端口语义」编码进节点组件；当前项目的连接点更像通用图形编辑器的做法，未体现输入/输出或分支类型。

## 4. 边

| 维度 | 当前项目 | n8n | Dify |
| --- | --- | --- | --- |
| 线宽 | `1.5`（`canvas-style.ts:106`） | 由主题/缩放决定 | `2`（`custom-edge.tsx:78`） |
| 曲线 | `bezier`（`canvas-style.ts:111`） | VueFlow 贝塞尔 + `connection-radius: 60`（`Canvas.vue:2070` 附近） | `getBezierPath` + `curvature: 0.16`（`custom-edge.tsx:19-26`） |
| 箭头 | `target-arrow-shape: triangle`、颜色跟随 `data(color)`（`canvas-style.ts:109-110`） | `MarkerType.ArrowClosed`（`Canvas.vue` connection line options） | 自定义边组件按状态着色 |
| 条件分支 | 无专门样式 | 非 Main 连接 `strokeDasharray: '5,6'`（`CanvasEdge.vue:69`） | `sourceHandleId === failBranch` 时用错误色（`custom-edge.tsx:52`） |
| 状态色 | 静态 class | success → `--color--success`，pinned → `--color--secondary`（`CanvasEdge.vue:110`）；亮度随缩放计算（`:35`、`:123`） | 源/目标状态生成线性渐变（`custom-edge.tsx:30-47`），`_waitingRun` 时 `opacity: 0.7`（`:79`） |
| hover 工具条 | 无 | 延迟显示，只读时隐藏（`CanvasEdge.vue:55-61`） | 无 |

当前项目的边是「统一的静态样式」，执行状态只能通过节点间接表达；n8n 用虚线区分非主连接、用颜色区分成功/固定；Dify 用渐变直接表达「从源状态流向目标状态」，信息量最大。

## 5. 工具条、控件与小地图

### 5.1 当前项目

`GraphExplorer` 顶部工具条包含：缩放、fit、重新布局、重置布局、布局选择、导出 PNG、过滤、小地图循环、zoom to selection、fit highlight（`GraphExplorer.svelte:842-857`）。编辑态追加：Enter edit（`:641-642`、`:883`）、Undo/Redo（`:894-902`）、Add node（`:908`）、Delete selected（`:911`）、Save draft（`:918`）、Validate（`:921`）、Promote（`:924`）。右侧 16rem 列显示大图提示、选中节点卡与图例；过滤器面板包含搜索与 `kind` 复选（`GraphExplorer.svelte:998`）。小地图由 `preferences.minimapMode` 控制（`:262-264`、`:1092`），自动阈值 `MINIMAP_AUTO_THRESHOLD`（`GraphCanvas.svelte:29`、`:217`）。

### 5.2 n8n

`Canvas.vue` 在画布上叠加：

- `CanvasSelectionToolbar`：仅当有分组且未选中单个分组时显示（`Canvas.vue:2186`），用于把多选节点打组（`CanvasSelectionToolbar.vue:100-132`）。
- `MiniMap`：120×200，`BottomLeft`，可平移缩放，节点圆角 16（`Canvas.vue:2197`）。
- `CanvasControlButtons`：复用 `Controls` 但关闭其 zoom/fit（`show-zoom=false`、`show-fit-view=false`），改用 `N8nButtonList variant="toolbar"`，每个按钮包 `KeyboardShortcutTooltip`（`CanvasControlButtons.vue:60-139`）。
- `ContextMenu` 通过 `Suspense` 懒加载（`Canvas.vue:2229-2231`）。

### 5.3 Dify

- `Control`：左下角模式切换（Pointer / Hand / Comment），`ControlMode` 驱动画布的拖拽、框选、评论行为（`workflow/index.tsx:648-656`、`operator/control.tsx:62-109`）。
- `Operator`：撤销/重做（`workflow/index.tsx:656`）。
- 右侧面板由 `NodePanel`、`VersionHistoryPanel`、`EnvPanel` 组成（`panel/index.tsx:130-136`）。
- 没有常驻小地图；画布缩放范围 0.25 起（`workflow/index.tsx:797`）。

当前项目的工具条最全（含布局切换、导出、过滤、小地图循环），但按钮是平面排列，缺少 n8n 的快捷键提示与分组；Dify 则把「模式」提升为一等控件，减少误操作。

| --- | --- | --- |

## 7. 编辑交互

### 7.1 连线

- 当前项目：编辑态按下连接点开始拖拽，移动时更新临时线，松开时校验；样式有 `connect-ok` / `connect-bad` 两类（`GraphCanvas.svelte:481-505`、`canvas-style.ts:160-180`）。
- n8n：VueFlow 连接线使用 `CanvasConnectionLine` 插槽与 `markerEnd: ArrowClosed`，`connection-radius: 60`；是否允许连接由业务校验函数决定（`Canvas.vue` RF 配置）。
- Dify：`connectionLineComponent={CustomConnectionLine}`、`isValidConnection` 由业务提供（`workflow/index.tsx:779`、`:795`）。

三者都具备「拖拽 + 校验」；差异在于当前项目把校验结果直接映射为颜色类，n8n/Dify 更依赖组件层的连接线渲染。

### 7.2 节点创建

- 当前项目：`AddNodeDrawer`（`GraphExplorer.svelte:1373`），属于「先打开抽屉再选类型」。
- n8n：`n` 键或右键菜单在画布位置创建，`LazyNodeCreation` 懒加载创建面板（`NodeView.vue` 的画布浮层区）。
- Dify：`CandidateNode` + `BlockSelector`（`workflow/index.tsx:648`），在画布内弹出块选择器，支持分类、搜索、推荐。

当前项目的创建流程离开画布上下文；n8n/Dify 都在画布原位弹出，缩短了「想在哪里加 → 加什么」的路径。

### 7.3 节点配置

- 当前项目：参数/定义编辑在「edit」Tab（`routes/workflows/[id]/+page.svelte:44-48`、`:350`），图 Tab 只负责查看与结构编辑（添加/删除/连线/校验/保存草稿/发布）。
- n8n：NDV 模态层，`Teleport` 到 `#APP_MODALS_ELEMENT_ID`，三列布局（左输入、中参数、右输出），中列可拖拽调宽（`NodeDetailsView.vue:761-772`、`:800-880`）。
- Dify：右侧 NodePanel，`Tabs`（settings / last run）、`ResizeHandle` 左侧拖拽、最小 400px、标题行含 `UserAvatarList` presence（`workflow-panel/index.tsx:615-657`、`:771-793`）。

当前项目的「图/参数分离」有利于大表单，但编辑节点时必须离开图上下文；n8n 的 NDV 与 Dify 的 NodePanel 都保持画布可见。

### 7.4 分组与撤销

- 当前项目：分组标题、组框、组折叠、组拖拽批量移动（`GraphCanvas.svelte` 的 `groupTitles`、`collapsedIds`，`GraphExplorer.svelte:399-471`）。
- n8n：`groupExpansionMode: 'all' | 'errored'`（`WorkflowCanvas.vue:52`、`:109`），只读时按错误展开；分组标题栏由 `CanvasNodeGroupTitleBar` 插槽渲染（`Canvas.vue:2181` 附近）。
- Dify：历史记录由 `temporal` 管理，撤销/重做在 `Operator`；初始化时暂停记录（`workflow/index.tsx:840-879`）。

当前项目与 n8n 都有分组；Dify 更强调「历史栈的正确性」。

## 9. 性能与规模策略

| 项目 | 策略 |
| --- | --- |
| 当前项目 | `GRAPH_NODE_CAP` 截断 + `foldForCap` 分组折叠（`GraphExplorer.svelte:331-343`）；布局保存 800ms 防抖（`:196-232`）；懒加载 `GraphExplorer`（`WorkflowGraphTab.svelte`） |
| n8n | `effectScope` 重建渲染上下文（`WorkflowCanvas.vue:87`）；执行中 200ms 节流（`:228-229`）；`apply-changes=false` 避免双向写回（`Canvas.vue:2069`） |

当前项目的「节点上限 + 分组折叠」是三家唯一显式的规模降级策略；n8n 的节流只作用于执行态，编辑态保持即时；Dify 更关注面板与请求节流。

## 10. 结论与建议

### 10.1 结论

1. **当前项目在「图的信息表达」上最丰富，在「图的交互闭环」上最弱。** 热力/关键路径/决策点/回放是独有能力；但节点创建、参数编辑、日志查看都要离开画布。
2. **n8n 的优势是「一切都在画布上下文中」**：底部日志、NDV 模态、快捷键、右键菜单、分组工具条共同构成闭环。
3. **Dify 的优势是「模式与面板的产品化」**：Pointer/Hand/Comment 三模式、右侧 NodePanel、底部 RunPanel，交互心智清晰。
4. **视觉精度差距集中在节点与边**：当前节点/边是「静态类名 + 硬编码色」，缺少缩放补偿、状态渐变、运行动画。

### 10.2 建议（按收益排序）

1. 在画布下方增加可折叠的执行日志条，复用现有 `NodeTracePanel` / `Timeline` 数据，避免「图 ↔ trace」Tab 往返。
2. 为节点增加可配置的最小尺寸或「详情卡」模式，至少在选中时展示输入/输出端口、状态文本与副标题。
3. 边引入「源状态 → 目标状态」渐变与分支虚线，替代单一静态色。
4. 把画布交互键位抽成独立定义表（参考 Dify `shortcuts/definitions.ts`），先覆盖 fit、缩放、删除、撤销、运行、日志开关。
5. 选中环与运行态动画使用缩放补偿变量，保证任意 zoom 下视觉一致。
