# 01-wf-cli-shared 共享逻辑

> 范围：`crates/app/cli/wf-cli-shared`（参数解析、无头会话驱动、管理命令、输出与连接等横切能力）
> 定位：全部 CLI 形态共享的逻辑层，零全屏依赖，供无头、轻量行式与全屏三形态复用

该 crate 是 CLI 的逻辑内核：定义全局参数与全部子命令形态，实现模式解析、服务连接、单次会话管线、输出分层，以及按域分组的管理命令处理。所有命令与会话都经由 `wf-client` 与运行中的 `wf-server` 对话，渲染保留在本地。

## 入口分发

共享入口承担两类职责：先处理诊断与管理类子命令，再按解析出的形态进入单次无头会话或报错提示全屏形态不可用。无头专用入口是同一逻辑的薄别名，保证无头判定与分发不会分叉。输出槽构造器集中处理标准输出与日志文件的扇出，以及颜色开关。

诊断形态包含模式解析结果展示与终端能力探针两类：前者输出当前形态与 TTY 状态，后者验证终端守卫的进入与恢复、外置命令窗口与主题探测。

## 参数体系

顶层参数覆盖三类：全局输出与连接开关、交互形态选项、轻量形态显示开关。子命令缺省时进入交互形态，存在时强制无头。

- 全局开关：输出格式、日志扇出文件、颜色禁用、远端地址与凭证、破坏性操作免确认、超时预算、结构化上下文及其文件来源。
- 交互形态选项：全屏开关、无头强制开关、智能体与模型选择、会话恢复与最近恢复互斥约束。
- 轻量形态显示开关：历史文件路径与禁用互斥、助手 Markdown 呈现模式、推理与用量与工具生命周期三路标准错误流的抑制开关。
- 交叉校验：子命令与全屏开关互斥，会话恢复类选项仅限交互形态，工作流输入类选项要求工作流标识且与智能体转向载荷互斥，图片与附件仅限智能体转向，交互式应答与全盲批准互斥且应答超时仅限交互式。

子命令按域拆分为多个参数模块：检查点与审批、实体（技能、变量、消息、任务）、执行、LLM 相关（档案、供应商、认证、代理、模板）、可观测性（审计、事件、指标、分析）、远端主机、工具链（工具、脚本、模板、触发器）、工作流。单次会话子命令自带提示词、智能体与模型选择、批准前缀白名单、交互式应答与超时、全盲批准、工作流执行与输入来源、图片与附件载荷、单次远端覆盖。

判定 helper 集中回答两个问题：任一子命令是否属于无头（当前全部子命令均为无头），以及是否为管理类命令（除单次会话与诊断形态之外均为管理命令，供全屏门面决定是否直接委托共享库）。

## 模式解析

交互形态只有两种取值：单次无头运行与全屏。解析器按优先级依次判定显式全屏开关、子命令、强制无头开关、标准输出 TTY 状态，最后回落到 TTY 默认全屏。TTY 状态以参数注入以便单测覆盖全分支。

解析结果除形态外还携带无头提示词来源（非 TTY 且无位置参数时消费标准输入全文作为提示词）与交互形态的会话恢复意图（指定会话或最近会话）。

## 服务连接

连接是全部命令与会话驱动共用的唯一建连位置。地址解析顺序为单次会话级远端覆盖、顶层远端标志、隧道端口环境变量、远端环境变量，最终回落本地默认；凭证来自标志或环境变量。构造后立即探测健康端点，服务未启动时直接失败并提示先启动服务，避免后续以难懂的请求错误暴露。

## 输出分层

输出分为格式层与目标层两个正交维度，业务代码只面向槽接口，不感知最终去向。

- 格式层：人类可读文本、单对象 JSON（含汇总信封收尾）、按行 JSON（无信封，面向管道与文件）、静默（仅以退出码携带结果）。
- 目标层：标准输出槽、文件槽、内存槽（供交互形态使用）、扇出槽（同时写入主槽与日志文件）。
- 消息形态：与领域消息类型解耦的轻量结构化消息（角色、内容、可选元数据），适配器在边界处转换领域消息；信封封装成功载荷并按格式渲染。
- 着色策略：仅文本格式且允许颜色时使用最小 ANSI 修饰，JSON 系列保持机器可读。

## 会话转向的公共形态

转向是无头与轻量形态共享的请求语义：一次转向执行智能体消息或工作流其一。公共参数包含智能体与模型选择、批准前缀、超时预算、结构化上下文、历史对话（无头单次为空，行式会话由笔录填充）。转向类型决定载荷：智能体转向携带提示词与图片附件，工作流转向携带工作流标识与输入。

请求体翻译集中在一处，流式与阻塞两条路径共用同一构造，避免字段漂移。解析 helper 覆盖工作流变量赋值、智能体上下文对象、图片细节档位、远端图片地址合法性、工作流输入 JSON 形态等校验。

## 无头会话管线

无头驱动实现单次会话端到端：解析请求体，经服务执行（优先事件流，辅以阻塞调用兜底），渲染事件（助手文本进主槽，工具生命周期进诊断通道），以汇总行或信封收尾并映射退出码。

管线按职责拆分为独立模块：

- 事件流驱动：流式帧的驱动与终端结算，区分智能体流与工作流流的收尾语义。
- 增量渲染：增量缓冲与智能体事件到文本的渲染，保持管道友好的行边界刷新。
- 服务端交互应答：监听执行事件，仅在出现审批公告或重连后读取待处理交互，按白名单、标准输入单行应答或全盲批准作答；无应答模式下遵循服务端宿主默认，问答类交互失败收尾。
- 标准输入问答：交互式下的问询行渲染与单行读取、超时语义（超时即拒绝审批并取消问答）。
- 汇总：会话收尾的汇总信封与耗时格式化，判定何种结果需要输出。
- 诊断通道：标准错误诊断写入器，承载工具符号行、拒绝与中断提示。

工作流执行输入支持三层合并：文件输入为底，直接输入居中，重复变量赋值优先级最高，值尽可能按 JSON 解析否则回落为字符串。

## 管理命令域

管理命令按域分组，每个域独立成模块，经统一连接句柄访问服务，输出渲染保留在本地以稳定既有信封名与文本版式。主要分组如下：

- 执行外观：统一的执行管理，跨智能体与工作流两域解析，先按智能体后按工作流回退；列表、状态、生命周期、日志分页与跟随、层级与子树检视、性能与瓶颈与错误与对比与进度等分析臂复用共享分析构造器。
- 工作流：定义增删改查与版本管理、图结构与统计、校验与执行控制。
- 触发器：模板注册与触发台账；模板：节点与触发器模板；技能、消息、变量、任务等实体管理。
- LLM：档案增删改查、供应商连接模板与发现、认证登录登出与状态、代理凭证管理（口令只存凭证库）。
- 检查点：统一记录、文件检查点、智能体循环检查点、链路与回收、文件工作区与冲突与同步与会话台账；变更审批走独立的审批命令，面向文件检查点审批接口；运行时工具调用审批由会话中的交互应答器回答，不走该命令。
- 可观测性：审计三源、事件订阅与时间线、指标导出、查询（执行记录过滤分页聚合导出）、全文检索、分析统计。
- 系统：健康与完整诊断透传后端原样渲染；远端主机注册与执行包拉取；前端展示配置文件备份（仅展示文件，键位与主题文件需手工复制）。

## 横切能力

- 应用配置：最小用户配置，仅收纳确有消费者的选项；遵循系统配置目录约定，缺失或不可读即回落默认且不使调用失败；明确与内核宿主配置文件的归属边界，前端开关不触碰内核键。
- 展示选项：轻量形态的 Markdown 呈现档位与标准错误流开关，跨形态共享解析；Markdown 档位覆盖原文、去标记纯文本、按终端能力降级的着色三种语义。
- 路径：状态目录与历史文件等本地路径的集中解析，支持显式标志覆盖环境变量。
- 通知：长转向与待审批的站外提醒，文本一次构造后按终端转义序列、响铃、可选声音包、后台原生横幅的优先级扇出；调用方只提供事件与焦点状态，终端不可用时静默跳过且永不阻塞。
- 回顾门槛：纯函数判定长转向或失焦或超屏回复是否值得一条屏显回顾，手动回顾绕过门槛。
- 错误与退出码：参数错误、配置错误、终端失败、业务失败、中断、输入输出错误分型，分别映射到成功、业务失败、参数错误、配置错误、中断四类退出码。
