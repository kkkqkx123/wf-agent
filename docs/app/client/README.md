# 客户端同步总览

> 范围：`apps/web-app/src/lib/api`（Web 类型客户端）与 `crates/app/wf-client`（Rust 生成客户端）
> 状态：基于当前代码的静态整理

两个客户端共享同一真相源，但同步时机与产物形态完全不同。Web 侧为按需离线生成并入库类型文件，Rust 侧为构建期生成且不入库。流式通道在两侧都排除在生成之外，由手写层承担。

## 真相源

后端 `wf-server` 以注解聚合出完整文档，经快照测试写入 `crates/app/wf-server/openapi.json` 并入库。快照漂移会使后端测试失败，需显式刷新。另有路由表与注解双向对账，防止漏注册或漏登记。两个客户端都只读该快照，不直连运行中的后端。

详细后端链路见 `docs/app/api/09-openapi-doc-generation.md`。

## 对照

| 维度 | Web 客户端 | Rust 客户端 |
|------|-----------|------------|
| 输入 | 同一快照文件 | 同一快照文件 |
| 时机 | 按需手动执行 | 每次构建自动执行 |
| 生成器 | 类型声明生成器 | 代码生成器 |
| 产物位置 | 仓库内类型文件 | 构建输出目录，不入库 |
| 漂移保障 | 新鲜度检查命令，落后即失败 | 快照变更触发重建，天然一致 |
| 流式 | 手写传输层，排除在生成外 | 手写传输层，生成前剔除流式操作 |
| 类型粒度 | 全量路径与构件类型，运行时薄封装 | 全量操作与模型，另有兼容查询入口 |
| 预览 | 别名替换为固件实现，服务层无分支 | 无预览形态 |
