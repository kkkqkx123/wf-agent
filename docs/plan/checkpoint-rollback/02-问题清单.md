# 问题清单

按严重程度排序，只记录现象与影响，不展开实现细节。

## 一、命名与概念混乱

* 恢复、回滚、撤销、恢复提交四个词混用。编辑分组回滚与特性回滚同名但语义完全不同，前者移动指针，后者追加历史。
* 工作区物化有全量、范围、选中、联动、最新等多个入口，调用方难以选择，且部分入口仅为参数组合，增加了学习成本。
* 数据交换能力与回滚入口并列，容易误用。

## 二、多特性合入主线非原子

* 多特性按输入顺序逐个独立合并，中途冲突则前面的已进入主线，后面的未进入，留下半合状态，调用方需自行收尾。
* 重叠行按输入顺序决定结果，顺序即语义，但接口未强制要求调用方声明顺序意图，也未提供预演能力。

## 三、回滚寻址脆弱

* 特性回滚依赖精确提交标识查找吸收合并，无操作合并与祖先包含等边界下可能找不到吸收者。
* 分组回滚要求目标分组位于指针头部，中间插入并发写入即拒绝，调用方缺少排队或变基选项。

## 四、冲突表达与解决成本高

* 冲突标记字节直接成为特性历史的一部分，解决状态靠重新解析标记判断，可靠性依赖文本格式。
* 二进制冲突无区间信息，只能文件级处理。
* 主线健康仅检查头提交标记，历史中残留的未解决提交依赖枚举发现，两处口径可能漂移。

## 五、状态与文件联动松散

* 历史数据允许长期无关联，统一恢复时文件侧可能静默缺席，调用方若忽略空结果会误以为完整恢复。
* 待补偿关联依赖启动时重试，若长期不触发补偿，关联持续处于待定态。

## 六、清理与可观测性缺口

* 回收以可达性为准，保留策略偏保守，长期运行下存储增长快。
* 清理失败仅记录日志，调用方无法感知存储水位。
* 部分恢复路径缺少统一的预览确认，误操作风险高于指针移动路径。
