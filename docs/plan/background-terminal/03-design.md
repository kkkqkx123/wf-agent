# 后台终端设计方案

> 本篇回答借鉴什么、不借鉴什么，以及分阶段怎么做。自然语言描述为主，不含完整代码实现。

## 可借鉴的设计

### 值得直接借鉴

- **任务与载体分离**。任务注册只管标题、状态、阻塞与后台化竞速与通知，终端存储只管进程与字节。当前项目把两者揉在会话忙闲里，导致无法回答有哪些后台任务在跑。分离后前端聚合视图与手动后台化才有事实源。
- **后台开关语义**。工具输入加后台标记，后台时不限时并立即返回会话标识与输出位置，前台时阻塞等待但允许被后台化抢占。当前单发路径超时钳制与后台会话创建即返回各做了一半，缺统一语义。
- **完成即合成通知**。后台任务结算后经现有事件通知面唤醒关联执行，而非经终端字节流推送。当前监视线程只收尾会话，无人通知是最大体验缺口，补这一环性价比最高。
- **文件加游标的大输出模型**。小输出走内存，大输出溢出到文件并按绝对游标分页，分页返回输出片段、游标与总量。当前环形截尾在长构建日志场景必丢早段，溢出文件是最小改动解。
- **后台化附带不要轮询的提示**。返回文案明确告知调用方不要等待或轮询，等通知即可。该提示对语言模型调用方尤为重要，可显著减少空转等待。
- **运行中列表只返回运行中**。已完成经通知消费，不长期驻留列表，列表保持小而活。当前会话池混放空闲与忙碌，聚合视图需另做过滤。
- **重启语义显式化**。重启后不复活进程，而是对可恢复任务回放结果或说明取消原因。当前进程随进程结束是预期行为，但需给前端一个明确交代而非静默消失。

### 不借鉴或暂缓

- **会话级常驻伪终端守护进程**。该服务为桌面多终端窗格设计，含独立守护目录、套接字远调与交接文件，与当前单工作区网页加命令行形态不匹配，成本远大于收益。
- **伪终端双向套接字直连**。现有事件订阅套接字为广播语义，硬塞一连一会话的双向流会污染协议。前期已有 Git 终端设计走独立终端套接字，后台 shell 不再开第二条双向流，轮询加通知已够用。
- **客户端直连进程**。命令行界面保持为服务端事件流渲染端，不直连本地进程，避免传输与鉴权双轨。
- **终端仿真器引入**。后台任务输出为块状文本，用现有折叠尾部展示即可，不引入终端仿真依赖。真正的交互式接管留给 Git 终端域解决。

## 总体设计

### 分层归属

- 后台会话存储继续留在基础设施层 shell crate，只做三件事：进程管理、输出缓冲与文件溢出、生命周期事件。按架构规则只改原模块，不建替代模块。
- 新增轻量任务注册留在引擎层执行共享设施（与交互注册表同层），只管任务标题、状态、阻塞计数、后台化标记与通知标识，不感知字节流。工具层 shell 族在创建与结算时向其登记。
- 应用门面层新增 shell 后台领域，做任务与会话的关联组装（任务列表、任务详情、输出分页、等待、终止），不直接管进程。
- 传输层在现有路由下新增 shell 后台域路由，前缀挂在版本化接口下，走统一信封与分页规范。事件复用现有执行事件与通知事件，不新增事件大类。

### 生命周期

创建时工具层先建会话再登记任务，返回会话标识。等待时区分已完成、已后台化、仍运行三种返回，运行中允许调用方转后台。后台化时清超时（转无限等待）、记通知标识、解除阻塞者。结算时监视线程收尾会话，任务注册记完成并经通知面合成消息，任务条目在通知确认后清理。终止时先优雅终止进程组，宽限后强制杀，会话移除并记取消。空闲回收仅动无绑定的空闲会话，逻辑沿用现状。

### 输出模型

- 单命令输出小于阈值时全驻内存，读输出走现有快照与增量接口。
- 超阈值后溢出到按会话与命令组织的文件，分页接口按绝对字节游标返回片段、游标与总量，语义与现有窗口接口对齐（窗口末端、总写入量、前缀丢弃），只是后端由纯内存改为内存加文件。
- 等待接口保留正则匹配与静默期，用于日志关键字探活，不做语义变更。
- 伪终端输出仍合并标准输出与标准错误，前端仍按纯文本展示，不做转义序列解析。

### 接口划分

- 任务面：列出运行中后台任务（按执行标识过滤）、查询单个任务（含关联会话标识与命令标题）、手动后台化执行下全部阻塞任务。
- 会话面：沿用现有工具族语义升为一等接口，即创建、读输出（支持游标与长度）、等待（含模式匹配）、发输入、调尺寸、终止。Git 终端域保持独立（仓库锁定语义不同），不合并不复用。
- 事件面：后台完成经通知事件推送，载荷仅含任务标识、会话标识、状态与摘要，详情经任务查询拉取，保持事件元数据化、详情走接口的现有约定。

### 前端策略

- 工具调用卡不变（折叠尾部加展开），运行中状态加后台化按钮，点击后调手动后台化并提示等通知。
- 新增后台任务聚合视图，数据源为任务面列表加执行流增量，展示标题、运行时长、关联会话与快捷跳转（跳到输出分页或对应工具卡）。无终端仿真、无字节流直连。
- Git 终端面板不变，与后台 shell 分属两个域，避免语义混淆。

### 命令行界面策略

- 流式渲染在收到后台化返回时打印一行后台提示（含任务标识与查询指引），与 `opencode` 的后台提示文案对齐。
- 轻量与完整终端均加运行中后台任务的聚合行（数量与标题），详情经任务查询接口拉取，不做尾随循环。
- 不新增本地进程派生、不新增伪终端挂件。

### 安全与资源边界

- 命令安全与沙箱网关沿用现状，伪终端跳过内核强制需在文档中显式声明。
- 会话上限、按任务限额、空闲超时、输出上限四组阈值沿用现有配置项，仅新增文件溢出阈值与保留时长两项。
- 审计沿用现有工具调用审计，后台化与终止记为工具调用的子动作，不新增审计实体。

## 分阶段落地

| 阶段 | 内容 | 验收 |
|---|---|---|
| 第一阶段 | 任务注册与后台开关语义统一，单发与会话路径共用同一后台标记 | 同一命令前后台语义一致，后台返回会话标识而不阻塞 |
| 第二阶段 | 完成通知闭环，后台结算经通知面唤醒关联执行 | 后台命令完成后不再需人肉轮询，通知可跳到任务详情 |
| 第三阶段 | 输出文件溢出与游标分页，阈值可配 | 长构建日志早段可回看，分页游标单调递增 |
| 第四阶段 | 应用门面任务与会话组装接口加 OpenAPI 快照，前端聚合视图与工具卡后台按钮 | 运行中后台任务有统一一览，工具卡可一键转后台 |
| 第五阶段 | 命令行界面后台提示与聚合行，文档与阈值调优 | 命令行用户可见后台任务数与查询指引，无尾随循环 |

每阶段只动本阶段所述模块，不提前引入后续阶段的传输或界面依赖。

## 风险与取舍

- 输出文件溢出引入磁盘占用，需配额与保留时长，默认阈值宜保守。
- 通知面为纯推送、无持久未读，离线客户端靠重连后查任务列表补齐，需在界面空态文案中说明。
- 单会话单命令并发限制保留，多并发需求经多会话满足，不放开同会话并发。
- 重启不复活进程，需在任务详情中明确展示已取消原因，避免用户误以为任务仍在跑。
