# 差距清单与优先级

本文把前五篇的结论收敛为可执行清单。优先级按「对主路径效率 / 规范一致性 / 实现风险」综合排序，不涉及工期估算。

## 1. 优先级定义

| 级别 | 判定标准 |
| --- | --- |
| P0 | 违反现有规范，或主路径上存在明显摩擦；应尽快处理 |
| P1 | 显著提升可读性/操作效率，且改动局限在前端组件层 |
| P2 | 结构性改良，收益中等，需要跨组件或跨页面协调 |
| P3 | 选择性能力，依赖产品/后端配套 |

## 3. 落地顺序

### 3.1 第一批：规范与主路径

1. **V1 画布令牌化**：先建立画布颜色/字号变量，再改 `canvas-style.ts`。这是后续所有画布视觉改进的前提。
2. **G1 画布日志条**：复用现有 trace/timeline 数据，先在 workflow 详情页做可折叠底部面板，不改变路由。
3. **E1 选中即预览**：在宽屏执行列表复用现有 `SplitView` 检查器，保留 `/executions/[id]` 作为窄屏与深链。

这三项互不依赖，可并行。

### 3.2 第二批：编辑闭环

4. **G2 节点配置面板**：先将 `WorkflowEditSection` 的表单嵌入画布侧栏，保留 edit Tab 作为完整编辑入口。
5. **G3 节点创建弹层**：复用 `AddNodeDrawer` 的内容，改为画布锚定弹层。
6. **G4 快捷键体系**：抽定义表，先覆盖 fit、缩放、删除、撤销、运行、日志开关。
7. **E2 执行动作组**：在详情页头部与列表卡片补重跑/复制/删除。

### 3.3 第三批：视觉与结构

8. **V3/V4 选中环与边渐变**：依赖 V1。
9. **E3 状态字典**：先补 token 映射，再替换列表图标。
10. **E4 树形日志**：可与 G1 合并设计，避免两套日志 UI。
11. **L1/L3 布局插槽与 Tab 溢出**：影响面较大，放在交互稳定后。

### 3.4 第四批：选择性能力

12. **G6 协作评论**、**E6 标注/数据集**、**V5 面板层级统一**：需要产品决策或后端字段，按实际需求启动。

## 4. 不建议照搬的部分

| 项 | 原因 |
| --- | --- |
| n8n 的双横线令牌命名与 legacy fallback | 属于其嵌入生态的历史包袱；当前项目没有外部嵌入兼容需求 |
| n8n 的 NDV 三列布局 | 适合参数极多的节点；当前项目节点参数规模未知，直接照搬会增加空列 |
| Dify 的大量任意值类（`rounded-[15px]`、`border-[0.5px]`） | 会削弱令牌体系；应沉淀为语义类再使用 |
| Dify 的 `min-w-240` 画布最小宽度 | 与当前项目窄屏 `Sheet` 策略冲突 |
| n8n 的固定 310px 执行侧栏 | 当前项目已有可拖拽 `SplitView`，无需降级为固定宽 |
| 任何直接复制上游源码 | 许可与维护成本；只借鉴结构与方法 |

## 5. 验收建议

- **V1**：暗色模式下画布节点/边/分组标题无突兀色块；`canvas-style.ts` 中不再出现十六进制色值。
- **G1**：在 workflow 详情页可同时看到图与最近执行日志，切换 Tab 不丢失日志选中项。
- **E1**：在列表选中第二条执行时，右侧检查器更新且列表滚动位置不变；刷新页面仍可通过 URL 恢复。
- **E3**：8 种状态在列表/详情中图标与颜色一致，且颜色不是唯一区分手段（配合图标/文案）。
- **G4**：`?` 或帮助面板能列出画布键位，按钮 tooltip 与定义表同源。

## 6. 结论

当前项目不需要重做信息架构。它的差异化优势在「执行可观测性」与「多维度分析」，短板集中在「画布内闭环」与「视觉令牌一致性」。因此优先级应放在：

1. 把已有能力（trace/timeline/graph）从互斥 Tab 变成可并存面板。
2. 把画布视觉从硬编码迁回令牌体系。
3. 把执行列表从「进出详情页」变成「选中即预览」。

其余能力（协作评论、标注、数据集）属于产品扩展，不应在基础体验补齐前投入。
