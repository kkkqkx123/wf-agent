# Native C ABI 对等补齐设计

本文基于上层集成实测与现有 C ABI 覆盖分析，给出补齐方案。只改原模块，不新增并行模块，不做历史兼容。

## 0. 结论速览

* 上层已消费全部约26种贡献，C ABI 动态注册仅覆盖13种，缺口12种加作者侧2个缺失。
* 补齐后 C 插件与 Lua/Wasm/原生 Rust 达到声明能力对等，行为通道复用单一分发入口，无需改分发协议。
* 保持手写头文件，补一致性测试，不引入生成管线。ABI 主版本保持不变，开发期要求重新编译。

## 1. 现状实测

### 1.1 上层集成链路

* 生命周期位于 `wf-plugin` 引擎：发现、依赖解算、按后端加载实例、加载钩子、注册贡献、桥接同步后激活，停用时对称移除，守卫与事件总线包外层。
* 消费分两路，均在 `wf-runtime` 单点落地：
* 行为路经处理器源进入执行路径：节点、工具、事件、中间件、语言模型编解码与认证在调用时分发。
* 声明路经桥接同步写入注册表：资源包、可执行工具、语言模型网关、检索扩展、命令行快照在激活时安装。

### 1.2 三后端声明能力不对称

* 统一注册口约26种，C ABI 覆盖行为加命令行共13种。
* 缺口为图像生成、服务商声明、六种声明式资源、压缩与检索五件套，共12种动态能力。
* 清单静态兜底8种经 manifest 到达三后端，因此缺口恰是清单也盖不住的部分。
* 作者侧记录器比 C ABI 还少2种，可执行工具与工具描述在 Rust 原生侧走不通，只能走清单兜底；中间件记录丢弃了阶段与优先级，转发恒用固定值。

### 1.3 分发通道本身通用

* 单一分发入口以类型加名称加输入 JSON 复用，已验证编解码与认证一通道多操作。
* 新增行为只需新增注册回调与类型字符串，无需改分发协议与两阶段缓冲语义。

## 2. 目标与范围

* 目标：C 插件可声明上层已消费的全部贡献，缺失项显式失败不静默。
* 范围：C 头文件、作者侧记录器与转发、宿主侧注册桩与分发处理、一致性测试与示例说明。
* 不做：Wasm 与 Lua 的命令行与高级扩展补齐、多语言绑定生成、旧插件二进制兼容、版本号升级。

## 3. 功能规格

### 3.1 注册回调补齐

* 在现有结构体尾部追加，不调整既有字段顺序。
* 行为类按名称注册：图像生成、压缩建议、文本分析、检索建议、向量编码。
* 声明类按 JSON 注册：服务商声明、工作流、提示词、片段、智能体模板、节点模板、触发器；快照策略按名称加策略 JSON 注册。
* 作者侧补齐可执行工具与工具描述的记录方法，与宿主已有回调对齐。

### 3.2 分发类型字符串

* 沿用现有命名习惯，类型与名称均为普通字符串：
* 图像生成按名称加操作区分，输入携带上下文、提示词与选项，输出为宿主图像结果形状。
* 压缩与检索建议直接透传输入输出 JSON。
* 文本分析输入为文本对象，输出为词串数组。
* 向量编码输入为文本加选项对象，输出为宿主约定的向量形状。
* 节点、工具、事件、中间件、编解码、认证保持不变。

### 3.3 作者侧记录语义修复

* 记录条目需同时携带种类、第一参数、第二参数与优先级，覆盖中间件优先级与快照策略双参数。
* 中间件如实记录阶段与优先级，不再使用固定值。
* 转发时双参数如实传递，缺失的宿主回调视为跳过，未知种类视为失败。

### 3.4 宿主侧转发语义

* 声明类解析 JSON 后按标识注册，非法 JSON 直接记首错并使激活失败。
* 行为类以名称构造分发处理柄，调用时经统一分发调用并做输出扩容重试。
* 清单声明的工具继续在宿主侧兜底注册，与新增动态路径共用同一注册口。

## 4. 上层集成说明

* 新增能力复用现有桥接同步，无需改桥接与执行路径。
* 图像、压缩、检索类自动进入网关与检索注册表，随停用对称移除。
* 六种资源自动进入资源包安装与卸载，与直接安装共用校验与跳过语义。
* 命令行快照不受影响。

## 5. 测试策略

* 作者侧单测覆盖新增记录种类、中间件优先级如实转发、快照双参数、转发未知种类失败。
* 头文件一致性测试断言符号与结构体名存在，防止改一侧忘另一侧。
* 宿主侧以现有工具注册模式补充图像与检索最小用例，验证安装与对称移除。
* 全量编译验证一次完成，开发期不保留额外编译轮次。

## 6. 风险与取舍

* 结构体尾部追加要求 C 插件重新编译，开发期可接受，不做旧版适配。
* JSON 载荷的模式错误只能在激活时暴露，依赖首错记录与 loudly 失败语义，不做静默丢弃。
* 文本分析与向量编码的输出形状由宿主约定，文档需写明数组与对象形状，不依赖 C 侧头文件表达泛型。
