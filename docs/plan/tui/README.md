# TUI 渲染优化分阶段修改方案

本文档是 `docs/plan/tui` 的总览与实施路线。问题分析基于 `docs/ref/jcode-tui` 的现状与目标描述，并对照 `ref/jcode/docs/tui` 的分层、渲染管线、内容渲染、样式动画与可测试性设计。细化方案见本目录各专题文档，分阶段实施时引用它们，不重复展开细节。

## 结论速览

现有全屏交互路径已经可用，事件循环、帧率限制、状态归并、流式切分、快照测试、差异录制都在。核心问题集中在每帧从头重建整屏内容：滚动区全量排版、解析按增量触发、重绘只有整帧一档、流式无缓速、动画与主题重复计算、时间与状态不可替换、缺少帧预算度量。

改进方向是引入四层能力：增量准备缓存、重绘范围分级、流式缓速与解析节流、可注入时钟与性能分级。预期收益是稳态流式帧的处理器成本从与历史行数成正比降为与新增行数成正比，解析从平方级降为线性，渲染路径可离线回归。

- `05-主题适配与性能分级.md`：缓冲级单点适配、能力驱动的档位策略、同步输出启用条件。

## 分阶段路线

每阶段独立可验证，结束后可编译并通过现有测试。阶段编号只表示建议顺序，具备条件时可部分并行。

### 阶段零：建立基线

目标是让后续优化有回归依据。工作来自 `07-渲染模型与可测性度量.md` 的度量部分。

- 把差异录制后端扩展为帧度量后端，记录变更单元格数、差异字节数、耗时，并预留实际排版行数与解析字节数的采集点。
- 在演示包基础上增加回放固定事件序列并输出帧度量的能力。
- 记录一万行历史下流式帧的耗时与行数基线。

验收是能输出一份基线报告，作为后续对比。

### 阶段一：增量准备缓存

目标是消除全量滚动区重排。工作来自 `01-准备缓存与增量排版.md`。

- 新增准备与缓存键模块，实现追加、前插、替换、裁剪路径与宽度变化全量重排。
- 在沉淀、回放整段替换、回放前插、裁剪处递增内容版本号。
- 绘制入口改为消费准备结果的可见区间。

验收是稳态追加时每帧实际排版行数等于新增行数，快照输出不变，长历史下流式帧耗时显著下降。

### 阶段二：解析节流

目标是消除按增量触发的全量解析。工作来自 `02-markdown节流与增量解析.md`。

- 增量到达只累积并标脏，帧准备阶段按间隔执行一次解析。
- 保留最终兜底路径与现有滞留规则不变。
- 复用现有等价性测试验证流式与全量一致。

验收是解析字节数呈线性，固定序列下最终文本与之前完全一致。本阶段与阶段一互不依赖，可并行。

### 阶段三：重绘分级

目标是让动画与底部状态变化不再重建整屏。工作来自 `03-重绘分级与帧调度.md`，依赖阶段一的准备结果。

- 新增范围判定，应用层维护待处理范围并按严重程度合并。
- 保留上一帧缓冲与区域几何，实现三种提交路径并记录动画区域。
- 范围感知的帧请求使动画帧按动画帧率触发。

验收是动画帧变更单元格显著下降，整帧路径快照逐字节一致。

### 阶段四：流式缓速

目标是平滑突发输出。工作来自 `04-流式缓速.md`，依赖阶段一与阶段二暴露的每帧可见文本接口。

- 新增缓速控制器，在增量分支入口接入，帧准备阶段推进并取可见前缀。
- 完成与中断事件强制排空，最终内容一致性用等价测试覆盖。
- 分段感知可在缓速稳定后单独合入。

验收是固定序列下逐帧可见字节符合速率曲线，最终文本与直通模式一致。

### 阶段五：主题与性能分级

目标是浅色终端统一适配与能力驱动降级。工作来自 `05-主题适配与性能分级.md`，依赖阶段三的提交路径。

- 新增明暗模式与缓冲级适配，显式配置优先，适配仅在未显式配置时启用。
- 能力探测接入档位策略，输入能力开关与同步输出按档位与支持情况启用。
- 底部状态可展示当前档位标记。

验收是深浅快照各自稳定，重置颜色保持透出，不支持能力的终端行为与现状一致。

### 阶段六：时钟与动画降本

目标是测试确定性与动画分配下降。工作来自 `06-动画降本与可注入时钟.md`。时钟部分建议尽早伴随阶段一落地，替换面逐步扩大，降本部分放在最后。

- 新增时钟抽象，替换动画、通知存续、交互时刻、双击判断中的直接时间读取。
- 扫光改为三段分配，指示符查表，动画时刻按桶离散化。
- 是否拆分为独立 crate 在本阶段末评估，当前先把纯函数集中以便搬迁。

验收是动画帧与通知消失时刻可断言而无需睡眠，扫光分配降为常数量级，静态内容不因动画推进而重排。

### 阶段七：渲染模型收敛

目标是整帧可离线断言。工作来自 `07-渲染模型与可测性度量.md` 的视图与隔离部分，前面的阶段已逐步铺垫。

- 引入只读渲染视图，绘制与准备只依赖该视图。
- 测试替身加无头渲染覆盖整帧序列，几何探针暴露关键矩形。
- 绘制加异常隔离与统一后处理，度量预算纳入回归。

验收是整帧序列可在无终端环境下断言，绘制异常退回恢复帧，优化指标有预算护栏。

## 依赖关系

阶段零无依赖，建议最先完成。阶段一与阶段二可并行。阶段三依赖阶段一。阶段四依赖阶段一与阶段二的帧准备接口。阶段五依赖阶段三的提交路径。阶段六的时钟可与各阶段并行，降本依赖时钟注入。阶段七收敛前面的视图与度量，可持续合入。

## 主要风险

缓存失效遗漏导致画面不更新，缓解方式是版本号私有并集中递增，配合快照覆盖。增量与全量不一致，缓解方式是保留全量作为参考实现并做随机序列等价对比。增量解析正确性风险，缓解方式是仅对安全前缀增量、可疑结构退化为全量。局部重绘与后端状态不一致，缓解方式是整帧路径仍走标准接口并封装呈现方法。主题双重生效，缓解方式是显式配置与缓冲适配互斥。新增成员的构建成本，缓解方式是拆分评估放在最后。

- 无新增的直接解包，增量告警清零。
- 新模块文件扁平命名并在入口显式登记，不引入嵌套模块目录。
- 注释为英文且只描述代码意图。
- 变更后对照阶段零基线输出度量对比。
