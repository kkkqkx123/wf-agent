# Server 层需为 Web 前端补充的功能分析

> 范围：`crates/app/wf-server` 与 `crates/app/wf-api`。判定标准是功能清单中的前端需求是否找得到对应通道；找得到的只写接入约束，找不到的列为补充项。优先级按阻塞程度划分。
>
> 落地状态：阻塞级五项与高优先级七项中的五项已实现（见各节末尾的落地注记），其余列为后续工作。

## 1. 阻塞级补充

### 1.1 统一分页包络

现状各列表只回裸数组，有的参数支持有限分页参数，调用方拿不到总数与是否有更多。前端只能做客户端分页兜底，数据量稍大即失真。需为列表通道统一补总数与游标语义，排序参数一并收敛。涉及工作流、执行、回路、检查点、消息、任务、变量、事件各列表。

> 落地：`paged.rs` 提供统一游标包络（`items`、`limit`、`offset`、`has_more`，默认 50、上限 500），已迁移工作流、执行、Agent 回路、Agent 执行、消息、任务、事件七条核心列表；总数未补（存储适配层未暴露带过滤计数，伪造总数不如不给），排序未收敛（适配层无排序能力，页内排序会失真）。其余列表保持裸数组，待存储层补计数后再迁。

### 1.2 契约发布

现状无接口描述文件，前端只能对照服务源码手写类型。需发布机器可读契约并随构建更新，至少覆盖路径、方法、请求响应形状与错误码。未发布前前端类型以手写适配层隔离，不得散落各组件。

> 落地：`GET /api/v1/contract` 发布 445 条路由清单（含包络、错误码、分页约定），由 `scripts/gen_server_contract.py` 从源码生成，探针测试逐条验证可达，漂移即失败。请求响应形状仍需手写类型，待后续引入模式生成。

### 1.3 浏览器鉴权可用性

现状跨域允许头缺失自定义鉴权头，浏览器用头鉴权会被预检拒绝，只能改走查询参数，有泄露风险；流式与套接字通道默认免鉴权免限流。需补允许头、暴露限流头，并收紧流式与套接字通道的鉴权与限流，或给出代理建议。

> 落地：默认允许头补 `x-api-key`（含 `configs/server/cors.toml`），暴露限流头，鉴权与限流默认排除项移除流式与套接字路径；套接字鉴权同时接受头与查询参数（浏览器只能用后者）。

### 1.4 静态托管与单页回退

现状服务不托管静态资源，前端须另行托管。生产部署需明确由谁托管前端产物与回退规则，避免刷新深路由出现缺页。若仍由独立静态服务承载，需约定接口基地址注入方式。

> 落地：`ServerConfig::static_dir`（`--static-dir`、`WF_SERVER_STATIC_DIR`、`server.toml` 三层）启用静态托管与单页回退（`index.html`）；`/api/*` 未知路径保持空 404，不返回 HTML。未配置时为纯 API 模式。

### 1.5 文件内容通道

现状文件域只有变更、差异、会话、审批，没有内容读取、目录树、上传下载。功能清单已将前端限定为变更展示，但长期要做文件 Tab，必须补内容读、树列举、分页变更、上传下载或签名地址。

> 未落地：仍为长期项，前端维持变更展示边界。

## 2. 高优先级补充

### 2.1 批量操作

执行批量取消、回路与执行批量删除、变量批量写（回路级）、交互批量响应。现状只有导入导出批量与触发器清理，前端只能逐个调用，易产生半成功状态。

> 落地：新增执行批量取消与删除、回路批量删除、交互批量响应（单次上限 100，逐项返回成功与否）。回路级变量批量写未补（全局变量批量通道已存在，回路级暂走多次单写）。

### 2.2 收藏语义

星标、置顶、标签的读写通道。现状只有只读标签过滤，前端收藏只能存本地，多端不同步。补齐后前端本地收藏迁移到服务端。

> 落地：`wf-api::web::favorites` 加 HTTP 层，支持按资源种类收藏、置顶、标签、分页列表。前端本地收藏可迁移到服务端。

### 2.3 统一搜索

跨工作流、执行、模板、工具、消息的统一分页搜索，带分面与总数。现状各有一套参数互不兼容的前缀式搜索，前端只能多源合并排序。

> 部分落地：统一搜索通道本就存在分面与总数，本次补空查询拒绝（防全量扫描）。跨源分页游标与消息域纳入未补，仍需前端多源合并。

### 2.4 大 dump 分页与流式化

审计报告、错误分析、性能分析、事件时间线现状为全量返回，大执行会撑爆前端。需分页或分段，或复用流式通道；至少给出大小上限与截断语义。

> 部分落地：事件列表已分页（单次拉取上限 5000）。审计与错误分析等全量报告未分页，仍需前端分段请求与虚拟化。

### 2.5 订阅面扩展

套接字订阅现状仅支持单执行，负载仅元数据。需补回路级订阅、全局主题、通知通道、在线状态；流式通道需补取消、重连位点、心跳。补齐前前端用多订阅合并与定时补拉模拟。

> 部分落地：套接字订阅补回路与工作流维度，服务端每 30 秒协议心跳。全局主题、通知通道、流式取消与重连位点未补。

### 2.6 用户偏好持久化

主题、字号、布局、默认参数、收藏的前端偏好现状无服务端存放，只能存本地。需补按用户或按键的偏好读写。多用户前可用单用户全局偏好过渡。

> 落地：`wf-api::web::preferences` 加 HTTP 层，整档替换与单键读写，持久性跟随已配置的持久化后端。单用户全局文档过渡方案。

### 2.7 导出下载语义

查询导出、模板导出、工作流导出、变量导出、审计报告现状走消息体返回，前端自行组装下载。需补文件下载头或签名地址，明确内容类型与文件名。

> 部分落地：即席查询导出支持下载模式（附件头加文件名）。其余导出仍走消息体，前端自行组装。

## 3. 中优先级补充

- 触发器模板的启用停用、定时启停、构建期校验通道开放。
- 大模型供应商健康检查、请求排队取消、按档案的用量成本记账。
- 模板版本、发布下线、批量克隆删除。
- 技能安装卸载与版本管理。
- 已保存查询与仪表盘。
- 只读分享令牌（审计报告分享页需要访问控制）。
- 操作审计日志的按用户查询（现有日志偏运维视角）。
- 备份恢复、配置重载、版本迁移通道（现有运维通道只覆盖健康与诊断）。

## 4. 不建议补充

- 密码与 OAuth 登录会话体系：当前为单机 API 密钥模型，引入完整身份体系超出前端首期范围，维持密钥加代理即可。
- 计费与订阅：与执行计费无关，不为前端单独建账单模型。
- 多媒体生成模式：后端无对应生成能力，不建前端模式开关。
- 桌面专属能力：标题栏、托盘、防休眠与后端无关。

## 5. 推进顺序建议

先做阻塞级五项，解除前端分页、契约、鉴权、部署、文件五处硬约束；再做高优先级七项，使列表、搜索、订阅、偏好、导出达到生产可用；中优先级随具体页面进入开发时按需认领，不提前铺开。

> 本轮已完成除文件内容通道外的全部阻塞项与高优先级中的偏好、收藏、批量三项全量，搜索、大 dump、订阅、导出四项部分。前端可按功能清单正式开工：列表一律按游标包络接入，收藏与偏好走服务端，批量操作直调，审计大报告仍做虚拟化，文件 Tab 仍维持变更展示边界。
