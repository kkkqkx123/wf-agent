# RAG 剩余任务清单

> 口径：以 `01-requirements.md` 的功能清单为需求基线，以 `03-design.md` 的模块划分与衔接约定为验收参照，以代码现状为准核对完成度。事实声明附文件引用。
>
> 核对范围：`crates/infra/vector-contracts/src/`（`types.rs`、`filter.rs`、`store.rs`、`memory.rs`、`simvec_adapter.rs`、`qdrant.rs`）、`crates/infra/rag-core/src/`（`document.rs`、`chunker.rs`、`converter.rs`、`pipeline.rs`、`retriever.rs`、`rerank_adapter.rs`、`citation.rs`、`config.rs`）。工作区已包含两包（根 `Cargo.toml` 成员表）。

## 完成情况核对

### 已落地：向量契约包

`crates/infra/vector-contracts` 覆盖了 `04-implementation-plan.md` 中“向量契约”步骤的全部验收项：

- 类型、过滤、存储契约与内存实现：`types.rs`（点、带分结果、距离度量、保留键）、`filter.rs`（命名空间、来源、任意字段精确匹配，交集语义）、`store.rs`（建集合、写入、稠密查询、按标识删除、按来源删除、计数，对象安全）、`memory.rs`（精确扫描加元数据过滤，维度与非有限向量显式报错）。
- simvec 适配：`simvec_adapter.rs`（`LocalVectorEngine` 薄封装，过滤逐字段映射为子句组，分数透传），未复用 CCE 的 local 实现，符合 `04-external-and-reuse.md` 决策。
- Qdrant 客户端：`qdrant.rs`（REST 薄客户端，仅建集合、写入、查询、过滤删除、计数），未引入官方 gRPC 客户端，符合选型决策。
- 契约测试：内存后端有行为测试；Qdrant 侧为纯函数单测（过滤 JSON 形状等），远端联调未做（预期内，见下文规模任务）。

### 已落地：RAG 内核包

`crates/infra/rag-core` 覆盖了 `04-implementation-plan.md` 中“RAG 骨架”步骤的验收项，并且提前落地了原属“质量”步骤的部分能力：

- 文档模型：`document.rs`（文档、切片、来源与前后关系、父子关系字段、切片标识派生规则，幂等）。
- 切分：`chunker.rs`（递归切分默认实现，目标长度、重叠、分隔符管线；层级模式附带父块存储，供自动合并提升用）。切分接口为纯变换，不耦合向量化与存储。
- 摄入与查询管线：`pipeline.rs`（`ingest_documents` 批量向量化写入、去重三态跳过覆盖报错、`query` 单问句、`query_multi` 多变体融合、`query_with_rerank` 查询加排序；存储一律经向量契约，不直连具体后端）。
- 融合与关系回填：`retriever.rs`（倒数排名融合、句子窗口扩展、父块提升、命中映射），对应两框架的合并器与上下文增强检索思想。
- 重排适配：`rerank_adapter.rs`（切片到候选的标识回填、内容截断、初始分保留，结果回填名次变化），复用 `llm-suite-rerank` 内核，未另起服务。
- 引用与转换：`citation.rs`（引用列表、编号上下文渲染）、`converter.rs`（纯文本、Markdown、JSON 内置转换，`DocumentConverter` 外部端口）。
- 配置：`config.rs`（切分、向量化批量、检索、重排四段可序列化配置，支持命名空间隔离）。

内存闭环已可跑通：`pipeline.rs` 内测试用内存后端加测试替向量化完成写入一批示例文档并回答查询，命中含来源标识。

### 与计划的偏差说明

原计划把混合融合、重排、关系回填、引用归入“质量”步骤，实际已随骨架提前落地。因此“质量”步骤的剩余量比 `04-implementation-plan.md` 字面小，见下文任务划分。计划文档其余部分的判断仍然有效，不需推翻。

### 未落地：集成层（全部未开始）

代码检索确认以下均无实现（`rag-core` 与 `vector-contracts` 仅被自身引用，无上层调用方）：

- `wf-tools` 无检索工具处理器与工具描述。
- `wf-resource` 无检索上下文片段模板与引用排版模板。
- `wf-workflow` 无摄入与查询节点类型。
- `wf-agent` 无检索工具装配确认。
- `wf-api` 与传输层无索引管理只读接口与查询排障接口。

这是当前最大缺口：内核可用但无人可用，Agent 对话与工作流编排都调不到检索。

### 部分缺失：管线内环节与质量增强

- 清洗环节缺失：`pipeline.rs` 摄入流程为归一、切分、向量化、写入，无空白、重复、特殊字符清洗开关（`01-requirements.md` 摄入侧要求）。
- 关键词召回缺失：仅稠密余弦加元数据过滤，混合检索中的词频分支未实现（计划要求首版可用轻量词频实现，不引入外部检索引擎）。
- 融合模式单一：仅倒数排名融合，拼接与加权合并两种备选未实现。
- 查询改写缺失：`query_multi` 只接受调用方备好的多变体，无经大模型网关的改写实现（设计要求改写调用复用网关，内核只收变体，因此缺的是调用方实现）。
- 合成侧缺口：`citation.rs` 只产编号上下文与引用列表，无无命中模板、无引用完整性标注（设计要求引用缺失时明确标注不伪造）。
- 切分扩展未做：层级模式已落地，但按标题切分、按句切分的独立默认形态未显式提供（当前以后缀分隔符参数复用同一管线，形态上够用但无具名预设）。
- 删除语义只有契约：`store.rs` 有按标识与按来源删除，`pipeline.rs` 摄入仅在覆盖策略下按来源删除，无面向调用方的来源级更新封装（按内容哈希判断变更、孤儿切片清理、按标识列表删除的内核级便利接口）。
- 度量评估缺失：检索延迟、候选规模、重排位移三组指标未补齐；可复跑评测集与命中记录未建；排障文档（切分过粗、过滤过严、维度错配）未写。
- 持久化验证缺失：simvec 嵌入持久化、Qdrant 远端联调、重启后可用性验证均未做；SQLite 文档切片元数据形态未定；Postgres 仅预留接口（符合计划，本步不做）。

## 剩余任务

任务按依赖排序，编号仅为本文件内顺序。描述只讲改动点与验收，不贴完整实现。

### 集成组（最优先，全部未开始）

- 检索工具：在 `wf-tools` 新增最小只读检索工具处理器与工具描述。入参为问句、返回数量、过滤条件、知识库标识，出参为命中列表（内容、分数、来源、引用定位）。处理器内部调用 RAG 包查询接口，超时与截断可配。注册进默认工具集，纳入暴露决议计算。丰富参数形态走 MCP 与插件扩展，不进内置定义。验收：Agent 对话中模型可自主调用检索工具并引用来源；敏感库降为发现式后调用链符合预期。
- 提示词片段模板：在 `wf-resource` 新增检索上下文片段与引用排版模板，支持展示与模型两种渲染模式，截断阈值可配。验收：同一命中列表可分别产出可读排版与模型输入，超长内容按阈值截断。
- 工作流节点：在 `wf-workflow` 新增摄入与查询两类节点类型。节点参数为内核配置引用名加本次覆盖值，执行体为对内核的异步调用，检查点记录输入摘要与命中标识，不记录完整向量。向量化失败可重试，存储不可用按节点失败处理，不静默降级为空答案。验收：查询节点可串接在问答分支后；摄入节点可以批量调用形态先行，不阻塞查询集成。
- 代理接线确认：`wf-agent` 无需改执行主干，只需确认检索工具参与单轮装配，门控与发现语义生效。验收：门控集收纳未激活库时，可见集形态符合四态划分预期。可并入检索工具任务一并验收。
- 管理与排障接口：在 `wf-api` 与传输层增补只读接口，包括文档数、来源列表、命中预览、候选分数分布。完整向量默认不外传。验收：不依赖私有接口即可回答索引里有什么、某问句召回了什么、分数如何分布。

### 管线补齐组（内核内增量）

- 清洗环节：在摄入流程中新增清洗开关，覆盖空白、重复、特殊字符三类规则，规则可开关可配置。验收：同一批含噪文档在开关开合下产出可区分的切片，且开关状态可序列化进配置。
- 切分具名预设：在现有递归管线之上提供按标题、按句两套默认分隔符与后处理规则，不另起抽象。验收：Markdown 标题文档与长句文档分别用对应预设切分，关系字段保留情况符合预期。
- 关键词召回与混合：新增轻量词频召回分支，与稠密召回合流，默认倒数排名融合，另支持拼接与加权合并两种备选。验收：一组需字面命中与语义命中互补的问句，开启混合后来源覆盖度可观测提升；融合模式可配。
- 查询改写调用：在工作流或代理侧实现经大模型网关的改写调用，把一问改写为多变体后送入既有 `query_multi`。内核不新增调用路径。验收：多查询检索端到端可用，改写失败时降级为原问句单路检索并记录原因。
- 合成模板补齐：新增无命中模板与引用完整性标注。引用缺失时答案明确标注来源不完整，不伪造来源。验收：构造无命中与缺来源引用两种用例，答案形态符合要求。

### 规模组（持久化、增量、管理闭环）

- 来源级增量更新：在内核层封装来源级更新语义。按内容哈希判断新增、变更与删除，按来源删除同步清理孤儿切片，支持按标识列表删除。写入三态语义完整实现。验收：更新来源文件后增量生效；删除来源后相关切片不可检出。
- 持久化验证：完成 simvec 嵌入持久化验证（重启后索引仍可用）与 Qdrant 远端联调。SQLite 只存文档与切片元数据，形态对齐现有后端划分；向量索引不塞进实体语义。Postgres 接口保持预留。验收：重启前后同一问句命中一致；远端后端通过同组契约行为测试。
- 度量与排障：补齐检索延迟、候选规模、重排位移三组指标，沿用现有收集器；编写排障文档说明常见无命中原因。验收：一次典型查询可观测到三组信号；按文档可定位切分、过滤、维度三类常见问题。
- 评测集：记录可复跑的评测集与命中情况，不引入完整评估框架。验收：评测集可重复执行并输出命中来源分布与名次变化。

## 建议实施顺序

先集成组（检索工具、模板、查询节点、管理接口），让内核先被用起来；再管线补齐组（清洗、关键词混合、改写、合成模板），提升命中质量；最后规模组（增量更新、持久化验证、度量评测），解决长期运行问题。集成组内部允许并行，管线补齐组依赖集成形态稳定后开始，规模组依赖质量管线稳定后开始。不跨步提前引入持久化细节或评估框架。

## 回归与约束

每步均需通过全量编译检查、新增模块格式化、日志与错误信息英文、代码注释只描述意图。无循环依赖，新增依赖在中央依赖表声明。设计文档避免完整代码段，后续实现文档同样遵循该约定。
