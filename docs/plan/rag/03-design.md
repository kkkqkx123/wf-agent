# 总体设计

> 本文件给出新增内核的形状、两条流程与各层衔接方式。描述以自然语言为主，只出现类型与方法名，不贴完整实现。

## 两个独立包的位置与依赖方向

向量存储抽象与 RAG 分为两个独立包，均置于 `infra` 层，均使用中立命名以便未来抽为独立仓库加 submodule 复用（与 `simvec`、`llm-suite` 的复用方式一致）：

- 向量包 `crates/infra/vector-contracts`（已落地）：后端中立的向量存储契约。只允许依赖 `foundation` 工具链与标准异步运行时，禁止依赖任何项目业务 crate。默认特性零重依赖；`simvec` 适配与 Qdrant 客户端为可选特性。
- RAG 包 `crates/infra/rag-core`（已落地）：文档、切分、摄入与查询管线、重排适配、引用。依赖向量契约加 `llm-suite-embedding` 与 `llm-suite-rerank` 的 trait，不依赖任何具体后端（内存、simvec、Qdrant 均由调用方注入）。
- `wf-tools` 依赖 RAG 包实现检索工具，`wf-workflow` 依赖 RAG 包实现摄入与查询节点，`wf-resource` 消费命中结果。若把 RAG 包放在 `engine` 层上部，`wf-tools` 将向上依赖，破坏 `wf-tools` 为引擎层起始点的有向无环结构。放在 `infra` 层则依赖方向自然向下收敛。

依赖链：`RAG 包 -> vector-contracts`，`后端 -> vector-contracts`，`wf-tools / wf-workflow -> RAG 包`。禁止反向依赖，不形成循环。

文件组织遵循项目惯例：扁平文件，每个模块为同目录下同名文件，不使用 `mod.rs`。

## 向量包模块划分（已落地）

- 类型模块：点、带分结果、距离度量、保留键（`namespace`、`source`、`pid`）与载荷文本表示。分数一律越高越好，欧氏取负距离以统一排序方向。
- 过滤模块：命名空间、来源、任意字段精确匹配三类约束，全设时取交集；空过滤匹配全部。匹配语义为各后端必须遵守的同一约定。
- 存储模块：`VectorStorage` 操作契约（建集合、写入、稠密查询、按标识删除、按来源删除、计数），对象安全，调用方可持 `Arc<dyn VectorStorage>` 按配置换后端。
- 内存模块：精确扫描加元数据过滤的进程内实现，用于测试与小规模场景；维度不一致、非有限向量一律显式报错。
- simvec 适配（`simvec` 特性）：`LocalVectorEngine` 的薄封装，过滤逐字段映射为子句组，分数透传，`pid` 载荷回填契约标识。不复用 CCE 的 local 实现，各项目自写薄适配。
- Qdrant 客户端（`qdrant` 特性）：REST 薄客户端，仅覆盖 RAG 所需子集（建集合、写入、查询、过滤删除、计数）。官方 gRPC 客户端不引入，`ref/rust-client` 仅作协议参考。

## RAG 包模块划分（已落地）

- 文档模块：定义文档与切片类型。文档面向写入侧，切片面向检索侧。切片保留来源标识、来源内序号、前后相邻标识，便于句子窗口与自动合并检索按关系回填上下文。
- 切分模块：定义切分器接口与递归切分实现。接口输入为文档列表，输出为切片列表。递归实现按分隔符列表逐级降级，参数含目标长度、重叠长度、是否保留元数据、是否保留前后关系。其余切分器（按标题、按句、层级）实现为不同默认分隔符与后处理规则，不另起抽象。
- 检索模块：定义检索器接口与四种实现。稠密检索负责问句向量化加存储查询；过滤检索负责纯条件召回；混合检索负责多路召回加融合；多查询检索负责改写后多路调用再合并。融合策略默认倒数排名融合，权重与裁剪参数可配。存储访问一律经 `VectorStorage` 契约，不直连具体后端。
- 合成模块：定义查询改写、上下文组装、答案与引用结构。改写调用经大模型网关，上下文组装只输出模板变量，不直接拼提示词字符串，渲染仍由 `wf-resource` 完成。
- 转换模块：内置轻量格式转换（纯文本、Markdown、JSON）与外部 converter 服务端口（`DocumentConverter` trait）。复杂格式（公式、表格、扫描版面）交 minerU 一类外部服务处理，经归一化后再进切分；详见 `docs/research/rag/04-external-and-reuse.md`。
- 配置模块：承载切分、向量化、检索、重排四段可序列化配置。时长一律用持续时间类型表达，对外展示用毫秒后缀字段。配置支持按知识库命名空间隔离，多个知识库可各配切分与检索参数。

## 两条流程

摄入流程处理写路径：

1. 输入归一为文档列表，来源标识必填，元数据透传。
2. 清洗按开关执行，规则可配。
3. 切分器产出切片，切片标识由来源标识加序号派生，保证幂等。
4. 批量向量化，批次大小可配，失败重试边界在服务层。
5. 按去重策略写入：跳过已存在、覆盖已存在、遇冲突报错三种语义，默认跳过。删除按来源或标识列表执行，同步清理孤儿切片。

查询流程处理读路径：

1. 问句预处理（前缀或模板），复用向量化层的预处理配置。
2. 问句向量化，单次调用。
3. 存储查询，参数为返回数量、分数下限、元数据过滤。
4. 可选混合召回与融合，可选重排与截断。
5. 关系回填：句子窗口按前后相邻扩展，自动合并按父子关系提升为父块。
6. 组装模板变量，经 `wf-resource` 渲染后送入大模型网关合成答案，答案附带引用列表。

两流程共享文档模型与存储协议，但执行触发点不同：摄入由索引任务触发，查询由问答或工具调用触发。

## 与现有机制的衔接

工具衔接：

- 在 `wf-tools` 新增检索工具处理器，入参为问句、返回数量、过滤条件、知识库标识，出参为命中列表（含内容、分数、来源、引用定位）。工具为只读，不产生副作用，不参与审批流。
- 暴露形态复用四态机制：默认直接可见，敏感库降为发现式，门控集收纳未激活的库。运行时拦截只做权限与配额控制，不改变可见工具集形态。

工作流衔接：

- 在 `wf-workflow` 新增摄入与查询两类节点类型。节点参数为内核配置的引用名加本次覆盖值，执行体为对内核的异步调用，检查点记录输入摘要与命中标识，不记录完整向量。
- 失败语义沿用现有错误分支：向量化失败可重试，存储不可用按节点失败处理，不静默降级为空答案。

资源衔接：

- 在 `wf-resource` 新增检索上下文片段模板，变量含命中内容、来源、分数。渲染模式区分展示用与模型用，截断阈值可配。
- 引用列表由合成模块产出，模板只负责排版，不负责引用正确性校验。

传输衔接：

- 在 `wf-api` 增补索引管理只读接口（文档数、来源列表、命中预览）与查询排障接口（返回候选分数分布），完整向量默认不外传。
- 事件与度量沿用现有收集器，新增检索延迟、候选规模、重排位移三组指标。

## 错误与边界

- 空文档、超长文档、缺向量写入、维度不一致、存储不可用、重排服务不可用，均以明确错误返回，调用方决定重试或降级。
- 问句为空、返回数量为零、过滤无匹配，返回空命中而非错误，合成侧按无命中模板应答。
- 引用缺失来源时，合成结果必须标注引用不完整，不伪造来源。
- 日志与错误信息使用英文，不在代码注释中引用本文档结构位置。
