# CLI 纯客户端化设计：progenitor 生成 wf-client

## 一、背景与目标

当前 `CLI` 默认内嵌 `Runtime`，`wf-tui` 直调领域层，远程模式仅覆盖部分命令。`wf-server` 已有完整 `OpenAPI` 快照，`web-app` 已消费该快照。

目标：删除内嵌执行路径，三个 `CLI` 形态完全作为 `HTTP` 客户端；`Rust` 客户端代码由 `progenitor` 从快照生成，放入新建的 `wf-client` 箱，供 `CLI` 与后续桌面应用共用。

## 二、关键约束

经 `ctx7` 核实 `progenitor` 特性并在实现中验证：

- 仅接受 `OpenAPI 3.0`，而快照为 `3.1`，且含大量 `3.1` 风格的可空表达，直接生成必失败，须在生成前做内存归一化。
- 推荐以构建脚本驱动生成器并将产物引入箱内，而非使用声明宏，便于预处理与统一配置。
- 每个接口生成一个链式调用构造器较为适合本项目近五百个接口的规模；单客户端形态与前端现有单客户端对应；鉴权通过底层请求客户端的默认请求头注入。
- 生成方法的错误模型携带类型化错误体，而本服务端统一在成功体内再包一层结果信封，需在手写层统一拆包。
- 流式接口无法生成，须由手写层基于现有请求与事件流组合实现；生成时需将其剔除。
- 实现中另发现两处阻碍生成的快照特征：无响应体的中间件错误声明与多类型错误并存冲突，构建脚本一并剔除无响应体声明；可空分支的单元素化简同样在归一化中处理。

结论：归一化只发生在 `wf-client` 构建时的内存副本，不回写快照，前端继续消费原 `3.1` 快照。

## 三、总体架构

快照作为唯一真相，提交库内并由漂移测试守门。`wf-client` 构建脚本读取快照、归一化、生成客户端源码。手写层在其上提供连接配置、信封拆包、流式订阅与健康检查。`wf-cli-shared` 瘦身为纯编排与输出渲染，三个 `CLI` 二进制均只依赖 `wf-client`。

依赖铁律：`wf-client` 永不依赖领域与服务端箱；底层界面箱永不依赖领域层，现有违规依赖必须断开。

## 四、wf-client 箱设计

箱位置与成员注册已完成。依赖分为运行侧的请求、序列化、流式与错误设施，以及构建侧的生成器与语法设施。

构建流程为读取快照并声明重构建监听，内存归一化后解析为规范模型，经默认配置的生成器产出源码并格式化写入构建产物目录，失败时直接中断构建以暴露首个违规点。

手写层包含连接配置解析（显式地址优先于环境变量，缺省指向本地默认端口）、基于默认请求头的鉴权注入、连通性探活、信封拆包与错误映射、流式订阅封装，以及供新调用点使用的类型化客户端透出。管理命令迁移优先使用非类型化载荷出入口，以保持现有输出渲染不变。

## 五、CLI 改造清单

共享箱去内嵌已完成（含领域适配、内嵌会话驱动、本地执行分支与特性门删除）。会话运行路径已收敛到流式客户端（`SSE` 优先、阻塞 `POST` 兜底）。管理命令已逐个改调客户端出入口。轻量与全屏前端已断开引擎依赖，会话数据拉取改为客户端并发调用。三个二进制箱特性已清理（`embedded`/`remote` 特性门删除）。手写层出入口为泛型（`get_json<T>`/`post_json<B,T>` 等），调用点以 `serde_json::Value` 为主，类型化客户端透出供新调用点使用。

Git 域不出现在 CLI：服务端 `/api/v1/git/*` 面向前端（浏览器无法直接执行本地 `git`，需服务端代理，属于远程执行场景）；而 CLI 运行在持有仓库的机器上，直接调用 `git` 的成本近乎为零，包一层 HTTP 往返只会复制一套更差的子集，并拖累快照面与维护面。故 `wf git` 子命令与全屏 `Git` 屏幕一并移除（含 `ScreenKind::Git`、屏幕数据模型与绘制、数字键位重排），服务端接口与前端界面保持不动。

输出纪律不变：标准输出纯业务、标准错误诊断、结构化输出信封与顶层分发表结构保持稳定。

## 六、非目标与后续

服务端需用户显式启动，连接失败时报错指引，不做后台服务自拉起与注册。注解风格与快照版本不做迁移。新增接口只需刷新快照后重编客户端。
