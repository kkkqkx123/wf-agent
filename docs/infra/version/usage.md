# 版本功能与使用规范

## 通用规范

开发阶段所有版本锁定为一。任何版本不一致均为错误，不做自动修复、不做数据迁移、不保留旧数据兼容。调用方收到版本不兼容错误后应丢弃旧数据并用当前版本重建。开发阶段禁止以任何理由提升版本号，禁止为旧数据编写兼容分支。

## 检查点格式版本

创建检查点时自动盖章当前格式版本。恢复时按存储行的格式版本判定：与当前一致则直通，缺失格式版本直接拒绝，高于当前或低于最低兼容均直接拒绝。需要迁移的中间版本在开发阶段不会出现，若出现同样拒绝。新增检查点字段必须保持旧行可解码，删除或改义字段属于正式发布后的版本演进，需注册迁移处理器并提升版本号，开发阶段不做此类变更。

## 存储表结构版本

打开关系型后端时检查每表版本行，无记录则写入当前版本，有记录但不一致则拒绝启动，同一文件以同一表名重开同样拒绝。应用查询自动排除版本行，业务代码无需关心。单表清理与批量清理均只删除业务行并保留版本行，清理后无需重新打开即可继续接受版本检查。内存后端无版本行概念。表结构或元数据语义变更时，开发阶段直接调整代码并保持版本号为一，正式发布后才按变更提升版本号并配套升级说明。

## 文件历史表结构

打开文件历史数据库时执行幂等建表，可重复运行，只保留一个完整初始化入口，文件与内存构造器共用该入口。仅支持新增表与索引，不支持改列、回填与删表。轻量建表仅用于单测验证部分表结构。需要结构性变更时，开发阶段直接调整建表语句并重建本地数据库，正式发布后才引入版本化迁移表。

## 工作流业务版本

工作流定义的版本标签须为严格的三段点分数字格式，任何缺段、空段、非数字、多余分段都会被校验拒绝，不做折算。版本递增按补丁、小版本、大版本策略进位。更新时可选择保留原版快照，保留标签已存在时自动附加时间戳避免覆盖。回滚先保存当前再覆盖，保存失败时回滚整体失败。快照标签作为内部键可沿用历史自由字符串，但定义体自身的版本字段必须严格合法。智能体定义版本遵循同一规范。

## 接口协议版本

后端业务域统一挂载在接口主版本路径下，信息接口返回应用版本与协议版本，协议版本的运行时唯一来源为路由模块的常量，健康返回引用该常量，接口文档声明以单测断言与常量一致。开放接口快照为前后端唯一契约，改动路由、请求体、响应体后必须刷新快照并重新生成前端类型，漂移时测试即失败。流式事件新增字段必须为可选并提供默认值，老服务端缺字段时前端回退展示。前端健康检查在探活的同时校验协议版本，发现失配时标记并告警，不静默兼容。开发阶段协议版本保持为一，不新增版本分支，破坏性变更直接修改当前版本并同步快照与前端类型。

## 配置索引版本

索引文件加载时校验版本号取值，只接受当前取值，不符时返回解析失败。校验大小写敏感，不做归一化。仓库内现有索引与单测构造均使用该取值，手写索引误填会在加载时直接失败。

## 正式发布后启用

正式发布后需做三件事方可启用版本演进：明确新版本号与最低兼容值，在对应模块注册迁移或升级路径，更新本目录文档与变更说明。在此之前，任何版本差异一律按开发阶段政策拒绝处理。
