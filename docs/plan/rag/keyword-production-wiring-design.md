> FTS 关键词索引生产装配方案。中文撰写、自然语言为主，不贴完整实现。改动点与验收一一对应，顺序即实施顺序。

## 现状与问题

内存关键词实现删除后，`SqliteKeywordIndex` 是唯一内置实现，对外提供文件打开与内存打开两种构造，测试已全部切到内存 FTS 覆盖生产路径。但生产装配完全断开，共三处：

- 应用句柄 `wf-api` 的检索句柄只有向量库与嵌入器，没有关键词字段；附带的注入入口在生产代码中零调用，管理面检索路由因此常驻服务不可用。
- 工作流检索句柄的关键词槽位恒为空，附带的装配方法在生产代码中零调用，混合检索恒关闭；两个检索节点的注册函数同样只有测试调用。
- 工具侧检索服务为纯稠密实现，没有关键词槽位，工具链路走不到混合管线。

结论是索引能力已就绪，缺的只是从引导到三条消费链的装配。本方案只补装配，不碰融合、分词与评分。

## 目标与非目标

- 目标为运行时构造唯一的 FTS 索引实例，由工作流节点、工具检索、管理面三条链共享同一引用；默认读行为零变化，写链路开始双写以积累关键词数据。
- 非目标为不调整任何检索算法与配置默认值，不引入新后端，不做存量向量数据的自动回填迁移，只给出重建指引。

## 构造位置与生命周期

- 唯一构造点放在运行时引导。引导层拥有存储路径推导与生命周期管理，关键词库路径与既有存储库路径走同一派生规则，属同一职责。
- 具体打开逻辑放在应用 facade 的检索模块（该层已依赖检索核心），引导层只调用不直连检索核心，保持应用层单向依赖红线，运行时不新增底层依赖。
- 索引实例以共享引用单例存在，随应用上下文创建与销毁；各消费链只克隆引用，禁止各自打开同一库文件。各自打开会导致文件写锁争用，而内存模式下各自打开更会直接分叉成互不可见的多份索引，这是必须在文档中写明的禁止项。
- 关闭时无特殊动作，连接随引用释放而关闭。

## 路径与配置语义

采用三个显式分支，不设掩盖式回退：

- 存储类型为内存时使用内存 FTS，随进程消亡，语义与内存向量库一致。
- 文件或远端存储类型时使用文件 FTS，路径派生自存储配置（应用库旁的同名关键词库文件），支持配置项与环境变量覆盖；父目录不存在时沿用存储引导的目录准备逻辑创建。
- 显式禁用关键词时句柄为空，混合链路按“未启用”处理。

打开失败必须中断启动并显式报错，不允许静默降级为空。静默降级会让混合检索无声失效，把配置错误推迟成召回问题，违背失败显性原则。唯一合法的空来源是显式禁用。启动日志记录后端名与生效路径，便于排障时确认生效的是哪一个索引。

## 句柄改动

- 应用检索句柄新增可选的关键词字段，构造签名直接修改，不保留旧构造（项目不做向后兼容）。原有的“句柄缺失即服务不可用”检查保持不变，面向稠密链路；混合链路把“关键词缺失”当作正常分支回退纯稠密，由调用方显式处理。
- 应用上下文的两个构造入口不再把检索句柄留空，改为由引导注入；原有“无句柄即不可用”的单测保留，覆盖显式禁用分支。
- 工作流侧在真正拥有向量库与嵌入器的装配点调用关键词装配与节点注册，不往无后端的默认 handler 工厂里塞空句柄。空句柄进默认工厂只会让节点在运行时报不可用，把装配问题伪装成运行时问题。
- 工具侧检索服务新增可选关键词槽位，缺失时行为与现网完全一致；配了候选数后走混合管线。

## 默认行为与存量数据

- 读默认不变。关键词候选数默认零即混合关闭，现有工作流与工具查询结果零漂移；混合是显式 opt-in，由调用方配置打开。
- 写开始双写。摄入与删除统一走管线双写封装，不新增旁路写入点；计数口径以向量侧为准的既有约定不变。
- 存量漂移需要文档声明。现存向量数据没有对应的关键词行，重建之前的混合召回天然偏低；给出用覆盖策略重摄入的重建指引，不做自动迁移，不读旧格式。

## 并发与性能说明

- 内置索引内部为阻塞互斥，引导期的打开动作放在阻塞线程池执行，不占用异步执行线程。本方案不重构其并发模型，只要求装配层不引入第二个连接。
- 批量写入的事务切分已有，本方案不在装配层加队列或缓冲。

## 可观测

- 管理面统计新增关键词计数，两端分别计数以便对账发现漂移；诊断接口区分“关键词未启用”与“启用但无匹配”，两者是不同的运维动作。
- 预览查询默认保持纯稠密不变；是否随混合开关透传二选其一，选定后文档锁定，避免同一接口在不同部署下行为不一致。
- 混合查询的候选数度量已有，装配完成后自然可用。

## 测试与验收

- 引导装配测试：内存存储引导后句柄齐备且一次摄入双写、混合查询命中；文件存储用临时目录验证关闭重开后计数仍在；非法路径或不可写目录引导显式失败。
- 回归测试：原有空句柄（服务不可用）与纯稠密用例全部保留通过；受影响包的编译检查与单测通过。
- 验收标准为默认部署读行为零变化、显式打开混合后两路信号均参与结果、双写后两端计数一致、失败路径可观测。

## 实施顺序

句柄字段先行，其次构造与路径推导，再做工作流、工具、管理面三链透传，最后补装配测试并更新运维文档说明默认关闭语义与重建指引。

## 回归约束

每步通过受影响包的编译检查与单测，日志与错误信息英文，注释只描述意图。无循环依赖，新增依赖在中央依赖表声明。不做旧数据兼容，不更新版本号。编译输出先重定向到文件再阅读，集中为最少次数的验证。

## 实施进度

状态更新日期：2026-11-05。前五个库层阶段已完成；本轮补齐宿主装配所需的访问器、装配配方测试与引导装配测试。向量库与嵌入器的供给仍归宿主，引导层不持有。

### 已完成

- **阶段一：句柄字段**（`wf-api`）
  - `RagHandles` 新增可选 `keyword` 字段，构造签名改为三参，Debug 输出关键词开关。
  - 应用上下文新增 `keyword_index` 字段、`with_keyword_index` / `keyword_index` 访问器，以及 `rag_node_handles(collection, namespace)` 辅助，把共享关键词索引透传到工作流节点句柄。
  - 两处上下文构造器均初始化 `keyword_index: None`。
- **阶段二：构造与路径推导**（`wf-api` + `wf-runtime`）
  - `rag.rs` 新增 `KeywordIndexLocation`、`SharedKeywordIndex`、`resolve_keyword_location`、`keyword_db_path`、`open_keyword_index`，三分支显式、打开失败显式报错、环境变量覆盖、父目录创建、启动日志记录后端与路径。
  - `wf-types` 新增 `KeywordIndexConfig { enabled, db_path }`，并挂到 `RuntimeConfig.keyword`（默认启用）。
  - 运行时 `Runtime` 新增 `keyword_index` 字段；引导流程在存储初始化后于阻塞线程池打开索引，失败中断启动；API 上下文装配时注入。
- **阶段三：工具链透传**（`wf-tools`）
  - `RagService` 新增可选 `keyword` 槽位与 `with_keyword`；`search` 在候选数大于零且索引存在时走 `query_hybrid`，否则保持纯稠密，现有行为零漂移。
- **阶段四：管理面透传**（`wf-api` + `wf-server`）
  - `CollectionStats` 新增 `keyword_point_count: Option<u64>`；`collection_stats` / `source_stats` 接受可选关键词索引并分别计数，便于对账漂移。
  - `diagnose_no_hits` 新增 `keyword_enabled` 参数，区分“启用但无匹配”与“未启用”。
  - 服务端统计与诊断路由传入 `handles.keyword.as_deref()` 与上下文关键词开关。
- **阶段五：编译与依赖检查**
  - `wf-api`、`wf-tools`、`wf-server`、`wf-runtime`、`wf-workflow` 全部 `clippy --all-targets` 通过；无新增循环依赖；新增依赖仅 `wf-types` 已有链路与 `rag-core`，无中央依赖表改动。

### 阶段六：宿主装配收尾（本轮补齐）

- 运行时的关键词单例新增只读访问器，宿主无需经过应用上下文即可拿到共享引用，再分别装配三条消费链。
- 应用层补齐三分支解析、路径派生、三种打开方式的单测，以及内存双写对账与混合命中的端到端用例，锁定默认纯稠密与显式 opt-in 的边界。
- 应用层补齐宿主装配配方测试：同一关键词单例同时驱动管理面计数、工具服务混合开关、工作流节点注册，验证三链共享同一引用。
- 引导层补齐装配测试：内存引导单例齐备、显式禁用留空、文件引导落盘且重启后仍在、非法路径中断启动并显式报错。
- 管线文档补齐存量重建指引：存量向量数据需用覆盖策略重摄入回填关键词行，重建前混合召回偏低属预期，不做自动迁移。

### 未完成 / 留给宿主层

- 向量库与嵌入器的供给仍归宿主：引导层不持有这两者，宿主在拥有后端的装配点按既有配方装配三链，即应用上下文透传节点句柄后注册、工作流与工具服务附带共享索引、管理面构造时传入关键词槽位。
- 预览查询保持纯稠密不变，不随混合开关透传。
- 存量数据不做自动迁移，宿主按文档指引用覆盖策略重摄入。

### 验收现状

- 默认部署读行为零变化：候选数默认零，混合关闭。
- 写链路双写生效：摄入与删除管线同时写向量与关键词索引，宿主注入索引后即生效。
- 失败路径可观测：打开失败中断启动并报错；管理面区分未启用与无匹配；两端计数可对账。
- 本轮新增验收：内存双写后两端计数一致且混合命中；文件引导落盘且重启后仍在；非法路径引导显式失败；三链共享同一单例。
