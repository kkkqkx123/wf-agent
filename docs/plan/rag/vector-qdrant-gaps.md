# 向量抽象层 Qdrant 实现对照分析与补齐方案

> 对照对象为 `ref/rust-client` 官方客户端源码快照，落点为 `crates/infra/vector-contracts` 的 REST 薄客户端（`src/qdrant.rs`）与操作契约（`src/store.rs`、`src/filter.rs`）。中文撰写、自然语言为主，不贴完整实现。顺序即实施顺序。

## 结论先行

REST 薄客户端方向合理，与既有研究结论一致：复用现有请求栈、只实现检索所需子集、官方客户端只当协议参考而不进依赖。该选择成立，不推翻。

当前实现可用但只覆盖最小子集，且存在语义不一致与效率问题。对照官方能力地图，缺失集中在集合校验、索引、运维与高级查询四处；其中集合校验、类型一致性、原子性与批量效率必须补，运维能力补最小集，高级查询明确延后。

## 官方能力地图摘要

以 `ref/rust-client/src/qdrant_client` 七个操作组加基础能力为尺子：

- 集合：创建、查询、列表、存在性、更新、删除、别名、集群与分片键。
- 点：单批写入、分块写入、按标识取、滚动列举、计数、批量更新、按标识或过滤删除、向量增删、命名向量增删、分布统计、矩阵采样。
- 检索：旧检索与批量检索、分组检索、推荐、发现；新统一查询与批量查询、分组查询，支持预取、融合、排序、推荐与发现输入、上下文对。
- 载荷：设置、覆盖、删除键、清空。
- 索引：字段索引创建与删除，覆盖关键词、整数、文本、地理等多类型。
- 快照：集合与全量快照的创建、列表、删除与下载。
- 配置与传输：地址、请求超时与连接超时分离、空闲保活、压缩、兼容性检查、连接检查、连接池轮询加失败重试、自定义请求头、健康检查、版本兼容规则、结构化错误。
- 过滤：必含、可选、最小满足数、必不含四种组合，匹配支持关键词与整数、布尔、全文与短语、任意词、前缀与子串、数值区间、时间区间、地理半径与包络与多边形、数组长度、嵌套、标识与向量存在性、空与 null、切片。

当前契约与实现只用了其中一小部分：确保集合、写入、稠密检索、按标识取、按标识与按来源删除、计数，以及必含与必不含的相等与区间过滤。这是有意裁剪，但裁剪边界之内的正确性仍有缺口。

## 问题清单

### 集合语义不对等

现状在 `qdrant.rs` 的集合确保逻辑：存在即返回未创建，不存在即创建。内存与 simvec 实现会校验已存在集合的维度并报维度不匹配，Qdrant 实现不校验维度与距离，直接复用。

- 风险为维度或距离变更后静默复用旧集合，写入在服务端报参数错误，读路径分数不可比。
- 写入前也不做维度预检，服务端返回的参数错误被归为通用后端错误，调用方无法区分输入问题与服务问题。

### 类型一致性缺口

契约规定精确字段按文本表示比较，内存实现据此让字符串三分与数值三分互相匹配。Qdrant 实现对结构化相等按类型发送数值匹配，但对通用精确字段一律按字符串匹配。

- 风险为管线把纯数字元数据存成数值后，字符串形式的字段过滤在内存能命中、在 Qdrant 命中不了，双后端行为分叉。
- 检索向量解析只处理数组形态。单未命名向量时成立，遇到命名向量对象形态会退化为空向量而不报错。

### 分数与阈值语义待验证

内存实现把欧几里得取负以保证分数越高越好。Qdrant 服务端对不同距离返回的分数方向与阈值语义是否与该约定一致，当前没有跨度量用例锁定。

- 风险为切换距离后排序看似正常但阈值过滤行为分叉。

### 标识映射的原子性与效率

Qdrant 原生标识只支持整数与通用标识符，字符串标识走载荷中的业务标识字段。当前每次写入按固定批尺寸先按业务标识删除再用新鲜随机标识符插入。

- 非原子：删除与插入之间并发检索可见空窗或双份；中途失败可能丢数据。
- 低效：每批两次往返；取数据时每个标识一次滚动查询，邻居扩展与窗口扩展会放大为多倍往返。
- 计数口径不一致：内存按实际删除计数，Qdrant 与 simvec 按请求数计数；按来源删除走先计数再删除，与按标识删除的口径不统一。

### 一致性参数缺失

写入与删除未要求服务端等待生效，检索紧随写入可能看不到新点。计数一律要求精确，大集合代价高但无开关。

### 索引缺失

确保集合后从不创建载荷索引。命名空间、来源、业务标识是每次检索与删除的过滤条件，无索引时靠全扫描，数据量稍大即退化。官方索引管理能力在当前实现中完全没有对应物。

### 配置与运维过薄

连接配置只有地址、可选密钥与单超时。官方配置中的连接超时分离、自定义请求头、连接池、压缩、兼容性检查、连接检查均无对应。客户端构建时不发任何请求，地址错误与版本不兼容都延迟到首次调用。错误映射只区分未找到与鉴权，其余一律归为后端错误，参数错误、限流与重试信号无法区分。缺少重试与退避，缺少请求链路日志与延迟度量。缺少集合删除、集合信息、健康检查，运维与测试清理只能绕开抽象层。

### 契约缺失但暂不需要的能力

滚动列举、批量查询、预取融合、排序输入、推荐与发现输入、分组、稀疏与多向量、命名向量、载荷局部更新、快照、分片与别名，当前检索管线均未使用。属于明确延后项，不在本轮补齐，但需在文档中写明触发条件，避免后续误以为后端已支持。

### 测试与文档缺口

过滤构建只有纯函数单测，跨后端行为一致性没有统一用例。随机标识、串行取数、类型分叉、欧几里得分数方向均无锁定用例。端口语义、版本要求、索引要求、业务标识映射、非原子窗口、等待语义均未在文档中说明。

## 修改方案

### 第一阶段：语义对齐

- 集合确保补校验：存在时查询集合信息并比对向量尺寸与距离，不一致报维度不匹配或非法输入；行为与内存和 simvec 对齐。验收为维度变更后确保集合失败而非静默复用。
- 写入补维度预检：批量写入前获取集合配置并逐点校验维度与有限性，服务端参数错误中的维度信息映射为维度不匹配。验收为错误类型可区分。
- 字段过滤补类型一致性：通用精确字段在 Qdrant 侧按文本相等语义发送多形态匹配，使字符串条件能命中数值与布尔载荷；结构化相等保持类型化匹配。验收为同语料下内存与 Qdrant 过滤结果一致。
- 取数解析补形态兼容：同时处理数组向量与命名向量对象形态，后者取默认或首个向量；缺向量显式报错而非返回空向量。验收为两种形态单测通过。
- 分数方向锁定：补跨度量用例验证排序与阈值在余弦、点积、欧几里得下三后端一致；不一致则在 Qdrant 检索侧归一化。验收为阈值用例三后端一致。
- 等待语义补齐：写入与删除要求服务端等待生效，默认同步可见。验收为写入后立即检索可见。
- 删除计数统一口径：按标识删除改为先计数再删除或按实际删除计数，与按来源删除一致；三后端统一为实际删除数。验收为缺失标识不计入删除数。

### 第二阶段：效率与原子性

- 标识映射改为确定性标识：由业务标识派生稳定的原生标识，一次写入即覆盖，无需先删后插。验收为写入往返减半且无空窗，重复写入不产生双份。
- 取数改为单次批量：一次滚动请求携带多条件并按请求顺序回填，缺失跳过。验收为多次取数只有一次往返且顺序与请求一致。
- 批尺寸与等待可配置：写入批尺寸、等待开关、计数精确开关收敛到连接配置，默认保证正确性，大集合可放宽计数精度。验收为默认行为不变，大集合有降本开关。

### 第三阶段：最小运维集

- 索引随集合创建：确保集合成功后幂等创建命名空间、来源、业务标识的关键词索引；数值过滤常用字段按需创建整数索引，已存在不报错。验收为过滤查询不再全扫描且重复确保无错。
- 集合生命周期补最小集：契约新增删除集合，三后端各自实现；集合信息、列表、健康检查作为 Qdrant 专有扩展而不进契约。验收为测试与运维可清理集合，日常检索仍只依赖契约。
- 配置补齐：拆分请求超时与连接超时，支持自定义请求头，文档写明 REST 端口与官方 gRPC 端口的区别、要求的服务端版本范围。验收为地址与端口配错时报错可读。
- 健康与版本：新增健康检查方法，构建后可按需校验连通性；版本不兼容只告警不阻断，规则沿用官方主版本一致且次版本差不超过一。验收为版本漂移可见。
- 错误细分与重试：参数错误映射为非法输入，限流与服务端瞬错映射为传输错误并触发有界重试，只对幂等读操作自动重试，写操作仅在明确可重试时重试。验收为瞬错可恢复且不产生重复写。
- 可观测性：每个操作记录链路与延迟，日志只记集合、数量与过滤形状，不倾倒载荷与向量。验收为排障可定位到操作与集合。

### 第四阶段：契约演进预案

- 检索参数只加可选字段：如需暴露近似参数则新增可选的召回整定与精确开关，默认保持现有行为；不引入后端逃生舱。验收为旧配置反序列化不变。
- 滚动列举按需新增：仅当管线需要扫描或维护需要分页时再加滚动接口，在此之前取数接口保持不变。验收为新增调用方明确。
- 以下能力本轮不做，触发条件写入文档：稀疏与多向量、命名向量、预取融合、排序与推荐发现输入、分组、载荷局部更新、快照、分片与别名、gRPC 后端。触发条件为混合稀疏需求、分布式运维需求或压测证明 REST 为瓶颈。

### 测试与文档

- 新增三后端对等用例：同语料同查询比较排序与过滤，不比较分数绝对值；覆盖命名空间、来源、通用字段、结构化条件、阈值与上限、取数顺序、删除口径、计数。
- 新增中文与数值字段用例：锁定文本表示一致性；新增欧几里得阈值用例。
- 文档补齐：端口、版本、索引、标识映射、等待语义、非原子窗口消除情况、计数口径、重试边界。验收为新接入者只读文档即可正确部署。

## 回归约束

改动只修改原模块，不新增替代模块；新增依赖在中央依赖表声明。日志与错误信息英文，注释只描述意图。无旧数据兼容，不更新版本号。每步通过受影响包的编译检查与单测，编译输出先重定向到文件再阅读，集中为最少次数的验证。
