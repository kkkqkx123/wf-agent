# 回滚场景划分与统一性分析

## 一、现有四套逻辑

### 1. 工作区物化：把某次提交写回磁盘

包含只读投影与写回两类。只读投影用于预览与查询，写回用于真正恢复工作区。典型场景是用户想回到某次文件快照、按范围恢复部分目录、按文件清单精确恢复、跟随状态检查点联动恢复文件。底层共享同一物化核心，具备幂等跳过、越界拒绝、保护路径豁免、嵌套仓库与超大文件豁免、失败策略分级等能力。

该层从不改写提交历史，只动工作区文件，是最常用的恢复手段。

### 2. 编辑指针移动：本地撤销与重做

作用域限定在单个执行者的编辑线，不触碰评审、特性与主线引用。场景是智能体写错一步、用户想撤销一次分组编辑、重做刚撤销的内容。实现方式是移动编辑引用指针并维护重做栈，附带并发写入重试。分组回滚要求目标分组位于指针头部，否则拒绝。

该层只动指针，不动工作区文件，与工作区物化正交。

### 3. 分支历史追加：评审合并与特性回滚

作用域在评审引用、特性引用与主线引用之间。场景包括提交评审、批准合并入特性、多特性合入主线、解决冲突、驳回评审、回滚某个已合入主线的特性。合并采用三路合并，冲突时将带标记的内容提交到特性引用并阻塞主线合入，解决后追加解决提交。回滚已合特性采用逆向合并追加恢复提交，主线指针只前进不后退。

该层只动提交历史，不直接决定工作区内容，冲突标记写回工作区仅为辅助展示。

### 4. 状态恢复：执行状态与子层级恢复

作用域在智能体循环与工作流执行状态。场景是执行中断后从某检查点继续运行，需要加载并迁移检查点数据，再按父子关系发现并恢复子执行。文件侧通过状态与文件提交的关联键联动，缺失关联时显式返回空而非猜测。

该层恢复的是内存中的执行状态，与文件工作区恢复通过关联键衔接。

### 5. 附带的数据交换能力

另有导出导入与基线同步能力，用于外部改动进入检查点体系或检查点内容写出。这类能力不是回滚，但在恢复后常被连用，划分时应明确其非回滚属性，避免与恢复入口混淆。

## 二、各场景对照

* 回到某次文件快照并继续改：使用工作区物化。
* 只撤销最近一次本地写入且保留历史可重做：使用编辑指针移动。
* 评审写错想整体作废：使用驳回评审。
* 合并冲突想人工介入：使用冲突解决。
* 某特性合入主线后发现有问题：使用分支历史追加式回滚。
* 执行崩溃后从断点继续：使用状态恢复，必要时联动文件物化。

## 三、是否应该统一

不应统一为单一入口，理由是三者互斥维度不同：作用对象不同（工作区文件、引用指针、提交历史、执行状态），可逆性不同（物化可重复执行，指针移动可重做，历史追加不可删除只能再追加），并发语义不同（物化以文件失败策略为准，指针移动以引用比较交换为准，历史合并以三路合并为准）。

但应统一三件事：

1. 统一底层执行器：工作区写入只走物化核心，历史合并只走三路合并核心，避免各入口自带一套删除与豁免规则。
2. 统一两阶段协议：凡是写工作区的恢复都应具备预览与执行两阶段，且预览与执行看到的目标集合一致。
3. 统一命名：恢复仅指工作区写入，撤销仅指编辑指针移动，恢复提交仅指历史追加。现有命名混用是主要混乱来源，应先改名再谈重构。
