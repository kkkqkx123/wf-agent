# IDE 页面布局改造方案：终端懒加载、初始尺寸与三区可调

## 背景与问题

IDE 页面当前有三个布局问题：

1. 终端初始占用过高，进入页面即压窄编辑器，观感上终端过大。
2. 终端默认打开，进入 IDE 页面即挂载终端并触发会话对账与新建，导致不必要地建立连接并创建服务端会话，与常见编辑器手动打开面板的预期不符。
3. 文件树、历史侧栏、终端均不可自由调节，终端虽有高度手柄但能力单一，两个侧栏宽度写死，整体不满足常见布局预期。

本方案只改原有模块，不新增替代模块，不新增后端接口，文案优先复用现有键。

## 现状分析

状态默认值方面，IDE 存储中终端打开态默认为开，且不做持久化，每次进入页面都是打开。侧栏开关与历史开关做了会话持久化，终端开关没有，行为不一致。

挂载链路方面，IDE 页面在打开态下挂载嵌入式终端面板，面板再以打开态挂载通用终端面板。通用终端面板在打开后先做服务端对账，空会话时直接新建并聚焦，于是进入页面即产生连接与新建会话。面板关闭时本地会话与滚动回放保留在以仓库为键的注册表中，重开可恢复，这是懒加载改造可以依赖的基础。

尺寸方面，嵌入式终端面板的标称高度为固定值，最大化为另一个固定值。但通用终端面板是带标题、描述、会话标签行、底部分隔与按钮行的完整卡片，嵌入到 IDE 时这些 chrome 全部计入高度，实际占用远大于标称高度。固定最大化高度在小视口下会吞掉编辑器，在大视口下又不够大。

可调性方面，左右侧栏宽度写死为固定档，终端高度是唯一可调量，且手柄只支持纵向。通用分栏视图另有一套横向拖拽逻辑，仅用于检查器，与 IDE 侧栏不通用。宽度与高度的持久化分散在会话存储与偏好存储中，没有统一的 IDE 布局持久化位置。

## 目标

进入 IDE 页面默认只看到文件树与编辑器，终端不挂载、不连接、不新建会话，用户通过按钮或快捷键手动打开。

终端打开后的默认高度回到常见编辑器下方面板的比例，不过度挤压编辑器，最大化改为视口比例而非固定像素。

文件树宽度、历史宽度、终端高度均可拖拽调节，带合理上下限、键盘操作与会话持久化，移动端保持现有抽屉式覆盖层不变。

非目标：不做浮动面板，不做终端分屏，不动独立终端页与 Git 页，不改服务端会话接口。

## 设计

### 终端默认关闭与懒挂载

将终端打开态默认值改为关，并与侧栏、历史开关一样做会话级持久化。页面仅在打开态下挂载嵌入式终端面板，面板仅在打开态下挂载通用终端面板。未打开时不做对账、不新建、不连接。

关闭面板保留本地会话注册表与滚动回放，重开时走已有恢复链路：有本地会话则对账后按需重连，无本地会话则按当前面板视口尺寸新建。文件树右键菜单中的在终端中打开统一走先置打开态再按目录新建的入口，避免后台静默建会话。

打开后聚焦终端，关闭后将焦点还给编辑器，保持现有快捷键在终端聚焦时不被 IDE 动作吞键的行为。

### 初始尺寸收敛

嵌入式终端改用紧凑形态，不复用完整卡片的标题、描述与底部按钮行。会话标签、新建、最大化、关闭收敛到面板顶部的单行工具条，视口区占满剩余高度。标称默认高度下调到常见下方面板档，最大化改为容器或视口的比例并设上下限，普通高度的上限也随视口收敛，避免固定大高度在小屏下溢出。

服务端尺寸通告保持由终端视图的实测尺寸驱动，尺寸变化仍走现有防抖同步，拖拽过程中暂停频繁通告、松手后做一次适配即可。

### 三区可调布局

左侧文件树、右侧历史、底部终端统一为可调窗格。文件树与历史为横向拖拽，终端为纵向拖拽。拖拽采用指针捕获的增量模式，双击回到默认值，方向键支持步进微调，聚焦手柄可通过键盘操作。

宽度与高度均设最小值、最大值与默认值。侧栏建议最小值保证可读，最大值防止吞掉编辑器，拖到极限附近可选用折叠而非无穷压缩。终端建议最小值保证一两行可见，最大值不超过容器的大半。所有尺寸做钳制，非法持久化值回退到默认值，无需兼容旧值。

拖拽手柄复用现有纵向手柄并扩展出横向能力，或将分栏视图中的横向逻辑收敛为同一手柄，避免两套拖拽实现长期并存。移动端窄视口保持现有覆盖层，不启用拖拽。

持久化放在 IDE 存储的会话键空间下，与现有终端高度、最大化、侧栏开关同位置。跨设备偏好不进入服务端偏好文档，保持会话级即可。

### 文案与快捷键

复用现有显示、隐藏、最大化、恢复、调节等文案。新增文案仅限于宽度调节提示与重置提示，且中英同步。现有切换侧栏、切换终端、切换历史的快捷键保持不变，打开终端的命令面板入口保持不变。

## 改动清单

IDE 存储负责打开态默认值、会话持久化、新增两侧宽度与终端高度上下限、钳制与重置。

IDE 页面负责三区弹性布局、按打开态条件挂载终端、接入横向与纵向手柄、移动端覆盖层保持不变。

嵌入式终端面板负责紧凑工具条、移除多余卡片 chrome、按新默认值与比例最大化计算高度、只在打开时挂载通用终端面板。

通用终端面板负责支持紧凑嵌入模式，完整卡片形态留给独立终端页使用，打开态门控与对账新建逻辑保持不变。

文件树负责移除写死宽度依赖，由父容器传入宽度，打开终端入口统一走先开面板再建会话。

通用分隔手柄负责同时支持横向与纵向，保留键盘操作与禁用态，拖拽态样式保持现有风格。

消息文件仅在确需新增宽度提示时补充，保持现有键不动。

## 验收

首次进入 IDE 页面终端不可见，网络面板无会话相关请求，编辑器获得主要高度。

手动打开终端后出现合理高度的下方面板，新建一个会话，关闭再打开后会话与滚动回放仍在。

拖拽文件树右边界可改宽度，拖拽历史左边界可改宽度，拖拽终端顶边可改高度，刷新后尺寸保持，双击回到默认，键盘可微调。

窄视口下侧栏仍为覆盖层，拖拽手柄不出现，现有快捷键在终端聚焦时不吞键。

## 风险

紧凑终端去掉卡片标题后，独立终端页不受影响，需保证两种形态共用同一会话注册表但互不串扰。

高度上限改为视口相关后，需在窗口缩放时重新钳制，避免持久化的大高度在小窗口下溢出。

拖拽与终端自适应同时触发时可能产生尺寸回写抖动，通过拖拽中暂停通告、松手后单次适配规避。
