# Terraform 参考与本项目落地对照

本文沉淀插件版本管理参考 Terraform Plugin Protocol 的 durable 内容：先整理 Terraform 的设计思想，再逐项说明本项目参考与落地情况。过程性讨论见计划目录历史归档，本文只保留结论。

## Terraform 的设计思想

### 版本分层

协议版本分两层。主版本编码进接口包名，不兼容变更必须创建新包名，单个插件进程可同时导出多个主版本的服务；次版本不体现在线上协议中，仅作为沟通工具，兼容性通过特性探测（可选字段加默认行为）实现。该分层的收益是编译期即可发现不兼容，运行时再从双方都支持的主版本中选择。

### 运行时握手协商

宿主启动插件子进程并监听其标准输出，插件输出一行握手信息，包含服务端口与协议版本列表；宿主连接服务端口并发送握手请求，包含自身支持的协议主版本列表；插件选择双方都支持的最高主版本并返回确认，后续调用全部使用协商确定的版本。核心理念是双方各自声明支持范围，运行时取交集，而非由一方单独判定。

### 版本约束语法

约束使用版本解析库处理，支持悲观约束（等价于下闭上开区间）与逗号分隔的多约束组合，错误信息包含可兼容版本号的具体建议。

### 多版本共存

单个插件二进制可同时注册新旧两代协议服务，宿主按协商结果连接对应服务。新旧宿主因此可共用同一个插件二进制，无需维护多个构建产物，升级与回滚有载体基础。

### 全局约束聚合

各子模块的版本约束递归汇入根模块统一检测，跨插件的约束冲突在启动阶段暴露，而非运行期逐个暴露。

## 本项目的落地对照

| Terraform 思想 | 本项目落地 |
|---|---|
| 主版本编码进包名 | 接口世界包名携带主版本，破坏性变更必须新开主版本世界；接口常量与主版本一一对应，组件绑定在编译期即可发现不一致 |
| 次版本只做沟通、兼容靠特性探测 | 门控只比较主版本号段；未知声明字段忽略，新宿主兼容旧访客的声明 |
| 双方声明取交集的握手 | 原生与 wasm 核心模块路径在加载时交换支持的主版本数组，选最高公共版本；缺失声明、空列表、无交集均加载失败，错误同时列出双方范围并给出升级建议 |
| 单二进制多版本共存 | 清单支持按主版本声明多个入口产物，原生单库通过声明多版本实现共存；包管理仍以插件标识为唯一键 |
| 约束全局聚合 | 依赖解析构建全局约束表，同一依赖的多个必选约束在启动期统一检测，冲突信息列出各自来源与声明；缺失依赖的错误逐项列出引用方，互斥时附加说明 |
| 错误携带修复建议 | 握手失败、世界主版本失配、入口与导出不一致、依赖失配、全局冲突、缺失依赖统一包含双方值与修复建议 |

## 有意不照搬的内容

- 子进程加标准输出加远程调用的握手形态：本项目插件以内嵌方式运行在宿主进程内，无子进程边界，握手简化为加载时的版本数组交换与世界主版本门控。
- 旧插件回退路径：原方案曾设想缺失声明视为仅支持首个版本并保留旧版本字段做兼容检查，现已删除，不保留任何回退分支，未实现握手的插件一律加载失败。
- 宽松继续开关：原方案曾设想约束冲突可降级为警告继续，现不引入，必选冲突必须失败即停，仅可选依赖记告警。
- 版本求解器：只做冲突检测，不做版本选择与自动升级；互斥判断采用候选版本探测，不实现完整求解。
- 次版本机制：当前仅有一个主版本，开发阶段版本号保持为一，不引入次版本分支。
