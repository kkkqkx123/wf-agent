# IDE 终端面板与独立终端页的会话共用与管理设计

本文回答四个问题：两处是否可以共用 PTY 会话；detach 到底是相对哪一层的语义，两处应该是同步显示还是另设状态；是否需要 pending 与 idle 状态以及命名规则；前端批量快捷操作如何设计。本文不涉及后端批量接口。全文为自然语言设计说明，不含完整代码。

## 现状梳理

后端 PTY 会话是全局的。创建、查询、改名、改尺寸、删除、附着都以会话标识为键，后端不感知仓库，也不感知哪个前端页面在看。仓库键只是前端持久化分组。前端按仓库根取会话库，同仓库键在单次页面生命期内拿到同一个库对象。布局层挂有一个无头保活，按固定周期为没有可见视图的存活会话保持连接，只推进游标与接收退出，不做渲染。有可见视图时无头连接让路，视图卸载后自动接回。模块级视图注册表保证同一会话同一时刻只有一个有效视图持有套接字，后挂载接管先挂载。

当前 detach 是前端视图隐藏，不是后端状态。后端只有运行与已退出两种状态，前端会话库在运行与已退出之外，另有一套按库保存的隐藏集合，以及连接相位与删除墓碑。隐藏集合随持久化保存，面板只渲染未隐藏的页签。接入对话框列出本库已隐藏的会话，以及其他仓库库中的会话。跨库接管通过迁出与迁入实现，服务端进程不受影响，只搬运本地记录。关闭则结束服务端进程并删除本地记录，运行中的会话关闭前需要二次确认，隐藏不需要确认。

标题的流动目前是单向的。新建时前端按编号生成默认标题并随创建请求发给后端，重命名走更新接口同步到后端，后端存什么标题，前端就显示什么标题。终端进程自己通过转义序列改标题的能力没有接进来，手动命名与自动标题没有区分。

## 共用结论：可以共用，且已经在共用

只要两处传入的仓库键相同，它们拿到的是同一个前端会话库，看到的是同一组会话。后端会话本来就是全局唯一的，跨库接管也只是本地记录搬家，不复制进程。所以问题不是能不能共用，而是共用之后的两处显示关系与隐藏语义如何定义。

需要明确一个容易误解的点。当前隐藏集合是按库保存的，不是按面板保存的。同库的两处看到的隐藏集合是同一份，一处隐藏，另一处同样看不到该页签。所谓相对当前页面的 detach，在实现上其实是相对当前库的隐藏。接入对话框里其他仓库分组的本质是跨库可见性，而不是跨页可见性。

## detach 语义的两种理解与取舍

第一种理解是 detach 相对整个前端。隐藏即全局隐藏，所有面板都不再显示该页签，进程在后台继续跑，无头保活继续推进游标。这正是当前同库行为的自然延伸，语义简单，与后端无差别的状态也是一致的。缺点是用户在终端页隐藏了一个会话，切到 IDE 面板也找不到它，容易误以为会话丢了。

第二种理解是 detach 相对当前面板。每个面板各持一份隐藏集合，IDE 面板隐藏的不影响终端页显示。这更符合用户字面提问中的相对当前页预期，但代价很大。同一会话要在两处同时有不同的可见状态，页签顺序、活动选中、持久化都要按面板拆分，视图注册表的单套接字假设也要重新处理双视图同时可见的竞争，得不偿失。

建议采用第一种理解并配一个管理入口来弥补可发现性。语义上明确隐藏是全局的，两处默认同步显示同一组可见页签；体验上把现有的接入对话框升级为会话管理器，让用户在任何一处都能看到全部会话，包括已隐藏的、已退出的、其他仓库的。隐藏动作改称为隐藏或转入后台，关闭动作保持结束进程不变。这样后端实际状态没有差别的问题就不再是问题，因为前端不再假装隐藏是状态，而是诚实地把它表达为全局视图过滤。

需要同步调整的细节有三处。隐藏集合的说明文案要从本面板已藏改为在全部面板隐藏，避免用户期待相对当前页的行为。空态要区分三类：从未建过、全部已关闭、全部已隐藏，每类给出不同的主按钮。跨库接管保留，但入口收敛到管理器中的其他仓库分组，接管后原库记录迁出，新库记录迁入并选中。

## 同步显示规则

同库的两处显示同一组可见页签，同一活动选中。当前已经是这样，建议保持并写进约定：选中切换在一处发生，另一处跟随；新建会话在两处同时出现并成为活动页签；关闭会话在两处同时消失；隐藏会话在两处同时消失但保留在管理器中；已退出会话保留页签与回显，直到用户关闭或重拉。

跨库的会话不自动同步，只在管理器中可见。用户显式接管后才进入当前库。这样 IDE 根与终端页根不一致时，两处天然是两组会话，不会互相干扰；根一致时，两处天然是同一组会话，不需要额外同步逻辑。

双挂载的竞争沿用现有规则。后挂载的视图接管套接字，先挂载的视图停止读写，无头保活在有视图时一律让路。IDE 面板隐藏时保持挂载的策略不变，保证切换显隐不重建视图。

## 状态模型：补充忙闲，不引入新后端终态

后端保持运行与已退出两个终态不变。前端在运行之下区分忙碌与空闲，用于检索与排序，不作为后端状态机的一部分。忙碌的含义是最近有输入或有输出，空闲的含义是长时间无输入无输出。判断依据是本地记录的最后输入时间与最后输出时间，加上后端附着时可得的游标推进情况。阈值取数十秒量级，忙碌转空闲需要连续无活动达到阈值，空闲转忙碌由任何一次输入输出立即触发。

之所以不把忙碌做成后端状态，是因为真正的命令执行中与空闲提示符在 PTY 字节流层面无法可靠区分。可靠的做法是 Shell 集成扩展，由 Shell 在命令开始与结束时发送专用转义序列，前端据此置位。该能力建议作为远期可选增强，首期只做基于活动时间的忙闲推导，并在界面上明确标注为空闲推测而非精确执行状态，避免用户把它当作任务完成信号。

已退出的语义保持不变。退出保留回显，页签标注已退出，支持重拉新会话继承原标题与来源。缺失指服务端已没有该会话，当前对账逻辑按有无本地回显分别处理为标死或丢弃，建议保留。连接相位继续由会话库持有，视图只上报套接字事件，不自行决定下一相位，失败横幅改读库相位。

建议后端在查询与列表视图中补齐创建时刻与最后活动时刻，前端据此做最近活跃排序与空闲时长展示。无头保活的触碰行为与服务端闲置回收的互动要写进约定：无头连接的存在意味着会话被视为有人关注，不应被闲置回收误杀；超过较长的无人查看期限后，无头连接主动让路，使服务端回收能够生效。

## 命名规则：手动优先，自动次之，默认兜底

标题分三层。手动标题优先级最高，由用户双击重命名产生，同步到后端并持久化。自动标题次之，来自终端进程自己发送的标题转义序列。默认标题兜底，由前端按编号或来源命令生成。规则是自动标题只在没有手动标题时生效，一旦用户手动命名过，该会话不再接受自动覆盖，除非用户清除手动命名。

为实现该规则，前端需要在本地记录中区分手动命名标记，持久化时一并保存。后端是否需要区分标题来源可以二选一。简单做法是后端只存最终标题，前端用本地标记决定是否上报自动标题；严格做法是后端增加标题来源字段，更新接口接受来源参数，手动来源覆盖自动来源，自动来源不覆盖手动来源。建议首期用前端标记实现，后续如需多端同步再把来源字段做到后端。

自动标题的采集通过终端组件的标题事件接进来，收到后做去首尾空格与限长，超长截断，空标题丢弃。采集到自动标题后按手动优先规则决定是否更新本地并同步后端。检索时同时匹配手动标题、自动标题、来源命令与工作目录，排序上手动命名的会话优先。

分类标签建议首期只做前端派生，不做后端字段。按来源命令与工作目录派生常见分类，例如服务日志、迁移 Shell、构建任务，用户可改名表达意图。独立的后端分类字段等检索量上来后再评估。

## 批量快捷操作：只做前端，不做后端批量接口

批量操作定位为前端快捷操作，不新增后端批量接口。典型场景是联调时开出大量终端，任务结束后一次性收尾，例如前后端加外部监控联调结束后，把相关的监听服务终端一起关闭。这类收尾动作的语义就是对当前可见集合逐个执行已有的隐藏、显示、关闭、重拉，不需要后端引入新的批量语义。

过滤条件全部在前端执行。搜索框匹配标题、命令与目录，状态筛选项至少有全部、可见、后台、已退出，仓库维度沿用现有多库结构，默认展示当前库的全部会话并汇总其他仓库计数，排序默认按最近活跃。隐藏条件天然是前端私有的，后端本来就不知道隐藏，所以关闭所有已隐藏这类动作只能是前端批量，这也反过来说明不需要后端批量接口。

按类别一键关闭不再作为主要手段。管理器提供多选，多选即代替按类别关闭：用户勾选若干行后通过底部批量条统一显示、隐藏或关闭。唯一保留的一键操作是一键关闭已退出会话，因为已退出会话的收尾是最高频且无风险的动作。关闭所有已隐藏与关闭全部会话同样通过全选加批量关闭完成，不再各设一个独立按钮，避免按钮膨胀。

执行方式是循环调用现有单会话接口。限制并发数，逐个收集成功与失败并汇总提示，失败的会话保留在列表中并保持勾选，成功的行就地从列表中消失或更新状态。删除墓碑机制保证循环中的迟到写不会复活已删会话。运行中会话的关闭确认在批量中只弹一次，确认后对所选全部生效，已退出的不参与确认。

## 管理器入口与交互：对话框常驻，多选为默认操作方式

现有页签栏右侧的接入按钮升级为会话管理入口，计数徽标从可接入数改为后台加已退出的总数。管理器对话框分三个区块：当前可见、后台运行、已退出，其他仓库收拢为可折叠分组。每行展示标题、状态、来源摘要与空闲时长，已退出的行提供重拉与关闭，运行中的行提供显示、隐藏与关闭。搜索框与状态筛选置于顶部，空结果给出明确文案。

对话框的核心交互准则是常驻。单行的显示、隐藏、关闭、重拉都不关闭对话框，操作结果就地反映在行上：显示的行移到可见分组，隐藏的行移到后台分组，关闭的行直接消失并顺延选中，重拉的行更新为运行态。对话框只在用户点击关闭按钮、点击遮罩或按下退出键时关闭。当前每操作一步就退出的做法必须改掉，否则连续处理多个会话时过于繁琐。

多选是默认操作方式。每行提供勾选框，支持全选与按当前过滤结果全选，底部常驻批量条，提供显示所选、隐藏所选、关闭所选，以及一键关闭已退出。批量条展示已选项数量，操作完成后保留对话框并保留未处理完的勾选，全部成功则清空勾选。单行操作保留，作为只处理一个会话时的捷径，但不再是唯一路径。

文案上统一用语。隐藏表示在全部面板隐藏但进程继续运行，关闭表示结束进程，显示表示重新在当前库页签栏中展示。原有的 detach 与 attach 字样在中文界面中替换为更直白的说法，对外接口与事件名保持不变以免波及面扩大。

## 实施顺序与验证

建议分两个阶段，全部是前端。第一阶段明确隐藏的全局语义与文案，接入对话框升级为常驻管理器，补齐空态区分、搜索过滤、多选批量循环调用现有接口、一键关闭已退出，补齐手动标题标记与自动标题采集，批量确认框与失败保留勾选一并做掉。第二阶段补后端查询视图的创建时刻与最后活动时刻，以及列表排序与标题来源字段。不再设后端批量接口阶段。

验证上，前端补单测覆盖同库两处同步显示、隐藏全局生效、对话框操作后常驻、管理器多选批量关闭与显示、失败保留勾选、一键关闭已退出、手动命名不被自动覆盖、损坏持久化载荷不影响全表。后端补单测覆盖列表视图字段与标题来源覆盖规则。路由切换与显隐切换做手工验证，确认无头保活交接正常，回挂后只重放小增量。
