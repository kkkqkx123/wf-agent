# 维度二：工作流可视化编辑（Workflow Visual Editing）

> 关注点：用户在画布上**搭建/修改**工作流的能力——节点与连线的增删、手柄映射、节点创建器、连线编辑、协作与 AI 辅助。

---

## 1. Dify 的可视化编辑

Dify 的编辑体验围绕 `reactflow` 封装，**低概念开销**：少量自定义节点类型 + 单一自定义边 + 顶部悬浮工具栏。

### 1.1 画布主体与节点/边注册

`web/app/components/workflow/index.tsx`：

- **节点类型映射**（`:111-118`）：`CUSTOM_NODE`→`CustomNode`、`CUSTOM_NOTE_NODE`、`CUSTOM_SIMPLE_NODE`、`CUSTOM_ITERATION_START_NODE`、`CUSTOM_LOOP_START_NODE`、`CUSTOM_DATA_SOURCE_EMPTY_NODE`。
- **边类型映射**（`:119-121`）：仅 `CUSTOM_EDGE`→`CustomEdge`。
- 引入 `reactflow/dist/style.css` + 自定义 `./style.css`（`:108-109`），并挂载协作管理器、评论管理器、候选节点、辅助线、节点键盘交互等（`index.tsx:59-76`）。

### 1.2 自定义边编辑

`custom-edge.tsx`：

- 贝塞尔路径：`getBezierPath({ curvature: 0.16 })`（`:30-38`，源右侧→目标左侧）。
- **边中点插入节点**：`EdgeLabelRenderer` 内嵌 `BlockSelector`，hover/聚焦时显形（`:131-161`），调用 `handleNodeAdd` 在前驱/后继之间插节点；可用块由 `intersection(availablePrevBlocks, availableNextBlocks)` 求交（`:158`）。
- 临时边虚线：`strokeDasharray: '8 8'`（`:127`）。
- 失败分支手柄：`ErrorHandleTypeEnum.failBranch` 影响着色（`:98`）。

### 1.3 基础节点

`nodes/_base/node.tsx`（298 行）：`BaseNode` 通过 `getNodeStatusBorders(data._runningStatus, …)`（`:34,132`）绘制状态边框，并承载循环索引文本、协作在线状态、插件安装态等。`nodes/_base/components/` 下还有 `add-button`、`add-variable-popup`、`editor/code-editor` 等编辑辅助组件。

### 1.4 顶部悬浮工具栏（模式切换）

`header/index.tsx`：头部以**绝对定位覆盖在画布之上**（`:28` `absolute top-7 left-0 z-10 … bg-mask-top2bottom-gray-50-to-transparent px-3`），通过 `useWorkflowMode()` 在 `normal` / `restoring`（恢复历史版本）/ `viewHistory` 三种模式间切换（`:25-31`）。各子头组件按需 `dynamic()` 懒加载（`:8-13`）。

### 1.5 协作与评论

画布内集成 `collaborationManager`、`UserCursors`、`CommentManager` 及评论图标/输入/线程组件（`index.tsx:60-67`），支持多人同编与画布批注。

> **小结**：Dify 以"reactflow + 少量自定义类型 + 悬浮工具条 + 协作层"实现轻量但完整的编辑闭环，概念模型贴近"节点-连线-运行"的 AI 工作流语义。

## 2. n8n 的可视化编辑

n8n 的编辑能力是**分层、组合式、强类型**的：画布宿主（Canvas/VueFlow）→ 容器映射（WorkflowCanvas）→ 节点/边渲染组件 → 句柄 → 节点创建器，并有 AI Builder、分组、上下文菜单等增强。

### 2.1 画布宿主

`features/workflows/canvas/components/Canvas.vue`：核心 `<VueFlow>`，含庞大的 `defineEmits` 事件映射（创建/删除/运行节点、连线、视口变化等），并挂载 `MiniMap`、`CanvasBackground`、`Edge`、`Node`、选择工具条与 AI 集成。

### 2.2 容器与数据映射

`WorkflowCanvas.vue`：

- 将 `workflowDocumentStore.value.allNodes` / `connectionsBySourceNode`（`:98-103`）经 `useCanvasMapping` 映射为 VueFlow 节点/连线（`:136-149`）。
- **执行中节流**：`executing` 时用 `throttledRef` 限频更新（`:228-229`），避免高频重绘。
- **分组视图**：`nodeGroupView` 支持折叠/展开，`groupExpansionMode` 可为 `all` / `errored`（`:151-172`），分组态用 `mappedGroupVueFlowNodes` 渲染（`:191-206`）。
- 画布背景条纹：`--canvas--color--background`（`:341`）；`provide(NodeGroupViewKey, …)` 向子树注入分组状态（`:208-215`）。

### 2.3 节点与手柄映射

`CanvasNode.vue`：

- **输入/输出手柄方位**：主输入 `Left`、非主输入 `Bottom`、主输出 `Right`、非主输出 `Top`，由 `createEndpointMappingFn`（`:174-247`）按 `CanvasConnectionMode.Input/Output` 生成；偏移按端点数量百分比或网格计算（`:204-211`）。
- **渲染类型**：`renderType` 为 `Default / StickyNote / AddNodes / ChoicePrompt`（`:120`，`CanvasNodeRenderType`）；`AddNodes`/`ChoicePrompt` 无工具条（`:334-337`）。
- **事件**：`add / delete / run / select / toggle / activate / replace:node / add:ai` 等（`:58-75`），经 `CanvasHandleRenderer` 渲染手柄。
- **工具条 hover 显形**：SCSS 中 `:hover:not(:has(> .trigger:hover))`、`:focus-within`、`.showToolbar` 时工具条项 `opacity: 1`（`:466-489`）。

### 2.4 边的编辑

`CanvasEdge.vue`：

- 多段 `BaseEdge` 渲染（`:163-172`）；非主连接虚线（`:67-70`）。
- **hover 延迟**：`delayedHovered` 用 600ms 延时退隐（`:42-59`），避免快速划过时工具条闪烁。
- **边工具条**：hover 且在非只读时显示 `CanvasEdgeToolbar`，提供 add/delete（`:61,136-142,186-193`）。
- 着色：success→`--color--success`、pinned→`--color--secondary`（`:110-117`）。

### 2.5 节点创建器与交互编排

`NodeView.vue`（约 2000 行，编辑器主编排组件）：

- **节点创建**：`LazyNodeCreation` 懒加载 `NodeCreation`（`NodeView.vue:167-169`）；`onAddNodesAndConnections`（`:1024-1055`）支持拖拽（`onDragAndDrop` `:1769`）、连线末端打开创建器（`onCreateConnectionCancelled` `:892-918`）、替换节点（`onClickReplaceNode` `:1207-1246`）。
- **撤销/重做**：经 `historyBus` 与 `historyStore` 绑定（`:1586-1612`）。
- **AI Builder**：`builderStore.streaming` 期间将画布置只读并注入 fallback 节点（`AddNodes` / `ChoicePrompt`）（`:1911-1924`）。
- **权限/只读**：`isCanvasReadOnly` 综合演示路由、分支只读、协作只读、归档、AI 流式等（`:335-345`）。

### 2.6 连线模式与类型

`canvas.types.ts` 定义 `CanvasConnectionMode`（Input/Output）与 `NodeConnectionTypes`（Main、AiTool 等），手柄字符串经 `createCanvasConnectionHandleString` / `parseCanvasConnectionHandleString` 编解码（`CanvasNode.vue:193, NodeView.vue:1013`）。

> **小结**：n8n 把编辑拆成"宿主→容器→节点/边→手柄→创建器"的细粒度组合，配合 composables（`useCanvas`、`useCanvasMapping`、`useCanvasNode`）、Pinia store 与 `provide/inject`，可扩展性极强，适合承载数百种节点类型与复杂连接语义。

## 3. 横向对比

| 对比项 | Dify | n8n |
| --- | --- | --- |
| 画布引擎 | `reactflow`（React） | `@vue-flow/core`（Vue） |
| 节点类型 | 6 种自定义类型，概念精简 | `Default/StickyNote/AddNodes/ChoicePrompt` 渲染类型 + 数百业务节点 |
| 边编辑 | 单 `CustomEdge` + 中点插入 `BlockSelector` | `CanvasEdge` + hover 工具条 + 多段 + 类型化手柄 |
| 手柄方位 | 右出→左入（主），失败分支独立 | 主入 Left/主出 Right，非主入 Bottom/非主出 Top |
| 创建节点 | 画布 + 顶部工具条触发 | 节点创建器（NodeCreator）+ 拖拽 + 连线末端 + 替换 |
| 增强能力 | 协作光标、评论、版本恢复 | 分组折叠、上下文菜单、AI Builder、撤销重做、权限只读 |
| 状态管理 | Zustand | Pinia + composables + inject/provide |
| 节流/性能 | 依赖 reactflow 内置 | 显式 `throttledRef`、执行态限频 |

---

## 4. 设计启示

- **概念数量 vs 可扩展性**：Dify 用"少类型 + 语义化节点"降低认知负荷，适合固定范式的 AI 工作流；n8n 用"渲染类型 + 业务节点库 + 组合式组件"换取无限扩展，适合通用集成平台。
- **手柄方位编码连接语义**：n8n 用方位区分主/非主连接（Top/Bottom 表达 AI 分支等），比 Dify 的单主通道 + 失败分支更显式，值得在复杂连接场景借鉴。
- **AI 辅助已成标配**：两者都内置 AI 创建/Builder（Dify 偏追踪解释，n8n 偏节点生成），且都在 AI 流式期间对画布施加只读/半只读约束。
