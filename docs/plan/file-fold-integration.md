# 文件折叠独立任务方案

从压缩回退遗留项中抽取。文件内容折叠不再混合在剩余任务中，作为独立任务落地。解析引擎侧的服务设计见其 `docs/plan` 下的折叠服务设计与改造方案，本文只描述本项目侧的集成。

## 1. 目标

读文件类工具结果是大 token 消耗源。把文件内容折叠为符号骨架后写回，token 大幅下降但保留结构信息。折叠是无语义的有损压缩，产物即使在 LLM 摘要失败时也可直接作为降级数组写回。工具调用轮次折叠已落地，本任务只补文件内容折叠一块。

## 2. 非目标与禁区

本项目不引入 tree-sitter 或任何原生解析依赖，不提供内置字符匹配，不提供行级启发式骨架提取。无语法支持、大文件超限、解析失败等情形一律不在本项目内做骨架推导，由服务端按其降级口径返回。

## 3. 服务门控

折叠是否执行完全以折叠服务是否存在为门控：服务已配置且可达，则对命中策略的工具结果发起折叠；服务不存在或调用超时失败，则跳过文件折叠步骤，直接走既有的工具轮次折叠与摘要链路。跳过时不产生折叠说明消息，不改变现有降级窗口语义。

## 4. 输入输出约定

折叠器输入为工具结果文本加语言标识，输出为折叠文本、一条折叠说明、折叠前后 token 估算。说明消息随折叠产物一起写回，使 LLM 可见边界。语言标识优先取工具结果自带元数据，缺失时按文件后缀推断；推断只决定透传给服务的线索，不在本项目内触发任何骨架提取。

## 5. 组合顺序与预算归属

同一降级窗口内先做文件内容折叠，再做工具轮次折叠，最后尝试摘要；摘要仍失败则写回折叠后上下文。折叠不新增 LLM 调用，耗时计入压缩链路预算并受已有嵌套超时告警约束。折叠说明消息计入预算内 token，不允许说明本身把窗口撑爆。折叠失败不触发错误分支路由。

## 6. 测试

服务存在时覆盖折叠接入与说明消息存在性；服务不存在时覆盖跳过行为与既有链路不变；超时失败覆盖跳过且无残留状态；压缩 e2e 增加“摘要失败但折叠产物写回”的用例，断言写回数组含折叠说明且无损关键锚点。

## 7. 落地顺序与验收

1. 折叠服务客户端与服务存在门控接入降级窗口。
2. 说明消息组装与写回，含预算内 token 约束。
3. 服务存在与不存在双态回归。

验收：服务存在时折叠前后 token 下降可观测；摘要失败时写回含折叠说明；服务不存在时行为与现状一致且现有测试全过；代码中无字符匹配或启发式骨架逻辑。
