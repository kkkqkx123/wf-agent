# 修改方案

分三个阶段推进，每阶段可独立交付。描述仅限定行为与边界，不涉及具体代码形状。

## 阶段一：概念收敛与安全补齐

目标是先止血，不动核心算法。

* 统一术语：工作区写入统称恢复，编辑指针移动统称撤销与重做，历史追加统称合并与恢复提交。旧名称保留为兼容别名并标记废弃。
* 收敛工作区恢复入口：保留全量、范围、选中三个写入口，其余收敛为参数组合，联动恢复明确为状态恢复的可选跟随步骤。
* 多特性合入增加预演模式：先逐个预测冲突再决定是否执行，默认保持现有顺序语义但要求调用方显式确认顺序。
* 统一恢复两阶段协议：所有工作区写入提供预览与执行，且两者目标集合一致，超大与嵌套等不透明项在预览中显式标出。
* 状态与文件无关联时由调用方显式选择：报错、中止或仅恢复状态，不允许静默缺席。

## 阶段二：合并与回滚语义加固

目标是消除半合状态与寻址脆弱。

* 多特性合入提供全有或全无选项：预演通过后一次性推进，失败时主线不动；保留现有逐个推进作为显式选择的非原子模式。
* 特性回滚改用吸收合并标识寻址：在合并时记录可稳定引用的合并标识，回滚按标识查找而非按精确提交匹配，找不到时给出明确的不可回滚原因。
* 分组回滚增加非头部处理策略：拒绝时返回当前头部位置与冲突原因，支持调用方选择重试或转人工。
* 冲突状态改由结构化元数据承载：提交信息中的标记仅作展示，是否未解决以元数据为准，解决时校验元数据而非重新解析文本。
* 主线与特性健康检查统一口径：阻塞判断与冲突列表使用同一来源。

## 阶段三：清理与体验优化

目标是长期可维护。

* 回收策略分级：区分指针可达、近期孤儿、基线锚点三类，明确各自保留时长与配额，并在管理面暴露水位。
* 清理结果可观测：回收数量与跳过原因进入事件通道，而非仅日志。
* 数据交换能力正名：导出导入与基线同步移出恢复命名空间，文档中明确其非回滚属性。
* 补充恢复演练：覆盖全量恢复、范围恢复、选中恢复、冲突后恢复、特性回滚、状态联动恢复六条主路径的验收标准。

## 不做事项

* 不合并四个层次为单一入口。
* 不引入变基改写历史，历史追加原则不变。
* 不改变主线只前进不后退的不变量。
