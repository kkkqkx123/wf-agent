# TUI 渲染对齐 jcode 的分阶段改造

> 依据：`docs/ref/jcode-tui/05-现状复核与可借鉴差异.md`。目标是把复核出的差异逐项落地：先修正确性，再补内容表现力、滚动体验、主题感知与观测，最后按需处理图表/图像。
>
> 约束：不改 reducer 与 markdown 的对外语义；不引入 GPU；保持现有 crate 分层、命名与文件扁平约定；不以"退化"作为过渡，直接实现目标能力。

## 阶段一：帧呈现正确性与同步输出（正确性优先）

目标：消除"仅动画帧/无变化帧把整屏清空"，让局部重绘真正可用；同时接通同步输出。

当前问题：应用层不持上一帧缓冲，依赖 ratatui 保留上一帧；而 ratatui 每次绘制会重置当前缓冲，导致只写动画单元格的帧把其余内容清空（空闲时也会因动画刻度变化触发）。

任务：

- 外壳自持"上一帧合成缓冲"（主题适配前的原始缓冲）。局部与无变化帧先以该缓冲播种，再只覆盖目标单元格；无法播种时（首帧、尺寸变化、无上一帧）自动升级为整帧。
- 统一帧范围的取值：合并"待处理的显式请求"与"当帧重新判定的范围"，绘制与播种共用同一取值，杜绝两处判定不一致。
- 主题适配保持"整帧执行一次"且位于播种之后，确保播种内容不会被二次适配（明暗翻转不可重入），使局部帧与整帧路径产出同一像素。
- 同步输出：补齐终端能力探测（已知支持 DEC 同步更新的终端）；整帧与底部帧包同步更新，仅动画/无变化帧不包。
- 新增覆盖测试：以内存后端断言"整帧后接仅动画帧"时其余内容保持；整帧输出与改造前逐字节一致。

验收：局部帧不再清屏；整帧输出不变；`cargo clippy` 与现有测试全绿。

## 阶段二：内容表现力（高亮 / 方言 / 数学）

目标：补齐 Markdown 表现力差距。

任务：

- 语法高亮：引入高亮后端与有限容量缓存，代码块按语言着色。
- 离屏懒渲染：不可见代码块跳过高亮，仅保留占位，滚动进入视口时再高亮。
- 方言扩展：在共享方言模块启用数学、脚注、定义列表。
- 数学渲染：落地 Unicode 数学渲染（文档模型已预留 `latex` 字段）；图像路径按需再议。
- 缓存失效：把高亮版本、方言开关等新增输入纳入准备/渲染缓存键。

验收：代码块着色快照；流式与整段渲染一致性测试保持；解析/高亮字节数满足预算。

## 阶段三：滚动与失效模式

目标：平滑大段输出，避免清屏闪烁。

任务：

- 流式追赶：追加超过一屏时按"每帧有限步、滞后不超过一个视口"滑动贴底；显式导航瞬时贴底；关闭装饰动画时退回瞬时贴底。
- 软重绘失效哨兵：区分"真实脱同步需硬清屏"与"滚动/重排只需软失效"，避免中间清屏造成图像占位闪烁。

验收：固定追加序列下逐帧滚动量符合曲线；视觉占位不闪。

## 阶段四：主题感知

目标：让用户调色板与浅色/深色适配覆盖所有颜色来源。

任务：

- 缓冲级调色板重映射：把散落字面色按最近语义角色吸附，并相对角色色重表达（保留明度/彩度偏移）；纳入固定后处理顺序（先明暗适配、后调色板）。
- 主题校验：以感知色彩空间（OKLab）计算对比度、区分度与色盲安全，作为配置校验与告警（不强制自动生成）。

验收：浅色/深色快照各一套；用户自定义调色板下不再出现不可读配色。

## 阶段五：观测量与回归基线

目标：把"体感回归"变成可断言项。

任务：

- 新增度量：闪烁检测、键到绘制延迟、锚点稳定性分类（重定位/上方插入/大跳/整体重排）、准备缓存命中率与阶段耗时。
- 在演示/测试中开启度量采集，并把稳定态帧的重排行数、解析字节、变更单元格、闪烁率、键到绘制延迟纳入预算断言。

验收：可输出一份回归报告，后续改动若退化会失败。

## 阶段六：图表 / 图像 / 包裹行映射（按需）

任务：

- 终端图像协议与图表（mermaid 等）渲染，按产品需要引入。
- 包裹行 ↔ 源列区间映射，支撑跨行选择与复制精确对齐。

验收：按具体需求定义。

## 依赖与顺序

阶段一独立且最先落地；阶段二与阶段三可并行；阶段四依赖阶段一的缓冲级后处理顺序；阶段五依赖阶段一与阶段三的提交边界；阶段六按产品节奏。

## 回归与度量

- 保留现有快照测试、无头渲染等价测试与事件回放作为护栏。
- 阶段一新增帧缓冲内容保持与整帧字节不变量测试。
- 后续阶段以帧预算（重排行数/解析字节/变更单元格/闪烁率/键到绘制延迟）作为回归断言。

## 实现状态

阶段一已实现，涉及：

- `tui-core/src/redraw.rs`：新增 `FrameCache`（上一帧合成缓冲的播种/记录/失效），并附单元测试与"内存后端下部分帧保持其余单元格"的契约测试。
- `wf-tui/src/tui.rs`：外壳持有 `FrameCache`，绘制前对非整帧范围播种、绘制后（主题适配前）记录；统一 `resolve_frame_scope` 合并待处理请求与当帧判定；无法播种时自动升级为整帧；同步输出版块按当帧范围判定。
- `wf-tui/src/interactive/render.rs`：`draw` 接收外壳判定的范围（仅做缓存冷启动的升级），不再自行重判，保证播种与渲染使用同一范围。
- `tui-terminal/src/capabilities.rs`：新增 `TerminalType::supports_synchronized_output` 与探测，使同步输出分支可达。

阶段二已实现，涉及：

- `tui-markdown/src/markdown/dialect.rs`：方言启用数学、脚注、定义列表，新增 `DIALECT_VERSION` 并纳入缓存键。
- `tui-markdown/src/markdown/highlight.rs`（新增）：无依赖按语言分词高亮后端与 256 项有界缓存，含预算统计。
- `tui-markdown/src/markdown/math.rs`（新增）：LaTeX 到 Unicode 可读回退渲染，原文保留于 `latex` 字段。
- `tui-markdown/src/markdown/document.rs`：数学显示文本、脚注引用/定义、定义列表折叠为列表块。
- `tui-markdown/src/markdown/plain.rs` 与 `wf-mini/src/render.rs`：纯文本与行规程前端同步支持数学/脚注。
- `tui-markdown/src/markdown/styled.rs`：代码块按语言着色（主题角色表达），`document_to_lines_lazy` 支持共享缓存、占位开关与可见窗口懒渲染（占位与高亮行数一致）。
- `tui-markdown/src/markdown/stream.rs`：`$` 纳入流式不安全字符，新增数学/脚注/定义列表的流式一致性测试。
- `tui-components/src/transcript.rs`：`contains_code_fence` 与缓存感知的 `display_lines_highlighted`。
- `tui-core/src/prep_keys.rs`：准备/行缓存键新增方言与高亮版本输入。
- `tui-render/src/prep_cache/scrollback.rs`：围栏代码延迟高亮、`ensure_highlighted_for_window` 可见即高亮（几何不变）、`highlight_stats` 预算观测。

阶段三已实现，涉及：

- `tui-core/src/tail.rs`（新增）：追赶步长与单视口滞后上限的纯函数，含逐帧曲线测试。
- `wf-tui/src/interactive.rs`：`tail_lag` 滞后量、`advance_tail_catchup` 逐帧滑动（静态渲染瞬时贴底）、`soft_invalidate` 软失效；快照采用有效滚动偏移。
- `wf-tui/src/interactive/turn.rs`：新回合/回放重置滞后，追加按视口上限增长滞后。
- `wf-tui/src/interactive/keys.rs` 与 `anchors.rs`：显式导航瞬时贴底并 abandon 滞后，滚动接管仅经软失效。
- `wf-tui/src/interactive/render.rs`：绘制采用追赶后的有效偏移，窗口确定后升级可见高亮。
- `tui-core/src/redraw.rs`：`InvalidationKind`（软/硬）与 `InvalidationSentinel`，`FrameCache::invalidate`。
- `wf-tui/src/tui.rs`：外壳持有哨兵并在提交点统一应用（硬清屏仅来自绘制崩溃恢复与挂起恢复，重排/缩放仅软失效）。

阶段四至六尚未实现，按上表推进。
