# 第一部分：Codex 终端交互全景

## 一、终端模式与能力（crossterm 层）

| 能力 | Codex 实现 | 说明 |
| :--- | :--- | :--- |
| **raw mode** | `enable_raw_mode()` | 关闭行缓冲与回显，逐键读取 |
| **bracketed paste** | `EnableBracketedPaste` | 粘贴内容以 `\x1b[200~ ... \x1b[201~` 包裹，区分"粘贴"与"键盘输入" |
| **kitty 键盘增强** | `PushKeyboardEnhancementFlags`（`DISAMBIGUATE_ESCAPE_CODES` + `REPORT_ALTERNATE_KEYS` + `REPORT_EVENT_TYPES`） | 识别 `Ctrl+Enter`、`Shift+Tab` 等修饰键组合与按键按下/释放/重复；不支持的终端优雅降级（`enhanced_keys_supported=false`） |
| **焦点事件** | `EnableFocusChange`（Unix） | 失焦/聚焦通知，用于重绘与粘滞键状态清理 |
| **RAII 终端恢复** | `TerminalGuard`（Drop + panic hook 双保险） | 异常/崩溃时恢复 raw mode、粘贴、光标、alt-screen |
| **挂起/恢复** | `SuspendContext`（SIGTSTP/SIGCONT） | `Ctrl+Z` 挂起前恢复终端并记录光标，`fg` 返回后重应用 raw mode + 全量重绘 |
| **外部程序运行** | `Tui::with_restored` | 暂停事件流 → 离开视图 → 恢复终端 → 运行 `$EDITOR`/`$VISUAL`/vim/git rebase → 恢复 + 重绘（外部编辑器 `Ctrl+G` 走此路径） |
| **stderr 抑制** | `TerminalStderrGuard` | TUI 运行期间重定向子进程/后端 stderr 防止污染界面，`with_restored` 期间恢复 |
| **终端探测** | OSC 10/11 查询默认前景/背景色 + `supports-color` 色域 | 主题适配 TrueColor/Ansi256/Ansi16 |
| **OSC 8 超链接** | `terminal_hyperlinks.rs` | 文件路径/URL 注入可点击超链接（P2） |
| **渲染模式** | **inline 视口**（`custom_terminal.rs` 双缓冲 diff + `insert_history.rs` scroll region 写 normal scrollback） | 与 wf-cli 的全屏 alt-screen 语义不同（详见 02 文档"模式决策"） |
| **鼠标事件** | 忽略（`event_stream.rs` 明确跳过 mouse） | 纯键盘驱动 |
| **帧调度** | `FrameRequester`（mpsc actor）+ `FrameRateLimiter`（120FPS 上限，8.3ms 最小间隔） | 动画/业务事件触发重绘，resize 合并 75ms debounce 后 reflow |

## 二、键位解析机制

- **上下文回退**（`keymap.rs`）：`context → global → built-in defaults` 三级解析，`RuntimeKeymap` 一次性解析快照。
- **冲突校验**：同一输入路径（app + composer / app + chat）不允许一键多义；`Esc` 为保留键（`interrupt_turn` 与 `fixed.backtrack` 共享，见 3.1）。
- **键和弦（chord）**：`KeyChordMatcher` 支持两键组合（如 `ctrl-x ctrl-t`），`KEY_CHORD_TIMEOUT` 超时自动取消，footer 显示 `prefix … waiting for next key`。
- **可重映射**：`tui.keymap.<context>.<action>` 配置，`/keymap` 提供交互式重映射 UI（picker → action menu → 捕获按键 → 冲突验证 → 写配置），支持 replace/add-alternate/remove/两键和弦。
- **主表面别名**：`ctrl-/` 与 `ctrl-7` 视为同一键（终端差异），`shift-?` 与 `?` 同样处理。

## 四、Slash 命令（`/` 前缀，60+）

`/` 输入即弹出命令 palette：模糊搜索、`↑/↓` 导航、`Tab` 补全（补成 `/name `）、`Enter` 执行、`Esc` 关闭；无参数命令首行输入后 Enter 直接分发；数字键 auto-submit。

命令清单（按弹窗展示顺序）：`/model /ide /permissions /keymap /vim /setup-default-sandbox /sandbox-add-read-dir /experimental /approve /memories /skills /import /hooks /review /rename /new /archive /delete /resume /fork /app /init /compact /plan /goal /agent /side /btw /copy /export /raw /diff /mention /status /usage /debug-config /title /statusline /theme /pets /mcp /apps /plugins /logout /quit /exit /feedback /rollout /ps /stop /clear /personality /test-approval /subagents` 等。

关键语义：
- 任务运行中仍可用：`/new /archive /delete /fork /side /btw ...`（会话管理类）；
- 侧边对话中受限：仅 `copy/export/raw/diff/mention/status/usage/ide` 可用；
- 支持行内参数：`/review ...`、`/keymap composer.submit`、`/sandbox-add-read-dir <path>` 等。

## 五、其他交互机制

### 5.1 命令 palette / 弹窗

`/` 打开命令弹窗（`command_popup.rs`），`@` 打开文件弹窗（mention），技能弹窗（skill popup）等共用 `list` 键位语义 + 模糊过滤。

### 5.2 历史导航

- `↑/↓`：shell 风格历史召回（仅光标在行首/行尾时拦截，避免干扰编辑）；有持久化历史（多会话恢复）。
- `Ctrl+R`：反向增量搜索（footer 变为搜索输入），`Ctrl+S` 下一个匹配，`Esc` 退出搜索并恢复原草稿。

### 5.3 粘贴（paste）

- bracketed paste 事件直接插入；
- **paste burst 检测**（`paste_burst.rs`）：不支持 bracketed paste 的终端上，快速连续字符输入判定为粘贴（首字符 hold 防闪烁、IME 非 ASCII 路径除外、`disable_paste_burst` 逃生舱）；
- **大文本粘贴**：占位符（placeholder）+ 提交时替换，避免插入卡顿。

### 5.4 输入排队（type-ahead）

任务运行中输入被排队（`queued_user_messages`），footer 显示 `Pending input: N` 预览；`Tab` 立即排队提交；`Alt+↑` 编辑最近一条排队消息；turn 结束后按序释放。

### 5.5 消息编辑（backtrack）

composer 为空时按 `Esc` prime backtrack，`Enter` 确认后编辑上一条用户消息（重新提交覆盖）；vim insert 模式中 `Esc` 优先退出插入模式。

### 5.6 Bash/shell 模式

输入以 `!` 开头进入 shell 模式（footer 显示 "Shell mode"），`Enter` 执行而非提交对话；`Esc` 退出 shell 模式。

### 5.7 键位重映射（/keymap）

三步交互：选择动作（全部/常用/自定义/未绑定/分上下文 tab）→ 选择 replace/add/remove/chord → 捕获按键 → 复用运行时解析器做冲突校验 → 写 `tui.keymap.*` 配置并热重载。Debug tab 可进入按键检查器（按任意键显示解析结果，`Ctrl+C` 退出）。

### 5.8 会话导航

- `Alt+←/→`：多 agent 会话快速切换（空草稿时）；
- `Ctrl+/`：侧边对话（side conversation）开合；
- `/resume`、`/fork`、`/new`：会话生命周期。

# 第二部分：wf-cli 交互设计

## 六、设计原则（承接 docs/cli 01-03）

wf-cli 交互设计继承 `design-philosophy.md` 的可预期键位原则，并在此基础上吸收 codex 验证过的机制：

1. **上下文回退键位解析**（codex `keymap.rs` 同构）：`modal > 当前屏幕上下文 > global > built-in defaults`；P0 内置默认表，P1 开放 `keybindings.toml` 覆盖 + 热重载（对齐 02 文档 4.1）。
2. **全屏 alt-screen + 标准 ratatui Terminal**：交互键位与渲染解耦；不做 scroll region 写 scrollback（codex inline 机制的差异点，见第 11 节）。
3. **列表驱动导航**：所有列表屏共用一套 `list` 键位语义（↑/↓/j/k、Enter、Esc），禁止各屏散落裸 `match key`（03 文档红线 8）。
4. **模态框独占键盘**：捕获型模态框（PasswordModal）无视 phase 接管全部按键（02 文档 4.2）。
5. **每屏 1 行状态行承载按键提示**：`↑/↓ navigate  Enter select  ? help  Esc back`（02 文档全局骨架）。
6. **`?` 帮助模态框**：列出当前屏幕全部可用按键（当前上下文键位表）。

## 七、wf-cli 键位上下文（KeymapContext）

## 十一、与 Codex 的差异决策（wf-cli 交互侧）

1. **Esc 语义裁剪**：codex 将 `Esc` 同时用于 interrupt_turn / backtrack / 弹窗关闭（上下文重载）。wf-cli 明确分层：**chat 上下文 `Ctrl+C` 取消 turn**（对齐 02 文档 4.2 "Ctrl+C 全局"），`Esc` 专用于"返回/关闭/清空"，避免歧义；P1 若引入 vim 模式再为 Normal 提供 `Esc` 退出。
2. **无 inline scrollback 交互**：codex 的 `insert_history`（scroll region 写 terminal scrollback）与 `raw_output` 模式（Alt+R）面向 inline 视口；wf-cli 全屏 alt-screen 下日志滚动在 ratatui 视口内完成（02 文档 1.2 规则 4），不提供 Alt+R raw 模式。长日志 P1 走全屏分页查看器（退出时内容进 normal scrollback，可被终端原生选择/复制）。
3. **无鼠标交互**：同 codex（忽略 mouse），纯键盘驱动；依赖 P1 的 OSC 8 超链接提供文件跳转。
4. **审批键位对齐 codex approval 语义**：`y` 批准本次 / `a` 批准会话 / `p` 批准前缀 / `d` 拒绝 / `n`+`Esc` 拒绝本次 / `c` 取消（对应 01 文档 4.4 "TUI 下走模态框"）。
5. **bash/shell 模式（`!` 前缀）不引入**：wf-cli 的执行语义与 codex 的 shell 直通不同，`!` 前缀交互由 workflow/execution 命令面承担（headless 子命令），避免双语义。
6. **多行输入节奏**：P0 单行 Input（Enter 提交语义无歧义）；P1 引入 TextArea 后 Enter/Tab 的提交与换行判定参考 codex（submit 与 queue 分离：`Enter` 提交、`Tab` 排队），并保留 codex 的"粘贴突发内 Enter 插入换行"细节。

## 十二、80x24 键位可用性检查（对齐 02 文档六）

- 所有屏幕状态行 1 行，底部恒显示当前上下文 3-4 个主键提示（`?` 提供全量）；窄终端回退单行裁剪。
- 列表/详情/输入共用键位语义（list/detail/input），用户跨屏无需重新学习。
- 模态框打开时键盘独占，主键提示切换为模态框提示（`Y/N`、`Enter/Esc` 等）。
