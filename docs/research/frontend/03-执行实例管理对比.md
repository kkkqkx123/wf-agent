# 执行实例管理对比

本文比较三套前端在「执行实例」上的完整链路：列表与筛选、状态表达、详情入口、日志与追踪、回放/重跑、标注与协作。

## 1. 页面与入口

| 项目 | 入口结构 |
| --- | --- |
| 当前项目 | `/executions` 执行工作台（列表 + 检查器，可 A/B）与 `/executions/[id]` 执行详情两个路由（`apps/web-app/src/routes/executions/+page.svelte`、`routes/executions/[id]/+page.svelte`） |
| n8n | 全局执行页 `ExecutionsView`（项目维度）与工作流内执行页 `WorkflowExecutionsView`（工作流维度）；工作流内为「列表侧栏 + 预览」双栏（`docs/ref/n8n/.../executions/views/ExecutionsView.vue`、`WorkflowExecutionsView.vue:141-145`） |
| Dify | 应用日志页 `/app/[appId]/logs` 表格 + 右侧 Drawer；运行详情复用 `Run` 组件（`docs/ref/dify/web/app/components/app/workflow-log/index.tsx`、`list.tsx:154-162`、`detail.tsx:59-65`） |

当前项目是「列表页 + 独立详情页」；n8n 是「列表内预览」；Dify 是「表格 + 抽屉」。三者的返回成本依次为：独立详情页最高、列表内预览最低、抽屉居中。

## 2. 执行列表

### 2.1 当前项目

`/executions` 的页面结构（`apps/web-app/src/routes/executions/+page.svelte`）：

- `SplitView` 支持 `dual={compareMode}`（`:307-310`），主区列表 + 右侧检查器，对比模式下第二检查器显示 A/B 并支持 swap（`:424-440`）。
- `PageHeader` 聚合刷新、列表/表格切换、Compare、New task、Start from workflow（`:316-356`）。
- `MetricGrid` 提供顶部指标卡（`:383`）。
- `FilterBar` 提供 query、status 与 engine（all/workflow/agent/chat）筛选（`:385-417`）。
- 列表支持卡片网格与 `DataTable` 两种形态（`:479-490`），底部 `CursorPager`（`:490`）。
- SSE 脏标记：`watchListInvalidation`（`:35`、`:79`），新执行到达时提示「New execution activity arrived」。

卡片信息（`ExecutionCard.svelte`）：名称 + kind 徽标 + `StatusBadge`（`:60`）、短 id/相对时间/时长（`:68-70`）、`Progress`（`:75`）、tasks 与 failed/currentNode（`:82-95`）。

### 2.2 n8n

`ExecutionsView` 的层级很薄：加载态 → `PageViewLayout` → `GlobalExecutionsList`；无工作流时显示 `ResourcesListEmptyState`；筛选以 `filtersKey = project:{id}` 持久化并在列表建立前恢复；`visibilitychange` 时停止/恢复自动刷新（`docs/ref/n8n/packages/frontend/editor-ui/src/features/execution/executions/views/ExecutionsView.vue`）。

工作流维度的 `WorkflowExecutionsView`（`WorkflowExecutionsView.vue`）：

- `initializeRoute()` 在执行首页且已有执行时，`router.replace` 到 `EXECUTION_PREVIEW`，自动选中第一条（`:141-145`）。
- 删除当前执行后跳到相邻执行，否则回执行首页（`:228-249`）。
- 重跑支持 `{ id, loadWorkflow }`（`:274`）。
- `hasMore` 在状态包含 `running` 时为 false，避免运行中无限加载（`:311-314`）。
- `loadMore` 用 `callDebounced(..., { debounceTime: 1000 })`（`:307`）。

列表侧栏（`WorkflowExecutionsSidebar.vue`）：

- 固定 `flex: 310px 0 0`，`background-color: var(--color--background--light-3)`，右边框（`:262`）。
- 标题 + 并发执行头 + 自动刷新 `N8nCheckbox` + `ExecutionsFilter`（`:191-197`）。
- `useIntersectionObserver` 无限滚动，每次 20 条（`:60`）。
- `TransitionGroup name="executions-list"` 做插入/移除动画（`:231`）。
- 顶部 6px 渐变 fader，避免内容硬切（`:294`）。
- `scrollToActiveCard()` 使用 `LIST_HEADER_OFFSET = 200` 对齐（`:147`）。

列表项（`WorkflowExecutionsCard.vue`）：

- 重跑动作有两项：`current-workflow` 与 `original-workflow`，各带 label/description（`WorkflowExecutionsCard.vue:49-64`、`:170`）。
- 当前选中项 `isActive = execution.id === route.params.executionId`（`:64`）。
- 内容：running 时 `N8nSpinner`、状态 label、运行时长、`retry #id`、annotation（点赞/点踩 + tags）；右侧 `N8nActionDropdown`（重跑）、私密凭据图标、手动执行图标、评估图标。
- 选中态用左边框：`.active { border-left: var(--spacing--4xs) ... }`。

全局列表项（`GlobalExecutionsListItem.vue`）：

- `executionIconStatusDictionary` 为 8 种状态映射图标与颜色（`:76-112`）：crashed/error → `x-circle-filled`/danger；waiting → `hourglass-filled`/secondary；success → `check-circle-filled`/success；new → `circle-dashed-filled`；running → `spinner-filled`；unknown → `question-circle-filled`；canceled → `slash-circle-filled`。
- `errorStatuses = [error, crashed]` 控制整行危险背景（`:112-115`）。
- 停止时间用 `locale.displayTimer` 格式化（`:129`）。

### 2.3 Dify

日志页（`workflow-log/index.tsx`）：

- 顶部 `PageTitle` + `Filter` + 保留期/归档提示（`:109` 附近）。
- `total === undefined` → `LoadingPlaceholder`；`total > 0` → `List`；否则 `EmptyElement`（`:113-117`）。
- `Pagination` 仅在总数超过 `APP_PAGE_LIMIT` 时显示，页大小 `[10,25,50]`（`:121-132`）。
- 查询参数 `useDebounce(..., { wait: 500 })`（`:61`）。
- 时间周期 9 档：today / last7days / last4weeks / last3months / last12months / monthToDate / quarterToDate / yearToDate / allTime（`TIME_PERIOD_MAPPING`）。

筛选（`workflow-log/filter.tsx`）：

- 外层 `mb-2 flex flex-row flex-wrap gap-2`（`:53`）。
- 状态 `Chip`（all/succeeded/failed/stopped/partial-succeeded/scheduled/running/paused）。
- 时间 `Chip`，`min-w-37.5`、`panelClassName="w-[270px]"`、日历图标（`:77-78`）。
- `SearchInput className="w-50"`（`:96`）。

列表（`workflow-log/list.tsx`）：

- `table`：`mt-2 w-full min-w-110 border-collapse border-0`（`:162`）。
- `thead`：`system-xs-medium-uppercase text-text-tertiary`，表头底色 `bg-background-section-burn`，首列 `rounded-l-lg`（`:163-209`）。
- 排序按钮可聚焦并显示 `ArrowDownIcon`，`asc` 时旋转 180°（`:176-180`）。
- 状态列用 `StatusDot` + 语义色：success/partial-succeeded 绿、failed 红、stopped/paused 警告色、scheduled 次要色、running 蓝（`:75-135`）。
- 行点击打开 `Drawer`（右侧滑出，`modal`），关闭后回到表格（`:154-159`）。

## 3. 筛选与检索

| 维度 | 当前项目 | n8n | Dify |
| --- | --- | --- | --- |
| 字段 | query、status、engine | status、workflowId、annotationTags、startDate/endDate、metadata（key/value/exactMatch）、vote、workflowVersionId（`ExecutionsFilter.vue:69-79`） | status、时间周期、关键词（`filter.tsx:53-96`） |
| 触发 | 即输入即筛 | 日期变化 500ms 防抖（`ExecutionsFilter.vue:59`） | 查询参数 500ms 防抖（`workflow-log/index.tsx:61`） |
| 已选计数 | 无 | `countSelectedFilterProps` 显示 badge（`ExecutionsFilter.vue:155`、`:235-246`） | Chip 自身高亮 |
| 版本筛选 | 无 | 拉取 `/executions/versions/{workflowId}`（`ExecutionsFilter.vue:104`） | 无 |
| 持久化 | 依赖 URL/页面状态 | `filtersKey` 恢复（`ExecutionsView.vue`、`WorkflowExecutionsView.vue`） | 页面 state |

n8n 的筛选能力最强（元数据、投票、版本），且「已选条件计数」解决了多条件筛选的可见性问题；Dify 用 Chip 降低理解成本；当前项目的三元筛选最轻，但缺少版本、时间范围与条件计数。

## 4. 分页与实时更新

| 项目 | 分页 | 实时 |
| --- | --- | --- |
| 当前项目 | 游标分页 `CursorPager`（`routes/executions/+page.svelte:490`） | SSE 脏标记 + 提示条（`:35`、`:79`） |
| n8n | 无限滚动（IntersectionObserver，每次 20 条）+ `loadMore` 1s 防抖（`WorkflowExecutionsSidebar.vue:60`、`WorkflowExecutionsView.vue:307`） | 自动刷新复选框；`visibilitychange` 暂停；运行中禁止 `hasMore` |
| Dify | 页码分页，页大小 10/25/50，仅总数超限时显示（`workflow-log/index.tsx:121-132`） | 本次快照未见列表级 SSE；运行态由 `Run` 的 `isListening` 驱动 |

当前项目是唯一使用 SSE 主动通知列表变化的实现；n8n 用轮询 + 可见性管理；Dify 以手动/请求驱动为主。

## 5. 状态表达

| 项目 | 机制 |
| --- | --- |
| 当前项目 | `StatusBadge` 统一渲染，卡片/表格/详情共用（`ExecutionCard.svelte:60`、`ExecutionInspector` 头部） |
| n8n | 8 状态图标/颜色字典（`GlobalExecutionsListItem.vue:76-112`）+ 卡片内 spinner/label/时长 + 错误行背景 |
| Dify | `StatusDot` + 语义色；结果面板文案区分 `scheduled/succeeded/partial-succeeded/failed/stopped/paused/running`（`run/status.tsx:96-114`）；节点卡状态文案 7 种（`run/node.tsx:93`） |

三者都能区分成功/失败/运行中；n8n 与 Dify 额外覆盖 `crashed / waiting / new / canceled / paused / partial-succeeded / scheduled` 等细分状态，并在列表层用图标或整行背景强化。当前项目的 `StatusBadge` 若不扩展状态字典，会在这些边界状态上丢失语义。

## 6. 执行详情

### 6.1 当前项目

`/executions/[id]` 的结构（`apps/web-app/src/routes/executions/[id]/+page.svelte`）：

- 按 kind 分派 `SessionInspector`（agent/chat）或 `ExecutionInspector`（workflow）（`:8-11`）。
- 生命周期操作按 kind 选择不同 API（`:71-87`）。

`ExecutionInspector`（`apps/web-app/src/lib/components/domain/ExecutionInspector.svelte`）是当前项目最重的组件（1474 行）：

- 头部：名称、id、`StatusBadge`、`Progress`、started/duration/memoryPeak/trigger 四宫格。
- `Segmented` Tab，集合由 `EXECUTION_TABS` 决定（`apps/web-app/src/lib/config/execution-tabs.ts:9-21`）。
- overview：context、当前位置、live output（`StreamMarkdown`）、状态迁移。
- graph：live/replay 控制（start replay、play/pause、0.5/1/2/4×、step back/forward、range、exit）（`ExecutionInspector.svelte:163-165`）；回放视图派生（`:207-238`）；叠加 `pulseIds`、`criticalIds`、`heatTierById`、`decisionIds`（`:251-271`）；`GraphExplorer preset="execution"`。
- trace：`NodeTracePanel`。
- timeline：`Timeline` + `TimelineOutline`。
- tools：`ToolCallCard` / `ToolCallGroup`，按图节点过滤，点击定位。
- analysis：live error stream、efficiency、slow nodes、critical path、decision points。
- messages/variables/checkpoints：loop 面板。
- hierarchy：`ExecutionHierarchyBreadcrumb` + `ExecutionHierarchyTree`。
- history、state：变量、调用栈、内存。

Tab 集合按 kind 裁剪：workflow 9 个、agent 10 个、chat 6 个（`execution-tabs.ts:45-77`），默认 overview（`:80`）。

## 7. 回放、重跑与调试

| 能力 | 当前项目 | n8n | Dify |
| --- | --- | --- | --- |
| 回放 | 画布回放：播放/暂停、0.5–4×、单步、范围、退出（`ExecutionInspector.svelte:163-165`） | 无等价的画布回放；提供重跑与调试 | `canReplay` 时跳回画布并带 `replayRunId`（`workflow-log/detail.tsx:22`、`:39-49`） |
| 重跑 | 本次阅读范围内未看到执行级重跑入口 | 双选项：当前工作流 / 原始工作流（`WorkflowExecutionsCard.vue`、`WorkflowExecutionsPreview.vue:441-469`） | 通过 replay 进入画布重跑 |
| 调试 | 无「复制到编辑器」 | 成功 → copyToEditor，失败 → debugInEditor（`WorkflowExecutionsPreview.vue:68-75`） | replay 到画布 |
| 标注 | 无 | 投票、tags、加入数据集 | 无 |
| 单节点查看 | trace/tools/analysis Tab | 日志树选中 + `Enter` 打开 NDV | 追踪树节点卡展开 + NodePanel |

当前项目的回放粒度最细（时间轴游标 + 倍速 + 单步），但缺少「从执行回到可编辑状态」的闭环；n8n 的重跑/调试动作最完整；Dify 用 `replayRunId` 把历史运行直接带回画布。

## 8. 结论

1. **可观测深度：当前项目 > n8n > Dify。** 12 个 Tab、回放、热力/关键路径/决策点、工具调用分组、层级树，均为当前项目独有。
2. **列表浏览效率：n8n > Dify > 当前项目。** n8n 的固定侧栏 + 自动选中 + 无限滚动 + 键盘/动画，使「连续查看多次执行」成本最低；当前项目需要进出详情页。
3. **日志阅读体验：n8n ≈ Dify > 当前项目。** n8n 的树形实时日志 + `j/k` 导航 + pop-out，Dify 的折叠节点卡 + 追踪树，都比当前项目「timeline/trace 两个 Tab」更接近「读日志」这件事。
4. **动作闭环：n8n > Dify > 当前项目。** 重跑、调试、标注、数据集、删除在 n8n 形成完整动作组；Dify 至少能 replay；当前项目以查看与生命周期控制为主。
5. **状态语义：n8n 最细。** 8 状态图标字典 + 错误行背景，适合快速扫视；当前项目若继续使用单一 `StatusBadge`，需要在 token 层补齐状态映射。

## 9. 建议

1. 在列表侧引入「选中即预览」：保留 `/executions/[id]` 深链，但在宽屏用右侧检查器直接切换，减少路由往返。
2. 增加执行级动作组：重跑（当前工作流 / 原始版本）、复制到编辑器、删除；先复用现有 lifecycle API。
3. 把 `trace` 与 `timeline` 合并为可折叠的树形日志（参考 `LogsOverviewRow` 的缩进与实时计时），减少两个 Tab 的切换。
4. 为 `StatusBadge` 增加状态字典（crashed/waiting/new/canceled/paused/partial-succeeded），并在列表中用图标辅助扫视。
5. 在详情页顶部增加「在图上看」与「回放」的一键切换，保留当前 Tab 状态。
6. 补执行筛选的版本/时间范围与已选条件计数，优先复用 `ExecutionsFilter` 的字段设计。
