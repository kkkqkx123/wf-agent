# 插件版本架构

## 版本域

插件系统内存在三类相互隔离的版本概念，分属不同层级，不可混用：

| 版本域 | 载体 | 归属模块 | 取值 |
|---|---|---|---|
| 插件身份版本 | 清单中的版本字符串 | 契约模块的清单结构，宿主侧清单模块复出并提供统一合法性判定，引擎准入与依赖解析共用该判定 | 严格语义化版本 |
| 依赖约束版本 | 清单中的必选与可选依赖表，值为版本需求字符串 | 宿主依赖解析模块，单次解析全量约束 | 语义化版本需求 |
| 协议主版本 | 接口常量、受支持版本数组、接口世界包名与世界版本常量 | 契约模块的 wasm 与 native 定义，宿主各后端加载器分别执行协商 | 整数一 |

此外插件包管理仍以插件标识为唯一键，不参与上述各域的演进。

## 模块归属与依赖

清单契约定义在契约模块的清单结构中，宿主侧清单模块复出该结构并提供版本合法性统一判定，引擎准入校验与依赖解析均使用该判定，避免两处各写一份解析逻辑。协议常量定义在契约模块的 wasm 与 native 定义中，宿主侧原生接口模块复出常量并保留加载逻辑。接口世界描述文件与宿主组件绑定必须一致，世界版本常量钉死当前取值，兼容性只比较主版本号段。

## 协议协商流程

三条后端路径各走自己的版本门控，上层插件 trait 行为一致：

- 原生路径：加载时读取版本声明函数返回的主版本数组，与宿主受支持数组取交集选最高公共版本。缺失导出、空列表、无交集均加载失败，错误同时列出双方范围并给出升级建议。协商出的版本号存入加载结果，后续每次构造插件上下文与贡献注册器时填入该值，而非固定常量，为未来多版本分发打通管线。
- Wasm 核心模块路径：访客必须导出版本声明函数，宿主调用并取交集选最高公共版本，缺失导出直接加载失败。入口选择遵循声明优先语义：先按宿主偏好版本从版本化入口表中选文件，加载后再用访客导出做校验，选择键与协商值不一致时加载失败，错误同时给出清单声明值与访客实际值，便于定位是键写错还是产物放错。
- Wasm 组件路径：组件模型没有导出握手，宿主在编译前扫描二进制内嵌的世界名版本，主版本不一致即加载失败，错误格式与核心模块路径一致。兼容性只比较主版本，次版本差异走特性检测。扫不到可识别世界名时放行，由后续编译绑定自然报错，避免误判。

Lua 路径无接口版本概念，不参与协商。

## 多版本入口

清单中的版本化入口表以接口主版本为键、产物路径为值，单条安装记录不变。宿主按协商偏好选择对应产物，缺省回退到默认入口。签名校验覆盖默认入口加全部版本化入口，而非仅校验协商命中的那一个。引擎在解析插件类型时检查默认入口与全部版本化入口的后端一致性，混用后端时加载失败并提示显式声明类型或对齐产物。

## 依赖解析与初始化门控

依赖解析一次性解析全部约束，输出解析图，包含加载顺序、环、缺失、必选版本失配、全局冲突与可选告警。必选约束对照已安装版本逐条校验，失配即记录并附修复建议；可选约束失配只记告警，不阻断。同一依赖被两个以上必选约束指向时做全局聚合：已安装场景下有一个不满足即记全局冲突；缺失场景下用候选版本探测约束是否互斥，互斥则同样记全局冲突。缺失依赖直接返回错误，错误中逐项列出缺失插件的引用方与各自约束，互斥时附加说明。

引擎初始化流程为发现、解析、门控、按序激活：环、必选失配、全局冲突任一非空即初始化失败；可选告警只记日志。拓扑排序只考虑必选依赖，可选缺失不影响加载顺序。

## 错误信息规范

版本相关错误统一包含三要素：双方各自的支持范围或声明值、明确的失败原因、升级或放宽某一侧的修复建议。握手失败、世界主版本失配、入口与导出不一致、依赖失配、全局冲突、缺失依赖均遵循该格式。
