# 阶段 0 与阶段 1：探针与 recap 核心

## 阶段 0：立项探针（只回答问题，不写功能代码）

探针逐项固定后，阶段 1 才开工。允许的产出是几百行以内的 spike 或文档结论，不合入功能。

1. 模型槽归属：recap 必须读本会话账本，因此必须用执行该会话的 profile 发起旁路调用，
   不得回退到轻量 profile。探针确认 `LlmGateway` 调用方如何拿到「当前会话的 profile」，
   以及凭据归属是否跟随。若执行链路拿不到，则 recap 读取面必须显式接收 profile（调用方声明，无默认回退）。
2. 超时与取消：在 `generate_text_once` 之上确认超时（25 秒量级）与取消（`CancellationToken`）
   的装配位置，要求「超时只结束旁路、不影响主流程」，并确认网关层已有超时不会误杀。
3. 投影数据源：确认 recap 读取的会话内容来自 `ConversationSession::view_messages` 还是消息存储，
   以及 chat 会话与 agent loop 会话是否走同一读取函数。要求投影只读、不推进任何版本号。
4. 配置键：确认显示开关在 `wf-config` 显示旋钮一侧的精确键名与默认值（缺省 true，与快照语义一致），
   以及 `web-app` 偏好与 TUI 设置是否同源。
5. 路由形状：确认 recap 读取路由挂在 chat 会话还是 agent loop 之下（或两者各一），
   请求体是否需要 profile、响应沿用工作区既有 envelope。

## 阶段 1：recap 核心

### 做什么

在 `wf-execution-shared` 新增 recap 模块，在 `wf-api` 新增只读的 recap 读取面。前端在本阶段不接入，
但读取面完成后脚本与调试已可调用。

- 稳定转录投影：从尾部回填、要求最后一条是稳定 assistant（无工具调用、非空）、必须含 user、
  上限 16K 字符量级；工具参数脱敏（敏感键涂黑、内容类键省略并标注字节数、路径类键保留并截断），
  规则照搬快照。投影返回空表示「不值得问」，此时连模型请求都不发。
- 旁路调用：无工具、低推理量级、低温度、无输出上限（上限会先吃掉思考而非答案，见快照中的实测结论），
  超时收敛为无结果，只收集可见文本增量。
- 清洗：去围栏与强调、去模型自带前缀、`<none>` 即无结果、压成一行、超长按句末截断否则补省略号，
  240 字符上限。函数与常量命名与快照保持对应，便于对照审查。
- `wf-api` 读取面：按会话取内容、做投影、发旁路、做清洗，全程只读。任何一步失败都返回「无 recap」，
  不抛错、不写日志、不发事件、不改变执行状态。

### 不做什么

不碰压缩触发、不碰会话写入、不新增事件类型、不做前端、不做广播、不加白名单事实。

### 验收

- 清洗单测照搬快照三例（单行清洗、无内容即无、超长按句末截断），断言不变。
- 投影单测：非稳定结尾无投影、超限截断保尾、工具参数脱敏、注入式文本被转义而非解析。
- 集成单测：一次 recap 恰好产生一次模型请求、提示词含 recap 指令、未新建多余 provider/网关；
  网关失败与超时都收敛为无结果；投影为空时请求数为零。
- 门：`cargo clippy --all-targets --all-features`、`cargo fmt --all -- --check`、
  `cargo nextest run -p wf-execution-shared -p wf-api`。
