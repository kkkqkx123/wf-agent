# 04 落地路线与验证

## 1. 阶段划分

优化按"独立可验证、低风险先行"排序。每个阶段结束后都应能独立编译、通过现有测试，并产生可度量的改变。

### 阶段 0：建立基线（1 个小改动）

目标：让后续优化有回归依据。

- 新增 `metrics.rs`，把 `tui_debug/diff_recorder.rs` 的字节统计扩展为帧度量（`changed_cells`、`ansi_bytes`、`duration_us`）。
- 在 `wf-cli-demo/examples/tui_diff_record.rs` 基础上加一个"回放固定事件序列、输出帧度量"的例子。
- 记录当前的全量重排基线：1 万行 scrollback 下每帧换行耗时与行数。

验收：能输出一份基线报告，作为后续对比。

### 阶段 1：增量准备缓存（收益最大）

目标：消除全量 scrollback 重排。

- 新增 `prepare.rs` + `prepare_cache.rs`。
- `PreparedScrollback` 保存 `rows` + `RowIndex`，实现 `prepare_append` / `prepare_prepend` / `prepare_full`。
- `InteractiveController` 增加 `versions`，在 `settle_scrollback`（`interactive.rs:756`）、replay 分支（`interactive.rs:557-590`）、trim 处递增 `scrollback_version`。
- `draw_scrollback`（`interactive.rs:947`）改为消费 `PreparedFrame` 的可见区间。

验收：

- `reflowed_lines` 在稳态追加时等于新增源行数。
- 现有 `tests/tui_snapshot.rs` 快照输出不变（准备层只改缓存，不改渲染结果）。
- 1 万行 scrollback 下流式帧耗时下降一个数量级。

### 阶段 2：Markdown 解析节流

目标：消除每个 token 一次的全量解析。

- `MarkdownStream::push` 改为只累积 + 标脏（`markdown.rs:76`）。
- 新增 `parse_if_due(now_ms)`，在帧准备阶段调用。
- 保留 `final_plain_text` 兜底路径不变。

验收：

- 复用现有 `assert_streamed_equals_full`（`markdown.rs:948`）验证流式结果与全量一致。
- `markdown_bytes_parsed` 从 O(n²) 降到 O(n)。

### 阶段 3：重绘范围分级

目标：让 spinner/notice 不再重建整屏。

- 新增 `RedrawScope` 与判定函数。
- `TuiApp` 保留上一帧 `Buffer`（`FrameCache`），实现三种提交路径。
- 记录 `spinner_area`。
- `FrameRequester` 请求携带 scope。

验收：

- 动画帧只重绘 spinner 区域；`changed_cells` 显著下降。
- 快照测试不受影响（`Full` 路径输出应与之前逐字节一致）。

### 阶段 4：流式缓速

目标：平滑突发输出。

- 新增 `reveal.rs`，在 `handle_turn_event` 的 `LlmDelta` 处插入（`interactive.rs:634`）。
- 缓速产出的可见前缀再进入 markdown 与该帧的准备。

验收：

- 固定 delta 序列下，逐帧可见字节数符合速率曲线。
- 最终文本与不缓速时完全一致（新增等价性测试）。

### 阶段 5：主题单点适配 + 能力联动

目标：浅色终端统一适配，能力探测驱动降级。

- 新增 `theme_mode.rs`，在绘制后对 buffer 统一适配。
- `capabilities.rs` 的 `TerminalCapabilities` 接入 `perf.rs` 的 `TuiPerfPolicy`。
- 同步输出（DEC 2026）在 `Full`/`FooterOnly` 帧启用。

验收：

- 浅色/深色快照各一套，浅色下 `Color::Reset` 保持。
- 不支持同步输出的终端行为与现状一致。

### 阶段 6：可注入时钟 + 动画降本

目标：测试确定性与动画分配下降。

- 新增 `clock.rs`，替换 `animation.rs`、`motion.rs`、`state.rs` 的 notice TTL、`interactive.rs` 里的 `Instant::now()`。
- `shimmer_spans` 改为三段 span + 相位查找表。
- 视情况把动画纯核拆为 `wf-tui-anim` 新 crate，并在根 `Cargo.toml` 加 profile override。

验收：

- 动画测试可断言具体帧字符，无需 sleep。
- shimmer 的 span 分配从 O(n) 降到 O(1)。

## 2. 依赖关系

```
阶段0 基线 ──► 阶段1 准备缓存 ──► 阶段3 重绘分级 ──► 阶段5 主题/能力
                    │                    ▲
                    └──► 阶段2 md 节流 ──┘
阶段4 缓速 依赖 阶段1/2 的帧准备接口
阶段6 时钟 可与阶段3/4/5 并行，但动画降本依赖时钟注入
```

阶段 1 与 2 互不依赖，可并行。阶段 3 需要阶段 1 的 `PreparedFrame`。阶段 4 需要阶段 1/2 暴露"每帧可见文本"接口。阶段 6 的时钟注入越早越好，因为它让阶段 4/5 的测试更简单，建议作为阶段 1 的伴随改动先落 `clock.rs`，替换面可以逐步扩大。

## 3. 主要风险

| 风险 | 说明 | 缓解 |
| --- | --- | --- |
| 缓存失效漏标 | 某个变更点忘了 bump 版本号，表现为画面不更新 | 版本字段私有，所有变更走统一 `bump` 方法；整帧快照测试覆盖 |
| 增量准备与全量不一致 | 前插/裁剪后行索引错位 | 保留 `prepare_full` 作为参考实现，测试里随机操作序列对比两者输出 |
| markdown 增量正确性 | 引用定义、表格、围栏闭合会回改前文 | 只对"安全前缀"增量，其余退化为全量；复用现有等价性测试 |
| 局部重绘与后端 diff 冲突 | 自持 buffer 与 ratatui 后端状态不一致 | 封装 `present`，`Full` 路径仍走 `terminal.draw`；阶段 3 快照必须逐字节一致 |
| 主题双重翻转 | `light_default` 与 buffer 适配同时生效 | 显式配置优先，适配仅在未显式配置时启用 |
| 新 crate 拆分开销 | workspace 成员与 profile override 需登记 | 动画拆分放最后，纯函数先集中于 `motion.rs` |

## 4. 度量指标

优化前后对比以下指标（用阶段 0 的度量输出）：

- 稳态流式帧耗时（1 万行 scrollback）。
- 每帧 `reflowed_lines`（目标：等于新增行数）。
- 每帧 markdown 解析字节数（目标：线性）。
- 每帧 `changed_cells` 与 `ansi_bytes`（动画帧目标：只含 spinner 区域）。
- 空闲动画帧率（目标：由 `TuiPerfPolicy` 控制，不再 120 FPS 空转）。

## 5. 测试策略

- 现有测试全部保留，作为行为不发生回归的护栏：
  - `tests/tui_snapshot.rs`（insta 快照，逐行裁剪尾部空格）。
  - `tests/replay_fixture.rs`、`tests/session_pipeline.rs`。
  - `markdown.rs` 内的流式等价性测试。
  - `framer.rs` 的纯数学测试。
- 新增测试：
  - 准备层：`prepare_append` / `prepare_prepend` / `prepare_full` 与随机操作序列的等价性。
  - 缓速层：固定 delta 序列的逐帧可见字节曲线与最终一致性。
  - 重绘分级：`redraw_scope` 判定表，以及三种 scope 下的 buffer 等价性。
  - 时钟：`TestClock` 推进下 spinner 帧、notice TTL。
  - 度量：稳态流式帧的预算断言（防止性能回归）。
- 所有新增测试使用 `expect` 而非 `unwrap`，符合仓库约定。
- 测试用 `TestRenderModel` 实现只读渲染 trait，让整帧绘制可离线断言。
