# 终端程序状态与 pi 模式对齐方案

目标：终端程序状态（OSC 7501）上报语义与 pi 保持一致，只改原有模块，不新增替代模块。编码层（状态组装、控制字符替换、截断、base64）两边已实质一致，本方案只补语义层差距。

## pi 模式要点

- 上报内容限定为会话名、对话框标题、错误首行，提示词与助手输出永不进入消息字段。
- 运行中与完成后携带会话名，错误携带首行，中止回到空闲，阻塞覆盖运行态并按最新打开的对话框优先。
- 同一状态只发送一次，去重键覆盖全部字段。
- 终端确认支持后才发送，退出与挂起前先发清除，重启后重发。

## 现状差距

- 去重键只含状态与消息，阻塞类型不同但消息相同时会被吞掉。
- 运行中与完成状态的消息为空，丢失会话标题信息；提问阻塞的消息是固定文案，未使用实际问题。
- 挂起与外部编辑器路径直接恢复终端模式，未先清除程序状态，外部终端可能残留旧的运行中标记。
- 缺少查询序列与应答判定所需的协议常量， capability 协商暂时只靠环境变量开关。

## 改造内容

- 终端状态协议模块补查询序列常量、应答判定函数与环境变量显式开关解析，并配单测。启动时做一次带超时的实时查询：显式开关优先，否则打开控制终端询问，终端确认支持前不发送；确认后自动重发当前状态。
- 终端状态管理器的去重键补齐应用名与阻塞类型，清除路径与同步路径共用同一键构造，避免清除后无法去重或重复发送。
- 会话状态函数改为接收会话标题参数，运行中与完成状态携带标题，提问阻塞携带问题首行，错误保持首行不变，中止保持回到空闲。标题由帧同步处从当前标签页传入，退出路径的强制空闲逻辑不变。
- 帧同步处把当前标签页标题传入会话状态函数；挂起与外部编辑器路径在恢复终端前先清除程序状态与进度指示，下一次帧同步自动按新去重键重发，标题因未变化而不重发。
- 会话控制器维护阻塞源打开顺序：审批与提问安装时入栈（重开替换位置），状态函数取栈顶且仍在显示的对话框；清除路径零改动，过期条目被跳过。鉴权类型已在协议枚举中预留，暂无生产者。

## 本次不做的事项

- 启动时实时查询终端应答并按结果门控发送。同步查询复用控制终端读写模式，不经过键盘事件链路；显式环境变量开关可跳过查询，未探测路径保持原有发送行为。
- 阻塞多源栈已按打开顺序实现最新者优先；鉴权类型仅缺生产者，出现新的阻塞对话框时只需在安装点入栈。
- 压缩中状态。压缩发生在服务端黑盒内部，会话事件流无压缩事件，终端侧无生产者；服务端透出压缩事件后再接入，终端侧状态函数已预留运行态消息位。
- 事件推送式上报器。保留当前每帧派生的轮询模式，更贴合主循环，状态语义已折叠进纯函数，无需新增模块。

## 验证

- 全量编译检查一次通过。
- 终端状态协议、终端状态管理器、会话状态三处单测覆盖新增语义后一次通过。
