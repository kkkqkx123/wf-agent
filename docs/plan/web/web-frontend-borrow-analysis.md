# Web 前端可借鉴的 UI 与功能设计分析

> 基于 `docs/ref/frontend` 下两份说明：zcode（Agent IDE 工作台）与 deeix（文档型 Agent 工作台）。只借鉴功能与 UI，不照搬技术栈。

## 1. 当前项目现状

- `apps/web-app` 仅为 SvelteKit 加 Svelte 5 空壳，只有一个占位首页，无布局、无路由、无 store、无 API 客户端、无样式体系。
- `apps/vscode-app` 仅有动态上下文片段，不可用，不构成前端约束。
- 后端已就绪：`crates/app/wf-server` 提供统一包络的 REST、SSE 流、WS 订阅，覆盖工作流、Agent 回路、检查点、触发器、模板、实体、审计分析等域；`crates/app/wf-api` 为组合根，Web 可直连，无需 Node 中间层。
- TUI 已有屏幕栈、显示模型与异步拉取分离、流式 pacing、主题与动效、调试回放，可作为 Web 信息架构的对齐参照。

结论：Web 前端缺的是应用壳、页面信息架构、组件库、主题、流式与订阅接入，而非后端能力。

## 2. 可借鉴的 UI 设计

### 2.1 总体布局：学 zcode 三栏，学 deeix 页面群

- 采用 zcode 式三栏 Shell：左为任务侧栏，中为执行或对话主列，右为检查器 SidePane。当前项目的执行详情、Agent 回路时间线、审批、产物天然适合放入右侧标签页，避免为每个域做一级路由。
- 采用 deeix 式页面群组织一级导航：对话或执行工作台、最近执行、文件与检查点、模板与技能、设置、管理。当前项目已有工作流版本、执行分析、审计、用量等后端能力，正好落入这些页面。
- 布局细节直接借鉴：侧栏可折叠为图标并悬停展开，窄屏自动折叠，尺寸记忆持久化；对话或执行页居中最大宽度加两侧细导轨；移动端侧栏转抽屉。

### 2.2 组件体系：学两者的分层

- 基础层学 deeix 的约 55 个 shadcn 式原语：按钮、弹窗、抽屉、命令面板、表格（含虚拟化）、标签页、Toast、空态、骨架、快捷键展示。优先补齐命令面板、虚拟表格、消息滚动器三件套，否则执行列表与时间线撑不住数据量。
- 业务层学 zcode 的重型查看器：代码查看、Diff 查看、PDF 与表格与幻灯片预览、图表。当前项目的文件检查点、执行产物、审计报告可直接复用这一组合。
- 反馈层学两者共有：全局 Toast、骨架 shimmer、流式占位、空态问候。TUI 的同步渲染审查经验可用来定 Web 的加载态清单。

### 2.3 样式体系：学 deeix Token，学 zcode 语义覆盖

- Token 结构学 deeix：浅色深色两套，背景、卡片、浮层、边框、聚焦环、图表色、侧栏体系、圆角、阴影、字体分开定义；预注水避免主题闪烁；字号档与对话字体可切换。
- 语义覆盖学 zcode：除通用 Token 外，为执行状态、Git 变更、提及类型、轨迹、Workflow 规则单独设色，保证成功、危险、运行中、排队等状态一眼可辨，且与终端配色解耦。
- 动效克制：思考态渐变、流式进入、复刻脉冲、配额撒花一类只用于状态传达；尊重简化动效偏好；自定义细滚动条，终端与重型预览内隐藏。

## 3. 可借鉴的功能设计

### 3.1 向 zcode 学深度工作台能力

| zcode 能力 | 对应当前项目落地 |
|---|---|
| 草稿与正式任务分离、排队追问 | Agent 回路的草稿运行与正式执行分离，流式中允许追问与停止入队 |
| 约 35 种工具调用块渲染 | Tool 执行、MCP 调用、审批、Workflow 节点产物的卡片化渲染，而非纯 JSON |
| 权限与询问弹窗、工作流权限块 | 审批与高风险工具执行的前置确认链路 |
| 文件树加预览加 Git 面板加终端 | 文件检查点时间线、分区会话、回滚与重做、终端输出 SidePane 的组合 |
| 模型轨迹、白板入话、选区入话 | 执行路径、决策点、慢节点、分支对比的可视化与一键引用 |
| 命令中心与任务查找 | 跨工作流、执行、模板、文件的全局搜索与执行内查找 |
| 分享链路 | 执行与审计报告的只读分享页 |

### 3.2 向 deeix 学完整产品外环

| deeix 能力 | 对应当前项目落地 |
|---|---|
| 最近页的过滤、星标、标签、批量操作 | 执行列表的过滤、星标、标签、批量取消与归档 |
| 文件库三栏加抽取与 RAG 状态轮询 | 文件检查点分区、变更流、处理状态轮询、配额面板 |
| 知识库与技能与提示词画廊 | 模板库、技能、提示词预设的可复用画廊 |
| 设置分区（通用、对话、订阅、账号、关于） | 工作区设置、执行默认、用量与账单、身份与会话管理 |
| 管理后台约 15 页 | 模型路由、触发器、上游通道、内容审核、审计日志、统计图表、公告 |
| 模型感知输入框与多媒体模式 | LLM 生成页的参数控件随模型切换、计费内联、阻断原因提示 |
| 产物沙箱与消息内交互块 | 执行产物预览、图表与表格与决策树内联渲染，白名单 HTML 隔离 |
| 分享为图与大纲导轨 | 审计时间线导出为图、长执行的大纲导航与位置小地图 |

### 3.3 状态与数据流：学 deeix 分层，学 zcode 隔离

- 分层学 deeix：纯函数模型层、编排 Hook 层、格式化工具层、API 契约适配层；跨功能用事件与广播通道，避免一个全局 Store 包揽一切。
- 隔离学 zcode：按工作区或执行键隔离会话与面板状态，乐观列表，浅比较订阅，虚拟化时间线加跟随尾部加 pacing，避免流式重渲染风暴。
- 接入策略：简单日志与时间线用 SSE，多执行并行订阅用 WS；文件处理、用量、版本检查用轮询加哨兵无限滚动。

## 4. 落地建议

分三批推进，每批都是可用增量。

- 第一批应用壳：三栏 Shell、侧栏导航、主题 Token、基础组件、命令面板、Toast、空态；接通执行列表、执行详情、流式日志。
- 第二批执行深度：工具调用卡、审批确认、Diff 与产物预览、文件检查点时间线、Agent 回路分支与变量史、大纲与位置导轨。
- 第三批产品外环：最近与标签、模板与技能画廊、设置分区、管理与统计、分享页、截图导出、国际化。

不建议照搬的：zcode 的桌面专属（自绘标题栏、防休眠、未读徽标）与 deeix 的登录与计费细节；当前项目应先以后端已有的执行、检查点、审计能力为边界扩展，不为缺失后端的新功能做前端预设。
