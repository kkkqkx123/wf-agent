# 远端部署作业治理加固

## 目标

在保持“远端无 `desiredState`、`probe` 独立验证、固定命令集、不回滚”的前提下，把当前进程内临时作业补齐为可观测、可重连、可收敛、可审计的运维作业。管理面仍不接管远端期望状态，只对自己发起的作业记录负责。

## 问题清单

### 正确性

1. 停机强制收敛时只是丢弃 `JoinHandle`，并没有 abort 后台任务；任务可能在强制 `interrupted` 之后继续写回终态。
2. 同 backend 的并发准入是“先扫描再插入”，存在竞态，两个部署可能同时操作同一主机。
3. 作业查询与取消路径忽略 URL 中的 backend 名，可用 A 的路径操作 B 的作业。
4. 终态作业再取消返回 404，语义错误；未知 backend 提交部署也没有提前校验，会生成作业后再失败。
5. `DeployOutcomeView.job_id` 从未回填，缓存的最近结果与作业无法关联。
6. `job.status` 与 `outcome.status` 可能不一致；取消发生在 plan/probe 阶段时会把 blocked 失败改写成 interrupted。
7. 中断分支没有新的 probe，也没有回滚；用户无法从结果看出远端是“未开始”“半升级”还是“已换链未启动”。
8. `current_step` 在步骤完成后才写入，表示“刚完成”而不是“正在执行”；作业视图没有总步骤数。
9. 本地产物通过 stdin 写入时没有超时，SSH 已连接但远端不读管道时作业可无限挂起。
10. plan 与最终 probe 不在取消范围内；取消请求可能要等多个远程往返才生效。
11. reaper 只清作业表和 token，不清任务句柄；作业状态又只保留 600 秒，重启后完全丢失。
12. `BackendManager::deploy_apply` 仍保留且无调用点，形成两套 apply 路径。

### 使用习惯

1. 作业不可列举、不可按 backend 查历史、刷新页面或重启 CLI 后无法重新 attach。
2. Web 有取消 API 但没有按钮；CLI 没有作业列表/查询/取消命令，成功输出也不展示 job id。
3. 两端轮询上限 15 分钟，服务端没有对应上限；客户端超时后用户不知道作业去向。
4. plan 是预检，apply 会重算；界面仍展示预检命令，批准内容与最终执行可能不同。
5. `docs/features/remote/README.md` 指向的计划文档在当前工作区已删除，设计说明入口断裂。

## 修改方案

### 第一阶段：作业本体一致性

- 为 `DeployJobView` 增加总步骤数与取消标记；`current_step` 改为表示正在执行的步骤。
- 引入步骤进度事件：步骤开始前报告 running，完成后报告 done；apply 重算 plan 后把最终步骤数交给进度回调。
- 中断统一走同一个构造函数，并保证中断后附加一次只读 probe。
- plan 前、plan 后、最终 probe 前都检查取消令牌；stdin 写入纳入单步超时。
- 终态只使用 outcome 自己的 status；回填 `job_id`；删除未使用的同步 apply 路径。

### 第二阶段：准入、取消与停机收敛

- 用按 backend 的占位表把“检查 + 占位”做成原子操作，并在提交前校验 backend 存在。
- 查询/取消都校验 `job.backend == name`；已终态取消返回冲突而不是未找到。
- 停机超时路径显式 abort 任务并 await，同时加终态写入守卫，保证强制终态不会被后台任务覆盖。
- 强制中断也尝试 probe；隧道仍可用时给出远端事实。
- 删除 600 秒 reaper 与句柄泄漏，终态作业改为持久化记录。

### 第三阶段：持久化与恢复

- 在后端存储中增加部署作业表，保存提交、终态和取消请求时的完整视图；内存表只承载在飞进度。
- 启动时把持久化的 `queued/running` 作业收敛为 `interrupted`，说明“管理端重启导致中断”，不重建在飞 slot。
- 作业查询先读内存再读存储；新增按 backend 或全量列表接口。
- 管理端重启不恢复远端操作，只恢复作业事实与审计信息。

### 第四阶段：三个入口

- CLI 增加作业列表、作业查询、作业取消；`--apply` 保留等待但输出 job id，并提供“只提交不等待”选项。
- Web 增加取消按钮、最近作业列表，进度显示改用 `currentStep` + `totalSteps`；提交回执显示最终 plan 的步骤数。
- 同步刷新 OpenAPI 快照、TypeScript schema 与 i18n 资源。

### 第五阶段：验证与文档

- 覆盖并发提交、取消竞态、终态守卫、重启恢复、未知 backend、跨 backend 作业访问、stdin 挂死。
- 修正远端功能文档中的计划文档链接。
- 集中执行一次编译检查、OpenAPI 快照刷新与前端类型检查。

## 验证结果

按同步指南完成源码同步与模板同步，并执行统一验证：

- OpenAPI 快照一致性测试：通过；刷新后的 `openapi.json` 与生成的 TypeScript schema 已回传本地。
- `wf-server` backends 单元测试：98 项通过，覆盖作业名校验、终态取消、重启恢复、强制终态守卫、并发准入、stdin 超时边界、plan 摘要稳定性与 plan 漂移拒绝。
- `wf-cli-shared` 单元测试：173 项通过，覆盖等待结果与作业查询入口。
- `wf-metrics` 单元测试：155 项通过，覆盖新增的部署作业级计数与耗时统计。
- 前端服务单测：6 项通过，覆盖作业行映射与协作式取消语义。
- `svelte-check`：0 error / 0 warning。

SSH 真机场景仍不属于自动化验收范围；上述用例只验证本地可确定的准入、状态与提交契约。

## 保留边界

- 作业事实持久化在管理端 `backends.db`，远端仍不保存作业历史，也不维护 `desiredState`。
- 管理端重启只关闭遗留作业，不恢复或重放远端操作；操作者需要按 probe 结果决定下一步。
- 多个管理进程共享同一后端数据库时仍需外部保证唯一管理者，服务端不引入分布式锁。
- 强制中断后的 probe 使用短超时，只用于尽快呈现远端事实，不作为部署成功的判定。
