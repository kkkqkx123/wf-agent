# 后端只读域设计（P4）

> 范围：用户仓域的只读底座与动作注册表骨架。不涉及工作台界面、输入栏、终端实现。

## 1. 放置与命名

在应用接口层新增 Git 领域聚合文件与子目录，形态沿用检查点域的聚合加子模块惯例。对外经门面重导出，使传输层不直连底层存储与引擎。传输层新增 Git 路由组，叶文件各自拥有路由表，统一在路由合并点挂到现有版本前缀下。不为一组接口新建顶层 crate，文件命名遵守平铺约定。

涉及位置为应用接口层的领域聚合与子目录、传输层的接口聚合与路由叶文件、路由合并点、开放接口声明文件。

## 2. 只读查询划分

只读查询按面板对齐，每组一个查询：仓库元信息、状态、文件三态、差异、提交列表与提交文件、本地分支、远端与远端分支、标签、贮藏、子模块、工作树。另设动作注册表查询，返回全部动作标识、危险级别、参数声明与可用状态，供前端启动期校验绑定表漂移。

输出解析只用面向机器的稳定格式。文件状态采用 porcelain 二版含分支信息，差异按 hunk 解析，提交列表采用自定义分隔符，分支与引用遍历采用格式化输出。解析逻辑集中在领域层，不散落到传输层。领域转换后的模型才进入传输信封，组件与命令行不接触原始表示。

## 3. 注册表骨架

注册表在 P4 只做骨架：维护动作标识集合、危险级别声明、参数形态声明，以及可用状态计算。未知动作返回明确错误。写动作条目首期全部标记为不可用或缺席，前端据此置灰。注册表查询本身为只读，不触发任何写行为。

## 4. 执行策略

所有调用以参数数组形式发起，不经 Shell 拼接。需要管道的场景改用 Git 原生能力或在领域层做数据组合。路径参数统一做仓库内校验，解析后必须位于仓库根之内，逃逸拒绝并记录审计。常规命令设较短超时，推送拉取类放宽。同一仓库的写操作预留串行化位置，只读不串行。

## 5. 状态指纹

维护仓库状态指纹，成分为状态输出、头指针、分支与上游摘要。P4 先定义指纹结构与计算位置，推送联动在 P5 接线。触发时机预留统一动作入口执行后与终端前台命令结束后两处，另对长命令做节流。指纹未变不推送。

## 6. 配置与运维

服务端配置新增仓库根路径、命令超时分级两项，走现有配置体系。单仓库固定为首期默认值，多仓库切换不在首期。无仓库或仓库根非法时返回明确的未初始化或越界错误，不静默回退。终端空闲回收时长在 P4 预留配置项，实例化延至 P7。

## 7. 契约流程

传输叶处理器的开放接口标注与路由表同改，操作标识保持唯一。快照文件为生成器的唯一真相源，先刷新快照再重生成前端类型。流式订阅类型手写，不进生成器。事件订阅沿用现有订阅选项结构，P4 仅保证只读查询不依赖新增订阅维度。

## 8. 无头只读命令（已放弃）

CLI 放弃 Git 后本节取消：CLI 运行在持有仓库的机器上，直接调用 `git` 的成本近乎为零，服务端代理只会复制一套更差的子集。决策记录见 `docs/plan/cli/client-unification-design.md` 第五节。仓库信息消费统一走 `/git` 工作台，脚本消费走 `/api/v1/git/*` 只读端点。

## 9. 验收

状态、文件、差异、提交、分支、贮藏可用脚本验证；路径逃逸被拒；调用均为参数数组；快照含新域且类型重生成无漂移；注册表查询返回骨架且写动作不可用。

## 10. 测试

解析函数做纯函数单测，覆盖空仓库、无上游、改名、冲突标记等边界。路径校验做逃逸单测。传输层做路由与标注一致性测试。终端行为不纳入本阶段测试。
