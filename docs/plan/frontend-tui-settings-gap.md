# 前端与 TUI 自有设置盘点、缺口分析与配置导入导出补充方案

本文盘点 `apps/web-app` 前端与 `crates/app/tui` 系 TUI 各自拥有的用户可配置项，分析两者之间的功能缺口与集成缺口，并给出前端配置导入导出能力的现状结论与补充方案。所有结论均来自仓库现状代码实测，修改思路遵循只改原模块、按职责拆分、不保留历史兼容、不升级版本号的约束。

## 范围与方法

- 前端范围：`apps/web-app/src/routes/settings`、`apps/web-app/src/lib/stores`、`apps/web-app/src/lib/shortcuts`、`apps/web-app/src/lib/services/preferences.ts`、`apps/web-app/src/lib/config/tool-output.ts`、`apps/ui/src`。
- TUI 范围：`crates/app/tui` 下各低层包（`tui-core`、`tui-style`、`tui-terminal`、`tui-components`、`tui-render`、`tui-debug`）与外壳 `crates/app/cli/wf-cli-shared`、`crates/app/cli/wf-tui`。
- 后端对照：`crates/infra/wf-config` 装配与分层、`crates/app/wf-api/src/web/preferences.rs` 通用偏好文档。
- 关键词排查覆盖设置备份恢复、导入导出、下载上传、模板导出、工作流导出、查询导出、检查点恢复等语义，区分业务对象导出与偏好备份。

## 一、前端自有设置

前端设置页为单路由 `routes/settings/+page.svelte`，按页签分为外观、快捷键、执行默认值、通知、工作区五节。页头文案已明确双轨语义：外观与工作区为本地即时生效，执行与通知为服务端跨设备行为，需手动保存。

### 本地首绘轨：存浏览器本地存储，不调后端

以外观与壳几何为核心，键为 `wf-ui-preferences`，由 `lib/stores/preferences.svelte.ts` 持有。字段包括主题、外观密度、侧边栏折叠与宽度、检查器宽度与是否常驻、Minimap 模式、工具输出是否摘要及详细档位。主题与密度通过 CSS 变量在首屏内联脚本中提前应用，避免闪烁。密度另派生字号与圆角比例。

快捷键覆盖独立存储，键为带版本号的本地键，类型为动作编号到替代键位字符串或禁用标记的映射。注册表负责合并默认值与覆盖，校验与冲突查找，编辑器为 `ShortcutsSettings.svelte`，文案明确仅存本浏览器。动作目录目前为全局与画布两类共十余项，涵盖帮助、命令面板、转录首尾、画布适配、布局、缩放、聚焦、编辑、保存草稿、撤销重做、全选与删除。

除设置页外，前端还有多处本地约定：会话显示名、最近会话与未发送草稿；文件检查点面板的执行者输入；工作流单写锁的浏览器身份；接口密钥与接口基地址解析；纯内存的视口与面板开关状态。这些不经过统一设置页，但属于前端自有状态。

工具输出显示预算为本地偏好驱动的常量，compact、balanced、verbose 三档分别对应不同的行数与字符数预算，注释明确 balanced 与 TUI 默认对齐。命令表、执行页签、会话页签、导航与虚拟化配置为硬编码展示配置，无用户可改项。

### 服务端跨设备轨：调后端偏好文档接口

由 `lib/services/preferences.ts` 与 `lib/stores/behavior.svelte.ts` 承载。行为对象仅四个字段：分页大小、列表自动刷新、流尾跟随、减少动态效果。文档键分别为执行分页大小、执行自动刷新、执行流跟随、外观减少动态效果四个点分键。接口为偏好文档整体读取与整体替换，后端仅校验键字符集、条目数与文档大小，不解释语义。设置页对该节提供脏检查、离场拦截、保存与恢复默认能力，服务端不可达时控件禁用。

### 资源开关：可写但非偏好

资源页的模型与工具台为只读运维台，读取模型画像、供应商、工具、脚本与技能列表，技能与工具的启用禁用为运维操作，会失败回滚并提示，不是用户偏好，不进入上述两轨。

### 共享界面包无设置

`apps/ui/src` 仅为受控基础组件与设计变量，不持有状态、路由与存储，不读写本地存储，主题变量仅定义不消费。设置页消费其按钮、卡片、开关、下拉与未保存对话框等受控组件。

## 二、TUI 自有设置

核心分层结论为低层包不依赖统一配置、不读命令行参数，只定义纯数据类型、内置默认与终端探测。真正的用户可配置来源全部在命令行外壳。

### 低层包：纯数据与探测

键位抽象定义键、和弦、动作、上下文与键位表，附带各上下文内置默认绑定。设置屏快照定义本地设置与画像行，仅做只读渲染，值由外壳组装。复制策略定义默认复制目标与拒绝原因，解析时考虑终端能力与环境变量强制开关。性能策略定义重绘帧率、动画帧率、装饰动画、鼠标捕获、键盘增强、交替滚动、同步输出与简化渲染等开关，另有缺省关闭鼠标捕获、环境变量关闭动画、按连接与终端能力降级等规则。工具输出配置定义总开关、各类预览行数与字符预算、块字节上限与详细档位，内置默认与前端 balanced 同值。主题定义颜色结构与覆盖结构，解析顺序为显式文件、终端探测、缓存、内置深色，最后应用覆盖，另有深浅模式解析与缓冲适配。动画定义动画、弱化、静态三态与控制器，动态偏好探测考虑系统减少动态效果与终端类型。终端能力定义键盘、粘贴、焦点、同步输出、颜色深度、超链接与剪贴板等探测结果。编辑器交接仅处理外部编辑器挂起恢复，无编辑器选项存储。底部状态、事件、帧节拍等为纯运行时状态，不持久化。

### 外壳：三处真实来源

第一为用户文件 `~/.config/wf/tui.toml`（内核独占同目录下的 `config.toml`，归属划分见 `tui-kernel-config-separation.md`），对应结构为行为、终端、精简展示与工具输出四节。行为节为鼠标捕获与会话滚动条两项显式开关，默认关闭。终端节为复制目标可选项。精简节为 Markdown 呈现、是否显示推理、用量、工具生命周期与审批超时。工具输出节为总开关、各类预览预算、块上限与档位，缺键逐项回退，坏文件整体回默认。路径遵循桌面规范，加载器负责读，管理器负责写。

第二为键位覆盖，唯一走统一配置的 TUI 设置。全局与项目两级键位文件合并，解析为上下文、动作与和弦三元组，未知上下文或动作跳过告警，合并进内置键位表，并记录覆盖行供帮助显示。

第三为命令行参数、环境变量与运行时状态。参数包括界面开关、日志、颜色、智能体、模型、会话、恢复、超时、历史文件、展示开关、远程、密钥与运行期审批等。其中模型与智能体选择对应前端资源页的只读画像列表。展示类参数解析顺序为命令行、环境变量、文件、默认。运行时另有模型、画像、智能体、会话、滚动与提示等内存状态。

## 三、缺口分析

### 功能缺口

前端缺 TUI 已有能力：无鼠标捕获、会话滚动条、复制目标、终端剪贴板开关、工具输出细粒度阈值、主题文件与覆盖、精简展示开关、审批超时、模型命令行选择等。前端工具输出仅三档预设，不能逐项调行数与字符预算。前端无语言设置，文档语言硬编码。前端无字体族设置，仅有密度派生的字号比例。前端快捷键仅覆盖应用与画布动作，无 TUI 侧的审批、问题、面板、模态等上下文动作。

TUI 缺前端已有能力：无主题三态跟随系统的首绘切换界面，无密度三档界面，无侧边栏与检查器几何记忆，无分页大小、自动刷新、流尾跟随等跨设备行为界面，无快捷键录制界面。TUI 设置屏为只读快照，不能在屏内改值，改值依赖直接编辑文件或特定切换动作。TUI 无通知预览与无障碍减少动态效果的统一开关界面，相关能力分散在动画、动态偏好与环境变量中。

双方共缺：无语言、字体、代理、存储、沙箱、安全策略等编辑界面，这些目前只属于后端统一配置或运维文件。智能体参数、模型画像详情、工具全局配置、检查点策略、执行限额等后端字段在两端均不可编辑，前端仅只读或开关，TUI 仅选择编号。

### 集成缺口

存储碎片化最突出。同一语义存在四种载体：浏览器本地存储、TUI 用户文件、服务端偏好文档、主题缓存与覆盖文件。主题、密度、工具输出、快捷键、减少动态效果在两端各有独立实现与独立默认值，仅靠注释或数值巧合对齐，无共享契约。外观减少动态效果在服务端文档中以行为语义存储，前端首屏外观永不进服务端，TUI 动画另走环境变量与系统探测，三者语义相近但互不感知。

快捷键双轨不互通。前端为动作编号到热键字符串的本地覆盖，TUI 为上下文到动作到和弦的全局与项目文件合并，动作集、字符串格式、上下文划分均不同。帮助文案在前端已从注册表生成，在 TUI 仍需从键位表反查补齐，迁移尚未覆盖全部运行时硬编码路径。

键位设计文档已过时。早期方案称前端不支持自定义、TUI 未接入键位表，现已部分落地：前端已有覆盖存储与编辑器，TUI 已有用户键位加载合并。文档未更新，导致新人按旧图施工会重复造轮子。

后端统一配置与两端无编辑闭环。后端装配涵盖存储、指标、输出、沙箱、文件检查点、审批、预设、工具与限额，另有模型画像、智能体循环、技能与键位等域，但两端均无对应编辑界面。服务端偏好文档有意不解释语义，虽利于前端自治，但也意味着跨端语义只能靠前端约束，缺乏后端校验。

## 四、前端导入导出配置现状

结论为前端备份恢复能力已落地：设置页可移植性分区覆盖本地偏好、快捷键覆盖与服务端行为文档的导出导入，校验与落盘前置，版本恒为一。

设置页的恢复仅指两处：服务端行为回默认值并整体写回，单键回默认。均为重置语义，非文件导入。

真实存在的导入导出均为业务对象，与偏好无关：模板按种类导出下载，模板库按段导出下载，模板导入为种类限定的结构文本框；工作流按编号导出下载，画布另有图片导出；查询结果导出下载；文件预览下载；检查点恢复为按检查点编号恢复执行状态。这些走附件下载通道，绕过统一信封，与设置无关。

命令行侧仅有 TUI 本地文件写回，无导出界面。后端键位与模型配置的写文件能力为启动引导用，无前端调用。服务端偏好接口仅支持整文档读写与单键读写，无备份专用端点，但整文档读写已足以支撑备份组合，无需新增后端接口。

## 五、补充方案

### 目标与约束

目标为让用户能在浏览器之间迁移与备份自有设置，包括本地首绘轨、快捷键覆盖与服务端行为文档，操作入口在设置页，格式为单个可读文本文件，版本保持为一，不做历史兼容与迁移逻辑。未知版本、未知键、类型错误一律拒绝并提示，不静默丢弃、不自动修复。修改只动原模块，按职责拆分命名，不建替代模块。校验与落盘前置，不引入外部网络与完整性校验字段。验证集中在一次前端检查与一次后端编译检查。

### 范围界定

导出内容为三部分：本地偏好对象、快捷键覆盖对象、服务端行为对象。会话草稿、最近会话、锁身份、接口密钥、内存界面状态不进入备份，避免泄露密钥与污染他机状态。工具输出预算由档位派生，不单独导出预算数值。导入时按同范围整体替换，服务端部分经现有整体替换接口写回，本地部分经原存储的保存路径写回并重放应用。

TUI 文件与主题覆盖文件不进入浏览器备份。若需覆盖 TUI，由命令行侧的导出导入命令另行处理，保持职责边界，避免浏览器直接读写用户目录。

### 前端改动

设置页头在服务端节之外新增可移植性分区，放置导出与导入两个动作。导出动作为收集三部分当前值，组装为带版本标记的备份对象，触发浏览器下载，文件名含日期以便辨识。导入动作为文件选择后读取文本、解析结构、校验版本与字段白名单，校验通过后展示确认对话框，列出将被替换的三部分摘要，确认后先写本地两轨并重放主题与密度，再写服务端文档，任一步失败即停止并保留错误提示，不做部分回滚之外的自动修复。

可移植性职责独立为服务模块，命名体现备份组合与校验，不与加载保存职责混淆。校验规则为版本必须为一，本地偏好仅接受已知枚举与数值区间，快捷键覆盖仅接受已知动作编号与合法键位字符串或禁用标记，服务端行为仅接受已知四键与合法类型。损坏的本地存储仍按原逻辑回默认，不因备份功能改变。

用户体验要求为导出永不因服务端不可达而禁用，导入在服务端不可达时明确提示服务端部分将暂缓，需用户确认仅恢复本地或稍后重试。导入成功后提示重启无关，主题密度即时生效，服务端行为按原脏检查逻辑标记为已保存。

### 命令行改动

在原命令行共享配置管理器职责内扩展导出导入能力，不新增配置体系。导出为将用户文件整体序列化输出到指定路径，导入为读取指定文件并经原解析路径校验后写回原路径，坏文件拒绝写回并报错。键位文件与主题覆盖文件不在此次命令范围内，仅在帮助文本中说明位置，避免范围蔓延。TUI 设置屏保持只读，仅在屏内增加命令提示文案，指向命令行用法。

### 后端改动

无需新增接口与表。复用偏好文档的整文档读写，备份文件不经过后端解释。文档大小与条目上限已能容纳行为对象，备份文件本身不存后端。若后续需要跨设备自动同步本地偏好，再议服务端键扩展，不在本次实施。

### 测试与验收

前端为备份组装与校验的单元测试，覆盖正常往返、版本拒绝、未知键拒绝、类型错误拒绝、损坏存储回退。交互测试覆盖导出下载触发、导入确认、服务端不可达提示。命令行 for 配置管理器的读写往返测试已存在，补充导入拒绝坏文件的用例。验收标准为设置页可完成导出导入闭环，刷新后生效，服务端文档一致，坏文件有明确错误无崩溃。验证集中为一次前端检查与一次全特性编译检查，不分散多次编译。

## 落地顺序

先补前端可移植性服务与校验单测，再接设置页分区与确认对话框，然后补命令行导出导入命令与帮助文案，最后更新键位设计文档中的过时结论并补充本方案的备份格式说明。文档更新与代码同批提交，避免再次出现实现与方案脱节。

落地现状为上述顺序已走完：可移植性职责独立为备份组合校验服务，设置页新增可移植性分区，命令行共享配置管理器扩展导出导入能力并配备份子命令，键位设计文档过时结论已订正。主题目录碎片亦已随分离方案收敛，不再另立目录。
