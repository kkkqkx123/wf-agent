# 信息架构与页面布局对比

本文比较三套前端在「应用外壳 → 页面容器 → 图工作流 / 执行实例页面」三个层级上的组织方式。所有结论只针对本次代码快照。

## 1. 对比口径

| 层级 | 当前项目 | n8n | Dify |
| --- | --- | --- | --- |
| 应用外壳 | `AppShell` + `Sidebar` + `TopBar` | `BaseLayout` 具名插槽 + CSS grid | Next.js App Router 布局 + 画布内绝对定位 |
| 页面容器 | `PageHeader` + `SplitView` | `PageViewLayout` / `WorkflowLayout` | 画布容器 + 右侧面板 + 底部面板 |
| 图工作流 | 工作流详情页的一个 Tab | 全屏画布页 + 底部日志面板 | 全屏画布 + 浮动 Header + 右侧节点面板 |
| 执行实例 | 列表页（双栏）+ 详情页 | 列表/预览双栏 + 画布日志 | 独立日志页表格 + 右侧 Drawer |

## 2. 应用外壳

### 2.1 当前项目：组件内写死三栏

`AppShell` 固定渲染 `Sidebar`、`TopBar`、`main`，并按 `aside` snippet 是否存在决定第四列（`apps/web-app/src/lib/components/layout/AppShell.svelte:92-113`）：

- 左栏：`Sidebar`，支持 3.5rem 折叠 rail，hover 弹出 15rem 浮层（`Sidebar.svelte:14`、`:28-31`、`:72`），宽度可由 `preferences.sidebarWidth` 覆盖（`:101`）。
- 顶栏：`TopBar`。
- 主区：`min-h-0 min-w-0 flex-1 overflow-hidden`（`AppShell.svelte:103`）。
- 右栏：`hidden w-80 shrink-0 ... lg:flex xl:w-96`（`AppShell.svelte:107-113`），窄屏改为 `Sheet`（`:124`）。

这意味着外壳只有「有/无 aside」两种形态；aside 宽度、位置、层级都写死在组件内。页面若需要 footer 面板（例如画布下方日志）、overlay 层或 banners，需要自己在外壳外再包一层。

`SplitView` 在页面内部再切一次主区/检查器（`apps/web-app/src/lib/components/layout/SplitView.svelte:82-84`、`:108-158`）：

- 检查器默认宽度来自 `preferences.inspectorWidth`，可拖拽 1.5px 手柄调宽（`:128-130`）。
- 支持 `dual` 双检查器，用于 A/B 对比（`:20`、`:84`）。
- 窄屏时检查器变为 `Sheet`（`:176-195`）。

因此当前项目的页面骨架是「应用三栏 + 页面内可拖拽检查器」两层嵌套。

### 2.2 n8n：插槽化 + grid areas

`BaseLayout` 用 CSS grid 定义 `banners / header / sidebar / content / footer / aside` 六个区域（`docs/ref/n8n/packages/frontend/editor-ui/src/app/layouts/BaseLayout.vue:17-54`）：

```
grid-template-areas:
  'banners banners banners'
  'sidebar header aside'
  'sidebar content aside';
grid-template-columns: auto 1fr auto;
```

每个区域仅在对应插槽存在时渲染（`BaseLayout.vue:17-37`），`overlays` 插槽独立于 grid（`:37`）。这让「画布页没有侧栏」「执行页有 footer 日志」「设置页有 aside」都能由页面自身声明，而不需要改外壳。

`WorkflowLayout` 是插槽组合的具体示例（`docs/ref/n8n/packages/frontend/editor-ui/src/app/layouts/WorkflowLayout.vue:101-122`）：

- `#header` → `AppHeader`
- `#sidebar` → `AppSidebar`，`v-if="!isCanvasOnly"`（`:105`）
- 默认插槽 → `RouterView`
- `#footer` → `LogsPanel`，`v-if="layoutProps.logs"`（`:115-116`）
- `#overlays` → 助手浮层 / 聊天浮层（`:118-121`）

`isCanvasOnly` 直接决定侧栏是否出现（`WorkflowLayout.vue:28`），因此「画布专注模式」不需要复制一套布局。

`PageViewLayout` 负责普通内容页的统一容器（`docs/ref/n8n/packages/frontend/editor-ui/src/app/components/layouts/PageViewLayout.vue:8-36`）：

- `.wrapper { max-width: var(--content-container--width); padding: var(--spacing--lg) var(--spacing--2xl) 0 }`（`:24-27`）。
- `sm-and-down` 降为 `--spacing--sm`（`:30`）。
- `fullWidth` 时取消最大宽度、改用 `--spacing--md`（`:34-36`）。

### 2.3 Dify：画布即页面，面板绝对定位

Dify 的工作流页没有传统三栏外壳，画布容器直接占满可用区域（`docs/ref/dify/web/app/components/workflow/index.tsx:640`）：

```tsx
<div id="workflow-container" className="relative isolate h-full w-full min-w-240 overflow-hidden">
```

在此容器内：

- Header 绝对定位在顶部，并带自上而下的渐变遮罩：`absolute top-7 left-0 z-10 flex h-0 w-full ... bg-mask-top2bottom-gray-50-to-transparent px-3`（`docs/ref/dify/web/app/components/workflow/header/index.tsx:28`）。
- 右侧面板绝对定位：`absolute top-14 right-0 bottom-1 z-10 flex`（`docs/ref/dify/web/app/components/workflow/panel/index.tsx:124`）。
- 运行面板从底部展开（`docs/ref/dify/web/app/components/workflow/run/index.tsx:183-213`）。

这种「画布为底、所有 UI 浮在上面」的模型与当前项目的「外壳 + 页面容器」模型相反：Dify 的画布不会被 header 挤压，视觉上更沉浸，但也要求每个浮层自行处理层级、遮挡与窄屏。

## 3. 信息架构

### 3.1 当前项目：全局导航分组 + 页内 Tab

- 左侧导航分 8 组（`apps/web-app/src/lib/config/navigation.ts:20` 起）：overview / conversation / execution / orchestration / state / integration / insight / workspace，每组可含 `segments` 子 Tab（`:5-12`）。
- 工作流详情把「图 / 编辑 / 版本 / 草稿 / 运行」放在同一页的 `Segmented` 中（`apps/web-app/src/routes/workflows/[id]/+page.svelte:44-48`），并用 `?tab=` 同步（`:51-59`）。
- 执行详情把「概览 / 消息 / 变量 / 图 / 追踪 / 时间线 / 工具 / 分析 / 状态 / 层级 / 历史 / 检查点」放在右侧 Inspector 的 `Segmented` 中（`apps/web-app/src/lib/config/execution-tabs.ts:9-21`）。

该结构的优点是「一个实体一个 URL，所有维度都在同一页」；代价是画布与执行日志不能同时可见，且 Tab 数量多时首屏之外的信息发现成本高。

### 3.2 n8n：画布是工作流的一等页面

- 工作流的编辑、执行、日志都在同一个画布路由内；执行记录是工作流页的子路由，列表/预览双栏（`docs/ref/n8n/packages/frontend/editor-ui/src/features/execution/executions/views/WorkflowExecutionsView.vue:141-145`）。
- 节点配置通过 NDV 模态层完成，而不是切换页面（`docs/ref/n8n/packages/frontend/editor-ui/src/features/ndv/shared/views/NodeDetailsView.vue:761-772`）。
- 执行日志通过 `#footer` 常驻画布下方（`WorkflowLayout.vue:115-116`），可用快捷键 `l` 切换（`Canvas.vue` keyMap，随 `LogsPanel.vue:95` 的 `j/k/space/enter` 共同构成画布内操作闭环）。

n8n 的 IA 更接近「编辑器即工作台」：画布是主语，执行、日志、配置都是画布的附属面板。

### 3.3 Dify：应用详情下分 workflow / logs 两个一级页面

- 画布页与日志页是并列路由（`web/app/(commonLayout)/app/(appDetailLayout)/[appId]/{workflow,logs}`），日志页用表格 + 抽屉展开单次运行（`docs/ref/dify/web/app/components/app/workflow-log/index.tsx`、`list.tsx:154-162`）。
- 画布内再通过底部 RunPanel 展示「本次运行」的结果/详情/追踪（`run/index.tsx:183-213`），通过右侧 NodePanel 展示「选中节点」的配置与最近运行（`workflow-panel/index.tsx:637-792`）。

Dify 的 IA 是「历史看日志页、当下看画布底部、单节点看右侧」，三层职责分明。

## 4. 列表与详情的布局关系

| 场景 | 当前项目 | n8n | Dify |
| --- | --- | --- | --- |
| 工作流列表 | 主区卡片网格 `sm:grid-cols-2 xl:grid-cols-3` + 右侧摘要检查器（`routes/workflows/+page.svelte:161-231`） | 项目内工作流列表（本次未纳入快照对比） | 应用列表（本次未纳入快照对比） |
| 执行列表 | 主区卡片/表格切换 + 右侧检查器，可 `dual` 对比（`routes/executions/+page.svelte:307-490`） | 310px 固定侧栏 + 右侧预览（`WorkflowExecutionsSidebar.vue:262`、`WorkflowExecutionsList.vue`） | 独立页面表格 + 右侧 Drawer（`workflow-log/list.tsx:154`、`detail.tsx`） |
| 工作流详情 | 顶部 Header + 5 Tab，图 Tab 内再分画布与节点/边明细（`routes/workflows/[id]/+page.svelte:44-48`、`WorkflowGraphTab.svelte`） | 全屏画布 + NDV + 底部日志 | 全屏画布 + 右侧节点面板 + 底部运行面板 |
| 执行详情 | 独立路由 + 右侧 12 Tab Inspector（`routes/executions/[id]/+page.svelte`） | 工作流内预览面板 + 画布日志 | 日志抽屉内嵌 RunPanel |

一个直接后果：当前项目的「列表 → 详情」是路由跳转，n8n 是列表内选中预览，Dify 是页面内抽屉。三者在「返回时是否保留筛选/滚动位置」上的体验差异，主要来自这个结构选择。

- 当前项目通过 `?tab=` 与 `SplitView` 保留页内状态，但跨路由返回依赖浏览器/框架行为。
- n8n 的筛选通过 `filtersKey = workflow:{id}` 持久化并在组件建立前恢复（`WorkflowExecutionsView.vue` 中 `executionsStore.restoreFilters`），且选中项直接在 URL 的 `executionId` 中。
- Dify 的日志页筛选在页面 state 中，抽屉关闭即回到表格。

## 5. 内容宽度与密度

### 5.1 当前项目

- 列表页主区使用卡片网格，无显式最大宽度；密度由 `Card`、`gap-2`、`px-3 py-2.5` 等控制（`WorkflowCard.svelte`、`ExecutionCard.svelte:45`）。
- 检查器宽 22.5rem（`app.css:81`），可拖拽；`dual` 时两个检查器并排。
- `PageHeader` 在各页顶部，meta 与 actions 分区。

### 5.2 n8n

- 普通内容页统一 `--content-container--width`，并保留 `--spacing--2xl` 横向留白（`PageViewLayout.vue:24-27`）。
- 执行侧栏固定 310px，预览区自适应（`WorkflowExecutionsSidebar.vue:262`）。
- 画布全屏，不使用内容宽度令牌。

### 5.3 Dify

- 画布全屏，最小宽度 `min-w-240`（`workflow/index.tsx:640`）。
- 右侧节点面板有最小 400px、最大自适应夹紧（`workflow-panel/index.tsx:615-620`、`panel/index.tsx:109`）。
- 日志页表格 `min-w-110`，外层按页面宽度滚动（`workflow-log/list.tsx:162`）。

## 6. 响应式策略

| 断点 | 当前项目 | n8n | Dify |
| --- | --- | --- | --- |
| 桌面 | 三栏 + 可拖拽检查器 | grid 六区 + 面板 | 画布 + 浮层 |
| 中等 | 侧栏可折叠为 rail（`Sidebar.svelte:28`） | `sm-and-down` 收紧 padding（`PageViewLayout.vue:30`） | `tablet: 640px`、`pc: 769px`（`tailwind-core.css:38-41`） |
| 窄屏 | 侧栏与检查器改 `Sheet`（`AppShell.svelte:124`、`SplitView.svelte:176`） | 执行列表/预览改纵向 `flex-direction: column`（`WorkflowExecutionsList.vue`） | `mobile: 100px` 断点，面板宽度夹紧 |

当前项目的移动端策略更统一（都走 `Sheet`），n8n 更依赖媒体查询局部调整，Dify 则把断点作为主题令牌暴露。

## 7. 结论

1. **外壳扩展性：n8n > 当前项目 > Dify。** n8n 的具名插槽让「页面声明区域」成为惯例；当前项目的 `AppShell` 只有 `aside` 一个可选区；Dify 干脆放弃外壳，把布局责任下放给画布。
2. **画布沉浸感：Dify ≈ n8n > 当前项目。** 当前项目画布位于 Tab 内，顶部还有 PageHeader 与 Segmented；n8n 有全屏画布但保留 header/sidebar；Dify 画布铺满并用渐变遮罩隐藏边界。
3. **多维信息并存能力：当前项目 > n8n > Dify。** 当前项目能在同一详情页并列 graph/trace/timeline/analysis 等维度；n8n 依靠画布 + 底部日志 + NDV；Dify 受限于三 Tab。
4. **状态保持：n8n 最完整。** 筛选持久化、选中项在 URL、列表内预览，三者共同降低「返回后重新定位」的成本；当前项目依赖路由与 Tab 参数；Dify 依赖抽屉开关。

## 8. 可执行建议

- 若要保持当前项目的信息密度，优先把「图」与「执行日志」从互斥 Tab 改为可并存的上下分区（参考 n8n `WorkflowLayout` 的 footer 模式），而不是继续增加 Tab。
- 为列表页补一个「选中即预览」的窄屏替代方案，避免每次查看详情都丢失筛选上下文。
- 把 `AppShell` 的 `aside` 扩展为具名插槽（`banners` / `footer` / `overlays`），可在不改变现有页面的前提下支持画布页的沉浸模式。
- 统一内容宽度令牌，避免每个页面各自决定留白。
