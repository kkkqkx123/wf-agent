# 浏览器保留键清单与替换建议

> 范围：`apps/web-app` 终端页与 IDE 内嵌终端（含 lazygit 会话）
> 上游方案：`docs/plan/terminal-tui-capability.md`（按键绑定一节）
> 定位：该方案中“随附的键位重映射预设”的文字版，只定方向，不改代码

浏览器保留键是终端 TUI 改造中唯一的硬顶。页面 JavaScript 对这类按键要么根本收不到键盘事件（浏览器在派发前截获），要么收到也无法用阻止默认行为取消浏览器动作。xterm 收不到键，lazygit 自然无法响应，只能把冲突的缺省键位换走。本清单先把三档按键划分清楚，再给出与 lazygit 缺省键位的冲突对照与替换建议。

## 保留键清单

### 第一档：页面收不到，任何重映射都救不回来

浏览器在事件派发前直接截获，页面监听器完全无感知，禁止用于任何自定义：

| 按键 | 浏览器行为 | 覆盖面 |
|------|------------|--------|
| 标签页向前 / 向后切换 | 在多个标签页之间切换 | Chromium、Firefox 均不派发；Safari 同为标签页切换 |
| 开发者工具（功能键与 Ctrl、Shift 组合） | 打开元素检查与调试面板 | Chromium、Firefox 均不派发到页面 |
| 操作系统级组合（关闭窗口、退出应用、安全注意序列） | 关窗口、退应用、系统接管 | 全平台先于浏览器执行 |

### 第二档：页面收到但阻止无效，终端可用性为零

键盘事件能到达页面，但阻止默认行为会被浏览器忽略，浏览器动作照常执行。TUI 按下这类键会同时触发浏览器行为（新标签页、关标签页、地址栏聚焦、整页重载），同样禁止用于自定义：

| 按键 | 浏览器行为 | 说明 |
|------|------------|------|
| 新建标签页及其“重开已关标签页”变体 | 新建 / 恢复标签页 | 含 Shift 变体 |
| 新建窗口（含无痕）与关闭标签页、关闭窗口 | 开关窗口与标签页 | 含全部 Shift 变体 |
| 地址栏聚焦（控制键、Alt 组合与功能键三种形态） | 焦点跳到地址栏 | 三种形态行为一致，均不可拦截 |
| 页面重载与硬重载（控制键、功能键及其 Shift 变体） | 整页刷新 | lazygit 会话状态随页面一起丢失 |
| 收藏全部标签页、清除浏览数据 | 书签管理与数据清理 | 同属 Shift 加控制组合象限，见替换原则 |

### 第三档：页面可拦截，终端正常可用

事件到达页面且阻止默认行为有效，xterm 照常收到，TUI 可直接使用：

- 除第二档之外的全部控制加字母组合（复制、保存、打印、查找、过滤、补丁选项、提交移动、挂起除外挂起无 Web 语义等）。
- 除地址栏聚焦之外的 Alt 加字母组合。
- 全部可打印单键、方向键、翻页键、行首行尾键、回车、退出、制表键与其 Shift 组合。
- 帮助功能键（多数环境可阻止默认行为，个别环境需实测，见灰区）

Safari 上浏览器界面多为 Cmd 组合，而 TUI 使用 Ctrl 组合，两者天然错开；Safari 的历史导航对应 Cmd 加方括号，与 Ctrl 组合无冲突。Safari 用户只需同样避开第一档与第二档。

### 灰区：随版本与平台有差异，上线前实测

| 按键 | 现状 | 实测方法 |
|------|------|----------|
| 下载页组合 | 各家能否拦截不一致 | 终端聚焦按下，观察是否跳页且字符是否进入 TUI |
| 历史导航组合 | Chromium 可阻止，Safari 对应组合不可 | 同上，Safari 用其对应组合验证 |
| 帮助功能键 | 多数环境可阻止，个别精简环境先行 | 同上 |
| 全屏功能键 | 多数环境直接进全屏 | 终端页不依赖全屏，默认不使用 |

## 与 lazygit 缺省键位的冲突对照

对照依据为 lazygit 缺省键位中文速查表的控制键清单（复制、外部工具、日志菜单、补丁选项、路径过滤、空白开关、挂起、状态过滤、基准查找、网址复制、提交上下移、最近仓库、配置编辑，以及确认取消、面板切换与 Shift 选择）：

| lazygit 缺省键 | 动作 | 落档 | 结论 |
|----------------|------|------|------|
| 外部工具组合 | 外部 difftool 打开 | 第二档（新建标签页） | 必须换 |
| 空白开关组合 | 切换是否显示空白字符差异 | 第二档（关闭标签页） | 必须换 |
| 日志菜单组合 | 打开日志菜单 | 第二档（地址栏聚焦） | 必须换 |
| 最近仓库组合 | 切换到最近的仓库、重置已拣选的提交 | 第二档（页面重载） | 必须换 |
| 复制、保存、打印、查找、提交上下移、状态过滤、基准查找、网址复制、滚动、挂起 | 各面板对应动作 | 第三档 | 保持缺省 |
| 配置编辑组合 | 编辑配置文件 | 第三档 | 保持缺省 |
| 确认、取消、面板切换、Shift 加方向扩展选择 | 弹层与选择 | 第三档 | 保持缺省 |
| 标签页切换组合 | 无 lazygit 缺省绑定占用 | 第一档 | 用户自定义时禁用 |

其中复制、保存、打印、查找组合虽然在浏览器里各有对应功能（打开文件、保存网页、打印、页内查找），但页面拦截有效，终端可正常收到，不在替换之列。挂起应用在 Web 无对应语义，直接丢弃，无需替换。

## 替换建议

### 替换原则

- 只动冲突的四个，其余全部保持 lazygit 缺省手感，不做预防性重映射。
- 同字母换修饰：控制键改 Alt 键，字母不变，好记且单手可达；Alt 加字母无浏览器保留含义（地址栏聚焦的 Alt 组合除外，四个建议均不命中）。
- 不迁入 Shift 加控制组合：该象限多为浏览器保留（关闭窗口、无痕窗口、开发者工具、书签管理、硬刷新），是重灾区。
- 不使用页面收不到的组合（标签页切换）与重载、地址栏聚焦类组合做替换目标。
- 替换只需避开浏览器保留键，无需避开本应用快捷键：IDE、Git 页与应用壳全局热键在终端聚焦时均已豁免，终端拥有全部按键。

### 候选空间比较

四个动作需要四个空位，先看有哪些空间可选：

| 候选空间 | 优点 | 否决或降级理由 | 结论 |
|----------|------|----------------|------|
| Alt 加同字母 | 与原键同字母，好记；缺省键位仅占用一个 Alt 加 Shift 组合，Alt 加单字母空间完全空闲，无需逐条审计；单手可达；桌面两大平台浏览器均可拦截 | macOS 默认 Option 产出字符而非修饰，见下节说明 | 首选 |
| Ctrl 加其它字母 | 修饰不变，只换字母 | 干净字母只剩一个：行编辑圣键不可动，作业控制与浏览器保留占去一批，控制字符别名不可用，不确认空闲且无助记；四个动作放不下 | 否决 |
| 功能键 | 可拦截 | 笔记本需组合功能切换键，macOS 默认为媒体键；日志菜单是高频动作，人体工学差 | 否决 |
| 裸键单键 | 无需修饰 | 二百余个已被占用，任意挪用必撞已有绑定 | 否决 |
| 双键序列 | 无 | 绑定为单击模型，无序列语义 | 否决 |
| 前端翻译（拦截后再转码发送） | 无 | 冲突键到不了页面，物理不可行；非冲突键翻译会与用户自有配置打架 | 否决 |

控制键空间放不下四个，是 Alt 方案胜出的硬原因：除已被占用的十余个控制组合外，行首行尾与逐字删除类圣键不可动，作业控制类不可动，浏览器保留类不可动，控制字符别名类不可用，剩下的干净字母不够分，还丢掉了同字母助记。

### 建议对照

| 原缺省键 | 动作 | 建议键 | 取位理由 |
|----------|------|--------|----------|
| 外部工具组合 | 外部 difftool 打开 | Alt 加同字母 | 同字母对应工具首字母 |
| 空白开关组合 | 空白字符差异开关 | Alt 加同字母 | 同字母对应空白含义 |
| 日志菜单组合 | 日志菜单 | Alt 加同字母 | 同字母对应日志首字母 |
| 最近仓库组合 | 最近仓库、重置拣选 | Alt 加同字母 | 同字母对应最近与重置含义 |

统一规律为控制键整体平移到 Alt 键，四个一次记住。若用户环境 Alt 键被输入法或远端桌面占用，次选为控制加 Alt 加同字母（个别 Linux 桌面占用该象限，降级使用）。

### 用户自定义禁区

| 禁止使用的组合 | 原因 |
|----------------|------|
| 标签页切换及其 Shift 变体 | 页面收不到 |
| 新建与关闭标签页、窗口及其 Shift 变体 | 阻止无效，会丢会话 |
| 地址栏聚焦三形态 | 阻止无效，焦点逃逸 |
| 重载与硬刷新 | 阻止无效，会丢会话状态 |
| 开发者工具组合 | 页面收不到 |
| 收藏全部标签页、清除浏览数据 | 同属保留的 Shift 加控制象限 |

### macOS 说明

macOS 上浏览器界面操作多为 Cmd 组合，控制组合的冲突面显著小于桌面另两大平台，四个缺省键建议逐个实测：能用的沿用缺省，无需为统一而统一套用 Alt 预设。确需在 macOS 使用 Alt 预设时，需先启用 Option-as-Meta（将 Option 视为修饰键），否则 Option 加字母产出的是字符而非修饰组合，绑定不会触发。同一预设在 macOS 上保留无害，只是未启用的修饰位不生效。

### 是否为前端内置默认映射

结论是不内置，预设以本文档为准，用户按需取用。前端已完成的部分是键位归属：终端聚焦时应用内快捷键全部豁免，用户配置的任何键位到达终端后不再被应用壳吞掉。内置默认映射的四条路均走不通：

| 方案 | 做法 | 否决理由 |
|------|------|----------|
| 环境变量注入 | 经会话环境变量指定配置文件路径 | 后端仅接受 GIT 前缀（防注入），放开需改后端并扩大安全面 |
| 快捷命令带参 | 快捷入口改带参启动并指向服务端配置文件 | 快捷命令即为可执行文件本身且无 shell 包裹，路径需服务端预置而前端不可见；文件缺失即启动失败，破坏缺 binary 降级；还会覆盖用户自有配置 |
| 前端键位翻译 | 拦截冲突键再转码发送 | 冲突键到不了页面，物理不可行 |
| 后端预置默认配置 | 服务端随包一份默认键位 | 后端范围，多用户归属不清，与用户自有配置冲突，且方案限定不动后端 |

保持“缺配置不降级”：没有预设时用户停留在缺省键位，只是四个动作在浏览器里不可用，其余全部功能正常；预设是用户所有的个人配置文件，按操作系统取用本文不同小节即可。

### 落地方式

在用户侧 lazygit 配置文件的键位段按上表逐项重映射，不改前端代码。目标环境缺 binary 时终端页仍可普通使用，缺键位预设同样不降级：用户停留在缺省键位，只是四个动作在浏览器里不可用，其余全部功能正常。
