# Rust 客户端同步方式

> 范围：`crates/app/wf-client`
> 状态：基于当前代码的静态整理

## 1. 构建期生成

同步发生在构建脚本中，不入库任何生成文件。构建脚本读取后端快照，在内存中完成规范降级后调用生成器，经格式化写入构建输出目录，库源码以包含方式引入。快照与降级源码变更都会触发重建，因此编译产物天然与快照一致。

依赖仅出现在构建期，运行时不携带生成器。降级源码同时被构建脚本与库内单测引用，保证两者使用同一变换逻辑。

## 2. 规范降级

后端快照为新版规范，生成器只接受旧版规范，因此需要内存降级。变换限定四类：版本号改写、可空表达折叠、流式操作剔除、无内容错误响应剔除。

可空折叠处理数组式类型与组合式空分支，统一为可空标记。流式操作按成功内容类型识别并剔除，交由手写流式层承担。无内容错误响应在保留至少一个正文响应的前提下剔除，以满足生成器对单错误类型的要求，运行时仍经状态映射处理对应状态码。

降级模块限定为测试期编译，正式构建不再包含，避免死代码常驻。

## 3. 手写包装

生成产物只提供原始操作与模型命名空间，对外门面由手写层承担：

* 连接与身份：基础地址解析、请求键与业务目录的标志与环境优先级、目录头默认注入、请求客户端复用。
* 强类型优先：常用操作提供具名包装，内部拆开信封后返回视图或载荷；新调用点优先使用生成客户端或具名包装。
* 兼容查询入口：动态查询与透传载荷保留通用查询入口，按保留原因使用，内部经单一发送通道统一处理信封。
* 目录双通道：可设请求头通道走默认头，不可设请求头通道走查询参数拼接，两者共用同一编码规则。

信封拆包经通用载荷提取完成，空载荷按可选与必选分别处理。类型化调用的错误经专用映射保留服务端错误码与消息。

## 4. 错误映射

错误映射在手写信封路径与生成器路径之间共享，保证行为一致。鉴权失败单独表达，稳定业务码原样透出，通用缺失折叠为未找到，其余状态按默认码归一。无正文传输失败走状态兜底映射。

## 5. 流式与远端

流式端点由手写层拥有，不进入生成。端点表集中维护已知流式路径与会话快捷路径，发送与接收经字节流解析为帧，再解码为执行帧或系统帧。端点表有快照对照测试，流式集合漂移即失败。

远端传输只做系统命令组装与基础地址解析，不拼接远端命令，不实现私钥处理。隧道配置承载端口转发与启停参数，解析优先级为显式标志、活动隧道条目、通用远端环境、本地默认。

## 6. 调用分布

命令行各形态经由本客户端访问服务端，不内嵌执行能力。管理类命令同时使用类型化调用与兼容查询入口，交互形态的流式会话走手写流式层。兼容入口占比仍高，后续新增调用点应优先类型化，存量迁移按域逐步进行。
