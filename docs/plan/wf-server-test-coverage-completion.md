# wf-server 测试覆盖补齐实施设计

> 范围：`crates/app/wf-server` 的单元测试与集成测试。目标是把当前集中在基础设施层、薄弱在 HTTP 领域层与启动链路的测试结构，补齐到可稳定守卫传输契约与关键状态迁移的程度。

## 现状判断

静态盘点显示 `wf-server` 已有 313 个单元测试与 9 个集成测试，但分布很不均衡。`server_config`、`directory`、`envelope`、`middleware`、`static_files`、`openapi`、`ws`、`detached` 与 `backends/*` 已经有密集测试；`openapi.rs` 还通过快照与源码级路由一致性测试护卫了路由和文档不漂移。

缺口集中在三处：

- 二进制入口 `main.rs` 没有测试，配置覆盖、环境变量解析与失败退出完全裸奔；
- SSE、路径提取器、票据授权、WebSocket 纯协议函数缺少直接单测；
- API 领域层有 47 个非平凡文件没有任何测试，且现有集成测试只覆盖 metrics、静态托管和双节点备份恢复。

## 补齐原则

- 测试边界停在传输层：验证路由、提取、包络、鉴权、流协议与关键状态映射，不重复测试 `wf-api` 和引擎内部语义。
- 优先使用内存上下文和路由器直连测试，避免依赖外部服务；只有必须验证真实进程行为时才启动二进制。
- 不按 OpenAPI 操作数量机械堆测试；按风险选择代表性路径，覆盖成功、参数错误、不存在、禁用与越界。
- 新测试统一使用 `expect`，不使用 `unwrap`；修改进程级状态的测试必须串行或避免共享状态。

## 实施任务

### 任务一：启动配置与路径提取单测

在 `main.rs` 补充日志级别/格式解析、`env_usize`、运行时配置合并、`WF_USER_GIT_ENABLED` kill-switch 与存储覆盖的单测。在 `extract.rs` 补充路径结构体与占位符命名兼容性的反序列化单测。

验收：非法值与合法别名都有断言；配置优先级和 kill-switch 语义有明确断言；不需要启动真实运行时。

### 任务二：流协议单测

在 `sse.rs` 补充响应头和帧格式测试，区分 engine 事件与普通执行流事件。在 `ws.rs` 补充订阅目标解析、通知类型集合、重连游标编解码与事件帧字段的单测。

验收：帧名、事件名、游标和数据字段一旦漂移即失败；非法订阅输入返回无目标。

### 任务三：鉴权与票据单测

在 `ticket.rs` 补充票据铸造授权、过期裁剪、容量裁剪和认证豁免路径的单测；复用现有的一次性消费与 scope 测试。

验收：marker、Origin、配对与流握手路径的判定都有断言；票据存储不会无限增长。

### 任务四：请求映射单测

在 `api/fs.rs` 补充路径默认值与目录归属检查；在 `api/system/backends.rs` 补充 upsert 请求解析；在 `api/conversation.rs` 补充版本条件映射与流帧名称映射。

验收：路径逃逸、空名称、非法 entry、取消原因和 reasoning chunk 的映射有稳定断言。

### 任务五：路由级 API 契约集成测试

新增 `tests/http_api_contract.rs`，使用内存上下文构造完整 API 路由器，覆盖以下代表性路径：

- 未知工作流、未知执行体、非法 JSON 的统一错误包络；
- 实体变量 CRUD 往返；
- 模板库只读列表；
- 会话创建、快照、分支标签与删除；
- 工作流执行状态与分析路径的未知执行体映射；
- backend 管理面未启用时的 503。

验收：所有断言检查状态码与 `success` / `error.code`；成功路径检查回显标识与删后不可见。

### 任务六：鉴权与票据握手集成测试

新增 `tests/http_auth_stream.rs`，构造启用 API key 的中间件配置：

- 缺失或非法 key 被拒；
- 合法 key 能铸造事件流票据；
- 票据在事件流握手处一次消费成功、二次消费失败；
- 缺少 marker 的票据铸造请求被拒。

验收：断言覆盖中间件拒绝、处理器拒绝和票据一次性语义；不建立永久挂起的完整流消费。

### 任务七：CLI 失败退出集成测试

新增 `tests/server_cli.rs`，通过二进制入口验证非法日志参数、非法存储规格与未知参数会以非零退出，且错误信息输出到 stderr。

验收：失败路径不依赖运行时 bootstrap，不启动监听端口。

## 不在本轮范围

- 真实的 SIGTERM、SSH tunnel、PTY 子进程收敛与双节点新场景：这类用例成本高且已有相邻测试覆盖主体逻辑，后续按需补充。
- 为所有 731 个 OpenAPI 操作逐个建立测试：由路由一致性测试和契约测试共同守卫，不做低价值重复。
- E2E 脚本黄金输出补齐：属于 `wf-headless` 客户端链路，与本章的 Rust 测试门禁分开推进。
