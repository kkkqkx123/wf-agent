# 子 Agent 分发后查看功能设计

现状对比对象为 `ref/opencode` 与 `ref/atomcode`，分析目标为当前项目后端、前端、TUI 对同类问题的处理方式，并给出可借鉴的设计方向。

## 现状事实

### opencode 的做法

分发模型是显式的子会话。`packages/core/src/tool/plugin/subagent.ts` 定义 `subagent` 工具，输入含目标 agent、任务描述、提示词、可选模型与会话复用标识、是否后台运行；执行时沿 `parentID` 链检查嵌套深度，解析目标 agent 并做权限断言，新建以父会话为 `parentID` 的子会话，标题取任务描述。前景模式阻塞等待子会话完成并返回其输出，后台模式立即返回运行中句柄并配合作业系统做完成通知。子会话作业由 `session/subagent-job.ts` 与 `session/subagent-completion.ts` 承接，后台完成时向父会话写入一条来源标记为子 agent 的合成消息，前端渲染为可点击的完成提示行。

事件模型区分持久与瞬时。持久事件按会话聚合落库，含会话创建、执行起止、步骤与文本起止、工具输入与调用结果、合成消息等；瞬时事件只走直播流，含文本增量、推理增量、工具输入增量与工具进度，其中子 agent 派发进度通过工具进度事件携带子会话标识，不落库。服务端通过事件订阅做每个连接的丢弃式队列，通过会话日志接口支持按位置重放加跟随，客户端数据层在收到创建、工具进度与成功、合成消息、执行起止等事件时刷新会话族，并提供按父标识拉取子会话与解析根会话的能力。

查看侧分完整 TUI 与迷你 TUI 两层。完整 TUI 将合成消息渲染为可点击跳转的子会话完成行，子 agent 工具行展示目标与模型，支持父子会话间导航快捷键与子 agent 列表页，可中断指定子会话，权限与表单按会话族在根上聚合。迷你 TUI 用跟踪器从父工具元数据、会话族广度遍历、活跃映射与外来事件血缘四路发现子会话，对外来子事件做缓冲后按子会话归约，支持从消息与收件箱历史重建详情快照，快照按运行优先排序并附带阻断的权限与表单。网页侧几乎无实时查看，仅文档与分享页提及父标识，程序化接口可按父标识列子会话。

### atomcode 的做法

分发模型是组合而非内核类型。内核只定义通用工具上下文、进度发送端与工具进度事件，子 agent 由上层用普通 agent 加受限工具箱组合实现。主路径为进程内 `task` 工具：派发时解析子模型与工作量，构造受限工具集与独立提示词注册表，创建挂在父下的子 agent，设最大轮数后驱动其运行至回合结束，再把轮数、工具调用数、终止原因汇总为父工具结果返回，过程中向父进度通道发送首行摘要与完成标记。另有常驻型 `team` 负责多成员协作，`parallel_edit_files` 按文件扇出，以及可调用外部二进制的子 agent 后端。

事件模型分两轨。`task` 类走非结构化字符串：滚动区用符号前缀区分排队中、运行中、完成与失败，瞬时活动行用不可见分隔符前缀标记并在进入网页链路前被守护进程剥离；`team` 类走结构化团队事件，含运行开始、成员排队与开始、活动量、完成与运行结束，带运行标识、序号与代际标签。内核到界面的扇出经由后台转发器把内核事件转为界面事件。

查看侧以折叠归约为核心。界面状态持有当前子任务进度、可选的瞬时活动串与团队投影，子任务进度含调用标识、完成计数与条目表，每条含标签、描述、模型、活动、起止时间、令牌与工具使用量及状态。`task` 工具调用开始时按参数预置面板并压制通用工具行，后续工具进度增量按调用标识归入面板，终态行进入滚动区并冻结耗时；团队事件按代际与序号去重后更新同一面板的另一视图，页脚在待办面板活跃与否之间选择展示位置。命令行与无头模式丢弃进度只留起止与结果，网页端把工具进度事件就地更新到工具行的进度字段，不持久化。

### 两者对比

| 维度 | opencode | atomcode |
|---|---|---|
| 分发抽象 | 一等子会话，父子标识链可遍历 | 组合实现，子日志挂父标识但不进列表 |
| 后端事件 | 持久与瞬时分离，进度事件带子会话元数据 | 通用进度字符串加结构化团队事件双轨 |
| 发现机制 | 会话族同步加血缘回溯 | 调用标识关联加会话族遍历加外来缓冲 |
| 详情重建 | 消息与收件箱历史重建 | 消息历史重建面板快照 |
| 中断 | 按子会话标识中断 | 按父取消令牌派生子令牌取消 |
| 网页查看 | 几乎缺失 | 工具行就地进度更新 |
| 完成通知 | 合成消息加后台作业通知 | 父工具结果汇总加终端冻结行 |
| 脆弱点 | 会话导航与作业恢复链路重 | 字符串前缀解析脆弱，团队代际逻辑复杂 |

## 当前项目的处理方式

### 后端

`call_agent` 与 `execute_workflow` 为内置工具，`wait` 为真时同步执行并返回结果，为假时后台派发返回可轮询的句柄，父子关联通过调用点捕获的类型化父链接传递，含执行标识、层级管理器与取消信号，深度门限与文件作用域继承在执行器入口统一处理。流协议在三层均已定义子 agent 起止事件：`wf-agent/src/stream.rs` 的引擎事件、`wf-types/src/events/stream_event.rs` 的客户端事件、`wf-api/src/infra/stream.rs` 的适配，以及工作流内嵌 agent 环节的重发布分支。但生产路径从未发送这两个事件，调用链上只有定义、映射、测试与界面消费，没有发送点；触发式嵌套走钩子起止而非流事件。子执行的增量内容停留在子执行内部，父流只看到外层工具起止，外层工具调用标识与子执行标识之间没有关联字段，不携带深度、提示预览、后台标记与进度量。层级管理器与执行层级查询接口存在，但只服务于事后查看。

### 前端

`apps/web-app` 的流解析器已把子 agent 起止帧路由为 `onSubAgent` 回调，运行存储以瞬时备注列表持有，聊天会话以轮询投影将其映射到决策图节点高亮与检查器面板的运行态徽标。工具调用卡片把 `call_agent` 按普通工具卡渲染，展示输入与折叠输出。执行层级面包屑与子树树、检查器层级页基于层级与子树接口做事后查看，与直播无关。备注列表在下一轮开始时清空，不落盘，来访者刷新即失。预览应用为镜像实现，行为一致。

### TUI 与命令行

` tui-core` 的统一事件与归约器均已识别子 agent 起止，但归约结果只做计数加减，不产生可回放的提交，页脚仅在计数大于零时追加提示。完整交互表单把起止渲染为两行提示文本，`wf-mini` 在标准错误输出同类单行，`wf-cli-shared` 的流命令打印起止标识，无头渲染器明确忽略这两类事件。子 agent 与外层工具块之间无视觉归属，详情、进度、中断入口均缺失。

### 核心缺口

按严重程度排序，首要是后端从不断流，全部下游为空转；其次是缺少工具调用与子执行的关联键，界面无法把子状态挂到正确的工具卡下；再次是子进度不可见，父工具卡在同步等待期间呈不透明长耗时；最后是瞬时态不可重建，刷新、重连与回放丢失子视图。

## 可借鉴的设计

### 后端可借鉴之处

向 opencode 借用父子关联显式化。子派发应在工具运行器层面围绕子执行发送起止事件，起止负载在现有标识与名称之外补齐外层工具调用标识、子执行标识、深度与是否后台，并在开始时携带任务描述或提示预览的截断。深度检查沿用现有层级管理器，不新增并行体系。同步与后台两种等待语义保留，后台句柄应与起止事件中的子标识一致，使轮询与流观察指向同一执行。

向 atomcode 借用进度发送端与调用标识绑定。子执行的关键里程碑经由父链接回流为父流上的子进度事件，至少含迭代边界、工具起止摘要与令牌用量，避免初期就全量转发子增量文本。取消沿用现有父取消信号派生，不引入新的作业恢复机制。opencode 的后台作业持久化与重启恢复、atomcode 的字符串标记协议与团队代际序号机制均不建议引入，前者超出当前查看需求，后者以脆弱解析换取兼容，不如已有的类型化事件扩展。

分阶段建议为先补生命周期与关联键使计数与列表活起来，再补里程碑进度使等待可见，最后才考虑子增量透传与按子会话钻取。透传阶段可参考 opencode 的历史重建思路：详情按需拉取子消息历史，而非默认全量合流。

### 前端可借鉴之处

向 atomcode 借用就地更新。`call_agent` 工具卡应成为子视图的宿主，起止与进度事件按工具调用标识归入对应卡片，卡片内展示状态、耗时、迭代与用量，终态展示结果摘要。多个并发子按开始顺序堆叠，单个子收起时只留状态行。

向 opencode 借用会话族与根解析思路。异步派发返回的执行标识应可点击，点击后跳转到执行详情或层级树中的对应节点，复用已有的层级与子树接口做按需加载，不常驻全量子流。瞬时备注保留为过渡态，最终以工具卡归属取代轮询投影。决策图高亮与检查器徽标保留为轻量提示，不作为主视图。

### TUI 可借鉴之处

向 atomcode 借用页脚面板。归约器应在计数之外维护活跃子列表，含标识、名称、归属工具调用、状态与起止时间，页脚在有活跃子时展示为独立面板而非单行计数，支持有限条数与超出折叠。滚动区为子起止保留结构化块而非纯文本行，使搜索、回放与调试记录可见。

向 opencode 迷你跟踪器借用发现与重建。归约与渲染按工具调用标识优先关联，缺失关联时按时间窗口内的活跃子回填；重连后按子标识拉取子消息历史重建面板，不要求服务端补发瞬时事件。中断入口挂在子面板行上，复用现有取消执行能力。无头与 `wf-mini` 标准输出保持现状，仅在显式展示工具时输出单行，避免污染机器可读输出。

## TUI 内子 agent 跳转

### 键盘操作（本期落地）

跳转目标是子 agent 起止行，而非工具输出体。状态侧在工具块表旁新增子 agent 块表，以子执行标识为键并保留到达顺序，启动时记录摘要序列号，结束时补记结束序列号与成败，未结束的块以启动行为目标。现有起止事件已带标识，可直接作为键使用；名称仅用于展示与通知。

寻址复用工具块的序列号机制。滚动偏移语义不变，跳转换算为目标序列号到尾部的距离，找不到目标时保持当前视口并给出提示，不做静默回尾。子块被截断回收时按工具块同例丢弃记账，避免悬空跳转。

键位选择空闲的 `Ctrl+G`，含义为在子 agent 起始行之间跳转。首次按下跳到最近一个子起始行，连续按下按到达顺序向更早的子移动，尾部操作或新事件到达后重新从最近开始。返回尾部复用现有 `Ctrl+End` 与空输入 `End`，不新增回尾键。历史浮层内同一键作用于浮层行集合，分页与回尾语义保持现有行为，浮层重放页需给子行分配序列号，否则浮层内跳转无目标可寻。

生效范围与工具键一致，处于会话屏的页脚各视图下均可用。无子块时按键为空操作，可附带一行提示而非常驻报错。帮助文案与现有工具键并列说明，避免用户把该键误解为输出展开。

### 鼠标操作（并入长期方案）

子 agent 起止行的点击跳转并入 `docs/plan/long-term/mouse-click-expand-design.md` 一起立项，细节以该文档为准，本处只定契约。命中帧在工具摘要矩形之外另行发布子起始行矩形，附带子标识与是否可跳转，不可跳转的不发布。点击语义等价于键盘跳转到该子起始行，不做展开与查看器。遮罩、弹窗、加载占位下不发布子命中区，窄屏下随行隐藏而消失。捕获开关、代际校验、`Shift` 还原生、选区补偿与性能预算沿用该文档的既有约定，不另起一套。

## workflow 参与时的处理

workflow 通过两种通道参与子 agent，一是内嵌 agent 环节中模型调用 `call_agent` 派发子 agent，二是节点直接派发子工作流或子 agent。两种通道的父子归属统一走类型化父链接与层级管理器，使深度计数跨引擎生效，子执行同时出现在层级视图与子树查询中。内嵌 agent 环节已具备事件重发布分支，补齐子起止负载后即可把子状态带到总线，展示层无需区分子的直接父是循环还是节点。

分支同步与主子同步严格分开。`FORK` 派生的分支注册表与 `SYNC` 点等、`JOIN` 汇聚只服务于同一 `fork_id` 下的分支路径，不复用于 agent 子执行，避免分支变量合并语义污染子结果。主子等待需要新的原语，形态复用分支注册表的通知加超时加取消竞速，键改为子执行标识，唤醒源为子终态落槽或终态事件，后台派发句柄与该原语指向同一标识。查询轮询作为兜底保留，不删除。

进度归属上，子进度事件同时进入父流与工作流节点进度，前者用于工具卡与 TUI 面板，后者用于节点时间线与分支变量快照之外的轻量展示。子变量写回沿用触发式已有的结果变量快照与版本校验会话追加，不经过分支变量合并路径。

## 主子间通知工具与同步集成

### atomcode 的通知工具值得借鉴之处

atomcode 把同步子任务与常驻成员分开。同步 `task` 无通知工具，父阻塞等回合结束，子无提问对象；常驻 `team` 给成员挂载仅知首领标识的 `tell_parent` 工具，成员用其上报问题、进度与完工小结，首领侧按是否被问过来决定唤醒还是仅记入上下文，未显式上报的成员由完成监听器合成完工报告并去重。进度另有结构化团队事件承载成员活动量与完成摘要，摘要取结果首行截断。

可借鉴的四点为挂载方式、权限、去重与唤醒区分。挂载在派发时构造期捕获父标识，不做按名寻址，子不可见兄弟，从根上杜绝越权上报。风险定为安全级并常授作用域，数据面读写仍由既有角色工具集与委派通道约束，通知本身不授予写与寻址能力。完成合成器以前置上报标记去重，已上报的不再合成，避免双报。首领被问到时唤醒进入下一步，无人问时仅记入上下文，避免每个进度都打断父循环。

不可借鉴的是字符串前缀协议与团队代际序号机制，前者脆弱，后者为其历史包袱。已有类型化事件足以承载，直接扩展负载即可。

### 与 workflow 的集成方式

通知工具定位为子执行域内的专用工具，随子派发挂载，随子结束卸载，负载含父标识、子标识、所属节点与运行标识、种类（进度、提问、完工）与文本。提问类唤醒父并进入审批或问询通道，进度类只更新面板与节点进度，完工类写入结果变量快照并参与完成去重。父通过上述主子等待原语等子终态时，通知只做展示与上下文，不提前解除等待； fire-and-forget 的常驻子则靠通知唤醒父，实现与 `team` 一致的长驻协作。

同步语义保持两分。同步子沿用调用加等终态，结果直接作为工具结果返回；常驻子用后台派发加通知唤醒，不恢复已被删除的阻塞式团队等待，避免父循环死锁与转向能力丧失。`SYNC` 节点保持分支语义不变，新增的主子等待节点只等指定子标识并做结果变量映射，不做分支合并。取消沿用父取消信号派生，子失败不失败父，仅进入子终态与父工具结果的失败分支。

## 落地顺序与验收

建议按后端事件补齐、前端卡片归属、TUI 面板三步走，每步均可独立验收。首步以后，现有计数、单行提示与瞬时备注自动生效，可用一次同步与一次后台派发验证起止成对、标识一致、深度越界被拒、父取消连带子取消。次步以并发两子挂不同工具卡、刷新后按需重建为验收线。最后以页脚面板、中断操作与回放可见为验收线。后台完成通知、子增量全文透传与跨会话导航列为可选后续，不进入本次范围。

追加立项为键盘跳转先行，通知工具与主子等待随后，workflow 参与随两步一起覆盖。键盘跳转验收为连续按键在子起始行间前移、无目标时空操作、浮层内行为一致；通知工具验收为提问唤醒而进度不唤醒、已上报不双报、子不可见兄弟；主子等待验收为指定子终态解除等待、超时与取消按竞速语义结算、`SYNC` 与 `JOIN` 行为不变。
