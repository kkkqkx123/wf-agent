# Server 层需为 Web 前端补充的功能分析

> 范围：`crates/app/wf-server` 与 `crates/app/wf-api`。判定标准是功能清单中的前端需求是否找得到对应通道；找得到的只写接入约束，找不到的列为补充项。优先级按阻塞程度划分。
>
> 落地状态：本轮已完成剩余清单（见 `docs/issue`），阻塞级与高优先级无遗留。前端可按功能清单正式开工。
>
> 复核（对话优先翻转后）：翻转所需通道（回路流式、执行查询、收藏、统一搜索、偏好持久化）均在已落地范围内，无需新增后端补充项。中优先级仍随具体页面按需认领。

## 1. 阻塞级补充

### 1.1 统一分页包络

现状各列表统一回游标包络，含条目与 limit 与 offset 与是否有更多，默认 50 上限 500。总数不补，排序不收敛。过滤型与单亲列表已整体迁移，含执行与回路与工作流与检查点与触发器与任务与交互与消息与变量与作用域历史与工具与档案与模板与事件搜索。链与单视图结构不迁包络，改走封顶加截断标记。静态小枚举与单亲小集合保留裸数组并注明有界理由。

> 落地：共享分页写法覆盖全部过滤列表与事件搜索与审计分面，链与时间线走封顶视图。

### 1.2 契约发布

现状发布机器可读契约并随构建更新，覆盖路径与方法与请求响应形状与错误码。路由清单由生成器从源码派生，探针验证清单到路由的可达，反向漂移靠重生成加文件比对。形状为手工维护的说明，随契约一起发布。

> 落地：契约清单含自身路由，流式端点均为免探针，前端类型以契约形状为准，冲突时以服务端为准。

### 1.3 浏览器鉴权可用性

现状跨域允许头含自定义鉴权头并暴露限流头，流式与套接字通道与 REST 同受鉴权与限流约束。套接字鉴权同时接受头与查询参数。

> 落地：默认排除项仅健康与信息与根路径， shipped 配置与代码默认一致。

### 1.4 静态托管与单页回退

现状服务可选托管静态资源，未配置时为纯 API 模式。生产部署由服务端托管前端产物并做单页回退，接口未知路径保持空 404。

> 落地：三层静态目录配置与单页回退已启用。

### 1.5 文件内容通道

现状文件域提供内容读与目录树与分页变更与时间线，读操作带沙箱校验与大小封顶与二进制区分。目录树按路径排序后截断并带截断标记。写操作中重命名与会话为显式工作区操作，审批通道覆盖人机审批语义。

> 落地：只读三通道先行，旧裸数组路由已删除，调用方统一走分页变更。

## 2. 高优先级补充

### 2.1 批量操作

执行批量取消与删除、回路批量删除、交互批量响应、回路级变量批量写均已落地，单次上限一致，逐项返回成功与否。执行域保持 fail-fast 语义，回路级逐项不中断。交互批量支持可选回路归属校验。

> 落地：批量结果类型共享，空请求与超限一致拒绝。

### 2.2 收藏语义

星标与置顶与标签的读写通道已落地，前端本地收藏可迁移到服务端。

> 落地：服务端分页列表，持久性跟随已配置后端。

### 2.3 统一搜索

跨源统一分页搜索已落地，带分面与总数与不透明游标，含消息源扇出与回路归属，空查询拒绝。

> 落地：游标内部编码各源位点，下一页令牌可续。

### 2.4 大 dump 分页与流式化

审计汇总报告加硬封顶与截断标记与总量估计，分面通道做分页，错误分析中聚合型保持整篇加封顶，决策图路径枚举共用上限加截断标记，代理链与时间线走封顶视图。

> 落地：大执行下响应体积有界，前端配合虚拟化。

### 2.5 订阅面扩展

套接字订阅支持执行与回路与工作流与全局与通知维度，服务端协议心跳，流式通道支持取消与重连位点。通知为纯推送过渡，收到即消费，离线走 REST 重同步。在线状态 deferred。

> 落地：套接字与事件流共用不透明游标，重放窗口有界。

### 2.6 用户偏好持久化

主题与字号与布局等前端偏好已落地整档替换与单键读写，单用户全局文档过渡。

> 落地：持久性跟随已配置后端。

### 2.7 导出下载语义

查询导出与工作流与模板与变量与审计报告导出均支持下载模式，含内容类型与附件文件名与大小头。即席查询导出同时支持查询参数与请求体标记。批量导出与档案全量导出保持信封模式并在契约中注明。

> 落地：下载模式为服务端通用写法，契约注明两种模式。

## 3. 中优先级补充

- 触发器模板的启用停用、定时启停、构建期校验通道开放。
- 大模型供应商健康检查、请求排队取消、按档案的用量成本记账。
- 模板版本、发布下线、批量克隆删除。
- 技能安装卸载与版本管理。
- 已保存查询与仪表盘。
- 只读分享令牌（审计报告分享页需要访问控制）。
- 操作审计日志的按用户查询（现有日志偏运维视角）。
- 备份恢复、配置重载、版本迁移通道（现有运维通道只覆盖健康与诊断）。

## 4. 不建议补充

- 密码与 OAuth 登录会话体系：当前为单机 API 密钥模型，引入完整身份体系超出前端首期范围，维持密钥加代理即可。
- 计费与订阅：与执行计费无关，不为前端单独建账单模型。
- 多媒体生成模式：后端无对应生成能力，不建前端模式开关。
- 桌面专属能力：标题栏、托盘、防休眠与后端无关。

## 5. 推进顺序建议

阻塞级与高优先级已全部落地，中优先级随具体页面进入开发时按需认领，不提前铺开。每项启动前补一条现状与接入约束注记，保持文档与实现同步。
