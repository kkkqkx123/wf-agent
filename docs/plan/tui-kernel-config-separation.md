# TUI 与内核配置分离及多预设归属分析

本文回答两个问题：TUI 配置是否应独立成文件、把现有用户配置文件留给内核与服务端；各前端是否应共用同一套后端内核配置，还是各自按文件名指定多套预设。结论来自现状代码实测，修改只动原模块、不建替代模块、不做历史兼容。

## 一、现状实测

用户目录下存在同名文件复用问题。命令行展示配置与内核主机层共用同一路径，即用户全局目录下的通用配置文件与项目目录下的点文件。展示配置包含行为开关、终端复制目标、精简展示与工具输出四节，由命令行共享模块读写。内核主机层包含存储、日志级别与工具审批三节，由配置分层模块读写。两者结构体不同但路径相同，解析时互不知晓对方字段。

该复用已产生实际损害。展示侧的保存逻辑为读入后整体序列化写回，只写展示字段，文件中原有的内核字段会被丢弃。也就是说在 TUI 内切换一次鼠标或复制目标，就可能抹掉同文件中的存储与审批配置。展示侧加载失败时整体回默认，文件中任一语法错误会同时影响全部展示开关，内核笔误会波及展示，展示笔误虽被内核忽略但仍增加排查难度。

项目层行为亦不一致。内核层同时读取全局与项目点文件，项目获胜。展示侧只读全局文件，不读项目点文件。同一目录下键位配置已实现全局加项目两级合并，展示配置反而没有项目层，规则不统一。可读性方面，运维人员无法从文件名判断某节影响展示还是影响内核，文档也难以分工。

服务端在项目层已经分离。项目内的基础设施目录与服务目录各司其职，前者承载存储、指标、输出、沙箱、检查点、审批、预设、工具与限额，后者承载监听地址、静态目录与中间件。用户层没有服务传输文件，传输经命令行参数、环境变量与项目文件解析，密钥只走环境变量。该分层清晰，无需再拆。

主题归属已统一。展示配置、主题文件、主题覆盖与主题缓存同处用户应用目录，终端配置文件与主题文件并存，缓存文件亦归入同名应用目录，不再另立目录。

## 二、TUI 是否应独立文件

结论为应当独立，内核独占现有通用文件名。

新展示文件命名为交互终端配置文件，与内核文件同处用户应用目录。选择该名而非命令行或前端命名的原因是该文件实际服务于完整终端与精简终端两种交互形态，均为终端变体， headlines 工具不读该文件，网页前端不读该文件。键位与主题文件保持不动，仍各司其职。

分离后归属清晰。通用配置文件只承载内核主机层三节，终端配置文件只承载展示四节。展示保存不再触碰内核字段，根除误删。展示笔误不再牵连内核排查，内核笔误不再导致展示整体回退。项目点文件继续只服务内核，展示继续只读全局，差异由文档明确为有意为之：展示偏好跟人跟机器，内核配置跟项目走，键位项目覆盖为特例。

兼容策略为干净切换，不做回退与迁移。旧文件中残留的展示节会被内核解析忽略，新文件缺失时展示回内置默认。用户按需重建新文件。不保留双路径读取，不做自动搬运，避免遗留分支长期存在。

服务端不新增用户层文件。传输与中间件保持项目文件加环境加命令行的优先级，密钥仍只走环境。不为服务端在用户目录新增同名文件，防止与内核文件混淆。

## 三、前端是否共用后端内核配置

结论为各前端必须共用同一套后端内核配置，不存在客户端直传文件名指定内核文件的通道。文件名上行有三处硬伤：远端客户端与服务端文件系统根本不在同一台机器，客户端传路径服务端无法解析；路径字面量会把服务端目录结构泄漏到网络面上并引入越界读取风险；同名文件在客户端当前目录与服务端项目根下指向不同内容，极易出现客户端以为一套、服务端执行另一套的分裂，存储、审批与沙箱尤其危险。因此文件名永远不得出现在客户端到服务端的请求面上。

若未来确需按次切换后端能力，唯一可接受的形态是服务端维护注册表、客户端按注册名指定。注册表即现有索引机制：索引文件枚举候选，候选名到文件路径的映射只在服务端解析，网络上传输的仅为注册名。服务端收到注册名后在自有索引中查找，命中则装配，未命中则报错并返回可用名录，绝不接受路径、模式或通配符。本次只实现启动时注册名选择，即服务运维在启动参数中指定注册名，进程内仍为单例装配。按次切换本次不实现，原因有三：存储后端按次切换会分裂数据面；沙箱与限额按次切换需要多运行时并存，当前装配为进程单例；审批语义按次切换易被滥用。确需按次切换时，协议形态为请求体中的可选注册名字段，服务端按 turn 解析装配，路径永不上线。

## 四、修改任务

首项为展示配置文件改道。命令行共享模块的路径函数指向新终端文件名，并更新模块说明，明确内核文件与展示文件的分工。演示示例中的展示路径字符串同步更新。分层模块与运行时装配注释同步澄清通用文件仅属内核，避免后人误将展示节写回该文件。主题文件、主题覆盖与主题缓存同步归入同一应用目录。

次项为服务预设参数补齐。服务启动参数新增预设选项，语义为注册名而非文件名，透传至基础设施来源配置的预设名。缺省时保持现有默认行为，指定不存在的注册名时沿用现有装配报错路径并附可用名录，不新增错误类型。客户端不新增任何预设或文件参数，连接方式不变。

第三项为展示备份命令。共享配置管理器扩展导出导入能力，导出缺源时输出默认，导入先解析后写回，坏源拒绝且不动现文件；命令行新增备份子命令并复用同一校验路径，键位与主题文件不在命令范围内。

文档项为更新既有盘点文档中描述展示文件路径的段落，指向新文件名，并引用本文作为归属依据，防止实现与方案再次脱节。

## 五、验收

文件归属可读：用户目录下内核文件、终端文件与主题文件并存，各自只含所属节，终端内切换开关不再改动内核文件。服务预设可选：指定注册名时装配对应文件集，缺省时行为不变，不存在的注册名报错退出并列出可用名。展示可备份：导出导入经同一解析路径，坏源拒绝且不动现文件。请求面无文件名：客户端到服务端的任何请求均不携带路径，注册名仅在服务端索引中解析。验证集中为一次编译检查与受影响模块的单测，不分散多次构建。
