## 设计型（可边做边定，但最好在对应阶段开工前定）

### 输入栏（P3）

| # | 问题 | 选项 | 建议 | 影响 |
|---|---|---|---|---|
| **Q2** | 是否支持内联参数（`c "fix: bug"`） | 支持 / 不支持 | **不支持** | 支持则词元解析退化为小型 shell，复杂度失控；不支持则带参场景全走 CLI |
| **Q3** | 全局聚焦热键用哪个 | `Ctrl+/` / `Ctrl+K` / 其他 | **`Ctrl+/`** | 需先确认不与 `CommandPalette` 及浏览器默认行为冲突 |
| **Q4** | `soft` 级撤销窗口时长 | 5s / 8s / 15s | **8s** | 依赖 P4.7 的后端 undo 能力是否落地 |
| **Q5** | 是否保留 `legacyKey`（原 lazygit 键位）展示 | 保留 / 不保留 | **保留**（候选副标题 + 帮助面板） | 影响从 lazygit 迁移用户的上手速度，成本极低 |

### CLI（P5）

| # | 问题 | 选项 | 建议 | 影响 |
|---|---|---|---|---|
| **Q7** | 是否新增 `@xterm/xterm` 依赖 | 是 / 自研渲染 | **是** | 前端体积增加约 400KB（gzip 后约 130KB） |
| **Q9** | 终端空闲回收时长 | 10 / 30 / 60 分钟 | **30 分钟** | 太短会丢失用户 cwd 与上下文 |
| **Q10** | 是否做 GUI → CLI 命令回显 | 做 / 不做 | **P6 做** | 成本低（一个输出帧），教学价值高 |

### 后端（P1 / P4）

| # | 问题 | 选项 | 建议 | 影响 |
|---|---|---|---|---|
| **Q12** | 写操作超时 | 统一 15s / 分级（push·fetch 120s） | **分级** | 慢网络下 push 可能被误判超时 |
| **Q13** | 同一仓库写操作是否串行 | 串行锁 / 不锁 | **串行锁** | 防 `.git/index.lock` 冲突；代价是并发写需排队 |
| **Q14** | `destructive` 确认标识形式 | 目标分支名 / 短哈希 / 固定确认词 | **目标标识（分支名或短哈希）** | 影响弹窗文案与后端校验实现；固定确认词易被无脑复制 |
| **Q15** | git 动作是否纳入 `wf-api/audit` 审计域 | 纳入 / 不纳入 | **纳入** | 现有 audit 域已存在，接入成本低；不纳入则无法回溯谁改了仓库 |
| **Q23** | 中文路径与提交信息的编码处理 | 统一 UTF-8 并设 `LC_ALL` / 依赖系统默认 | **显式设 UTF-8 环境变量** | 不处理会导致中文路径在 `status --porcelain` 中被转义、提交信息乱码 |
| **Q24** | 超大仓库的性能边界 | 提交列表分页 + diff 截断 / 不限制 | **分页 + 截断** | 不限制时 `git log` 全量拉取会拖垮页面；需约定默认页数与 diff 最大行数 |

### 前端（P2）

| # | 问题 | 选项 | 建议 | 影响 |
|---|---|---|---|---|
| **Q16** | Git 页面放哪个导航组 | 新增 `Source` 组 / 并入 `Execution` | **新增 `Source` 组** | Git 与执行/工作流是不同心智模型，合并会稀释导航语义 |
| **Q17** | 是否用 URL 持久化面板与选中 | 用 `panel` / `tab` / 不用 | **用 `panel` + `tab`** | `route.ts` 的 `LIST_KEYS` 已含这两个 key，零成本 |

## 尚未评估的能力（明确不做，非开放问题）

以下 lazygit 能力在 Web 上无对应物或无价值，本方案**直接标记不可用**，不在待办中：

| 能力 | 原因 |
|---|---|
| 外部 difftool（`<ctrl+t>`） | 服务端无桌面环境 |
| 挂起应用（`<ctrl+z>`） | Web 无此语义 |
| PR 创建 / 打开 / 复制 URL（`o` / `O` / `G` / `<ctrl+y>`） | 无托管平台集成，超出本方案 |
| 最近仓库切换（`<ctrl+r>` 的一种语义） | 依赖 Q11；首期为单仓库 |
| git-flow（`i`，分支面板） | 低频，且 git-flow 本身已不主流 |
| snake（`Snake` context） | 彩蛋，无业务价值 |
