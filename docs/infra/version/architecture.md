# 版本架构设计

## 版本域

项目内存在五类相互隔离的版本概念，分属不同层级，不可混用：

| 版本域 | 载体 | 归属模块 | 取值 |
|---|---|---|---|
| 检查点格式版本 | 检查点元数据自定义字段中的格式版本 | 检查点基础模块的版本管理器，门面经检查点协调模块再导出 | 单整数一 |
| 存储表结构版本 | 每张业务表内一行特殊标识记录的版本号 | 存储域的键定义模块，双后端共用同一常量 | 整数一 |
| 文件历史表结构 | 文件历史数据库内按需创建的附属表 | 文件检查点存储的迁移模块 | 无版本号，幂等建表 |
| 工作流业务版本 | 工作流与智能体定义的版本标签 | 应用接口层的工作流版本模块 | 严格三段式主版本次版本补丁 |
| 接口协议版本 | 路由挂载前缀与信息接口返回的协议版本 | 服务端的路由组装与健康模块，前端健康存储做校验 | 主版本一 |

此外插件接口版本、大模型供应商协议版本、备份文档版本、调试轨迹模式版本各自独立，均为硬拒绝语义，不参与上述五域的演进。

## 模块归属与依赖

检查点格式版本能力集中在检查点基础模块，协调模块持有版本管理器并在创建时盖章、恢复时走迁移读取路径，上层只依赖协调门面。存储表结构版本常量定义在存储域键模块，关系型双后端在打开时共用同一检查逻辑，应用查询统一排除版本行。文件历史迁移仅做幂等表结构补齐。工作流业务版本逻辑集中在应用接口层的工作流版本模块，服务端版本路由为其传输封装。接口协议版本组装点唯一，开放接口快照与前端类型生成构成契约闸门。

## 演进预留

检查点版本管理器保留迁移处理器注册表与路径搜索能力，但开发阶段不注册任何处理器。存储层保留版本检查与拒绝分支，不提供升级脚本。文件历史保留轻量迁移入口，不做列级变更。接口层保留多版本挂载的扩展位置，但当前仅挂载单一主版本。上述预留能力在正式发布后才可启用，启用时需同步更新本文档与版本号。
