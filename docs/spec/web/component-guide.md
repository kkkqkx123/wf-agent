# Web 前端组件设计规范

> 适用 `apps/web-app`。组件借鉴 deeix 的原语广度与 zcode 的重型查看器，但分层与数据规则以本规范为准。

## 1. 分层模型

自下而上分为三层，上层可依赖下层，不得反向依赖：

- 原子层：按钮、输入、选择、开关、标签页、提示、浮层、弹窗、抽屉、表格、空态、骨架、快捷键展示。只收受众明确的展示属性，不感知业务域。
- 业务层：执行时间线、工具调用卡、审批卡、变量表、差异查看、产物预览、图 canvas、大纲导轨、位置小地图。允许感知单个域模型，禁止跨域拼装。
- 装配层：三栏 Shell、命令面板、设置分区、分享只读视图。负责路由、数据拉取、 store 装配，不做原子渲染细节。

## 2. 数据规则

- 域类型不得进入原子组件；业务组件接收已规整的视图模型，装配层负责适配。
- 服务返回的裸数组一律经适配层转为带总数与游标的分页模型，组件只消费分页模型。
- 流式数据经限速合并后写入 store；组件不得直接持有流读取器。
- 本地偏好（主题、字号、布局、收藏、草稿）走统一偏好通道，服务端补齐后整体迁移，组件不得直读写存储。

## 3. 原子组件要求

| 组件 | 要求 |
|---|---|
| 命令面板 | 命令、会话、文件统一入口，带历史与数量上限 |
| 表格 | 虚拟滚动、空态、分页脚，窄屏可降级为卡片 |
| 消息滚动器 | 自动跟随尾部、手动接管、回底按钮 |
| 弹窗与抽屉 | 焦点陷阱、遮罩关闭可配、移动端全屏降级 |
| Toast | 成功失败警告三类，错误附重试 |
| 快捷键展示 | 统一键名写法，冲突可提示 |

## 4. 业务组件要求

- 工具调用卡：按注册表类型渲染，不预置类型全集；未知类型走兜底原文展示，不得崩溃。
- 差异查看：复用同一差异组件，支持单文件与多文件；大差异分页加载。
- 产物预览：文本、代码、表格、图表、文档共用预览壳；白名单渲染，脚本默认沙箱隔离。
- 图：节点边渲染、缩放平移、选中详情、路径高亮；万节点以上只渲染摘要与按需节点。
- 时间线：虚拟化、手风琴默认收展规则（流式展开、结束收起）、错误节点可定位。
- 审批卡：请求上下文、风险提示、批准拒绝双操作，结果可追溯。

## 5. 状态与反馈

- 每个业务组件必须同时定义加载态、空态、错误态，不得只实现成功态。
- 危险操作组件必须内置二次确认，不得依赖调用方口头约束。
- 密钥类字段默认遮罩，禁止提供一键明文展示之外的复制原文能力；复制操作必须 Toast 回执。

## 6. 可访问性与键盘

- 所有可操作元素可聚焦可回车；弹窗遵循焦点陷阱与返回焦点。
- 全局快捷键收敛为搜索、命令面板、新建、回退四组以内；输入框级快捷键不得与全局冲突。
- 触控目标不小于常规行高；悬停才出现的操作必须同时提供聚焦可见路径。

## 7. 禁止事项

- 禁止在原子层引用路由、store、服务客户端。
- 禁止业务组件之间直接共享可变状态；共享状态一律上收到装配层。
- 禁止新增与现有组件仅差样式的近义组件；先扩展变体再考虑新组件。
- 禁止在注释中引用本规范的章节编号，注释只描述组件意图。
