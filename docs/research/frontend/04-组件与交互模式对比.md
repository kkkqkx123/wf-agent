# 组件与交互模式对比

本文比较三套前端在「组件职责划分、复用方式、交互反馈」上的差异，重点覆盖工作流与执行页面实际使用的组件。

## 1. 组件库与分层

| 项目 | 基础组件 | 领域组件 | 组合方式 |
| --- | --- | --- | --- |
| 当前项目 | `@wf-agent/ui`（Button/Input/Select/Dialog/Sheet/Segmented/DataTable/CursorPager/StatusBadge/Progress/Card/ContextMenu/Toast 等） | `lib/components/domain`（WorkflowCard、ExecutionCard、GraphExplorer、ExecutionInspector、RunsPanel 等） | props + snippet + 少量 `export function` |
| n8n | `@n8n/design-system`（N8nButton、N8nIconButton、N8nButtonList、N8nCheckbox、N8nHeading、N8nLoading、N8nTags、N8nActionDropdown、N8nSegmentControl、N8nResizeWrapper、KeyboardShortcutTooltip、N8nCallout 等） | `features/workflows/canvas`、`features/execution/{executions,logs}`、`features/ndv` | 具名插槽 + composables + Pinia |
| Dify | `@langgenius/dify-ui`（Tabs、Pagination、Drawer、StatusDot、Chip、Popover、IconButton、UserAvatarList、ResizeHandle、CodeEditor 等） | `app/components/workflow/*`、`app/components/app/workflow-log/*` | 组合式 React 组件 + Zustand + 自定义 hooks |

三者的共同点是「基础组件库 + 领域组件」两层；差异在扩展方式：当前项目以 props 为主，n8n 以插槽为主，Dify 以组合与 hooks 为主。

## 2. 卡片

### 2.1 工作流卡

当前项目 `WorkflowCard`（`apps/web-app/src/lib/components/domain/WorkflowCard.svelte`）：

- 名称 + `StatusBadge`（`:40`）。
- 描述 `line-clamp-2 text-caption text-muted-foreground`（`:43`）。
- 标签最多 3 个，超出显示 `+N`（`:48-53`）。
- 底部 meta：version、success rate、更新时间（`:64-72`）。

信息层级是「标题 → 描述 → 标签 → 元数据」，适合浏览型列表；没有主操作按钮，点击整卡进入详情。

### 2.2 执行卡

当前项目 `ExecutionCard`（`ExecutionCard.svelte`）：

- 名称 + kind 徽标 + `StatusBadge`（`:60`）。
- 短 id / 相对时间 / 时长（`:68-70`）。
- `Progress`（`:75`）。
- tasks 完成度、失败节点数、当前节点（`:82-95`）。

执行卡比工作流卡多一层「进度」，因此更适合「运行中」场景；但卡片整体是按钮（`w-full ... text-left`，`:45`），没有内联动作。

n8n 的执行卡（`WorkflowExecutionsCard.vue`）在同样信息外增加了：运行中 spinner、`retry #id`、annotation（投票 + tags）、右侧动作下拉、私密凭据/手动/评估图标。卡片本身承载了「查看 + 重跑 + 标注」三类操作。

Dify 没有执行卡，列表是表格行；单次运行的信息在 Drawer 内展开（`workflow-log/list.tsx:154`）。

### 2.3 对比结论

| 维度 | 当前项目 | n8n | Dify |
| --- | --- | --- | --- |
| 卡片职责 | 导航入口 | 导航 + 动作 + 标注 | 无卡片，表格行 |
| 信息密度 | 中 | 高 | 中（表格列） |
| 内联动作 | 无 | 重跑下拉、投票、标签 | 无（行点击开抽屉） |
| 批量操作 | 无 | 有（停止多个执行） | 无 |

## 3. 徽标与状态

| 项目 | 实现 | 特点 |
| --- | --- | --- |
| 当前项目 | `StatusBadge` + `Progress` tone | 统一、简洁；状态集合由组件内部决定 |
| n8n | 图标 + 颜色字典 + 行背景 | 8 状态（`GlobalExecutionsListItem.vue:76-112`），扫视效率高 |
| Dify | `StatusDot` + 语义色 + 文案 | 结果面板 7 状态文案（`run/status.tsx:96-114`），颜色与文案分离 |

n8n 把「状态 → 图标/颜色」做成显式字典，新增状态时必须补映射；当前项目把状态封装进 `StatusBadge`，扩展集中但列表层无法按状态做行级强化；Dify 用 `StatusDot` 承担颜色、文案单独渲染，组合更灵活。

## 4. Tab 与分段控件

| 项目 | 用法 |
| --- | --- |
| 当前项目 | `Segmented`：工作流详情 5 项（`routes/workflows/[id]/+page.svelte:44-48`）、执行详情最多 12 项（`execution-tabs.ts:9-21`） |
| n8n | `N8nSegmentControl` 用于日志概览的 overview/details 切换，默认隐藏、hover 才显示；NDV 用 `NodeSettingsTabs` |
| Dify | `Tabs`：RunPanel 3 项（`run/index.tsx:183-213`）、NodePanel settings/lastRun（`workflow-panel/index.tsx:771-793`） |

当前项目的 Tab 数量显著多于两家。Dify 的 Tab 文案统一 `system-sm-semibold-uppercase`，视觉一致；n8n 的 Tab 更偏「临时视图切换」，因此可以隐藏；当前项目的 12 项 Tab 在窄屏下会退化为横向滚动或换行，需要在组件层确认溢出策略（本次未看到专门处理）。

## 5. 面板与可调尺寸

| 项目 | 容器 | 调宽 | 视觉 |
| --- | --- | --- | --- |
| 当前项目 | `SplitView` + `Card` | 1.5px 手柄，宽度持久化（`SplitView.svelte:128-158`） | 边框 + 背景 |
| n8n | `N8nResizeWrapper` | 上/右/左三向，`grid-size: 8`，`min-width: 260`（`NodeDetailsView.vue:840-874`、`LogsPanel.vue:175-244`） | `border-top` / 背景 tint |
| Dify | `ResizeHandle` + `Tabs` | 左侧手柄，最小 400px，最大按画布宽度夹紧（`workflow-panel/index.tsx:615-620`、`panel/index.tsx:109`） | `rounded-2xl`、`border-[0.5px]`、`shadow-lg` |

n8n 的 resize 能力最通用（三向、栅格步进）；Dify 的面板视觉最「浮层化」（圆角 + 阴影 + 半像素边框）；当前项目的 SplitView 更像「分栏」而非「浮层」。

## 6. 筛选与输入

| 项目 | 形态 |
| --- | --- |
| 当前项目 | `FilterBar`：query 输入 + status 下拉 + engine 下拉（`routes/executions/+page.svelte:385-417`） |
| n8n | `ExecutionsFilter` popover：多字段、已选计数 badge、日期防抖、版本拉取（`ExecutionsFilter.vue:69-155`） |
| Dify | `Chip` + `SearchInput`：状态 chip、时间 chip（`filter.tsx:53-96`） |

当前项目的筛选是「常驻行内控件」，n8n 是「按钮 + popover」，Dify 是「chip 行」。常驻控件的可见性最好，但占空间；popover 最省空间且能承载复杂字段；chip 最适合少量枚举条件。

## 7. 空态、加载态与错误态

| 项目 | 加载 | 空 | 错误 |
| --- | --- | --- | --- |
| 当前项目 | `PageState` + skeleton shimmer（`app.css:160`） | `PageState` 空态 | toast + 页面错误态 |
| n8n | `ResourcesListLoadingState`、`N8nLoading`、`N8nSpinner`、`AnimatedSpinner` | `ResourcesListEmptyState` | `N8nCallout`、错误行背景 |
| Dify | `LoadingPlaceholder`（`workflow-log/index.tsx:113`） | `EmptyElement`（`:117`） | `StatusDot` + 错误文案 + `LargeDataAlert` |

当前项目把三类状态收敛到 `PageState`，一致性最好；n8n 的加载态更细（列表级/行级/按钮级）；Dify 用不同的占位组件区分页面级与数据级。

## 8. 浮层与模态

| 项目 | 模态 | 浮层 | 右键 |
| --- | --- | --- | --- |
| 当前项目 | `Dialog`（导入/新建）、`Sheet`（窄屏检查器/导航） | `ContextMenu`、`Sheet` | `ContextMenu`（`GraphExplorer.svelte:1363`） |
| n8n | NDV 用 `Teleport` + `<dialog aria-modal>`（`NodeDetailsView.vue:761-772`） | `N8nCallout`、协作 pill、助手浮层、日志 pop-out 窗口 | `ContextMenu` + `Suspense` 懒加载（`Canvas.vue:2229-2231`） |
| Dify | `Drawer`（右侧滑出，`list.tsx:154`） | `Popover`、`CommentThread`、`SyncingDataModal` | `WorkflowContextmenu` |

n8n 的 NDV 是「伪模态」：视觉上覆盖画布，但仍保留画布上下文（节点在浮层下方可见），并用 `aria-modal` 声明语义；Dify 的 Drawer 只用于日志详情，画布内配置用常驻面板。

## 9. 键盘与可访问性

| 项目 | 键盘 | ARIA |
| --- | --- | --- |
| 当前项目 | 全局帮助/命令面板；连线 `Escape`；按钮 `aria-label`（`SplitView.svelte:128`） | 局部 `aria-label` |
| n8n | 画布 keyMap（只读/编辑两套，`Canvas.vue:535-653`）；日志 `j/k/space/enter`（`LogsPanel.vue:95-104`）；`KeyboardShortcutTooltip` 展示快捷键（`CanvasControlButtons.vue:62-139`） | 日志行 `role=treeitem`、`aria-expanded`、`aria-selected`（`LogsOverviewRow.vue:185`）；NDV `aria-modal` |
| Dify | 独立快捷键定义表（`shortcuts/definitions.ts:29-112`）+ `shortcut-kbd` 展示 | `aria-expanded`、`aria-controls`（`tracing-panel.tsx:87-96`）；Tabs 组件语义 |

n8n 把「快捷键」做成可见的 tooltip 与 keymap 双层；Dify 把快捷键做成独立数据源，便于帮助面板与冲突检测；当前项目尚未形成画布级键位体系。

## 10. 协作与评论

| 项目 | 能力 |
| --- | --- |
| 当前项目 | `presence` 光标数据（`GraphCanvas.svelte:91`、`:1078`）；未看到评论模型 |
| n8n | 协作 pill、共享画布状态；无评论线程 |
| Dify | `UserCursors`（`workflow/index.tsx:805`）、`CommentManager` / `CommentCursor` / `CommentThread`（`:649`、`:684`）、节点面板 `UserAvatarList` presence（`workflow-panel/index.tsx:657`） |

Dify 的协作层次最完整：画布光标 → 节点面板「谁在看」→ 评论线程。当前项目已有光标通道，扩展到评论需要补数据模型与权限。

## 11. 结论

1. **当前项目的组件一致性最好，交互动作最少。** `PageState`、`StatusBadge`、`SplitView`、`FilterBar` 形成统一语言，但卡片/列表项缺少内联动作。
2. **n8n 的组件复用最「页面无关」。** 插槽 + composable 让同一画布既服务编辑、执行、只读、日志，又不需要分叉组件。
3. **Dify 的组件最「产品化」。** Chip、StatusDot、Drawer、Tabs、UserAvatarList 都是可独立解释的交互单元，组合出清晰的模式切换。
4. **可访问性投入不均。** n8n 在树形日志与模态上最完整；Dify 在 Tab/并行分支上补了 aria；当前项目仍以 `aria-label` 为主。

## 12. 建议

1. 给 `WorkflowCard` / `ExecutionCard` 增加 hover 动作区（打开、重跑、复制 id），避免所有操作都进详情页。
2. 将 `StatusBadge` 扩展为「状态字典 + 可选图标/行级 tone」，供列表与详情共用。
3. 把 `Segmented` 的溢出策略显式化（横向滚动 + 边缘渐隐），并支持分组标题，避免 12 项 Tab 在窄屏挤压。
4. 抽出 `ResizeHandle` 与面板容器，统一 `SplitView` / 未来画布侧栏的拖拽行为。
5. 建立画布快捷键定义表与 `ShortcutTooltip`，先覆盖高频动作。
6. 为日志/追踪行补 `role=treeitem`、`aria-expanded` 与键盘导航。
