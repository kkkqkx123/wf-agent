# 稀疏与多向量写入执行长期参考

本文是推迟项的立项参考，不是实现计划。正式实现之前，先重读立项门槛一节；
门槛未满足时，编码校验位保持现状，不动存储契约。

## 0. 结论速览

* 稀疏向量解决精确词面命中问题，多向量解决细粒度语义匹配问题，
  两者都是稠密单向量的补强，而非替代。
* 现有关键词混合通路已覆盖大部分词面需求，稀疏的增量价值必须用实测证明，
  不能用直觉立项。
* 正式实现是契约先行、后端逐个认领的顺序，管线消费最后接入。

## 1. 适用场景

### 稀疏向量

* 精确词面命中：型号、报错码、人名、法条编号等长尾实体，稠密嵌入
  容易语义漂移，词面权重能直接把含原词的块顶上来。
* 无嵌入模型可用的冷启动集合：稀疏表示可由词表直接构造，
  不依赖外部 embedding 服务。
* 成本与延迟敏感的召回：稀疏倒排检索通常比稠密暴力搜索便宜，
  适合做第一阶段粗排。
* 可解释性要求：词项权重天然可展示命中原因，稠密分数做不到。

### 多向量

* 长块内的细粒度匹配：单向量把整块压成一个点会丢失位置信息，
  查询只与块中一小段相关时多向量更准。
* 高精度问答：典型 late-interaction 做法以更大的索引与计算成本
  换取排序质量，适合对精度要求高于成本的集合。

## 2. 与现状的关系

* 关键词混合通路（关键词索引加稠密加融合）已覆盖“词面加语义”的
  主流需求，是稀疏要对比的基线，不是空白。
* 插件编码钩子当前只做形状校验，不改变写入；该校验位的意义是让
  未来的写入实现有明确的形状契约可对接，而不是默默存不透明文档。
* 稀疏的对手是关键词混合，多向量的对手是切分更细加父块提升；
  立项论证必须写清新方案赢的是哪一个基线。

## 3. 正式实现需补充的功能

* 契约 schema：把稀疏形状收敛为具名结构（有序索引数组加权重数组的
  合法性规则，如索引递增、长度一致、权重有限），替代现在的任意对象校验；
  多向量收敛为定内垫形状（每点向量数上限、单向量维度）。
  未经 schema 的写入一律拒绝，不做静默截断。
* 集合策略：集合声明新增向量种类（稠密、稀疏、多向量），维度与
  距离校验按种类分别执行；混用种类即建集合失败。
* 后端执行矩阵：内存、嵌入式与远端三个后端逐个认领稀疏倒排与
  多向量检索，未认领的后端对新种类集合返回明确不支持，而不是降级跑错结果。
* 摄取路径：编码插件输出经 schema 校验后写入对应结构；
  校验失败整批失败，不写半批数据。
* 查询路径：查询侧同样编码，稀疏走倒排、多向量走 late-interaction，
  结果与稠密、关键词统一进现有融合后再走建议与后处理。
* 插件形状：编码 trait 保持同步无副作用约定，输出契约从任意对象
  收紧为具名 schema；旧的宽松校验按开发期无兼容政策直接替换。
* 配置项：查询与摄取配置各加可选种类开关，缺省关闭时行为与改前一致。
* 评估：用现有命中率框架加裁判，对比基线（关键词混合、细切分）
  出增量报告，无增量不上线。

## 4. 立项门槛

以下任一满足时再立项，多向量与稀疏分别计数：

* 在真实集合上，候选方案相对最强基线有可复现的命中率或首命中排名提升，
  且成本增量在预算内。
* 出现嵌入服务不可用但仍需可检索的部署约束。
* 某后端原生支持稀疏或多向量，使执行矩阵的缺口只剩适配层。

## 5. 不做事项

* 不为假想的精度提升预留执行分支；校验位之外不加任何写入代码。
* 不把稀疏分数与稠密分数直接相加；跨尺度分数必须经归一化融合。
* 不在多向量实现前扩大块长度上限；用索引成本掩盖切分问题。
* 不做分布式分片与 gRPC 传输；那是另一篇长期参考的主题。
