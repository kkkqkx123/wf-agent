# 分阶段修改方案

> 本文件按依赖顺序组织改动，每步均可独立验收。文中不出现完整代码段，只描述改动点与验收方式。

## 实施顺序总览

| 步骤 | 主改动 | 验收 |
|---|---|---|
| 向量契约 | 新建 `vector-contracts`（已落地）：类型、过滤、存储契约、内存实现、simvec 适配、Qdrant REST 客户端 | 三后端各自跑通同组契约测试 |
| RAG 骨架 | 新建 `rag-core`（已落地）：文档模型、递归切分、摄入与查询管线、融合重排、引用 | 内存闭环问答跑通 |
| 集成 | 检索工具、提示词片段、工作流节点、外部 converter 端口 | Agent 可调用检索，工作流可编排查询，重格式走外部服务 |
| 质量 | 混合融合、重排、关系回填、引用 | 复杂问句命中质量可观测提升 |
| 规模 | simvec 嵌入持久化、增量更新删除、管理接口 | 重启不丢索引，来源级更新生效 |

步骤之间只允许向下依赖：集成步骤可用骨架能力，质量步骤可用集成形态，规模步骤可用质量管线。不允许跨步提前引入持久化或评估框架。

## 向量契约：三后端同契约（已落地）

改动点（`crates/infra/vector-contracts`，中立命名以便抽仓）：

- 类型、过滤、存储契约与内存实现，默认特性零重依赖；`simvec` 与 `qdrant` 为可选特性。注册到工作区成员。
- simvec 适配为 `LocalVectorEngine` 的薄封装，过滤逐字段映射，分数透传；不复用 CCE 的 local 实现。
- Qdrant 为 REST 薄客户端，仅覆盖建集合、写入、查询、过滤删除、计数；官方 gRPC 客户端不引入。
- 单元测试覆盖文本表示、过滤组合、余弦排序、维度不一致、缺集合、过滤器 JSON 形状。

验收：内存、simvec、Qdrant 各自通过同组契约行为测试（Qdrant 需远端服务，仅跑纯函数单测）。

## RAG 骨架：内存闭环（已落地 `crates/infra/rag-core`）

改动点：

- 独立 RAG 包，文件含文档模型、切分器接口与递归及层级实现、摄入与查询管线、融合与窗口回填与父块提升、重排适配、引用与转换端口、基础配置。存储访问一律经向量契约，不直连具体后端。
- 查询参数含返回数量、分数下限、元数据过滤。内存实现先满足正确性，性能不做承诺。
- 切片标识派生规则固定，保证同一来源重复摄入幂等。
- 单元测试覆盖切分边界（空输入、短文本、超长文本、重叠正确性）、过滤组合、余弦排序稳定性。

验收：纯内存下完成写入一批示例文档并回答查询，全程不依赖外部向量服务（向量化走测试替身），命中含来源标识。

## 集成：工具、模板、节点

改动点：

- `wf-tools` 新增最小只读检索工具处理器与工具描述，入参含问句、返回数量、过滤、知识库标识。处理器内部调用 RAG 包查询接口，超时与截断可配。注册进默认工具集，纳入暴露决议计算。丰富参数形态走 MCP 与插件扩展，不进内置定义。
- 转换侧新增外部 converter 服务端口：内置只做轻量格式，重格式（公式、表格、扫描版面）经外部服务归一化后再进切分。
- `wf-resource` 新增检索上下文片段与引用排版模板，支持展示与模型两种渲染模式，截断阈值可配。
- `wf-workflow` 新增查询节点类型，参数为配置引用加本次覆盖，执行体调用内核，检查点只记摘要与命中标识。摄入节点可先以批量调用形态出现，不阻塞查询集成。
- `wf-agent` 无需改执行主干，只需确认检索工具参与单轮装配，门控与发现语义生效。

验收：Agent 对话中模型可自主调用检索工具并引用来源；工作流图中查询节点可串接在问答分支后；敏感库降为发现式后调用链符合预期。

## 质量：融合、重排、回填、引用

改动点：

- 检索模块新增混合检索与融合逻辑，默认倒数排名融合，支持拼接与加权合并两种备选。关键词召回首版可用轻量词频实现，不引入外部检索引擎。
- 候选到重排的映射收敛一处：标识回填、内容截断、初始分保留。复用现有重排提供方与融合策略，不改重排内核。
- 关系回填实现句子窗口扩展与父块提升，依赖切片的前后与父子关系字段。
- 合成模块补齐查询改写（经大模型网关）、无命中模板、引用完整性标注。

验收：构造一组需多文档综合的问句，对比开启混合与重排前后的命中来源分布与名次变化；引用缺失时答案明确标注而非伪造。

## 规模：持久化、增量、管理

改动点：

- 持久化走 simvec 嵌入引擎（各项目自写薄适配），Qdrant 覆盖远端规模场景。SQLite 只存文档与切片元数据，形态对齐 `wf-storage` 现有后端划分；向量索引不塞进 `wf-storage` 实体语义。Postgres 接口预留，不在本步实现。
- 摄入流程补齐来源级更新：按内容哈希判断变更，按来源删除清理孤儿切片。写入策略三种语义完整实现。
- `wf-api` 与传输层增补只读管理接口：文档数、来源列表、命中预览、候选分数分布。完整向量默认不外传。
- 度量补齐检索延迟、候选规模、重排位移，排障文档说明常见无命中原因（切分过粗、过滤过严、向量维度错配）。

验收：重启后索引仍可用；更新来源文件后增量生效；删除来源后相关切片不可检出。

## 回归与约束

每步均需通过：

- 全量编译检查（现有 `cargo clippy --all-targets --all-features` 口径）。
- 新增模块格式化，日志与错误信息英文，代码注释只描述意图。
- 无循环依赖，新增依赖在中央依赖表声明。
- 设计文档避免完整代码段，后续实现文档同样遵循该约定。
