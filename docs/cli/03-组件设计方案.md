# wf-cli 组件设计方案

> 组件设计继承 TS 版 `apps/cli-app/src/tui` 的组件模型（SelectList/Text/Input/…），
> 渲染技术选型以 `docs/analysis/codex-tui.md`、`docs/analysis/codex-ratatui-implementation.md` 为参考：
> **ratatui 0.30 标准 `Terminal`（自带双缓冲 diff）作渲染底座，交互组件自研核心、外购评估多行编辑**。
> 事件循环机制参考 atomcode-tui / Codex 的 `tokio::select!` 多事件源汇合。
> 组件使用规则严格遵循 `design-philosophy.md`：`Block` 仅用于模态框、无折叠、无侧栏。
>
> **2026-08 修订要点**：
> 1. 移除"自定义 Terminal 双缓冲 diff"方案——标准 `ratatui::Terminal` 的 `draw`/`flush` 即逐格 diff，
>    codex `custom_terminal.rs` 的 `Put`/`ClearToEnd` 是为其 inline 视口 + scrollback 写入服务，全屏 alt-screen 下收益低、测试成本高。
> 2. 多行 TextArea 改为**优先评估第三方**：`tui-textarea-2`（0.12.x）或 `ratatui-textarea`（0.9.x，ratatui 官方组织维护），
>    二者均基于官方拆分 crate `ratatui-core`/`ratatui-widgets`，与 ratatui 0.30.2 兼容；**弃用** `tui-textarea` 0.7.0（停更，ratatui ^0.29）。
> 3. 补充 codex 验证过但原设计缺失的机制：`with_restored`（外部程序运行）、stderr 抑制、键位上下文回退、resize reflow、insta snapshot 测试。

## 一、分层架构

```
┌────────────────────────────────────────────────────────────┐
│ Event Loop（tokio::select!，biased 优先级）                   │
│  FrameRequester(120FPS) > config_poll(500ms) > spinner tick   │
│  > 终端输入 > agent/execution 事件 > 信号                     │
├────────────────────────────────────────────────────────────┤
│ App 状态：UiState（phase / screen_stack / scrollback）        │
├────────────────────────────────────────────────────────────┤
│ Screen 层（8 个屏幕，见 02 文档）                              │
├────────────────────────────────────────────────────────────┤
│ Component 层（自研交互组件，幂等渲染到 ratatui Buffer）         │
├────────────────────────────────────────────────────────────┤
│ 渲染层：标准 ratatui Terminal（monolith 双缓冲 diff）→ 终端     │
└────────────────────────────────────────────────────────────┘
```

核心决策：

1. **采用 ratatui 0.30 低层原语**（`Buffer`/`Line`/`Span`/`Style`/`Layout`/`Constraint`/`Clear`/`Rect`/`Paragraph` + `Frame`），**刻意不用高层组件**（Chart/Gauge/BarChart/Canvas/Scrollbar）——Codex 验证的路线，差异渲染与宽字符处理由 ratatui 承担。
2. **渲染底座用标准 `ratatui::Terminal`**：`Terminal::draw(|frame| ...)` 渲染当前帧，`flush` 时由 ratatui 内部逐格 diff 输出。**不派生 custom_terminal**——codex 的定制（`DrawCommand::{Put, ClearToEnd}`、`last_known_cursor_pos` 光标跟踪、`CellDiffOption::ForcedWidth`）全部围绕其 inline 视口 + OSC 8 注入 + scrollback 写入场景；全屏 alt-screen 模式下无闪烁问题，标准 Terminal 的 diff 已足够，且省去 100+ 行宽字符边界测试的维护成本。
3. **交互组件自研核心、外购评估多行编辑**：SelectList、单行 Input、选择器、弹窗栈、字符网格图表自研；**多行 TextArea（P1）优先评估 `tui-textarea-2` / `ratatui-textarea`**（见「四、组件清单」4.2），避免重蹈 codex `textarea.rs` 4000 行 + vim 子模块的自研成本。
4. **组件 = 纯函数 + 持有状态的数据结构**：`draw()` 幂等渲染到 Buffer；状态变更调用 `request_render()`，由 FrameRequester 合并调度（限帧 120FPS，两次绘制间隔 ≥ 8.3ms）。
5. **屏幕不共享可变组件实例**：每次绘制新建轻量视图结构，避免跨屏状态污染。

## 二、渲染层

### 2.1 终端管理与模式（crossterm）

| 能力 | 说明 |
| :--- | :--- |
| raw mode | crossterm `enable_raw_mode()` |
| bracketed paste | `EnableBracketedPaste`，区分粘贴与键盘输入 |
| 键盘增强 | kitty keyboard protocol（`EnableKeyboardEnhancement`），识别 `Ctrl+Enter` 等修饰键组合；不支持终端优雅降级 |
| 焦点事件 | `EnableFocusChange`（Unix） |
| RAII 保护 | `TerminalGuard`：Drop + panic hook 双保险恢复终端（raw mode/粘贴/光标/alt-screen） |
| 挂起恢复 | SIGTSTP/SIGCONT：`restore` → `SIGSTOP` → raw mode 重应用 + 全量重绘（对齐 Codex SuspendContext） |
| **外部程序运行** | **`with_restored`**（对齐 Codex `tui.rs with_restored`）：暂停事件流 → 离开 alt-screen → 恢复终端模式 → 运行外部程序（`$EDITOR`、vim、git rebase）→ 恢复 raw mode + 全量重绘。Settings 屏 `[E] edit`、Workflow 详情 `[E] edit` 必须走此路径 |
| **stderr 抑制** | **`TerminalStderrGuard`**（对齐 Codex）：TUI 运行期间将子进程/后端 stderr 重定向（headless 走 `-l/--log-file`），防止破坏界面；`with_restored` 期间恢复原 stderr |
| 终端探测 | OSC 10/11 查询默认前景/背景色回写主题；supports-color 判定色域（TrueColor/Ansi256/Ansi16）并映射颜色 |

### 2.2 渲染管线

```
Screen::draw → 组件自绘 → Buffer（当前帧）
                              │
        Terminal::flush：ratatui 内部 diff(prev_buffer, current_buffer)
        → 最小 ANSI 输出 → 交换内部 buffer
```

- **主模式：全屏 alt-screen**（`EnterAlternateScreen`，对齐 design-philosophy Pattern A/B/C）。
- **滚动区**：内容区用 ratatui 滚动视口（`Paragraph::scroll((y, 0))`）；日志区为源文本环形缓冲 + 按宽度重算。
  - **P1 可选增强**：长日志屏的全屏分页查看器（参考 codex `pager_overlay.rs`——按 `desired_height` 手动裁剪渲染，退出时内容经 normal scrollback 保留，终端复制/搜索能力由退出后终端原生滚动提供）。**不采用** codex `insert_history_lines` 的 scroll region + 反向索引方案（面向 inline 模式，alt-screen 下语义冲突）。
- **diff 批量化**：由 ratatui 内部完成；footer/状态行独立于内容区绘制。
- **resize 处理**：
  - 合并连续 resize 事件仅处理最终尺寸（75ms debounce）。
  - **reflow**：宽度变化后，所有含 wrap 的内容按新宽度重新渲染——`HistoryLine`/`MarkdownRenderer` 等必须持有**源文本**，`display_lines(width)` 按当前宽度重算换行，禁止依赖固定宽度的渲染缓存（参考 codex `transcript_reflow`）。

### 2.3 内容渲染子模块（Codex 已验证，直接对齐）

| 子模块 | 方案 | 参考 |
| :--- | :--- | :--- |
| Markdown 渲染 | pulldown-cmark（strikethrough/tables/codeblock）→ ratatui `Text`/`Line`；表格列分类（Narrative 吸收余宽 / TokenHeavy 抗拒换行） | codex markdown_render.rs |
| Diff 渲染 | GitHub 风格调色板（dark/light × TrueColor/Ansi256/Ansi16 预计算）+ 行号 gutter（宽度按最大行号动态） | codex diff_render.rs |
| ANSI 解析 | `ansi-to-tui` 把工具/命令输出的 ANSI 转义解析为 `Text`；tab 先展开 4 空格 | codex ansi-escape crate |
| 换行/截断 | textwrap（`initial_indent`/`subsequent_indent`）+ 自研 URL 感知 wrap（URL 整 token 不拆行，可点击）+ grapheme 截断 | codex wrapping.rs / line_truncation.rs |
| 语法高亮（P2） | syntect + 超限保护（512KB / 10000 行 / 4KiB 单行） | codex render/highlight.rs |

## 三、事件循环（Event Loop）

参考 atomcode-tui / Codex 的 `tokio::select!` biased 优先级设计：

| 优先级 | 事件源 | 说明 |
| :--- | :--- | :--- |
| 1 | 绘制请求（FrameRequester broadcast） | 动画/后台任务/业务事件调度重绘，限帧 120FPS |
| 2 | config poll tick (500ms) | 配置热重载（仅 Idle 且无模态框时应用） |
| 3 | spinner tick | 仅 Streaming 阶段（帧驱动经 FrameRequester） |
| 4 | 固定间隔循环（`/loop` 命令） | P1 |
| 5 | 终端输入 | `Key / Paste / Resize / Focus / Mouse` |
| 6 | 业务事件 | agent/execution 事件流（工具调用、节点完成、审批请求） |
| 7 | 信号 | SIGINT/SIGTSTP/SIGCONT；Windows Ctrl+C |

### 3.1 输入处理管线

1. **事件归一化**：EventBroker 共享 crossterm 事件流，映射为 `TuiEvent`（Key/Paste/Resize/Draw/Resume）并触发绘制请求；支持丢弃重建流以释放 stdin。
2. **键位解析走 Keymap**：`Keymap::resolve(context, key)` 按 **modal > 当前屏幕上下文 > global** 回退查表（参考 codex `keymap.rs` 的 context 回退），P0 内置默认表，P1 支持 `keybindings.toml` 覆盖。**禁止在屏幕/组件内散落裸 match 分支**。
3. **Resize 合并**：drain 连续 resize，仅处理最终尺寸（75ms debounce 后 reflow）。
4. **模态框优先路由**：捕获型模态框（PasswordModal）接收所有按键（无视 phase）；普通模态框仅 Idle 接收。
5. **Ctrl+C 全局**：任何状态优先，模态框不可拦截。
6. **阶段分发**：Idle（编辑/历史/palette/submit）、Streaming（type-ahead 缓冲、Ctrl+O 跳过审批、Ctrl+C 取消 turn）、Approval（键盘归模态框）。
7. **Type-ahead**：FIFO 队列，TurnFinished 释放一条；provider 切换期间暂停释放。

### 3.2 绘制调度

- `FrameRequester`（actor + mpsc）：`schedule_frame()` / `schedule_frame_in(dur)` 合并多个请求为一次 broadcast `Draw`；动画与后台任务持 clone 触发重绘。
- `FrameRateLimiter`：`MIN_FRAME_INTERVAL = 8.3ms`（120FPS 上限），`clamp_deadline` 保证最小帧间隔。
- 业务事件到达（agent/execution 流）优先触发绘制，不依赖轮询。

## 四、组件清单

### 4.1 导航类

**SelectList**（核心组件，所有列表屏，自研）

```rust
pub struct SelectList<'a> {
    pub items: Vec<ListItem<'a>>,      // { label, description: Option<String>, data: ItemData }
    pub selected: usize,
    pub filter: Option<String>,        // 模糊搜索
    pub wrap: bool,                    // 默认 true
}
```

- 渲染：`→` 选中标记 + label + description 两列（宽 > 40 时两列，否则单列截断）；`(N/M)` 滚动指示。
- 行为：↑/↓/j/k 导航（wrap）、Enter 触发 `on_select`、模糊过滤（fuzzy 算法，对齐 TS fuzzy.ts）。
- 使用规则：**列表屏的唯一导航组件**，禁止包 `Block`/`Box`。

**Spacer / Text**：空行填充与多行文本（ANSI 感知宽度、自动换行、截断）。

### 4.2 输入类

**Input**（单行，P0，自研）
- grapheme 感知光标、水平滚动、placeholder、bracketed paste、kill ring、undo、onSubmit/onEscape。

**TextArea**（多行，P1）
- **优先评估第三方**：
  - `tui-textarea-2`（0.12.x，2026-07 活跃）——社区 fork 延续；
  - `ratatui-textarea`（0.9.x，ratatui 官方组织维护，2026-06 活跃）——官方背书，首选；
  - 二者均基于官方拆分 crate `ratatui-core`/`ratatui-widgets`（ratatui 0.30.2 monolith 即二者组合，兼容）。
- **弃用** `tui-textarea` 0.7.0：2024-10 停更，绑定 ratatui ^0.29，与 0.30 不兼容。
- 若第三方 API 不满足需求（如需要 codex 式视觉换行缓存 + vim 模式），再裁剪自研**核心子集**：视觉换行缓存、光标保持可视（`effective_scroll`）、kill buffer、历史 100 条、undo 栈；vim 模式标记可选。**不做** codex `chat_composer.rs` 级别的完整状态机（1.26 万行）。

**Command Palette**（输入框上方覆盖）
```rust
pub struct MenuPayload { pub items: Vec<MenuItem>, pub selected: usize, pub filter: String }
```
- 模糊搜索、↑/↓ 导航、Enter 执行、Esc 关闭；作为输入区的弹层渲染（`Clear` + 居中或输入框上方）。

### 4.4 布局类

| 组件 | 使用规则 |
| :--- | :--- |
| `Block`（ratatui） | **仅用于模态框/覆盖层**，默认无边框无 padding；内容区一律裸渲染（零装饰） |
| `Layout`（ratatui） | 仅用于少量关键切分：状态行/内容区/输入区；对话区用自研 flex 分配（`desired_height` + 权重，参考 codex `FlexRenderable`） |
| 折叠/分栏 | **禁用**，长内容 drill-down 为独立视图（design-philosophy） |

## 五、模态框系统

### 5.1 Trait

```rust
pub trait Modal {
    fn handle_key(&mut self, ev: &InputEvent, ctx: &mut UiContext) -> Result<ModalAction>;
    fn draw(&self, ctx: &mut UiContext, frame: &mut Frame, area: Rect);  // Clear + 居中
    fn captures_all_keys(&self) -> bool { false }   // 捕获型：Streaming 也生效
    fn on_engine_event(&mut self, _ev: &EngineEvent) {}
    fn close_requested(&self) -> bool { false }
}

pub enum ModalAction { Continue, Close }
```

- `ModalManager`：栈管理 + 孤儿清理（turn 结束仍挂着的密码框自动关闭）。
- 打开为 async 静态 API（对齐 TS）：`ConfirmModal::show(...) -> Option<bool>`、`PasswordModal::ask(...) -> Option<String>`，内部 `oneshot` 返回。
- **结果回传语义**：pop 时把结果回传给上一个模态框/调用方（参考 codex `BottomPaneView` 的 `ViewCompletion::{Accepted, Cancelled}`），
  `ModalManager::pop_with_completion` 与 UI 事件解耦，避免回调穿透。
- 渲染：`Clear` 逐 cell 清残留 + `Block` 边框 + 居中 `Rect`；定位用 `Layout` 分区而非手算。

### 5.2 模态框清单

| 模态框 | 用途 | 捕获型 | 宽度 |
| :--- | :--- | :---: | :--- |
| `ConfirmModal` | 删除/危险操作确认（Y/Enter、N/Esc） | 否 | 60 |
| `PasswordModal` | askpass 密码输入（• 掩码，Enter 提交，Esc 取消） | **是** | 50 |
| `ModelPicker` | `/model` 选择 | 否 | 70 |

| `FileViewer` | 文件查看（j/k、Ctrl+u/d、g/G、q/Esc） | 否 | 80% |
| `DiffViewer` | diff 查看（着色滚动） | 否 | 80% |
| `HelpModal` | `?` 按键帮助（当前上下文键位表） | 否 | 60% |
| `FileSelectionDialog` | 文件浏览（P1） | 否 | 70% |

## 六、主题与文本度量

- **ColorRole**：`Default / Muted / Brand / Add / Remove / Warning / Error / Highlight` 8 角色（对齐 TS theme.ts），映射到 ratatui `Style`。
- **状态符号**：集中定义语义符号表（`●` 助手、`▲` 工具调用中、`✓`/`✗` 成功失败、`▶`/`⏸`/`○` 阶段），**不使用 emoji**（字体差异导致对齐错乱），低色终端降级纯文本标记。
- **主题检测**：启动探测 OSC 10/11 默认前景/背景色（100ms 超时，事件流暂停期间）+ `COLORTERM`，fallback 深色。
- **色域适配**：supports-color 判定 TrueColor/Ansi256/Ansi16；RGB → 最近色映射（CIE76 Lab 距离），低色终端自动降级（对齐 Codex terminal_palette）。
- **文本工具**：`display_width`（对齐 ratatui 宽度语义）、grapheme 截断、URL 感知换行、tab 展开 4 空格——组件层统一使用。
- **样式约定**：优先 `Stylize` 链式 helper（`.dim()`/`.bold()`/`.cyan()`），避免硬编码白色，默认前景即可。

## 七、状态管理

- **UiState**（全局）：`phase: Idle|Streaming|Approval|Normal`、`screen_stack: Vec<ScreenId>`、`active_modal: Option<Box<dyn Modal>>`、`scrollback: RingBuffer<HistoryLine>`、`type_ahead: InputBuffer`。
- **阶段转换**（带校验）：`Idle→Streaming`（Submit）、`Streaming→Approval`（ToolCall）、`Approval→Streaming`（Approve）、`Approval→Idle`（Reject）、`Streaming→Idle`（TurnFinished/Cancel）。
- **历史行抽象**：`HistoryLine`（对应 Codex HistoryCell 的轻量版）：
  - **`display_lines(width) -> Vec<Line>`**：按当前宽度重算换行（resize reflow 的地基）；
  - **`desired_height(width) -> u16`**：真实视口行数（参考 codex 用 `Paragraph::wrap().line_count()` 计算）——滚动区、80x24 裁剪、reflow 依赖此通道；
  - 源文本双视图（显示 vs 可搜索原文）；提交型行与在途 streaming 行并存，commit tick 沉淀。
- **组件本地状态**：屏幕内持有（如 Agent 屏 log 环形缓冲 + scrollOffset）；跨屏数据（列表）重新拉取，不做全局缓存。
- **渲染调度**：`request_render()` → FrameRequester 合并（120FPS 限帧）+ 业务事件即时触发。

## 九、组件使用红线（违反即视为设计错误）

1. `Block`/边框包列表、输入 → 禁止（仅模态框）。
2. 折叠区块/左右分栏/双面板 → 禁止（drill-down 替代）。
3. 常驻帮助栏 → 禁止（`?` 帮助模态框）。
4. 面板自带标题 → 禁止（视图标题即标题）。
5. 列表行折行 → 禁止（单行截断）。
6. 使用 ratatui 高层组件（Chart/Gauge/BarChart/Canvas/Scrollbar）→ 禁止（自研或字符网格）。
7. 组件内直接写 ANSI 转义 → 禁止（必须经 ratatui Buffer 渲染，ANSI 只用于解析输入/OSC 8 注入）。
8. 屏幕/组件内裸 match 解析按键 → 禁止（必须走 `Keymap` 上下文回退）。
9. 渲染缓存固定宽度、resize 后不重算换行 → 禁止（内容必须持有源文本 + `display_lines(width)`）。
10. UI 渲染变更无 insta snapshot 覆盖 → 禁止合并（开发流程要求）。
