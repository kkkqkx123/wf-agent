# RAG 后续细化修改方案

> 基线为 `06-implementation-record.md` 的已落地状态与已知缺口。本文件只描述改动点与验收，不贴完整实现。语言为中文，代码注释与日志保持英文。

## 背景与范围

内核与集成主干已可用，剩余工作集中在三处断点：工作流读路径能力弱于内核、排障接口止于 `wf-api` 未进传输层、调用方侧语料与度量缺少可复用助手。SQLite 切片元数据、Postgres 接口、原生倒排、gRPC 后端保持预留，不在本轮实现。内置工具保持最小只读定义，丰富参数形态仍走 MCP 与插件扩展。

本轮分三阶段推进，每阶段独立验收，阶段之间只允许向下依赖。

## 阶段一：内核助手补齐

目标是让调用方无需重复实现语料维护、改写回退、增量判断与度量透出。

- 关键词语料助手：在检索模块新增调用方侧语料容器，支持追加摄入点位、按词符重叠度检索前若干候选、返回空语料时退化为空列表。容器只保存调用方已知的点位快照，不新增存储扫描调用。
- 启发式改写器：在改写模块新增无模型依赖的确定性改写器，按句子边界拆分问句并与原问句合并去重，数量封顶。网关改写仍走既有改写端口注入，启发式改写器作为网关不可用时的默认回退。
- 度量标签化：在度量模块新增标签映射，把延迟、候选规模、保留命中数、是否重排、重排位移转为调用方可直接写入既有收集器的字段。
- 增量判断助手：在同步模块新增面向文档列表的待处理过滤，按内容哈希与已索引哈希对照产出插入更新跳过决议，调用方持久化哈希表即可复用。

验收：语料容器在给定问句下返回字面命中；启发式改写器对长问句产出多变体且空问句返回空；度量标签含五组信号；增量助手对新增变更未变三类来源给出正确决议。

## 阶段二：工作流读写对齐

目标是让工作流节点的读路径能力对齐内核已验证的质量管线，写路径支持内容哈希增量。

- 查询节点参数扩展：新增多变体变量、关键词语料变量、窗口半径、自动合并、融合模式与权重、关键词候选数与权重。缺省时行为与现网一致，不改变已有图的执行结果。
- 改写端口注入：节点句柄新增可选改写器，默认空即原问句直查；配置改写器时先经回退改写再做多变体融合，失败自动降级为原问句单路。
- 执行分支收敛：有多变体时走多变体融合，有语料时走稠密加关键词混合，两者兼备时先多变体融合再与关键词混合；空命中直接返回空数组，由合成侧无命中模板应答。
- 可观测性：在查询与摄入执行后记录通用调用耗时到工具收集器，并在节点结果元数据中携带检索延迟与变体数。
- 摄入增量：新增增量开关与哈希表输入输出变量。开启时先做内容哈希对照，仅对需处理来源执行删除与写入，并把更新后哈希表写回输出变量；关闭时保持现有去重策略路径。

验收：同一知识库下窗口合并与融合模式切换可观测命中变化；多变体变量与语料变量同时配置时混合链路可用；改写器注入失败时降级为原问句；增量二次写入跳过未变来源并清理已删来源。

## 阶段三：工具默认与传输闭环

目标是让默认链路可配质量参数，让只读排障接口可经 HTTP 到达。

- 工具服务端默认：在检索服务端新增查询默认配置，调用方未传参时沿用默认的返回数、分数下限、过滤、窗口、合并与融合设置，请求级参数仍可覆盖。工具参数形态不变。
- 应用上下文句柄：在应用接口层新增检索句柄，持有向量存储与向量化提供方的共享引用，上下文新增可选注入与读取方法，未注入时排障接口返回服务不可用而非静默空结果。
- 传输路由：在传输层新增检索只读路由组，包括集合统计、来源统计、命中预览、分数直方图、无命中诊断。预览不外传向量，按调用方预算截断摘要。路由合并进主路由，未配置句柄时返回服务不可用。
- 诊断增强：无命中诊断在现有形态基础上叠加命名空间点数提示，调用方先查统计再展示诊断。

验收：工具服务端在默认配置下支持窗口与融合切换而无需改工具定义；未注入句柄时传输接口返回服务不可用；注入内存后端后统计预览诊断链路可用；预览摘要长度受预算控制。

## 回归与约束

- 每阶段通过全量编译检查与新增模块格式化，日志与错误信息英文，注释只描述意图。
- 无循环依赖，新增依赖在中央依赖表声明。
- 不做向后兼容与旧数据迁移，不更新版本号。
- 编译输出先重定向到文件再阅读，合并为最少次数的集中验证。
