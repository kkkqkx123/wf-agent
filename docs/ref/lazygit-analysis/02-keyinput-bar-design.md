# 键位输入栏（KeyCommandBar）设计

> 本文是整套方案的核心：把 lazygit 的「按单键触发动作」重新表达为「在输入栏键入词元 + Enter 提交」，并约定无法以字符输入表达的控制键如何控件化。
>
> 上游依据：`01-lazygit-interaction-model.md`（三分类量化）、`00-overview.md`（决策摘要）。

---

## 1. 设计要解决的问题

lazygit 的输入是**隐式模态**：同一个 `d` 键，在文件面板是「放弃变更」，在分支面板是「删除分支」，用户靠面板边框高亮判断当前模态。这套机制搬到 Web 上有三个必须解决的问题：

1. **模态不可见**：浏览器没有「当前面板高亮边框」的强约定，用户不知道输入栏此刻作用于谁。
2. **部分键位无法输入**：`<esc>` / `<enter>` / `<ctrl+x>` 打不进输入框。
3. **浏览器要抢焦点**：输入框常驻聚焦会吞掉列表的原生键盘导航。

对应三条设计主线：**上下文显式化**、**控件自动派生**、**焦点仲裁**。

---

## 2. 语义模型：动作 ID 为主，单字符为别名

### 2.1 核心决策

不要让输入栏去理解「键」，而让它理解「动作」：

> 每个动作有唯一 `actionId`（如 `files.toggle-stage`）。单字符只是 `actionId` 的**别名**之一。输入栏解析词元 → 命中 `actionId` → 调用统一动作入口。

这样一举三得：

- A 类键位（73%）手感与 lazygit 完全一致：敲 `c` 回车 = 提交。
- C 类键位（`<ctrl+o>` 复制等）不会丢失，因为它们只是**没有单字符别名**的动作，仍可用动作名触达。
- 一份绑定表同时驱动三处 UI：输入栏候选、不可见键控件条、右键菜单。**三者永不脱节**。

### 2.2 绑定表项的结构（描述，非代码）

一个绑定表项包含：

| 字段 | 含义 | 备注 |
|---|---|---|
| `id` | 动作唯一 ID，形如 `files.toggle-stage` | 后端 action 注册表的键 |
| `context` | 所属上下文，如 `files` / `commits` / `*` | `*` 表示全局（对应 lazygit 的 `ViewName=""`） |
| `label` | 中文短名，如「切换暂存状态」 | 用于候选列表与按钮文案 |
| `alias` | 单字符别名数组，如 `[' ']` | 空数组表示无单字符别名（C 类） |
| `legacyKey` | 原 lazygit 键位描述，如 `<ctrl+o>` | 仅用于提示与文档，**不参与匹配** |
| `nonPrintable` | 该动作在原 lazygit 中是否由不可见键承载 | 决定是否需要派生控件 |
| `controlPriority` | 控件条排序权重 | 仅 `nonPrintable` 项需要 |
| `danger` | `safe` / `soft` / `confirm` / `destructive` | 见 §6 |
| `params` | 参数声明数组 | 见 §5 |
| `availability` | 可用性判定（选中项类型、仓库状态等） | 对应 lazygit 的 `GetDisabledReason` |

`legacyKey` 字段的价值：候选列表里可以同时显示「`c` · 切换暂存状态」和「`<ctrl+o>` · 复制路径」，让从 lazygit 迁过来的用户能看到原键位，降低迁移成本。

### 2.3 与后端 action 注册表的契约

后端维护一份 action 注册表（见 `04-backend-git-domain.md` §3），暴露 `GET /api/v1/git/actions`，返回每个 `actionId` 的 `danger` 级别与 `params` 声明。

前端绑定表的 `actionId` **必须**存在于该注册表。约定一条启动期校验：前端拿到注册表后比对本地绑定表，**发现未知 actionId 就在控制台告警并把该动作标记为不可用**，而不是让它在运行时报 404。

这样职责清晰：键位归属前端（UI 关注点），动作语义与危险级别归属后端（执行关注点），靠启动校验防漂移。

## 3. 输入栏的解析流程

### 3.1 词元解析状态机

| 输入状态 | 行为 |
|---|---|
| **空** | 显示当前上下文的提示行（`Files · 输入单键或动作名，? 查看全部`）；不发起搜索 |
| **1 个字符** | ① 先在当前上下文内做 `alias` **精确匹配**；命中则显示唯一候选并高亮 ② 未命中则退化为**全局前缀搜索**（动作名 + 别名 + 标签），列出候选 |
| **≥2 个字符** | 全局前缀搜索（匹配 `id` 后缀 / `label` / `legacyKey` 文本），按「当前上下文优先 → 别名命中优先 → 字典序」排序 |
| **以 `:` 开头** | 进入**命令模式**：剩余部分视为 CLI 命令，转发给终端执行（与 lazygit 的 `:` 语义一致，但落到本页 CLI 而非外部 shell） |
| **只输入 `?`** | 列出当前上下文全部动作（等价于 lazygit 的 `?` 打开菜单） |

**关键规则**：单字符时优先做「当前上下文的别名精确匹配」，这是为了保住 lazygit 的手感——敲 `c` 在文件面板必须立刻是「提交变更」，不能被全局搜索里某个以 c 开头的动作抢走。

### 3.2 提交与取消

| 操作 | 行为 |
|---|---|
| `Enter` | 执行**首个候选**。无候选时输入栏抖动 + toast「无匹配动作」；不做任何兜底猜测 |
| `Enter`（候选唯一且需参数） | 弹出参数 Dialog（见 §5） |
| `Esc` | 清空输入栏；若已有候选面板则先收起候选 |
| `Tab` | 在候选中循环移动（不提交） |
| 点击候选 | 直接执行该候选 |

**不做「输入即执行」**：必须 Enter 提交。原因是单字符别名极易误触（空格、字母都在输入区），即时执行会让误操作无法挽回。这与用户约定的「Enter 提交」一致。

### 3.3 「输入即预览」

输入过程中，输入栏右侧实时显示将被执行的动作全名与危险级别标记。这一条直接解决 §1 的「模态不可见」问题——用户敲下 `d` 的瞬间就能看到「放弃变更（危险）」，而不是执行后才发现删错了东西。

对 `danger >= confirm` 的动作，预览时同步显示警示色与图标。

## 4. 焦点仲裁（Web 特有问题）

浏览器里输入框聚焦会吞掉列表的原生键盘操作。约定一套仲裁规则：

| 场景 | 规则 |
|---|---|
| 进入 `/git` 页面 | 输入栏自动获得焦点 |
| 点击侧栏面板 / 列表行 / 主视图 | 焦点**归还**输入栏（除非点到的是另一个输入控件或弹层内） |
| 输入栏为空 | 方向键、`Enter`、`Home`/`End`、`PgUp`/`PgDn` **透传给当前列表**，做原生导航 |
| 输入栏非空 | `Enter` 提交输入栏；方向键在候选列表内移动；不再透传 |
| 弹层（Dialog）打开 | 输入栏禁用（置灰 + 提示），不静默失效——对齐 lazygit 的 `NoPopupPanel` 守卫但更显式 |
| 全局热键 | 提供一个热键（建议 `Ctrl+/`）从任意位置聚焦输入栏 |

「输入栏为空时方向键透传」这条很重要：它让输入栏常驻聚焦不成为负担，用户仍能纯键盘浏览列表。

## 5. 参数化动作

部分动作需要额外输入（提交信息、新分支名、重置模式）。参数声明形如 `{ name, kind, required, source }`：

| `source` | 行为 | 例子 |
|---|---|---|
| `selection` | 取当前上下文选中项，无需询问 | 切换暂存、删除分支 |
| `prompt` | 弹 Dialog 请求文本输入 | 提交信息、新分支名、标签名 |
| `choice` | 弹 Dialog 请求单选（枚举） | 重置模式 soft/mixed/hard、贮藏变体 |
| `ref` | 弹 ref 选择器（分支/标签/提交列表可搜索） | 变基目标、比较基准 |

**首期约定**：输入栏只承担「触发动作」，不承担参数传递。即不支持 `c "fix: bug"` 这类内联参数语法——那会让词元解析退化成一个小型 shell，复杂度失控。带参数的完整表达交给 CLI（见 03 文档）。

参数 Dialog 复用现有 `Dialog.svelte` + `Input.svelte` / `Select.svelte`，不新增组件。提交信息这类多行输入用 `Textarea.svelte`。

## 6. 危险操作分级

lazygit 用统一的 confirmation 弹窗（`gui.c.Confirm`）处理所有确认，并配 `SkipXWarning` 配置项（`pkg/config/user_config.go:875-877`）让用户关掉警告。Web 上信息展示能力更强，改为**四级分级**，而不是「要么每次问、要么永远不问」：

| 级别 | 判定标准 | 交互 | 例子 |
|---|---|---|---|
| `safe` | 只读，或完全可逆 | 直接执行，toast 结果 | 复制哈希、聚焦主视图、切换文件树视图 |
| `soft` | 改变工作区/索引，但 git 可恢复 | 直接执行，toast 带**撤销**按钮 | 暂存、取消暂存、提交、贮藏 |
| `confirm` | 会丢失改动，但范围明确且限于本地 | Dialog 确认，说明将丢失什么 | 放弃文件变更、删除本地分支、删除贮藏 |
| `destructive` | 改写历史 / 影响远程 / 不可恢复 | Dialog **二次确认**：需手动输入目标标识（分支名或提交短哈希）才启用按钮 | 强制推送、hard reset、删除远程分支、强制检出 |

`soft` 级的撤销按钮是 Web 相对 TUI 的天然优势（toast 有存活窗口），建议实现：toast 内保留 8 秒撤销入口，撤销动作走后端的 undo 能力（基于 reflog，对齐 lazygit 的 `z` / `Z`）。

**不做全局「不再提示」开关**：lazygit 的 `SkipDiscardChangeWarning` 在 Web 上没有对应物，因为 Web 的确认成本（点一下）远低于 TUI（弹窗打断）。若确有需要，后续可按 `danger` 级别单独配置到用户偏好中。

## 7. 不可见键的控件化

### 7.1 派生规则

输入栏右侧有一条**控件条**，内容由绑定表自动派生：

1. 取当前上下文（含全局 `*`）中 `nonPrintable = true` 的项。
2. 按 `controlPriority` 降序取前 4 个。
3. `<enter>` 对应的动作渲染为**主按钮**（最醒目，常驻最左）。
4. `<esc>` 对应的动作仅在存在活动弹层或子视图时渲染，文案为「返回」。
5. 当前上下文无任何 `nonPrintable` 项时，控件条**自动收起**（不占位）。

自动派生而非手工摆按钮的原因：键位表是唯一事实源，加一个新动作只需要加一行表项，控件条、输入栏候选、右键菜单同步生效。手工维护三处必然漂移。

### 7.2 控件化映射表

| lazygit 键 | 控件形态 | 优先级 | 备注 |
|---|---|---|---|
| `<enter>` | 主按钮「打开 / 进入」+ 列表项双击 | 高 | 文案随上下文变化（查看提交的文件 / 进入子模块 / 暂存块行） |
| `<esc>` | 「取消 / 返回」按钮 + 面包屑 + 点击遮罩关闭 | 高 | 仅弹层/子视图活动时显示 |
| `<tab>` | 主视图 Segmented 分段控件 | 中 | 已暂存 / 未暂存 / 补丁构建 三态切换 |
| `<ctrl+o>` 复制族 | 行内复制图标按钮 | 中 | **6 个面板的复制动作收敛为一个控件** |
| `<ctrl+j>` / `<ctrl+k>` | 提交行「上移 / 下移」按钮 + 拖拽 | 中 | 拖拽为主，按钮为辅 |
| `<shift+up>` / `<shift+down>` | 交给浏览器原生 shift+点击 / 拖拽 | — | 不需要控件 |
| `<ctrl+l>` / `<ctrl+s>` / `<ctrl+b>` / `<ctrl+w>` | 面板头部菜单项或开关 | 低 | 低频，收进「更多」菜单 |
| `<ctrl+p>` / `<ctrl+f>` | 主视图工具条按钮 | 低 | |
| `<ctrl+t>` difftool | **不提供** | — | 服务端无桌面环境，标记不可用 |
| `<ctrl+y>` PR URL | **不提供** | — | 首期无托管平台集成 |
| `<ctrl+z>` 挂起 | **不提供** | — | Web 无此语义 |
| `<alt+shift+c>` 编辑配置 | 跳转设置页链接 | 低 | |

### 7.3 被原生 UI 取代、无需控件的键

以下 lazygit 键位在 Web 上有天然等价物，**既不进输入栏也不派生控件**：

- 滚动类（`<pgup>` / `<pgdown>` / `<home>` / `<end>` / 鼠标滚轮）：浏览器滚动条。
- 列表导航（`<up>` / `<down>`）：原生键盘导航 + 鼠标点击。
- 剪贴板：Web 文本天然可选中复制，`<ctrl+o>` 退化为便利按钮（保留在控件条）。
- 范围选择（`v`）：shift+点击 / ctrl+点击 / 拖拽。

## 8. 与既有 CommandPalette 的关系

前端已有 `CommandPalette.svelte`（267 行，全局导航 + 跨实体搜索，见 `apps/web-app/src/lib/components/layout/CommandPalette.svelte:1-50`）。

| | CommandPalette | Git 键位输入栏 |
|---|---|---|
| 作用域 | 全应用（页面跳转、执行/工作流/Agent 循环搜索） | 仅 `/git` 页内，且绑定当前上下文 |
| 触发 | 主动唤出（弹层） | 常驻 |
| 提交语义 | 选择并执行导航/打开 | 执行 git 动作 |
| 词元 | 模糊搜索 | 别名精确匹配优先 + 动作名前缀 |

**不合并**。两者的匹配语义不同（一个模糊搜索、一个别名精确优先），强行合并会让 Git 动作的单键手感被模糊匹配污染。可以共享的部分只有候选列表的渲染与键盘导航逻辑，建议抽一个纯展示组件给两边用。

## 9. 状态与边界情况

| 情况 | 处理 |
|---|---|
| 仓库不存在 / 不是 git 仓库 | 输入栏禁用，页面显示空状态并引导到设置页配置仓库路径 |
| 动作执行中 | 输入栏保持可输入但提交后排队，按钮显示进行态；不做全局遮罩（git 命令通常很快） |
| 动作失败 | toast 显示 stderr 摘要 + 「在终端中查看」入口（跳到 CLI 并回显命令） |
| 后端 `repo.changed` 推送 | 输入栏不重置；仅刷新面板数据 |
| 当前上下文选中项不满足动作前置 | 输入栏仍可命中该动作，但提交后 toast 说明原因（对齐 lazygit 的 `GetDisabledReason` 提示分支） |
| 移动端 / 窄屏 | 输入栏降级为「动作搜索框」，控件条横向滚动；单键输入在触屏上无优势，此形态下以候选列表点击为主 |

## 10. 可发现性设计（Web 相对 TUI 的优势）

lazygit 最大的门槛是「不知道有什么键」。Web 上可以用三件 TUI 做不到的事来解决：

1. **常驻提示行**：输入栏为空时轮播/静态显示当前上下文的高频动作（如 `Files: space 暂存 · c 提交 · d 放弃变更 · s 贮藏`）。
2. **右键菜单**：列表项右键直接列出该上下文全部动作，每项标注别名与危险色。与输入栏共用绑定表。
3. **动作帮助面板**：`?` 唤出当前上下文全量动作表（含 `legacyKey`），等同于 lazygit 的 cheatsheet，但可按上下文筛选。

这三项的成本都很低（绑定表已存在），但它们决定了这套交互是「只有 lazygit 老用户能用」还是「新用户也能上手」。
