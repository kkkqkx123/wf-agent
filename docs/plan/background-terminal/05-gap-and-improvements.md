# 后台终端执行逻辑现状与参考 opencode 的差距改进分析

> 定位：对当前主干后台终端工具与执行链路的一次实证复核，对照 `ref/opencode` 主干设计，指出哪些值得借鉴、哪些暂缓，给出可直接排期的改进清单。
> 与 `00-overview.md` 至 `04-progress.md` 的关系：前者是设计基线与落地记录，本文件是基于代码实测的差距复核与后续改进建议。阅读时以本文件的时间戳为准，行号仅作定位辅助。
> 约定：自然语言描述为主，不贴完整代码实现。

## 一、当前项目后台终端工具及执行逻辑

### 1.1 工具族划分

后台能力全部经通用工具调用面暴露，没有 shell 直达路由，共十二个左右的有状态工具：

- 创建执行类：创建即运行的后台会话工具、在空闲会话内阻塞执行的工具、复用或创建空闲会话的工具、无状态单发执行工具。
- 观察等待类：读输出工具支持三种形态（全量快照、增量新输出、按绝对位置分页窗口加可选正则过滤），等待工具支持超时加正则匹配加静默期，另有会话观察工具。
- 干预类：发输入工具、调尺寸工具、终止工具、按任务批量释放工具、手动后台化工具、任务列表工具。

单发路径与会话路径语义不同。单发路径阻塞等待加超时钳制，默认约两分钟、上限约十分钟，无流式无交互。会话路径创建即返回会话标识与进程信息而不含输出，后续经轮询取输出。

### 1.2 执行链路

典型后台命令的生命周期为创建、等待或后台化、结算通知、清理四个阶段：

1. 创建时先建会话再向后台任务注册表登记，返回会话标识与后台指引文案。
2. 等待时调用方轮询快照，后台化工具仅置位后台标记并提示不要轮询。
3. 结算时会话池监视线程检测完成，终端会话做幂等收尾并排空事件，生命周期转发器先结算注册表再转交检查点与事件总线。
4. 清理时终止工具优雅终止进程组（先终止进程组、宽限后强制杀），会话移除并记取消，会话终止与回收删除溢出文件。

单会话同一时刻只允许一条运行命令，忙时直接报错。多并发需求经多会话满足。

### 1.3 存储与输出模型

基础设施层 shell crate 负责进程与字节，引擎层执行共享设施重出注册表类型，工具层负责登记与结算，运行时负责事件桥接：

- 会话池以并发映射持有终端会话，另有一根延迟启动的监视线程做完成检测，短轮询加读端结束时唤醒。会话上限约六十余个，支持按任务限额与空闲超时回收，仅回收无绑定的空闲会话。
- 终端会话记录空闲或忙碌状态、模式、工作目录与环境、累积输出、当前命令句柄、任务绑定与活跃时间。
- 输出为分段环形缓冲（约两百余 KB 尾部保留，绝对位置在截断后保持稳定），超阈值后溢出到按会话组织的追加写文件（惰性打开、后续分块直写、失败回退纯内存），尾部读、窗口读与增量读在有溢出文件时从历史 serving，窗口语义保持游标单调。快照与窗口回执携带溢出标记与字节数。
- 事件分发为异步单线程逐行，逐行输出事件默认关闭以限流，生命周期事件常开以便检查点收尾。同步执行路径在返回前排空事件，保证调用者返回时推送已达槽。运行时桥将创建、起止、完成、终止转为统一基础事件并经事件总线发布，前端经执行流透传后台标记。
- 后端双实现：管道后端保留原始字节，可走沙箱策略；伪终端后端合并标准输出与标准错误。伪终端支持始终编译进，仅由运行时开关与会话级交互标记决定是否启用。伪终端后端因无法挂载执行前钩子而跳过内核强制，仅走命令安全门，该差异需在文档中显式声明。

### 1.4 后台任务注册表现状

基础设施层新增的后台任务注册表按会话标识跟踪运行、后台化与结算，结算条目有界保留约二十五条。首次结算胜出，终止与释放路径同步取消或结算，生命周期转发器兜底自然退出的结算。任务列表工具可查运行中与按执行标识过滤（含是否包含已结算开关），但无全局已结算枚举。

已落地的标记链路：基础类型新增后台标记（会话标识与后台化旗标），两级工具完成事件携带，流适配层透传，前端不再嗅探结果文本。网页端工具卡展示后台徽标并悬浮提示会话标识，轻量终端在后台工具完成时打印跟进指引行，无头渲染在完成行追加后台会话后缀。

### 1.5 前端与命令行界面现状

前端无终端仿真器依赖。工具调用展示以工具调用卡为中心，shell 类工具映射为终端图标与尾部展示类型，默认折叠显示尾部若干行加省略提示，可展开看全量。实时聊天经执行流的事件增量驱动，而非原始 shell 字节流。无后台任务聚合视图，详情靠手动调任务列表与输出工具查询。

命令行界面不直连本地进程，仅为服务端事件流的渲染端。轻量终端做标准输出与标准错误分流加渲染，完整终端做可折叠工具块与查看器弹窗，均无交互式 shell 透传、无伪终端挂件、无输出尾随循环。

### 1.6 独立的 Git 终端边界

另一套独立的 Git 终端（仓库锁定，不走后台会话存储）提供创建、输入、按字节偏移读输出、调尺寸、关闭。输入为同步执行单条命令并拼接到约一 MB 上限的字符串缓冲，前端轮询。调尺寸为空操作，仅刷新时间戳。该域与后台 shell 完全隔离，不复用会话池、溢出文件、注册表与事件总线。

## 二、ref/opencode 的后台终端设计

### 2.1 两个正交概念

opencode 严格区分后台任务与终端载体。任务注册表只管任务状态与通知闭环，终端存储只管进程与字节流，两者经标识关联而非合一。通知经合成消息唤醒会话而非经终端字节流推送，大输出经文件加游标而非经事件广播。

### 2.2 任务注册表

核心为进程内注册表加键值持久化两部分。运行态记录标识、类型、标题、状态（运行中、完成、失败、已取消）、起止时间与输出摘要；持久态只保留可恢复任务的最小恢复信息（shell 类记录会话标识与命令，子 agent 类记录父子会话标识）。

关键行为包括启动时去重并在独立作用域分叉运行、退出时结算状态并落盘；阻塞等待区分已完成直接消费、已被后台化返回后台化分支、否则注册阻塞计数并竞速等待完成或后台化信号；后台化仅对运行中任务有效（已完成但可恢复的允许延迟交接），后台化时分配通知标识并持久化，解除阻塞等待者；等待支持可选超时；不可恢复的已完成任务进入小容量最近最少使用队列，可恢复任务保留至通知确认；取消标记状态、解除等待、关闭作用域并消费条目；重启恢复通过扫描持久化键回放输出或说明取消原因。

容量上有明确上限，已退出条目保留约二十余条，输出文件按天清理与定时回收。

### 2.3 非交互 shell 存储与伪终端体系

shell 服务按位置作用域隔离，内存映射加输出文件两部分组成。创建时解析环境与 shell 二进制、分配递增标识、落输出文件、派生子进程并将字节流泵入文件，同时计数大小与行数、发布创建与退出事件、维护已退出上限、触发超时终结。输出读取按绝对字节游标分页，返回输出片段、当前游标与总大小；结果组装做行数与字节数双截断并提示完整输出的文件位置。运行中列表只返回运行中，已完成经通知消费。

伪终端体系分三层：短暂伪终端（标题、尺寸、游标续播、套接字连接）、会话级常驻伪终端（实验域，按会话读写屏、启停与交接，有独立守护进程与交接文件）、桌面后台服务（服务宿主保活，与任务注册表无关）。

### 2.4 支持后台的工具语义

shell 工具与子 agent 工具同形。输入含后台开关，无后台时默认超时约两分钟，有后台时默认不限时。执行流程为创建会话并上报进度、注册后台任务、根据后台开关分流。后台路径直接后台化任务并派生完成通知后返回标识与输出文件位置，附带不要轮询等待的指示。非后台路径阻塞等待任务，等待期间若被会话级后台化动作抢占，则同样转后台（清除超时并派生通知），否则等待结算。完成通知等待任务结算，组装带状态的通知文本，通过合成会话消息唤醒原会话，再确认并清理后台条目。中断时同时中断子会话并取消任务。

### 2.5 会话集成与降噪

手动后台化将会话当前阻塞的任务整体转后台，并合成一条列出任务类型与标题的提示，告知不要等待或轮询。用户直发 shell 以不限时创建会话并返回结果句柄，同时发布会话级起止事件。标记为后台的合成消息在转语言模型消息、压缩与更新路径被跳过或压空，避免后台通知污染上下文。

### 2.6 协议、事件与界面落点

shell 域按位置作用域提供列表、创建、查询、按游标读输出、删除（含终止与删文件）；伪终端域提供列表、创建、查询、改标题尺寸、删除、连接令牌与套接字连接；会话域提供直发 shell 与整会话后台化两个动作。事件经统一套接字下发创建更新退出删除。客户端提供连接构造器与生成式调用，网页端后台任务视图不直接读任务注册表，而是从时间线派生（筛选运行中的 shell 与子 agent 工具片段，减去已完成的合成通知，加上活跃子会话与按会话过滤的运行中 shell），命令行界面无 shell 任务直达命令。

## 三、对比结论

| 维度 | opencode | 当前项目 | 差距定级 |
|---|---|---|---|
| 任务与载体分离 | 注册表只管状态与通知，存储只管进程与字节 | 注册表已建但仅按会话标识跟踪标题状态，无阻塞计数与竞速语义 | 部分弥补，需补竞速 |
| 阻塞与后台化竞速 | 阻塞等待与后台化信号竞速，后台化可抢占前台等待 | 前台等待为忙轮询快照，后台化仅置位，不唤醒等待者 | 未弥补，体验与空转核心差距 |
| 完成通知闭环 | 等待结算后合成消息唤醒原会话，再确认清理 | 生命周期桥推送事件到总线，前端需订阅 see 事件，无合成唤醒与确认清理 | 半弥补，需补合成唤醒 |
| 大输出翻页 | 文件加绝对游标分页，分页返回片段游标总量 | 内存环加溢出文件，语义已对齐，但读输出游标与窗口游标双轨易混 | 基本弥补，需统一游标文档 |
| 超时语义 | 后台默认不限时，后台化时清除超时转常驻 | 创建即运行不限时已有，但前台转后台不清超时，单发路径仍钳制 | 部分弥补，需统一清除超时 |
| 手动后台化 | 整会话一键后台化并合成提示 | 仅单会话后台化工具，无整执行一键后台化 | 未弥补 |
| 子 agent 后台 | 与 shell 同形，同享注册表与通知 | 子 agent 无后台化语义，各自为政 | 未弥补 |
| 语言模型降噪 | 后台合成消息跳过压缩与上下文 | 无降噪，后台输出全文进上下文 | 未弥补，上下文污染风险 |
| 重启恢复 | 扫描持久化键回放或说明取消 | 进程随进程结束，语义已明确但前端无统一取消交代 | 语义明确，展示待补 |
| 传输 | shell 与伪终端各有直达接口与套接字 | 无 shell 直达路由，经工具调用面访问（有意为之，保分层与审计） | 有意不做，保持 |
| 前端聚合视图 | 从时间线派生后台工作视图 | 仅单卡徽标，无聚合一览 | 未弥补 |
| 命令行聚合 | 服务启停加后台提示文案 | 轻量与无头提示行已落地，完整终端聚合行未落地 | 部分弥补 |
| 常驻伪终端守护 | 会话级常驻伪终端加守护进程 | 无，且不应引入 | 有意不做 |

## 四、值得参考的设计

- 任务与载体分离继续坚持。注册表不感知字节流，存储不感知通知，这是前端聚合视图与手动后台化的事实源，已落地的注册表应继续沿此边界演进，不回退到会话忙闲。
- 阻塞与后台化竞速值得引入。当前忙轮询加置位的语义导致前台等待无法被后台化抢占，语言模型调用方易空转。参考竞速语义可显著减少轮询与超时误杀。
- 完成即合成通知值得引入。当前事件推送解决了可感知问题，但未解决可找回问题。参考等待结算后合成一条带状态与跳转指引的消息并经确认清理，才能闭环。
- 后台化附带不要轮询的提示值得保留并统一。已落地的后台指引文案与 opencode 一致，应推广到所有后台返回路径，避免调用方轮询等待。
- 运行中列表只返回运行中的约定值得坚持。已完成经通知消费，不长期驻留列表，列表保持小而活，当前实现已符合，应在文档中固化。
- 文件加游标的大输出模型已基本对齐，只需统一游标口径。当前快照、增量、窗口三口径并存，建议文档明确绝对字节游标为唯一真相，增量读作为窗口的便捷封装。
- 后台化清除超时转常驻值得补齐。前台转后台时不清超时会导致后台任务被误杀，参考 opencode 的零超时语义统一处理。
- 整执行一键后台化与语言模型降噪值得排期。前者是多任务并行时的刚需，后者是后台输出进上下文前的必要卫生。

## 五、不建议照搬的设计

- 会话级常驻伪终端守护进程不引入。该服务为桌面多终端窗格设计，含独立守护目录、套接字远调与交接文件，与当前单工作区网页加命令行形态不匹配，成本远大于收益。
- 伪终端双向套接字直连不引入。现有事件订阅套接字为广播语义，硬塞一连一会话的双向流会污染协议。后台 shell 轮询加通知已够用，真正的交互式接管留给 Git 终端域解决。
- 客户端直连进程不引入。命令行界面保持为服务端事件流渲染端，不直连本地进程，避免传输与鉴权双轨。
- 终端仿真器依赖不引入。后台任务输出为块状文本，用现有折叠尾部展示即可，不引入终端仿真依赖。
- shell 直达路由不硬接。会话存储归属工具注册表的有状态实例，应用门面无法直达，硬接会破坏分层。工具面已有鉴权、审计与接口覆盖，应保持现状并在文档中说明理由。

## 六、具体改进清单

### 执行语义补齐

- 为等待工具补阻塞与后台化竞速。等待期间若任务被后台化，立即返回后台化分支而非等到超时，返回体与后台创建路径同形。
- 后台化时清除超时转无限等待。前台转后台与创建即后台统一走零超时语义，避免后台长任务被前台超时误杀。
- 新增整执行一键后台化能力。将当前执行下全部阻塞任务整体转后台，并合成一条列出任务类型与标题的提示，告知调用方等通知而非轮询。
- 子 agent 后台语义与 shell 同形。复用同一注册表与通知口径，后台返回子会话标识，前台阻塞等待可被抢占，中断时同时中断子会话并取消任务。

### 通知闭环补齐

- 后台结算后合成可跳转的通知。载荷仅含任务标识、会话标识、状态与摘要，详情经任务查询拉取，保持事件元数据化、详情走接口的约定。
- 通知确认后清理已结算条目。可恢复任务保留至通知确认，不可恢复任务进有界消费历史，避免列表膨胀。
- 前端历史与压缩路径降噪。标记为后台的合成消息在转语言模型消息与压缩路径跳过或压空，后台结果只经完成通知进一次上下文。

### 输出与查询体验

- 统一游标口径文档。明确绝对字节游标单调递增，窗口读为主口径，增量读为便捷封装，消除双轨混淆。
- 任务列表支持全局运行中枚举与已结算可选包含。当前按执行标识过滤已有开关，建议补全局一览以支撑聚合视图，避免前端三路拼接。
- 会话开始事件进总线。当前开始事件仅工具层建基线，前端历史无徽标，建议补开始事件以便历史回放一致。
- 重启语义显式展示。进程随进程结束保持不变，但在任务详情中明确展示已取消原因，避免用户误以为任务仍在跑。

### 界面落点

- 前端新增后台任务聚合视图。数据源为任务面列表加执行流增量，展示标题、运行时长、关联会话与快捷跳转（跳到输出分页或对应工具卡），无终端仿真、无字节流直连。
- 完整终端补聚合行。复用已落地的后台标记透传链路，在页脚追加运行中计数，详情经任务查询拉取，不做尾随循环。
- Git 终端保持独立域。不与后台 shell 合并或复用，避免仓库锁定语义与后台会话语义混淆。

## 七、分阶段建议与验收

- 第一阶段补竞速与超时语义。验收为前台等待可被后台化抢占并返回后台分支，后台任务不再被前台超时误杀。
- 第二阶段补合成通知与确认清理。验收为后台命令完成后无需人肉轮询，通知可跳到任务详情，已确认条目不再驻留列表。
- 第三阶段统一游标文档与任务列表口径。验收为长构建日志早段可回看，分页游标单调递增，聚合视图只需调两个接口。
- 第四阶段落地前端聚合视图与整执行后台化。验收为运行中后台任务有统一一览，工具卡可一键转后台，多任务执行可一键整体后台化。
- 第五阶段补命令行聚合行、降噪与阈值调优。验收为命令行用户可见后台任务数与查询指引，后台输出不污染模型上下文。

每阶段只动本阶段所述模块，不提前引入后续阶段的传输或界面依赖。阈值沿用现有配置项，仅新增文件溢出阈值与保留时长两项，默认宜保守并配配额。

## 八、风险与取舍

- 输出文件溢出引入磁盘占用，需配额与保留时长，默认阈值宜保守，會话终止与回收必须删文件。
- 通知面当前为推送、无持久未读，离线客户端靠重连后查任务列表补齐，需在界面空态文案中说明。
- 单会话单命令并发限制保留，多并发需求经多会话满足，不放开同会话并发。
- 伪终端跳过内核强制的现状不变，需在设计中显式声明而非试图补齐，审计沿用现有工具调用审计，后台化与终止记为子动作。
