# 上下文压缩扩展后续设计

本文承接上下文压缩插件扩展分析与两轮落地，给出剩余三项的下一阶段方案：请求级改写、静态钩子定义同步求值、插件钩子桥接。只改原模块，不新增并行系统，不做历史兼容，开发期版本号保持不变。

## 0. 结论速览

* 请求级改写走建议协议扩展：建议输出加可选指令字段，随信号与管线装配进入各条目切片头，链模板零改。
* 静态求值走分发线程：分发签名加静态定义切片，火力现有求值与优先级合并复用；工作流侧透传节点定义，智能体侧保持传空。
* 插件桥接走现有注册入口与清单映射：新增与建议同步文件同级的桥接同步文件，原生与 Lua 各一处理器适配，停用对称移除，门控点按能力表 enforcement。
* 三项均不改变火力语义、审计口径与触发器异步路径。

## 1. 现状与缺口

### 1.1 改写无处落笔

* 建议输出只有整形（条目与丢弃），校验在 `wf-execution-shared` 压缩规划内完成；计划的其余部分不随发射旅行，待定存储只留条目与丢弃。
* 管线在 `wf-runtime` 触发监听压缩管线内按固定键组装链输入，提示词在 `wf-resource` 摘要阶段构建时烘焙进节点配置。
* 轻量语言模型节点的系统提示词支持模板变量，但变量来自静态节点配置；`transform_context` 有静态消息注入先例，尚无按请求动态注入。
* 强制安全网路径走无状态计划，不查询建议，因此即使有指令也到不了强制压缩。

### 1.2 静态定义到不了分发

* 分发以空定义触发火力，只有动态注册的观察者有效；火力本身早已支持静态定义求值、条件过滤、处理器名解析与全局优先级合并。
* 智能体配置的钩子类型是枚举，表达不了压缩信号点；工作流节点执行的定义随执行入口可达，但语言模型节点上下文没有通用定义字段，发射包装函数拿不到它们。
* 配置侧要求压缩点声明处理器，但该要求在同步路径从未兑现，只在异步触发器侧有意义。

### 1.3 桥接有口无源

* `wf-runtime` 的钩子注册入口（含插件映射注册）存在且有单测，但全仓库无调用方；清单 schema 已有插件钩子名到引擎钩子类型的映射字段。
* 桥接在激活与停用时对称同步各贡献，有建议与检索的同步文件先例可抄。
* Lua 后端有阻塞调用与节点、工具、事件、中间件四件套处理器适配先例，生命周期钩子缺失即跳过；原生后端有同步分发先例，但钩子处理器 trait 是异步的，直接调分发会占住执行器。

## 2. 目标与范围

* 目标：插件可为单次压缩附加指令；工作流静态定义可在分发点否决；插件可注册同步钩子处理器并走同一门控与替换语义。
* 范围：下述三节功能规格与测试；文档同步更新分析结论。
* 不做：链模板改造（含内建与贡献链的显式指令键位）；Wasm 钩子通道（沿用建议通道原生专属先例，待 Lua 通道落地后再议）；智能体配置枚举词汇扩展；新权限大类（复用现有权限）；版本号升级。

## 3. 功能规格

### 3.1 请求级改写（建议协议扩展）

* 建议输出新增可选指令字段（字符串）。引擎侧裁剪空白，空视为无；长度按上限拒绝并回退内建（上限按头房预算原则取值，实施时对照现有头房比例核定；字符数与估计词元双约束，超其一即拒）。
* 计划结构加请求级指令字段，与条目同行。该字段不进待定存储（待定只存条目与丢弃的既有语义不变），由发射点从计划取出后放入信号请求结构。
* 信号请求结构加指令字段；钩子数据图携带指令（自动进入审计词汇）；管线请求结构加指令；路由事件加指令字段与读取，路由执行入口解析后走同一装配（路由路径不断链）。
* 管线装配在条目切片提取后，于每片头插一条系统角色指令消息（动态版 `transform_context` 注入）。计划索引基于原快照，插值发生在切片提取之后，不影响范围合法性；头房裁剪先对历史、指令后插且计入上限。
* 模板零改：内建链与贡献链都把历史头当普通消息消费，无感接收；多条目计划下同一指令进入每一片（请求级语义）。
* 强制安全网路径无指令（无状态计划不查建议），文档注明为已知边界，不在本轮打通。
* 审计与指标口径不变：指令长度随钩子数据进入审计事件；发射计数不因子母有无分裂。

### 3.2 静态定义同步求值

* 分发签名加静态定义切片参数；分发内按信号点过滤后交火力，复用条件求值、启用开关、全局优先级排序、处理器名解析与缺失响亮跳过，不改火力任何语义。
* 工作流侧：节点执行上下文加通用定义字段，节点执行入口在已有定义可达处赋值一次；语言模型压缩发射包装函数透传该字段。字段默认空，既有构造方式不受影响（新增字段的迁移由编译器指引）。
* 智能体侧两发射点继续传空：智能体钩子配置枚举无此点，传空即现状；词汇扩展（枚举加压缩点并打通配置校验）明确另议，不在本轮。
* 无处理器的静态定义仍是纯审计，不产生否决；处理器缺失在门控点按失败开放（现有语义不变，只记错）。
* 触发器异步路径不变；静态求值不延长火力 barrier，不改变接管时序。

### 3.3 插件钩子桥接

* 在插件桥接目录新增与建议同步文件同级的钩子同步文件：激活时按清单映射注册，停用时按名对称移除；注册复用现有注册入口（含未知类型拒绝与重名拒绝），不新增映射 schema。
* 原生适配器：以分发柄加稳定名实现钩子处理器 trait，调用约定复用建议分发的序列化与输出校验；不得阻塞异步执行器，阻塞调用走阻塞任务，超时与熔断复用注册管线已有机制。
* Lua 适配器：沿用注册键加阻塞调用加执行上限的先例实现同一 trait；快照附件转 JSON 仅供本次调用（不进审计数据图）；Lua 侧缺失对应函数视为未注册该点（与现有生命周期钩子缺失语义一致）。
* 附件可见性：进程内后端（原生）可见附件；脚本后端（Lua）仅见数据图加调用期快照；替换所需摘要由插件侧构造（消息结构已知），引擎侧照单校验。
* 权限：纯观察点凭映射声明即可；门控点按能力表 enforcement：压缩信号要压缩权限，工具调用门要工具权限，工作流执行门要工具权限。缺权限拒绝注册并记错；能力表后续扩展只加行，不改机制。
* 生命周期：停用按名移除；重载按现有桥接顺序先移除后同步；注册名全局唯一，冲突时后者失败并记错（沿用注册表语义）。
* Wasm 明确不做：无调用通道，文档注明沿用原生专属先例。

## 4. 测试策略

* 改写：超长与空指令回退内建；指令随路由事件往返不丢；管线装配头插且条目索引不变；强制路径无指令；审计事件携带指令。
* 静态求值：静态否决取消接管且不留待定；条件过滤与优先级合并符合火力既有单测语义；处理器缺失失败开放；智能体空定义行为不变。
* 桥接：原生与 Lua 适配最小用例（观察、否决、替换各一）；停用对称移除后再次分发无接管；缺权限拒绝注册；重载不残留旧名。
* 全量编译验证一次完成；新增单测随原文件走，不建新测试包。

## 5. 实施顺序与验收

* 顺序：改写先行（只碰建议与管线装配），静态求值次之（只加线程参数），桥接最后（依赖门控语义稳定）。三者无互相阻塞，可串行一次做完，中途不留双轨。
* 验收：上述用例全绿；无新增模块与并行路径；审计事件字段只增指令一项；触发器异步路径行为不变；分析文档结论段同步更新。
