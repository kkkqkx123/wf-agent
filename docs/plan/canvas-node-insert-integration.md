# 画布节点插入链路问题清单与修复方案

本文记录节点插入从模板选择、跨页面排队、画布编辑、校验到存储写入的完整问题清单，以及本次采用的修复方案。目标是让一个插入意图贯穿所有层，而不是由每一层自行猜测节点类型与来源。

## 现状链路

1. 节点模板详情页从存储定义读取 `node_type`，规范化后写入 `sessionStorage` 队列，并跳转到目标工作流画布。
2. 工作流模板进入 graph 模式时读取队列，把节点追加到编辑会话文档；画布再由会话文档投影出节点和边。
3. 画布自身的 Add Node 抽屉从节点模板列表读取候选，发出位置、节点类型和模板名。
4. 保存时对工作流定义执行服务端校验、临时草稿编译检查，最后正式写入工作流存储；后端正式保存再次校验。

## 问题清单

### 1. 画布 Add Node 事件契约断裂

`GraphExplorer` 已经发出位置、规范化节点类型和模板名，但模板编辑面板只接收位置并继续向下传递。控制器因此无条件创建 `STEP` 占位节点，节点名退化为自增 id。抽屉里的选择被完全丢弃，`STEP` 也不是后端内置节点类型，只会被当成缺少插件提供者的自定义类型。手工清空节点类型输入框时同样回退到 `STEP`。

### 2. 模板插入没有形成模板实例

跨页面队列只携带节点类型和模板显示名。后端已有按节点配置中的 `template_id` 应用模板默认配置的组合逻辑，但新增节点没有携带该引用，拓扑解析与合并也不保留节点配置。因此“插入模板”实际只是“插入同类型的裸节点”。

### 3. 队列不是可靠的一次性意图

队列条目带有时间戳但没有过期判断；恢复时只检查 `nodeType` 非空；消费发生在会话合并之前；目标工作流不匹配时队列会长期滞留；来源模板 id 也没有用于恢复提示。这些缺口会造成脏数据复活、插入失败后意图丢失、旧意图在后续会话中意外生效。

### 4. 校验没有覆盖插入动作

来源模板入队前没有再次校验；插入后的节点没有立即进入带节点定位的服务端校验；工作流校验接口只返回合并文本，缺少字段和节点定位；用于编译检查的临时草稿 id 固定，并发检查同一工作流时会互相覆盖。

### 5. 模板候选来源不完整

Add Node 抽屉只读取节点模板存储表，运行时装配器和插件贡献的节点模板只注册到内存注册表。干净环境下内置或插件模板不会出现在抽屉中。另一方面，存储中的节点模板在重启后没有重新注册进运行时注册表，节点配置中的模板引用无法应用默认配置。

### 6. 画布位置没有进入保存链路

新增节点的位置只写在编辑态的 `GraphEditStore.positions` 中，拓扑合并时不写布局；模板工作流重新打开后只能依赖自动布局。后端与前端已有工作流布局接口，模板编辑页没有接入。

## 修复方案

### 统一插入意图

在画布事件、跨页面队列和会话合并之间使用同一组字段：位置、规范化节点类型、节点名、来源模板 id。空白节点的默认类型使用正式的内置 `SCRIPT`，不再产生 `STEP`。模板 id 写入节点配置，使后端组合层可以应用模板默认配置。

### 修复事件转发链

扩展模板编辑面板及其两个使用方的回调签名，把 `GraphExplorer` 的完整选择结果传给控制器。控制器统一负责 id 分配、类型规范化、名称回退和模板引用写入。节点类型输入框清空后回退到正式默认类型。

### 扩展拓扑模型

显示节点增加可选配置字段；拓扑解析读取它，拓扑合并写回它，后端定义构造保留它。原有节点字段继续按 id 匹配更新，未知字段不丢失。

### 加固跨页面队列

读取时规范化并校验全部字段，依据入队时间剔除过期条目；先应用插入，成功后才清除队列；目标不匹配和锁定不可写时不消费意图。来源模板校验失败则不入队。

### 补齐校验闭环

入队前对来源节点模板执行 dry-run 校验。队列插入完成后触发一次静默服务端编译检查，使用草稿校验返回的字段与节点定位展示问题。编译检查草稿使用唯一 id，并在结束时清理。

### 合并模板候选来源

节点模板列表由存储记录与运行时注册表合并得到：同 id 以存储记录为准，注册表独有条目作为只读候选追加。启动时把存储中的节点模板重新注册进运行时注册表，保证重启后模板引用仍可解析。

### 持久化模板画布布局

工作流模板编辑页传入布局 id；保存拓扑成功后把编辑态位置与已有布局合并写回布局接口。纯查看模式继续沿用现有自动保存逻辑。布局写入失败只提示，不回滚已保存的定义。

## 编译基线修复

远端整包编译暴露出 `vector-contracts` 的 simvec 适配层仍按旧的 `VectorSpaceConfig` 结构体字段写法构造和读取配置，而当前 `simvec` 已改为枚举加方法访问器。该问题与画布插入无关，但会阻断任何完整编译，因此同步修正映射逻辑；稀疏命名空间的维度按引擎公开的开区间上界声明。

## 验收标准

- 抽屉选择任意模板后，画布节点类型、名称和模板引用与选择一致。
- 空白节点使用 `SCRIPT`，不存在 `STEP` 默认值。
- 从模板详情插入后，目标工作流画布自动出现节点，且刷新、错目标和过期队列不会造成重复或幽灵插入。
- 插入后的问题列表可以定位到具体节点，保存前校验与后端正式保存保持一致。
- 内置与插件模板出现在 Add Node 抽屉，存储模板在重启后仍可解析。
- 保存后重新打开工作流模板，节点位置和拓扑都保留。
