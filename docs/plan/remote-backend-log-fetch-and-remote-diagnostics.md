# 远程后端日志读取与远程诊断收敛方案

## 背景与结论

项目已有两类日志读取路径，但覆盖的层次不同：

- 执行日志来自生命周期事件，服务端提供按执行与全局查询接口，CLI 的 `execution logs` 通过全局 `--remote` 可以查询远程服务的执行日志，并支持跟随。这条链路已经完整，不重复建设。
- 远程部署节点的进程日志由启动脚本写入远端安装根目录下的 `logs/wf-server.log`。此前只有启动和健康检查失败时附带一小段尾部输出，没有独立的读取入口。

因此本次补充只针对远程部署节点的进程日志：作为后端域的只读能力，从管理端经既有 SSH 通道读取固定文件，不经由任意 shell 参数，也不新增日志存储。

## 远程进程日志读取

### 能力边界

- 服务端新增 `GET /api/v1/system/backends/{name}/logs`，按注册后端名读取远端进程日志尾部。
- CLI 新增 `wf remote logs NAME`，支持 `--lines`；文本格式直接输出日志正文，结构化格式返回包含后端名、远端路径、行数、截断标记和正文的响应。
- 每次读取都是实时远端操作，不在管理端持久化日志，也不进入执行恢复 bundle。执行恢复 bundle 继续只承载执行记录、历史、审计、检查点和文件归档。
- 未实现的伴随能力：跨后端聚合检索、关键字过滤、持续跟随、日志轮转管理和任意远端文件读取。

### 分层职责

- 部署模块持有唯一的命令构造点与远程执行通道。命令固定为对安装根下日志文件的尾部读取，行数先收敛到合法区间，安装根在部署配置解析时已限制为相对路径，路径在命令中按 POSIX 规则引用。
- 后端管理器负责解析注册项、读取部署设置、应用行数边界，并返回统一视图；不缓存日志内容。
- HTTP 层负责鉴权、后端域开关、参数校验和错误映射。行数为零或超过上限时直接拒绝，未知后端返回未找到，域名关闭时返回服务不可用。
- CLI 只负责调用管理端 API 和按输出格式渲染，不直接建立 SSH 连接，也不接受注册名以外的远端路径。

### 安全与可靠性约束

- 远端命令形制固定，调用方只能提供后端名和行数；后端名用于查注册表，行数在服务端收敛，路径由安装配置派生。
- 单次响应限制行数与字节数；超限时保留最新字节并在正文前标记截断，避免长行挤掉最新日志。
- SSH 失败、文件不存在和超时统一转成可读错误，错误信息来自有界裁切的远端输出。
- 该接口沿用后端管理域的 API key 鉴权。日志正文可能包含业务诊断信息，调用方仍需按运维凭据保护响应。

## Qdrant 日志逻辑评估

`vector-contracts` 中 Qdrant 后端的日志是合理的，原因如下：

- 它是远程 HTTP 后端，重试、限流、版本漂移和响应解码失败在调用点无法被本地状态推断，必须有可观测输出。
- 日志只记录集合名、行数、尝试次数等低基数字段，不记录向量、载荷和查询条件。
- 远端错误体进入日志或错误文本前统一做脱敏、控制字符清理和长度截断，避免凭据通过诊断信息外泄。
- 本地内存与 simvec 后端没有远端故障面，不需要复制同一套日志，避免为对称而制造噪声。

## 全文检索的同类处理

全文检索后端分为两类：SQLite FTS5 与 Tantivy 是本地索引，不需要镜像 Qdrant 的远程诊断；Elasticsearch 是与 Qdrant 对等的远程 HTTP 后端，存在相同的重试不可见和错误体无界问题。

本次将远端响应诊断函数上移到 `vector-contracts` 的错误模块，由 Qdrant 与 Elasticsearch 共同使用，避免两处脱敏规则漂移。Elasticsearch 侧补齐两项：

- 重试时在远端后端名下记录尝试次数与失败原因，使限流与瞬时故障可见。
- 所有带远端响应体的错误统一经过脱敏与截断，批量写入的条目错误同样处理。

版本漂移的既有判定保留为纯函数，不在本次扩大其调用面；全文检索的诊断增强不引入新的索引能力或检索语义变更。

## 验证范围

- 远端日志路径构造与响应截断使用单元测试覆盖。
- 远端响应脱敏在共享诊断函数与 Elasticsearch 错误构造处覆盖。
- 编译检查覆盖后端域、CLI 共享层和向量/检索相关包的全部目标。
