# 回溯设计方案

> 本篇回答借鉴什么、不借鉴什么，以及回溯怎么在现有分层里落地。以自然语言与表格为主，不含完整代码实现。

## 一、借鉴取舍

| atomcode 做法 | 是否借鉴 | 本仓库的处理 |
|---|---|---|
| 运行时是回溯的唯一所有者，界面只做投影 | 借鉴 | 组合动作放应用门面，命令行与网页只提交一个请求、消费一个终态 |
| 复用回合接缝，不新造状态机 | 借鉴 | 在 agent loop 的回合起止处挂接，复用现有检查点创建路径 |
| 逐回合两次全量扫描 | 不借鉴 | 优先引用链上已有检查点，仅在边界缺检查点且有变更时补拍 |
| 独立影子仓库 + alternates 借用对象 | 不借鉴 | 复用现有 `refs/wf/` 对象库，新增独立引用子命名空间 |
| 账本旁车文件 | 不借鉴 | 落 SQLite，新增表与幂等迁移 |
| `(current)` 默认空操作、两步提交 | 借鉴 | 面板首行是当前状态，回车即关闭；先选回合再选作用域 |
| 运行中只允许取消并抑制手势 | 借鉴 | 流式期间不武装双击 Esc，斜杠命令返回忙碌提示 |
| 缺失对象隔离为“仅会话” | 借鉴 | 点级状态投影，文件侧单独禁用，不整体关闭 |
| 先钉后回收、写失败回滚账本 | 借鉴 | 引用先写、账本后写；裁剪先写账本、后删引用 |
| 恢复前拍恢复树 | 借鉴 | 恢复树同时用于冲突判定与补偿 |
| 析构默认走恢复 | 借鉴 | 事务守卫未显式终结时按补偿方向处理 |
| 代码单改作用域 | 不借鉴 | 界面只给会话、会话加代码两档 |

补充两条本仓库特有的取舍：

- **会话回退用投影，不做物理删除**。所有可视化与历史读取都按“会话当前头序号”过滤，回退只是把头序号前移；因此可审计、可复核，也避免与既有消息去重逻辑打架。
- **引用即钉住**。为每个回溯点写持久引用，既保证对象不被回收，又省掉临时的钉住生命周期管理；提交失败只需删掉刚写的引用。

## 二、分层归属

| 层 | crate | 新增内容 |
|---|---|---|
| 基础类型 | `wf-types` | 回溯点、作用域、状态、账本页、预览与 receipts 的数据类型；回溯配置 |
| 文件存储 | `checkpoint-file` | 回溯账本表与迁移；点的持久引用写入/删除；树闭合预检；可用空间探测 |
| 门面 | `wf-checkpoint` | 账本读写协调、点捕获与保留、恢复前置与事务、与文件检查点管理器的组合 |
| 引擎 | `wf-agent` | 回合边界接缝：开始与终结时通知门面（不持有账本逻辑） |
| 应用门面 | `wf-api` | 会话锚、回溯领域接口、会话历史投影 |
| 传输层 | `wf-server` | 回溯路由与请求/响应信封 |
| 命令行 | `wf-tui` + `tui-core` + `tui-components` | 命令项、双击 Esc 手势、面板路由与面板状态、异步事件 |
| 网页 | `web-app` | 服务层函数、消息气泡动作、两步模态与状态回填 |

不新建 crate，不新建 `mod.rs`；新增模块一律为同目录下的独立文件。

## 三、前置改造：会话锚

回溯账本的主键必须是会话，而不是单次运行。当前 agent loop 域缺少这一层，需要先补，且补法与 `chat` 域保持一致。

### 语义

- **会话标识**：由客户端定义并跨回合稳定（命令行标签页标识、网页会话标识）。
- **运行标识**：仍由服务端每次运行生成，表示一次 agent loop 执行，保持不变。
- 一个会话包含多个运行；回溯点挂在会话上，指向所属运行。

### 改动面

1. 请求体与运行参数新增可选会话标识，缺省时服务端生成，保证旧调用方仍可用。
2. 消息元数据新增会话标识与消息序号两个字段；序号来自引擎会话快照的序号区间，不由数组下标推断。
3. 新增按会话读取历史的查询，跨运行按序号升序拼接；现有按运行读取的查询保留，供审计使用。
4. 消息持久化改为“只追加本回合新增消息”，对客户端回传的历史做幂等去重，避免多回合重复写入。
5. 聊天域已有会话标识，不改语义，只把共用的历史读取下沉为同一实现。

### 验收要点

- 同一会话连续三次运行后，按会话读取历史得到 3 个回合的完整消息，且无重复。
- `--resume` 与回放路径不回归。
- 会话标识在命令行标签页重连、迁移后保持不变。

会话锚是回溯的地基；它同时修掉“服务端看不到会话”这个既有缺陷，因此列为第一阶段的独立交付。

## 四、数据模型

### 回溯点

一个点描述“某个用户回合的边界”，字段分为四组：

| 组 | 字段 | 说明 |
|---|---|---|
| 身份 | 点标识、会话标识、回合序号 | 回合序号从 1 递增，单调不复用 |
| 提示词 | 提示词文本、预览、提示词消息序号 | 序号是会话回退的坐标：保留序号小于它的消息 |
| 文件 | 回合前树、回合后树、前后持久引用、变更计数、文件侧状态 | 树可引用已有检查点提交；文件侧状态区分准备中/就绪/仅会话/缺失 |
| 治理 | 创建时间、终结原因、是否归档、缺失原因 | 归档用于回退后被超越的点，保留审计 |

文件侧状态机：

- `Pending`：回合已结束，回合后树仍在后台捕获。
- `Ready`：两侧树齐备，可做文件回退。
- `ConversationOnly`：没有可用树（未启用、无变更、捕获失败、对象缺失），只支持会话回退。
- `Missing`：预检发现对象缺失，投影为仅会话并记录原因。

### 账本

- 按会话组织，按回合序号倒序分页读取。
- 有界保留，默认 100 个点，可配置；超出后从最旧开始裁剪。
- 裁剪只影响账本行与对应持久引用，不影响既有 actor 编辑线；被归档的点不再出现在默认列表。
- 写入失败必须回滚到上一版列表并上报，不允许出现“界面显示有点、实际不可用”的静默状态。

### 作用域与状态

- 作用域三档：会话、代码、会话加代码。命令行与网页只暴露会话、会话加代码两档。
- 可用性：启用、未启用（含原因）、无会话、预算不足、代码侧不可用（含原因）。界面据此决定作用域行是否可选，而不是整面板不可用。

### 配置

新增回溯配置段，默认值如下：

| 项 | 默认 | 说明 |
|---|---|---|
| 启用 | 是 | 关闭后不建点、不建引用 |
| 保留点数 | 100 | 每会话 |
| 边界补拍 | 是 | 回合边界没有既有检查点且有变更时补拍 |
| 存储预算 | 1 GiB | 超过后先回收再拒绝新捕获 |
| 磁盘余量下限 | 2 GiB | 低于该值拒绝捕获并提示 |
| 单文件上限 | 复用文件检查点上限 | 不引入第二套阈值 |

## 五、捕获接缝

### 位置

回合在 agent loop 域是“一次运行”，因此接缝放在应用门面的运行编排处：运行开始前登记回合起点，运行终结时登记终点。这样命令行与网页天然一致，引擎只保留一个“回合开始/回合终结”的通知点。

### 起点做什么

1. 记录提示词文本与预览、回合序号。
2. 记录会话当前的下一个消息序号，作为回退坐标。
3. 记录当前最新文件检查点提交作为回合前树；若没有可用检查点且有变更，按需补拍一棵树。

起点只做登记与一次引用查询，不扫描工作区（补拍除外），保证每回合开销可控。

### 终点做什么

1. 包括成功、失败、取消三种终结，都要落点，避免账本漏回合。
2. 优先取本回合内产生的最新文件检查点作为回合后树；没有则按配置在后臺补拍，点在补拍完成前保持 `Pending`。
3. 计算变更计数与受影响文件样本，写入点。
4. 写点顺序：先写持久引用，再写账本行；账本写失败则回滚并删除刚写的引用。

### 与既有节奏的关系

- 现有 `CheckpointTiming` 的按迭代节奏保持不变，回溯不改变检查点产生频率。
- 若用户关闭了常规检查点，只保留回溯所需的边界补拍，由回溯配置独立控制，避免耦合。
- 补拍在阻塞线程池执行并受超时约束，不阻塞回合终结事件的发出。

## 六、存储与回收

### 表结构

在文件检查点库新增两张表，走既有幂等迁移：

| 表 | 用途 | 关键列 |
|---|---|---|
| 回溯点 | 账本主体 | 会话、回合序号、提示词、序号边界、前后引用、文件侧状态、时间、归档标记 |
| 回溯事务 | 在途与历史事务 | 点标识、阶段、恢复引用、目标树、更新时间、结果 |

索引按会话与回合序号倒序，保证面板分页是一次日志级查询。

### 引用命名

统一挂在既有命名空间下，避免与主线、编辑线、评审、协作目标混淆：

- 点前树引用、点后树引用：按会话与回合组织。
- 恢复引用：按会话与点组织，供补偿与事后复核。
- 临时补拍引用：捕获期间使用，账本提交后转为点的持久引用。

### 顺序保证

这是最容易出错、必须写死的地方：

1. 捕获先写引用，再改索引/工作区。
2. 账本提交成功后才允许回收被裁剪点的引用。
3. 裁剪前先把“旧点集合 + 新点集合”的引用都视为存活，账本写完再删旧引用。
4. 事务未提交前，恢复引用不参与回收。
5. 引用删除失败只记日志，不把已提交的操作报成失败。

### 预算与余量

- 新增可用空间探测（`libc` 已在工作区依赖中，无需新依赖）。
- 捕获前检查：可用空间低于下限、或库体积超过预算时，先触发一次回收；仍不满足则拒绝捕获，把点降级为 `ConversationOnly` 并记录原因。
- 回收沿用现有保留策略与存储统计，不新增第二套 GC。

## 七、应用与事务

### 前置校验

应用一个点之前必须全部通过，任一失败都不改工作区：

1. 会话匹配、点未归档、文件侧状态允许所选作用域。
2. 会话空闲：没有在途运行、没有待审批、没有待回答的提问。
3. 点的前后引用仍可解析；所选作用域是代码时，目标树闭合预检通过。
4. 版本一致：请求携带的“回合后树”与点的当前值一致，避免面板过期后误应用。

### 冲突判定

- 代码作用域下，先把当前工作区拍成恢复树，这一步同时承担安全与判定两个职责。
- 用恢复树与点的回合后树比对，得到冲突路径集合。
- 冲突非空时，默认拒绝并返回冲突清单；调用方显式确认后才覆盖。
- 预览阶段不拍全树，改用文件大小与修改时间的快速比对给出“疑似冲突”，并明确标注为疑似。

### 事务状态机

三个阶段：已准备、已应用、已提交。

| 阶段 | 已完成的副作用 | 失败后的方向 |
|---|---|---|
| 已准备 | 写事务行、写恢复引用 | 补偿：删恢复引用与事务行 |
| 已应用 | 会话头序号前移、文件已恢复 | 补偿：按恢复树还原文件、会话头序号复位 |
| 已提交 | 账本更新、点归档、事务终结 | 只清理临时引用，不影响结果 |

- 事务守卫在未显式终结时按补偿方向处理，即崩溃或提前返回不会留下“半应用”状态。
- 启动时扫描未终结事务：能确定工作区已完全应用则补提交，否则按恢复树回滚并上报。

### 会话侧应用

- 不做消息删除，只把会话的回退头序号前移到一个序号边界（点的提示词序号）。
- 历史读取按头序号过滤；回退后可继续在同一会话追加新回合，新消息序号从边界继续递增。
- 返回给调用方的会话由服务端按边界物化，命令行与网页直接采用，不各自截断。
- 若该回合附近存在可用的执行状态检查点，可一并取回决策账本与令牌跟踪器；取不到则重新计算，不阻塞回退。

### 代码侧应用

- 目标为点的回合前树；按当前恢复树与目标树的差异计算恢复集合。
- 复用选择性恢复：写回目标内容的文件、删除目标树中不存在的文件、跳过嵌套与超大文件、保留 gitlink 现状。
- 恢复后按目标树逐个校验哈希，校验失败视为应用失败并走补偿。
- 空目录清单沿用对象库已有记录，不另建机制。

### 失败语义

- 所有失败都必须可见：忙碌、过期、冲突、缺失、预算、IO 各有明确原因。
- 代码侧失败但会话侧已前移时，必须把会话头序号复位，不能只回滚一半。
- 部分文件恢复成功再失败时，按恢复树整体补偿，而不是逐文件猜测。
- 补偿自身失败要上报为“需要人工介入”，并保留恢复引用与事务行，不做静默清理。

## 八、接口设计

### 门面接口

| 接口 | 输入 | 输出 | 说明 |
|---|---|---|---|
| 列举回溯点 | 会话、分页游标、条数 | 点摘要列表、下一页游标 | 摘要含提示词预览、回合序号、时间、变更计数、文件侧状态、是否当前头 |
| 查询回溯状态 | 会话 | 可用性、当前头序号、点数、存储统计 | 面板打开与按钮置灰依据 |
| 预览回溯 | 点、作用域 | 将移除与保留的消息条数、文件变更集合与样本、疑似冲突、阻断原因 | 无副作用 |
| 应用回溯 | 点、作用域、期望回合后树、是否覆盖冲突 | 新的会话、恢复/删除/跳过清单、恢复引用、被归档点数 | 有副作用，幂等键为点与期望树 |
| 保留裁剪 | 会话、保留点数 | 裁剪条数、剩余点数 | 由回合写入与手动维护共用 |

### 错误分类

未就绪、对象缺失、存在冲突、会话忙碌、会话不匹配、请求过期、预算不足、未启用、IO 失败。每类都要能映射到界面文案与可执行动作（重试、强制覆盖、改用仅会话、稍后再试）。

### 传输层路由

统一挂在版本化接口下，按会话与点两级组织：

| 方法 | 路径 | 用途 |
|---|---|---|
| 读 | `/api/v1/rewind/sessions/{session_id}/status` | 状态与可用性 |
| 读 | `/api/v1/rewind/sessions/{session_id}/points` | 分页列举 |
| 写 | `/api/v1/rewind/points/{point_id}/preview` | 预览 |
| 写 | `/api/v1/rewind/points/{point_id}/apply` | 应用 |

沿用现有信封与分页规范；应用接口要求携带期望回合后树，服务端据此做乐观并发校验。

## 九、命令行交互

### 入口

- 命令表新增一项：标识为会话回溯，标题“Rewind”，分组为会话，斜杠名 `rewind`（别名 `rw`），带 leader 快捷键，出现在命令面板。
- 低层动作新增一个“打开回溯面板”的取值，供命令表与键位解析共用。
- 双击 Esc 手势：单次 Esc 保持现有语义（取消、关闭浮层、清选区、退出搜索）；空闲且无浮层时，两次 Esc 在短窗口内连按才打开回溯。流式期间不武装，取消后清空武装状态，避免连续按键溢出。

### 面板

两阶段状态机：

1. 回合阶段：首行是“当前状态”伪条目，默认选中；向下选择更早回合；回车落在“当前状态”上即关闭，不产生任何副作用。
2. 作用域阶段：默认“仅会话”；“会话加代码”在不可用时置灰并显示原因；回车提交，Esc 返回上一阶段，再 Esc 关闭。

每行展示：提示词预览、回合序号、相对时间、文件变更计数、状态标记（当前、准备中、仅会话、缺失）。

### 异步与状态

- 打开面板时发起状态与列表请求，结果经专用交互事件回填，不阻塞按键循环。
- 应用请求在独立任务执行，结果同样经事件回填；期间面板禁用回车并显示进行中。
- 应用成功后：用返回的会话替换本地历史、同步消息序号、清空选区与锚点、把提示词回填到输入框、在转录区打印一行结果提示。
- 失败时只在面板内展示原因，不改本地历史、不改工作区。

### 与其他入口的关系

- 现有撤销上次输入保留，不合并进回溯；回溯是回合级，撤销是输入级，语义不同。
- 帮助视图、命令面板、快捷键提示全部由命令表派生，不新增第二份说明。

## 十、网页交互

- 消息气泡新增“回到此处”动作，与重试、继续、反馈同型扩展。
- 点击后打开两步模态：先选回合（同样有“当前状态”行），再选作用域；不可用原因就地显示。
- 服务层新增四个函数对齐门面接口，沿用现有检查点服务的错误处理风格。
- 应用成功后用返回的会话重建当前会话消息、更新当前头标记、滚动到输入区并提示结果；流式进行中禁用动作。
- 会话列表与回放视图只读取新的头序号，不做本地截断。

## 十一、安全与资源边界

| 边界 | 处理 |
|---|---|
| 破坏性操作 | 仅空闲可执行；默认不覆盖冲突；恢复前必拍恢复树 |
| 用户改动 | 冲突判定覆盖未提交改动；超大文件与 gitlink 不参与删除 |
| 对象完整性 | 代码作用域必须通过树闭合预检；缺失隔离为仅会话 |
| 磁盘 | 余量下限与存储预算双闸门；超限先回收后拒绝 |
| 崩溃 | 事务行 + 恢复引用 + 启动扫描；守卫默认补偿 |
| 并发 | 会话级串行；复用现有作用域序列化配置与超时 |
| 审计 | 账本不删除，只归档；恢复引用保留到被下一轮回收 |

## 十二、分阶段落地

| 阶段 | 内容 | 验收 |
|---|---|---|
| 第一阶段 | 会话锚：请求与会话标识、消息元数据补会话与序号、按会话读历史、去重回写 | 连续三回合后按会话读历史完整无重复，续跑与回放不回归 |
| 第二阶段 | 账本与捕获接缝：表与迁移、点模型、回合起止登记、引用与账本写入顺序、保留裁剪 | 成功/失败/取消三种回合都有点，写失败可回滚，裁剪不丢可用对象 |
| 第三阶段 | 应用与事务：预览、冲突判定、树闭合预检、选择性恢复、补偿与启动恢复 | 冲突默认拒绝，强制覆盖可回退，崩溃后无半应用 |
| 第四阶段 | 门面与路由：五个接口、状态投影、乐观并发校验、错误分类映射 | 接口可列举、可预览、可应用，错误可读 |
| 第五阶段 | 命令行：命令项、双击 Esc、面板两阶段、异步事件、结果回填 | 回车落在当前状态为空操作，流式期间不误触 |
| 第六阶段 | 网页：气泡动作、模态、服务函数、状态回填 | 网页与命令行在同一后端行为一致 |
| 第七阶段 | 预算与可观测：可用空间探测、回收联动、指标与审计查询 | 超限降级为仅会话且原因可见 |

每阶段只动本阶段所列模块；界面阶段不得提前引入后端未稳定的字段。

## 十三、开放问题

1. 消息序号持久化需要和多回合去重一起改，工作量集中在第一阶段；若想压缩周期，可先做“客户端截断 + 服务端账本只读”，但会牺牲跨端一致性与重启后的可恢复性，不推荐。
2. 工作流执行是否复用同一账本，取决于是否也引入会话锚；当前按阶段外处理。
3. 是否提供“前进回溯”（撤销一次回溯）。数据结构上可行（恢复引用即前向树），但会显著扩大界面状态，暂不做。
4. 多点并发回退的合并语义不做，保持会话级串行。
