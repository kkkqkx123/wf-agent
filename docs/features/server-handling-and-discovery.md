# 本地与远端服务处理及 CLI 发现列出

本文梳理当前本地 `wf-server`、远端 `wf-server` 的处理逻辑，以及 CLI 如何解析连接、发现并列出服务。引用路径相对仓库根目录，只讲结论与意图，不贴实现。

## 一、本地服务

本地服务指本机直接运行的 `wf-server` 进程，CLI 经 HTTP 直连。

* 启动入口为 `crates/app/wf-server/src/main.rs`，监听地址按显式 `--addr`、环境 `WF_SERVER_BIND_ADDR`、文件层 `server.toml`、内置默认 `127.0.0.1:3000` 的优先级解析，文件存在但非法则启动失败，不静默换端口。
* 单进程只绑一个端口，多本地服务即多进程各占一端口，不存在进程内多监听。远端场景下每个被管后端也各占一个本地回环端口，见第三节。
* 多目录服务由 `directory::DirectoryContext` 承载：`allowed_roots` 做显式目录白名单，非回环监听且白名单为空会告警；每个工作区请求经 `x-wf-directory` 请求头或 `directory` 查询参数携带归属，无目录请求在工作区处理器直接拒绝，除非运维用 `--directory` 指定单机默认目录。前端静态目录缺省为纯接口模式，配置后叠加单页回退。
* 指标与接口可合服，`serve_full_with_config` 把指标路由与接口路由合并后统一绑定、统一优雅停机；关闭时先标停服务、回收远端隧道与后台循环，再停接入层，最后停运行时。

## 二、远端服务

远端服务指跑在另一台机器上的 `wf-server`，本地经 `ssh -L` 隧道以回环地址访问，执行始终留在远端进程内。

* 连接引用为注册表条目，字段只有主机、端口、用户、密钥路径、跳板机、远端目录、远端服务端口、本地端口，不存密钥材料。服务端持久化在 `sqlite` 或内存，本地 `remotes.json` 只做一次性导入源与不可达时只读回退，写操作只走服务端单写者。
* 隧道由 `backends/tunnel.rs` 监管，按后端名最多一个常驻 `ssh -N` 子进程，参数与客户端展示形态逐字段对齐，启动前做同名检查与本地端口预检，冲突拒绝并提示换端口；异常退出只记中断原因，不自动重启；随服务关闭全量回收。
* 存活由后台探测轮维护，定周期分片并发，每项独立超时，先连本地端口，再请求远端健康与版本接口，单项失败只写本项状态。备份轮按条目间隔判断到期，到期才拉取执行包与检查点链并按数量与时间双上限裁剪。
* 准入期做有效本地端口唯一校验，不同名同端口在创建、更新、导入时直接拒绝，同名覆盖视为更新而放行，避免冲突延迟到启动时才暴露。
* 人工回退路径只打印命令不执行：隧道打印转发命令，拉起打印远端 `wf-server --addr 127.0.0.1:端口` 与隧道命令，停止打印按端口精确匹配的远端终止命令，同机多服务不会误伤。

## 三、多服务端口规则

* 本地端口有效值为显式值或服务端全局默认值 `18080`，远端服务端口默认 `3000`，两端可各自覆盖。
* 多后端必须各占不同本地端口，第二个缺省项会与第一个冲突并被准入或启动拒绝，不做静默自动分配，避免用户预期的隧道地址漂移。
* 端口占用预检用本地绑定试探，启动后另有短暂宽限复检，宽限内已退出的直接转启动失败，覆盖抢占与参数错误的即时反馈，慢失败仍走回收与中断原因。
* 跨管理进程无协同，多实例共享同库或同端口需外部保证唯一管理者。

## 四、CLI 连接解析

所有 CLI 形态经 `wf-client` 统一解析连接，不存在分支解析。

* 地址优先级为显式 `--remote`（含 `run` 子命令自带 `--remote`）、环境桥 `WF_REMOTE_TUNNEL_PORT` 拼出的回环地址、环境 `WF_REMOTE`、内置默认 `127.0.0.1:3000`。注册表主机名在此处不自动解析，需经隧道地址或环境桥显式传入。
* 凭证来自 `--api-key` 或 `WF_API_KEY`，经 `x-api-key` 请求头发送；业务目录来自 `--directory`、交互形态位置参数、`WF_DIRECTORY`、进程工作目录，经 `x-wf-directory` 默认头发送，下载与事件流等无头通道改用查询参数携带同一目录。
* 通用命令先按解析地址做健康探测，不可达即报启动服务提示；隧道桥存在时追加隧道可能中断的提示。工作区命令另做亲和性校验，对比本地项目标识与服务端上报标识，一致放行，缺失告警通过，不一致拒绝，需显式跳过才可覆盖。

## 五、CLI 发现与列出

发现分服务端优先、本地直探回退两档，读容错、写大声。

* 管理客户端为无目录客户端，只访问工作区无关的后端管理接口。能连通且后端域启用时，列表与状态优先取服务端注册表与实时状态，附带来源标记 `server`；不可达或后端域关闭时返回空位，调用方回退到本地快照，附带来源标记 `local`；鉴权与数据损坏等错误直接大声失败，不回退。
* 服务端列表每行含名称、隧道地址、当前标记、可达性、时延、版本、隧道状态；当前标记按本调用解析地址与行地址相等判定。本地回退列表由注册表隧道地址加本调用解析地址去重组成，每项独立超时直探健康与版本接口，不可达只记为行数据，不遮蔽其余行。
* `list` 只列名称与来源，`status` 列可达性与版本，`tunnel/start/stop` 只打印人工命令，`up/down` 才驱动服务端监管隧道，`backups/backup-now` 只查询与触发服务端计划备份，`pull` 按当前解析地址拉取执行包并合入检查点链写本地文件。
* 交互形态的服务列表只读，同样优先服务端、回退本地直探，当前行标记本会话连接，不在此处切换连接。
* 服务端上报的隧道地址用于对齐未显式配端口条目的本地打印，避免服务端自定义默认端口与本地回退默认值漂移；显式端口永远优先，不被服务端默认值覆盖。

## 六、剩余缺口

* 本地多进程无注册中心，端口分配与目录白名单靠人工编排，多实例共享同库需外部保证唯一写入者。
* 服务端列表规模增大时探测与备份仍偏串行，到期突发多时尾部等待偏长。
* 亲和性依赖版本控制元数据，纯拷贝目录只能弱确认，需人工确认或跳过。
* 远端服务进程本身不在服务端监管内，拉起、升级、多服务端口规划仍靠人工命令。
