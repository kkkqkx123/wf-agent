# wf-api 查询、审计与分析

对应 `src/query.rs`（1,025 行）、`src/audit.rs`（1,237 行）、`src/analysis.rs`（7 个文件约 4,000 行）。全部为**只读查询/分析面**，无运行时状态变更。

## 1. query.rs — 执行记录查询 API（TS `QueryAPI`）

### 双层过滤策略（核心设计）

1. **第一层 `FilterCriteria`（基础）**：`workflow_id`/`status` **下推**到存储层（`WorkflowExecutionListOptions` → SQL WHERE）；`start_time_from/to`、`tags`、`custom` 在内存过滤。
2. **第二层 `FilterExpression`（高级）**：内存求值（`evaluate_expression`）——`nin`/`contains`/`regex` 留在内存，避免触碰各后端 SQL 生成。

### 类型

- `FilterOperator`：Eq/Neq/Gt/Gte/Lt/Lte/In/Nin/Contains/Regex。
- `FilterExpression`：`{field, operator, value}`，支持 `a.b.c` 点路径访问（`get_field_value` 兼容 camelCase/snake_case）。
- `SortOptions` / `PaginationOptions`（默认 limit 100）。
- `AggregationType`（Count/Sum/Avg/Min/Max/GroupBy）+ `AggregationOp`；`AggregationResult` 为动态 map。
- `ExportFormat`：Json/Csv/Xml（parquet 映射 JSON）。
- `ExecutionRecord`：`WorkflowExecution` 扁平投影（含派生 `duration`）。
- `QueryBuilder`：流畅构造器（filter/filter_by/sort/limit/offset/get/first/count/aggregate/export/distinct/group_by）。

### 语义细节

- 缺失字段：匹配 `Neq`、不匹配其他操作符。
- 数值 vs 字符串比较 `compare_values`；非法 regex 匹配空集。
- 聚合：sum 保持整数完整性；GroupBy 输出 `{key: count}`。
- 导出：CSV camelCase 头 + 分隔符引号转义；XML 转义。
- 约 230 行单元测试。

## 2. audit.rs — 执行审计（三维数据源解析链）

### 数据源解析链（每次审计的唯一入口模式）

```
live（运行时注册表实体状态快照）
→ persisted（存储适配器执行记录）
→ checkpoint 快照（最近检查点 blob，记录被清理时的兜底）
```

每个视图携带 `AuditSource`（`Live | Persisted | CheckpointSnapshot | Unknown`）；未知执行返回 Unknown 源摘要而非报错。

### 能力与类型

- `audit_summary` / `audit_report`（summary + iterations + node_executions 组合）。
- `list_iterations` / `list_tool_calls` / `list_llm_calls`（由迭代扁平化）/ `list_node_executions`（工作流面）。
- `audit_timeline`：**离线时间线重建**——记录合并为时间序事件流，`timeline_phase` 相序打破平局（同时间戳 start 先于 end，零时长调用正确渲染 start→end）；纯审计视图，不参与恢复。
- 类型：`AuditSummary`（含 checkpoint 大小预算 `truncation_stats`）、`ToolCallAuditView`、`LlmCallAuditView`（每迭代 seq、profile_id、模型、token、时长）、`IterationAuditView`（嵌套工具/LLM 视图）、`NodeExecutionAuditView`、`AuditTimelineEntry`（12 种条目类型）。

## 3. analysis 模块

### 3.1 error_analysis.rs（1196 行）— 工作流错误根因分析（TS `WorkflowErrorAnalysisAPI` 家族）

基于 `wf-common::error_chain::ErrorRecord` 与 `FailurePolicyManager` 恢复语义（`RecoveryAction`）。

- 能力：`workflow_error_stats`、`recovery_recommendations`、`similar_errors`（消息归一化聚类跨执行）、`get_error_chain`（根→指定 id）、`analyze_root_cause`、`error_context`/`error_context_chain`（错误时刻状态：变量快照/调用栈/内存，经 state_tracker）、`get_advanced_error_analysis`（热点节点、时间模式 none/steady/accelerating/decelerating、趋势）、`get_recovery_proposal`（动作 retry/fallback/skip/abort + 概率 + 步骤 + 恢复时间）、`stream_error_chain`（Stream，根优先）、`subscribe_to_errors`（事件总线过滤订阅，RAII 守卫）。
- 启发式：`suggest_action` 错误类型→动作映射；`estimate_likelihood` 基础 50 + 可恢复性/严重度/动作加成；时间模式 ±30% 阈值；趋势 0.7/1.3 阈值。
- **降级**：live 提供结构化 ErrorRecord 链；持久化仅文本，用 `minimal_record` 合成最小记录维持分析可用。

### 3.2 performance.rs（820 行）— 性能剖析（TS `PerformanceMetricsAPI`）

- `profile()`：单执行时间线（live 状态快照，兜底持久化记录）。
- `identify_bottlenecks`：瓶颈 = 时长占比（高 ≥50% / 中 ≥20%，最多 10 个）。
- `get_performance_summary`：`PerformanceTier`（Fast <5s / Normal <30s / Slow）+ 建议（慢节点 >5s）。
- `get_iteration_comparison`：前半 vs 后半平均，0.8/1.2 趋势比。
- `compare`：基线 vs 对比，`improvement_rate` 截断 ±1。
- 兜底：结束时间未记录时用最后节点结束时间；分母塌缩为 0 时退化为节点时长求和。

### 3.3 progress.rs（534 行）— 执行进度跟踪（TS `progress.ts` 移植）

- `get_progress`：live 已完成节点 + 持久化时间戳/状态 + 图中节点总数。
- `ProgressTracker`：轮询（interval + CancellationToken 的 `select!`）、监听器列表（`Unsubscribe` RAII）、ETA（平均迭代时长 × 0.8 置信）、仅状态/迭代变化时发事件。
- `format_progress`：`Progress: x% | Iteration i/n | ETA: HH:MM:SS`。

### 3.4 search.rs（702 行）— 跨资源统一搜索（TS `SearchAPI`）

- 资源：Workflow/Execution/Task/Checkpoint/Event/AgentLoop。
- `search()`：`futures::join_all` **并行扇出**，单类型失败降级为空（warning）而非整体失败。
- 评分：id 命中 +2、其他字段 +1；确定性排序（score 降序 → type → id），输出不依赖注册表迭代顺序。
- `SearchOptions`：types / limit_per_type（默认 20）/ limit_total（默认 100）。

### 3.5 llm_metrics.rs（201 行）— LLM token/成本指标（TS `getAgentLlmMetrics`）

- 读取共享 `MetricsRegistry` token 收集器：TOTAL/PROMPT/COMPLETION_TOKENS、COST、REQUEST_COUNT 计数器，按模型 label 分组。
- `flush(ctx)`：冲刷持久化层 pending 写入。
- 未装配指标注册表时返回空/零值（优雅降级）。

### 3.6 stats.rs（299 行）— 指标注册表统计门面

- `workflow_stats`/`node_stats`/`agent_stats`/`tool_stats`/`error_stats`/`event_stats`：wf-metrics 收集器薄包装。
- `top_workflows`/`top_node_types`/`agent_stats_by_profile`：按执行数降序、截断、零用量省略。
- `export_json`/`export_prometheus`、`generate_report(ReportOptions)`（时间范围 + 趋势）。
- `registry(ctx)`：从 ApiContext 解析，未配置时报错。

## 4. 横切要点

- **一致性降级策略**：live → persisted →（audit 额外 checkpoint），无数据返回空/零而非报错。
- **TS 对齐**：模块 doc 显式映射 `packages/sdk-kit/src/**` 对应物。
- **纯查询面**：全部 `&ApiContext`；RAII 守卫（`Unsubscribe`、`ErrorSubscription`）管理订阅生命周期。
- 每个文件均含大比例单元测试（约 25–35% 行数）验证启发式与降级路径。
