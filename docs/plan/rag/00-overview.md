# RAG 引入设计方案 · 总览

> 目标：在当前项目中引入检索增强生成能力，对标 `ref/llama_index` 与 `ref/haystack` 的公共功能子集，给出一份可直接落地的设计与分阶段修改方案。
>
> 约定：中文撰写、自然语言为主、避免完整代码段；事实声明附文件引用，行号为定位辅助。

## 术语界定

严格区分四个易混概念：

- **文档**：待检索的原始内容单元，携带可过滤元数据与来源信息。
- **切片**：文档经切分后的检索最小单元，保留指向来源与前后相邻切片的关系。
- **索引**：切片向量化后写入存储并可被检索的状态，含去重与增量更新语义。
- **管线**：摄入（写）与查询（读）两条正交流程，不与 `wf-workflow` 的业务编排图混淆，前者是 RAG 专用流程，后者是通用执行引擎。

当前项目把向量化（`llm-suite-embedding`）、重排（`llm-suite-rerank`）、工具暴露（`wf-tools`）、图执行（`wf-workflow`）、提示词装配（`wf-resource`）分散在各层，缺少把它们串起来的文档-切分-存储-检索闭环。这是本方案的核心增量。

## 核心结论摘要

| 决策点 | 结论 | 理由 |
|---|---|---|
| 包拆分 | 向量存储抽象与 RAG 分为两个独立包 | 抽象包无理由依赖切分与向量化，RAG 包无理由依赖具体后端；各自可独立演进与抽仓 |
| 向量包 | `infra` 层新增 `vector-contracts`（已落地），中立命名以便抽为独立仓库 | 承载类型、过滤、操作契约与内存实现；simvec 与 Qdrant 适配为可选特性，不污染默认依赖 |
| RAG 包 | `infra` 层新增 `rag-core`（已落地），依赖向量契约加向量化与重排 trait | 不依赖具体后端，后端由调用方注入；详见 `03-design.md` |
| 本地后端 | 各项目自写 simvec 薄适配，不复用 CCE 的 local 实现 | CCE 的 local 只是引擎配集合名的薄封装，复用收益抵不过业务耦合 |
| 远端后端 | 自研 Qdrant REST 薄客户端，不引入官方 gRPC 客户端 | 复用现有 `reqwest` 栈，`ref/rust-client` 只当协议参考，不进依赖表 |
| 重解析 | 内置只做轻量格式，复杂格式走外部 converter 服务 | 公式、表格、扫描版面交 minerU 一类服务处理，经插件管线归一后再进切分 |
| 工具形态 | 内置只留最小只读检索工具，丰富形态走 MCP 与插件扩展 | 预定义工具为编译期静态 schema，覆盖不了多变的检索参数面 |
| 存储起步 | 内存实现先行，simvec 嵌入与 Qdrant 远端随后，Postgres 只预留接口 | 先跑通闭环再谈规模；`wf-storage` 实体语义不混入向量索引 |
| 切分起步 | 递归切分默认实现，句子窗口与层级切分复用同一分隔符管线 | 对应 Haystack 默认切分器语义，覆盖多数文本场景 |
| 检索起步 | 稠密余弦加元数据过滤先行，混合检索与倒数排名融合随后 | 稠密是两框架交集，混合是质量线而非可用性线 |
| 编排复用 | 不另起管线运行时，摄入与查询流程映射为 `wf-workflow` 节点类型 | 现有图引擎已有执行、检查点、可观测能力，另起运行时会重复建设 |
| 合成复用 | 查询改写与答案合成只走 `LlmGateway`，上下文注入只走 `wf-resource` | 不新增大模型调用路径，不新增提示词装配路径 |

## 范围

范围内：

- 文档模型、切分、向量化写入、存储检索、融合重排、引用合成。
- 检索作为工具与工作流节点的集成方式。
- 增量更新、删除语义、基础评估与排障接口。

范围外：

- 自研向量引擎（复用 simvec）、重型多格式连接器群（首版只做纯文本、Markdown、JSON，重格式走外部 converter 服务）。
- 图谱检索、结构化查询生成、多模态检索（仅预留扩展点）。
- 在线学习排序与大规模分布式索引。
- 官方 Qdrant gRPC 客户端的引入（以 REST 薄客户端覆盖 RAG 所需子集，`ref/rust-client` 仅作协议参考）。
