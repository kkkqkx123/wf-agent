# 维度四：组件设计（Component Design）

> 关注点：组件如何拆分与职责划分——基础节点、自定义边、追踪卡片、执行卡片等的抽象方式与复用策略。

---

## 1. Dify 的组件设计

Dify 倾向**"较少但较大的组件 + 共享 UI 库 + 集中式 store"**，强调单文件内聚。

### 1.1 画布层

- `workflow/index.tsx`：单一 `Workflow` 组件，集中注册 `nodeTypes`/`edgeTypes`（`:111-121`），并聚合协作、评论、候选节点、键盘交互等子模块。是个"编排器"而非纯展示。
- `custom-edge.tsx`：单文件 `CustomEdge`（`memo` 包裹，`:167`），内部自包含：路径计算、颜色、渐变渲染（`CustomEdgeLinearGradientRender`）、中点插入 `BlockSelector`、临时边虚线。
- `style.css`：React Flow 覆盖样式集中一处。

### 1.2 节点层

- `nodes/_base/node.tsx`（`BaseNode`）：统一基础节点，通过 `getNodeStatusBorders`（`:132`）处理状态描边，并承载循环索引、协作态、插件态。各业务节点继承/复用此基础。
- `nodes/_base/components/`：把"加号按钮、变量弹窗、代码编辑器"等拆成小部件，供基础节点组合。

### 1.3 运行/追踪层

- `run/index.tsx`（`RunPanel`）：三 Tab 容器，组合 `OutputPanel` / `ResultPanel` / `StatusPanel` / `TracingPanel` 四个子面板（`import` `:13-16`）。
- `run/node.tsx`（`NodePanel`，360 行）：单节点追踪卡片，内联状态图标（`RiCheckboxCircleFill/RiErrorWarningFill/RiLoader2Line`，`:185-226`）与三段 `CodeEditor`（`:303-331`）呈现 inputs/process/outputs。

### 1.4 设计特征

| 特征 | 体现 |
| --- | --- |
| 状态管理 | Zustand（`useStore` / `useWorkflowStore`）+ `immer` |
| 共享组件 | `@langgenius/dify-ui`（Tabs、CodeEditor、cn） |
| 抽象风格 | 较大组件内聚、单文件承载多职责 |
| 值传递 | props + store 直读（`data._runningStatus`） |

## 2. n8n 的组件设计

n8n 倾向**"细粒度组合式组件 + 设计系统 + composables + 依赖注入"**，强调关注点分离与类型安全。

### 2.1 画布宿主与容器

- `Canvas.vue`：VueFlow 宿主，声明大量 `defineEmits` 事件，组合 `MiniMap`/`CanvasBackground`/`Edge`/`Node`/选择工具条/AI。
- `WorkflowCanvas.vue`：**数据映射容器**，把 `workflowDocumentStore` 经 `useCanvasMapping` 转成 VueFlow 节点/连线（`:136-149`），并管理分组视图、节流、provide 注入（`:208-215`）。自身几乎不含视觉样式，只做"接线"。

### 2.2 节点组件族（关注点分离）

`features/workflows/canvas/components/elements/nodes/`：

- `CanvasNode.vue`：节点壳，计算 `classes`（running/waiting/selected…，`:109-118`）、映射输入/输出手柄（`:174-247`）、`provide(CanvasNodeKey, …)`（`:325-332`）、发出 add/delete/run 等事件。**不负责具体外观**。
- `CanvasNodeRenderer.vue`：实际视觉渲染（图标、标题、状态点）。
- `CanvasNodeToolbar.vue`：hover 工具条（删除/禁用/运行/替换/加 AI 等）。
- `CanvasNodeTrigger.vue`：触发器专用角标。
- `handles/CanvasHandleRenderer.vue`：手柄渲染。

### 2.3 边组件族

`elements/edges/`：

- `CanvasEdge.vue`：多段 `BaseEdge` + hover 延迟 + 着色 + `CanvasEdgeToolbar`/label（`:110-197`）。
- `CanvasEdgeToolbar.vue`、`CanvasConnectionLine.vue`、`CanvasArrowHeadMarker.vue`、`CanvasEdgeTooltip.vue`：各司其职。

### 2.4 执行组件族

`features/execution/executions/`：

- `views/WorkflowExecutionsView.vue`：取数 + 自动刷新 + 路由编排。
- `components/workflow/WorkflowExecutionsList.vue`：左列表 + 右预览分栏。
- `WorkflowExecutionsCard.vue`：数据驱动的状态卡片（左边框色编码，`:200-305`），聚合 `N8nSpinner`/`N8nTags`/`N8nActionDropdown`/`N8nIcon`。
- `GlobalExecutionsList.vue` + `GlobalExecutionsListItem*.vue`：跨工作流列表。

### 2.5 依赖注入与组合式

- `useCanvas()` → `injectStrict(CanvasKey)`（`composables/useCanvas.ts:4-6`），组件通过注入获取画布上下文，避免 prop 透传。
- `useCanvasMapping`、`useCanvasNode`、`useCanvasNodeGroupView` 等 composables 承载逻辑，组件只做渲染。

### 2.6 设计特征

| 特征 | 体现 |
| --- | --- |
| 状态管理 | Pinia（`@n8n/stores`/`@n8n/composables`）+ `inject/provide` |
| 设计系统 | `@n8n/design-system` 原子组件（`N8n*` 系列） |
| 抽象风格 | 壳/渲染/工具条/手柄拆分，细粒度 |
| 逻辑复用 | composables + 事件总线（`canvasEventBus`） |
| 类型 | `<script setup lang="ts">` 强类型，props/emits 显式声明 |

## 3. 横向对比

| 对比项 | Dify | n8n |
| --- | --- | --- |
| 组件粒度 | 偏粗（单文件内聚多职责） | 偏细（壳/渲染/工具条/手柄分文件） |
| 状态方案 | Zustand 集中式 | Pinia + composables + inject/provide |
| 共享 UI | `@langgenius/dify-ui`（Tabs/CodeEditor） | `@n8n/design-system`（`N8n*` 全系） |
| 逻辑复用 | 函数/store | composables + 事件总线 |
| 类型强度 | TS + React 类型 | `<script setup lang="ts">` 强类型声明 |
| 数据流 | props + store 直读 | provide/inject + 事件 emit |
| 可测试/可替换 | 中等 | 高（细粒度 + 设计系统） |

---

## 4. 设计启示

- **"壳/渲染"分离利于换肤与复用**：n8n 把 `CanvasNode`（逻辑壳）与 `CanvasNodeRenderer`（视觉）拆开，使同一逻辑可配多种外观；Dify 把状态/插值在 `BaseNode` 内聚，开发更快但换肤成本略高。
- **设计系统是规模化的前提**：n8n 的 `N8n*` 组件库让其数百节点与卡片保持视觉一致；Dify 借助 `@langgenius/dify-ui` 达到类似效果。两者都未"裸写"基础控件。
- **注入 vs 透传**：n8n 用 `provide/inject` + `injectStrict` 把画布上下文下沉，减少了 prop 钻探；Dify 靠 store 全局读，简单直接。组件层级深时，注入模式更可维护。
