# Git 集成收尾方案：CLI 清理与工作台补全

> 范围：`ce3377e`（CLI 去除 Git）之后的遗留清理，以及用户仓 Git 工作台相对 `01`-`04` 分篇的未落地部分。CLI 侧 Git 已彻底放弃，本文不复活任何 CLI Git 形态；用户交互侧统一收敛到 `/git` 工作台。
>
> 关系：只读域契约以 `01-backend-readonly.md` 为准，工作台契约以 `02-workbench.md`、`03-actions-input.md` 为准，终端增强以 `04-terminal-tui.md` §1-§3 为准；`04` 中属于 CLI/TUI 的章节（Git 屏、无头命令）按 `docs/plan/cli/client-unification-design.md` 第五节的决定视为放弃，本文第七阶段同步改写这些章节。

## 1. 现状盘点

上一个提交删除后，CLI 内已无 Git 功能代码，但留下五处遗留：`wf-tui` 侧边栏浮层调用点未跟随渲染层签名变更导致编译断裂；`wf-tui` 输入层仍持有一份数字键位私有映射，与 `tui-core` 新的权威映射重复且多出 `0` 键；帮助弹窗与 `DASHBOARD_ENTRIES` 注释仍是旧键位描述；`wf-cli-shared` 声明了三个已无引用的依赖；`wf-cli-demo` 示例沿用旧的检查点行结构，早于本次清理即已编译失败。

用户交互侧，只读域、注册表、统一写入口、路由与服务骨架均已落地，但存在四类缺口：写操作闭环有坏路径（需确认标识的动作没有确认入口、切换暂存不注入选中路径、纯客户端视图动作误走服务端）；绑定表只覆盖注册表的小部分且漂移只单向告警；只读视图有死代码与未接线端点（状态计数、提交文件、引用区间差异、贮藏动作、分支上游）；终端是轮询缓冲形态，交互式命令会挂死，与上半部分联动靠整页重载。

## 3. 阶段一：CLI 清理收尾

- 侧边栏浮层调用点补齐渲染层新增的条目参数，传仪表盘条目表，恢复 `wf-tui` 及下游目标编译（本次修改中已完成）。
- 删除输入层的私有数字键位函数，三处路由（普通态、侧边栏态、alt 态）改调 `tui-core` 的权威反查函数，键位映射收敛为单一真相源；对应测试改写为断言权威映射：数字键一至九映射九个屏幕、零无映射、仪表盘无数字仅侧边栏可达。
- 帮助弹窗文案更新为一至九的完整键位说明；`DASHBOARD_ENTRIES` 注释改为陈述侧边栏列表与回车选择语义，不再声称与数字键一一对应。
- 删除 `wf-cli-shared` 中三个零引用依赖声明。
- 修正 `wf-cli-demo` 示例中检查点行初始化缺失的三个字段，使 demo 示例恢复可编译。

验收：`cargo check` 覆盖 cli 全部箱的全部目标无错误；数字键行为与侧边栏浮层渲染的提示一致。

## 4. 阶段二：CLI 验证

对 cli 与 tui 各箱执行全目标编译检查，并运行 `wf-tui` 与 `wf-cli-shared` 的单元测试。确认无新增告警、无测试失败。

## 5. 阶段三：写操作闭环修复

- 派发路由补全：需要参数的动作统一走参数对话框，对话框字段由后端注册表的参数声明驱动；需要确认标识的动作按后端危险级别收集二次确认，确认串取主目标参数值（删除分支取分支名、放弃取路径、推送取远端与分支拼接、丢弃贮藏取贮藏引用、修订与改写历史类取后端声明的目标）。
- 切换暂存动作在派发前注入当前选中文件路径；无选中时给出明确提示而非把空参数打到服务端。
- 纯客户端视图动作（聚焦、过滤）不再走统一写入口：聚焦动作聚焦侧栏过滤框，过滤动作仅本地过滤当前面板列表，页面新增按面板保存的过滤词状态。
- 键盘流补全：输入框回车等价于执行按钮；问号动作唤出当前上下文全量帮助面板，面板内条目可点击执行。
- 死代码接线：状态计数服务接入状态面板；选中状态选择器接入主视图标题与详情展示。

验收：高频动作（暂存、提交、放弃、贮藏、检出、建分支、删分支、推送、拉取）均可从输入栏或控件条完成；危险动作执行前必须经确认；绕过界面直接调用无确认标识的请求被服务端拒绝的语义不变。

## 6. 阶段四：绑定表补全与漂移双向守门

- 绑定表补齐到后端注册表中可用动作的子集，按面板上下文分配单字符别名，别名在上下文内唯一；危险级别与参数声明以后端注册表为权威，前端表只做离线兜底。
- 启动期漂移检查双向告警：后端有而前端无的动作提示补齐，前端有而后端无的动作提示并置灰；后端标记不可用的动作在控件条与输入栏预览中置灰并展示原因。
- 为绑定表与词元解析补单元测试：绑定表唯一性与别名冲突、词元解析的各分支（空、单字符命中、单字符未命中退化前缀、多字符前缀排序、命令模式、帮助模式）。

验收：绑定表与注册表无常驻漂移；新增后端动作若未同步前端表会被启动期告警暴露。

## 7. 阶段五：只读视图补全

- 服务层补齐未接线的只读端点包装：提交文件、引用区间差异、远端、标签、子模块、工作树。
- 主视图三态落地：选中文件显示未存差异（现状保持），选中提交显示该提交的文件列表并可下钻到提交区间差异；差异窗格附加区间来源标注。
- 贮藏面板接入弹出、应用、丢弃动作，丢弃走确认；分支面板行内展示上游与前后计数；状态面板展示暂存、未存、未跟踪、冲突四组计数与中间态徽标。
- 预览工程补齐新增只读端点的夹具与路由，注册表夹具扩充到与后端一致的动作集合，使预览模式的漂移告警与置灰行为与真实模式一致。

验收：能看能选能切换，选中提交有内容；贮藏可操作；窄屏无溢出；预览工程可完整走通只读与动作流程。

## 8. 阶段六：终端体验增强

- 终端显示与会话偏移解耦：显示缓冲可清空而不影响服务端输出游标，清空按钮只清显示。
- 会话尺寸在建立时上报，提供重启会话入口（关闭旧会话并新建）。
- 终端写入后按指纹比对驱动上半部分刷新，指纹未变不刷新，替代整页无条件重载。
- 界面动作执行成功后，把等价命令回显到已打开的终端，用于教学；回显行与服务端输出共用同一显示缓冲，游标保持对齐。
- WebSocket 双向流与终端渲染组件明确不在本方案范围，记录为后续项：当前轮询形态无法承载交互式命令，需要时按 `04` §1-§3 实施。

验收：终端可清空、可重启、写入后上半部分按需刷新；界面动作有回显。

## 10. 阶段八：全量验证

- Rust 侧全工作区编译检查，覆盖所有目标；运行受影响箱的单元测试。
- 前端侧为绑定表、词元解析、服务层转换补单元测试；受离线环境限制（前端依赖未安装），类型检查与测试执行需在有网环境按 `apps/web-app` 的 `check` 与 `test` 脚本完成。
- 预览工程与主工程镜像一致性经同步脚本校验。

## 11. 不做事项

不复活任何 CLI Git 形态；不引入终端渲染依赖与 WebSocket 通道（记后续）；不做多仓库切换、托管平台集成、合并冲突解决界面、交互式变基编辑器；工作区与子模块写操作保持不可用，只读展示按需接入。

## 12. 执行记录

阶段一至八已完成。除方案内的修改外，验证阶段发现并修复了两处先于本方案存在的编译断裂：`wf-agent` 与其集成测试仍按旧的 `available_tool_names: Vec<String>` 字段构造配置（实际类型为 `Option<Vec<String>>`），统一改为 `Some(...)` 包裹；`tui-components` 审批浮层测试断言了已不存在的 `ApprovalAnswer::tool_call_id`，删除该断言。另删除 `tui-render` 测试中未使用的导入。这些修复随本方案一并落地，`cargo check --workspace --all-targets` 与相关箱的单元测试全部通过。

注册表真相源修正：`commit.reword`、`commit.squash`、`commit.fixup`、`commit.drop`、`fetch` 实际无法经统一写入口派发，注册表原标记为可用，已改为不可用并注明原因，同时删除派发层对应的不可达分支。前端绑定表补齐到注册表全部可用动作，漂移检查改为仅对可用动作双向比对。

前端验证（依赖就绪后补齐）：生成的 `schema.d.ts` 相对快照过期，四个终端路径操作的 `{id}` 路径参数缺失为 `path?: never`，经 `tools/openapi-codegen` 从已校验一致的快照重生成后修复。lint 修复 git 工作台六处 `{#each}` 缺键、executions 页两处未使用派生量、预览 mock client 未使用的夹具导入与 `paramsObj` 赋值。最终两个前端工程（web-app 与 web-app-preview）的 `check`、`lint`、`test`、web-app 的 `build` 全部通过（各 170 个单测，svelte-check 零告警）。

磁盘占用提示：全量 Rust 验证期间 `target/debug/incremental` 曾写满磁盘导致链接失败，清理该可再生缓存（16G）后恢复；后续 Rust 构建建议带 `CARGO_INCREMENTAL=0`。
