# 执行页浮窗式 Graph 查看研究

本目录回答一个具体问题：执行页面是否应该补充浮窗式的 graph 查看功能，在原始模板基础上补充执行进度等信息，该如何实现，如何设计图例。

结论前置：应该做，但形态不是常驻大图，而是一个跨 Tab 共享的三态浮窗（进度条 + 迷你图 + 跳转完整图），默认折叠，只在运行态主动提示。理由是当前项目把图与执行进度放在互斥 Tab 中，而 n8n 与 Dify 都让图与执行保持同屏可见。

## 研究方法

- 本地源码对照：当前项目执行链路以 `ExecutionInspector.svelte` 为中心，图渲染以 `GraphExplorer.svelte` 与 `GraphCanvas.svelte` 为中心，状态语义以 `status.ts` 与 `display-model.ts` 为中心。
- 外部参考通过 ctx7 cli 查询，不复制源码，只记录设计事实：
  - n8n 文档库 `/n8n-io/n8n-docs`，查询词为执行预览、画布覆盖层、日志面板、运行状态。
  - Dify 文档库 `/langgenius/dify-docs` 与代码库 `/langgenius/dify`，查询词为运行追踪、节点执行、运行状态。
- 本地浅克隆副本 `docs/ref/n8n` 与 `docs/ref/dify` 用于核对布局事实，行号只对本次快照有效。

## 核心判断摘要

1. 当前项目执行可观测性最深，但图与进度互斥，跨 Tab 即丢失空间上下文，这是浮窗要解决的主矛盾。
2. n8n 的答案是画布为主、日志为底部常驻面板；Dify 的答案是画布为主、运行面板为右侧浮层；两者都不让用户在图与执行之间二选一。
3. 当前项目的迷你图明确不渲染执行色，小图不能直接复用为进度总览，需要一个新的只读迷你执行图。
4. 图例是浮窗可读性的前提，当前仅有形状图例，缺少执行语气与边状态图例，需要一次性补齐。
5. 浮窗必须复用已有的叠加管线与状态字典，不新增第二套颜色语义，否则会出现双色源。
