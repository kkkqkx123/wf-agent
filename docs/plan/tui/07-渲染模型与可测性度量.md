# 渲染模型与可测性度量

## 现状

渲染直接读取应用与交互控制器的内部字段，没有统一的只读渲染视图。快照测试主要覆盖排版方法与少量组件，不覆盖整帧序列。时间、后端、状态三者都不可替换，导致流式缓速曲线、重绘节奏、局部重绘正确性、布局几何都难以自动化回归。

度量侧已有差异录制后端，位于 `crates/app/cli/wf-tui/src/tui_debug/diff_recorder.rs`，能力限于记录每帧差异字节数。缺少帧内耗时、实际排版行数、解析字节数等与优化目标直接对应的指标，也没有把这些指标纳入回归基线。

绘制缺少隔离与后处理。任一组件绘制异常都可能中断整帧，主题与配色分散在各组件，图片与表情等清理逻辑没有统一位置。

对照 jcode，差距在于缺少三个支点：状态源可替换、时间可替换、后端可替换。jcode 用宽接口隔离表现层与状态来源，用模拟时钟固化时间，用测试后端实现无头渲染，三者叠加使整条管线可在无终端环境下逐帧断言。同时用锚点稳定性与帧捕获作为渲染质量的回归指标。

## 修改目标

让整帧绘制可离线断言，让优化是否生效变成可回归的预算断言，让绘制异常不再中断整体。

## 方案

渲染模型侧引入只读视图接口，暴露历史行、流式行、版本号集合、宽度、滚动位置、主题模式、动画时刻、底部状态。交互控制器实现该接口，测试替身实现同一接口。绘制与准备只依赖该接口，不再直接读取具体字段。接口方法提供合理的默认实现以降低替身负担，版本号方法是单调递增的核心失效信号。

测试替身覆盖两类：内容替身提供固定历史与流式文本，状态替身提供底部与通知变化。两者都可配合测试时钟推进。无头渲染使用内存后端，整条管线在无终端环境下逐帧运行并断言缓冲内容与几何探针。

事件录制与回放在现有回放能力上扩展。录制侧把一段时间内的交互序列序列化为可读格式，回放侧从该格式恢复并逐步重放。该能力把用户报告的问题变成可重复的测试输入，优先级低于只读视图与时钟，先预留接口。

度量侧扩展差异录制后端为帧度量后端，记录帧序号、变更单元格数、差异字节数、耗时、实际排版行数、解析字节数。度量点分别位于准备层与呈现封装。测试中以预算断言稳态行为，例如稳态流式帧实际排版行数等于新增行数，解析字节数线性增长，动画帧变更单元格只含动画区域。

绘制隔离与后处理参照 jcode 的四步思想。绘制前重置动画区域记录，绘制体用异常隔离包裹，异常时退回可识别的恢复帧并保持整体存活，绘制后对整个缓冲做统一的主题与配色后处理。顺序固定，先明暗适配再应用用户配色。表情与图片清理等后续能力预留统一位置，不在本阶段实现。

几何探针作为辅助断言手段。视口、动画区域、侧栏等关键矩形通过探针暴露，便于验证布局而不依赖像素比对。探针只读，不参与绘制逻辑。

## 与现有模块的衔接

现有快照、回放、会话管线测试全部保留作为行为护栏。新增测试使用期望断言而非直接解包，符合仓库约定。新模块文件扁平命名并在 `lib.rs` 登记，不引入新 crate。注释使用英文且不引用文档编号。

## 验收

整帧绘制可在无终端环境下逐帧断言，时钟推进可复现动画帧与通知消失时刻。度量后端可输出基线报告，后续阶段的优化对比有据可依。绘制异常被隔离为恢复帧，整体不退出。

## 风险与回退

主要风险是只读视图接口过大导致实现负担。缓解方式是分组提供默认实现，测试替身只覆写关心的分组。其次是度量本身引入开销，缓解方式是度量后端仅在测试与录制形态启用，正式路径保持零开销。若接口收敛困难，可先从最小内容子集起步，逐步扩大覆盖。
