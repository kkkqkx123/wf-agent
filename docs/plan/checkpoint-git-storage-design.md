# 文件检查点 Git 存储设计

最终期望架构，不描述迁移过程。只回答一个问题：文件内容历史是否应完全交由独立 Git，SQLite 只留元数据与索引。

## 1. 结论

应完全移除 SQLite 中的文件内容重复存储。文件字节、目录树、历史关系、分支指针、合并与冲突全部以独立 Git 为真相源。SQLite 只保留 Git 表达不了或查起来太慢的东西：审核状态、空目录、执行态、轻量索引缓存与仓库级键值。

现有 `file_nodes / deltas / snapshots / partitions / partition_history / checkpoints / branches` 的线性分区历史模型是回退无法隔离的根因，不应保留。行级增量自研合并栈也不应保留。

## 2. 目标与非目标

目标：多智能体并行编辑可隔离回退，合并冲突走标准语义，脚本与人工编辑归因简单可靠，不污染用户仓库。

非目标：不做用户可见的版本控制界面，不代理用户自己的提交推送，不在本文讨论执行态检查点的存储细节，不规定具体的合并解决策略之外的产品流程。

## 3. 最终架构总览

每个工作区拥有一个独立裸仓库，目录与用户仓库完全分离。工作区文件是该裸仓库的唯一工作树，通过独立目录指针关联，用户自带的版本目录不受任何读写影响。

写入只经由管道式对象操作完成，不存在分支检出切换。多智能体可同时在各自引用上追加提交，互不干扰。工作树只在物化目标状态时被写入，且写入过程串行化。

读分为两类：工作树物化只从目标提交的目录树展开；血缘与差异查询走提交图，热点查询由 SQLite 索引加速，索引可整体重建。

分层状态机不再存在。原分层概念映射为引用命名空间加审核状态，不再有层间流转门控与指针搬运。

## 4. Git 仓库布局

每个工作区一个裸仓库，旁置一个小型 SQLite 文件。仓库内只有受控引用命名空间，不使用传统分支命名，避免与用户分支混淆。

引用划分按职责命名：主线引用为集成分支真相；每个执行者拥有独立的编辑引用；每个待审提交拥有独立的送审引用；每个协作目标拥有独立的特性引用；人类外部编辑拥有独立的人工引用。引用事务保证原子更新。

工作树解耦是核心约束：任何分支操作都不切换工作树。提交通过输入字节加父目录树直接构造，合并在内存中完成，工作树只反映当前主线或冲突解决结果。

忽略规则分三层：独立仓库自身的排除文件忽略版本目录与检查点自身目录；工作区已有的忽略文件继续生效；自定义忽略模式叠加其上。扫描、状态对比与提交构造使用同一套规则。

## 5. 提交模型

一次工具调用产生一个提交，单文件或多文件由调用本身决定。一次脚本运行产生一个原子提交，内容由运行前后的状态对比决定，不逐文件拆分。人类编辑由周期性状态轮询聚合成提交，落在人工引用上，永不自动并入主线。

提交作者为实际执行者，提交者为系统。提交说明携带执行意图，结构化归因信息以提交附注形式存放，包括执行者标识、会话标识与工具来源。会话不再需要独立的关联表，一个会话的一组操作要么合并为一个提交，要么共享同一会话附注。

空提交默认不产生。内容无变化的调用只返回已存在的提交标识。

## 6. 分支与送审语义

编辑引用到送审引用只是引用复制，不发生合并。送审到特性、特性到主线是真正的合并，产生多父提交并保留完整祖先。

审核状态不再用分区历史长度隐式表达，而是显式记录在 SQLite 送审状态表中，状态只有待审、已通过、已驳回三种。驳回只删除送审引用，不改动任何已合入的历史。

多特性合入主线逐个顺序合并，每个保留独立的合并提交，顺序只影响真正重叠行的结果。合入后特性引用可删除，血缘保留在提交图中，不依赖引用存续。

## 7. 冲突与回退

冲突使用标准标记落盘并阻塞对应合入，未解决前不产生新的主线提交。冲突提交保留全部输入父提交，冲突文件可通过常规手段解决后继续。

回退单个分支不移动主线指针到旧父提交，而是产生新的合并或还原提交，将目标输入排除在外或抵消其改动。其他已合入分支的历史不受影响。这正是现有单链分区指针模型做不到的，改用提交有向无环图后自然成立。

单执行者的本地撤销只是将其编辑引用回退到前一个提交，不触碰送审、特性与主线。

## 8. SQLite 保留范围

按表现状逐项处置：

删除文件节点表，内容由对象库承载。删除增量表，差异按需计算，不再持久化行级操作。删除快照表，文件状态由目录树承载。删除分区与分区历史表，分支指针由引用承载。删除会话关联表，会话以提交附注承载。删除文件移动表，重命名由差异相似度检测承载。删除文件历史提交与分支表，由提交与引用承载。

保留执行态大对象表，该表与文件树无关，键值加父子索引的查询模式不变。保留仓库级键值表，但只存工作区配置、当前引用名等少量条目。

新增三类小表，均不存文件字节：送审状态表记录送审项的待审通过驳回状态；空目录表以提交标识为键记录该提交的空目录清单，弥补对象库不跟踪空目录的缺口；来源索引表缓存提交到执行者、路径与时间的映射，仅作查询加速，损坏可从提交图全量重建。

## 9. 检测简化

工具精确上报为主路径，直接携带内存字节，不做磁盘二次读取。脚本运行前后状态对比为辅路径，范围限定在声明的可写前缀内，忽略规则复用同一套。周期性状态轮询只负责人类编辑，命中人工引用。

现有文件监视后台服务降级为可选提示器或直接删除。内容哈希注册表、优雅窗口、显式删除标记、未完成租约四种归因信号随之删除。归因只剩两条确定性规则：工具上报的内容以调用者为准；其余工作树脏文件以状态对比为准，人工引用单独存放，天然隔离。

路径规范化只保留一处实现。相对与绝对双注册、失败重排队列、去抖加轮询双层节流一并删除。

## 10. 查询与恢复

按执行者查询走来源索引，缺失时回退到提交日志扫描。按路径查询走提交路径索引加改名跟随，不再需要链头增量反查。执行者工作区视图为其编辑引用所指目录树的展开。差异视图为两棵目录树的对比，二进制只报告变更不展开。

文件时间线走改名跟随加提交日志，不再维护独立的移动表。冲突列表走未解决合并提交的枚举，不再重放历史合并推导冲突区域。

工作树恢复是从目标目录树展开并清理多余文件，受保护的忽略目录永不删除。空目录按空目录表的清单重建。恢复是幂等的，内容相同即跳过。

## 11. 技术选型

对象库访问选用纯 Rust 的 Git 实现。理由是无原生编译依赖，离线构建确定性好，支持无工作树切换的管道式提交与引用事务，单文件裸仓库易于携带。命令行实现需要目标环境预装版本控制二进制，且每次编辑派生进程，开销与错误处理都不合适。原生绑定实现引入 C 工具链与版本漂移，收益不足以抵消复杂度。

合并与改名检测复用对象库自身的语义，不再保留自研的三路文本合并与最低公共祖先实现。差异展示仍可保留现有的行级差异能力，仅作展示用，不作存储格式。

SQLite 访问保持现有嵌入式实现，不引入新依赖。索引表全部可重建是选型前提，对象库永远是真相源。

## 12. 回收与性能

对象库回收使用自带回收机制，不再维护独立的提交标记清除。来源索引的裁剪跟随引用删除，引用删除后不可达提交的索引条目在下次重建或后台清理中消失。

高频写入通过提交批处理节流，同一会话的连续小编辑可合并为一个提交。状态对比限定在可写范围与忽略规则内，大仓库不做全量重扫。热点查询命中索引，冷查询走提交图。

## 13. 模块归属

文件历史的分区、增量、合并、检查点仓库模块在最终架构中不再存在。文件检查点管理器的对外查询与恢复接口保持稳定，内部改写为引用加对象操作。执行态检查点与上层协调器不受影响。来源索引与送审状态作为文件检查点内部的私有辅助，不对外暴露为独立产品模块。

## 14. 验收

单分支回退不改变其他分支合入结果；重叠行合并结果符合标准合并语义；冲突以标准标记呈现且可继续解决；脚本多文件操作恰好产生一个原子提交；人类编辑永不混入执行者分支；删除全部索引后可从对象库完整重建查询视图；用户仓库无任何新增或修改。
