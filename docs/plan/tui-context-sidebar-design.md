# TUI Context Sidebar 细化设计

本文基于 `docs/plan/tui-interface-reference-alignment-design.md` 的范围决策，对 context sidebar 做落地前分析：相关数据是否已正式实现、sidebar 功能如何正式实现、UI 与 UX 如何设计、显示信息是否应可配置。结论来自现状代码实测，修改只动原模块，不新增并行模块，不做历史兼容。

## 0. 结论速览

- 相关数据尚未正式实现。`tui-components` 内仅有一个未接线的纯数据骨架，可视为库资产而非交付能力。
- sidebar 应实现为仅在 Interactive 会话工作区出现的右侧只读信息抽屉，与现有左侧导航 overlay 彻底区分命名。
- UI 采用右置固定宽度抽屉，窄终端自动隐藏；UX 采用无焦点只读面板，切换不抢占 transcript 光标。
- 显示信息应当可配置，但限定在总开关、默认显隐、宽度、分组可见性与顺序、快捷键与刷新节流六项，不开放任意数据源定制与服务端同步。

## 1. 现状实测

### 1.1 组件骨架存在但零接线

- 数据结构位于 `crates/app/tui/tui-components/src/context_sidebar.rs`：五个分组 `files`、`todos`、`context`、`mcp`、`git`，每个分组仅为标题加字符串行，提供空分组隐藏与纯文本行渲染，附两个单测。
- 全仓库检索 `ContextSidebar` 与 `ContextSection` 的引用仅命中该文件自身与模块声明，无任何来自 `tui-core`、`tui-render`、`wf-tui` 的构造或绘制调用。这与研究盘点结论一致：未接线的 `context_sidebar`、`bottom_pane`、`file_tree` 等仅为可复用库资产。
- Interactive 绘制路径位于 `crates/app/cli/wf-tui/src/interactive/render.rs`：当前为纵向三段布局，分别为滚动区、底部状态区与输入行，无横向分栏。`crates/app/cli/wf-tui/src/interactive/view.rs` 的侧栏可见性恒为假，几何探针仅记录纵向三段。
- 现有 `OverlayMode::Sidebar` 定义于 `crates/app/tui/tui-components/src/overlay.rs`，绘制于 `crates/app/tui/tui-render/src/screen_draw.rs` 的导航 overlay，为左侧约三成宽度的 screen 列表加数字跳转。它是导航入口而非上下文面板，标题已对齐为 Navigation，但枚举名与快捷键仍沿用旧名。
- 数据获取位于 `crates/app/cli/wf-tui/src/fetch.rs`：`ScreenKind::Interactive` 明确无管理屏数据模型，会话拥有独立流式状态。sidebar 若实现为会话本地视图，不应走 `ScreenData` 管理屏通道。

### 1.2 五组数据的正式实现程度

- Files：无正式实现。`interactive/tool_blocks.rs` 记录每次工具调用的名称、成败、截断输出与展示负载，但不解析文件路径参数；`interactive/anchors.rs` 仅记录跳转锚点，不聚合文件集合。服务端虽有 Git 文件接口与工作区文件能力，但不存在会话维度已触文件列表接口。
- Todos：半成品原材料，无正式实现。`update_todo_list` 工具调用结束时仅记录一条跳转锚点并截取结果首行；`wf-types` 已有待办条目结构，引擎侧有待办变量注入提示词的能力，但 TUI 侧丢弃结构化结果，不保留最新待办快照。
- Context：已部分实现。`ExecutionStreamEvent::Usage` 携带输入输出拆分、推理 token、缓存读写与 provider 总量，经 `wf-api` 映射进入 `tui-core` reducer 的 `UsageMeta` 快照，完整终端 footer 经 `merge_reducer` 消费。会话控制器滚动分支仍为空实现（用量为瞬态数据，不进滚动历史，符合预期）。上下文窗口不走协议：由 TUI 侧经 `resolve_context_window` 从已缓存的画像列表按模型匹配解析，未知时降级为绝对值显示。
- MCP：无会话视角实现。统一目录获取使用工具列表接口可拿到资源分组，项目与全局各有连接配置文件，但不存在当前会话可用连接与健康状态的展示模型。
- Git：唯一有现成数据源。Git screen 已通过服务端文件接口获取路径加状态行，sidebar 可复用该缓存做摘要，无需新增接口。完整 tree 与 hunk 查看器按既有范围决策不做，外部工具承担交互式操作。

综上，Git 有可直接复用的正式数据源，Todos 有可解析的事件原材料，Context 的用量拆分、缓存命中与窗口百分比已按本节决策落地（footer 紧凑拆分加 sidebar 完整节），Files 与 MCP 仍需新增轻量派生或聚合逻辑。

## 2. 术语与信息架构

- 将现有导航 overlay 在文案与帮助中统一称为 Navigation Palette，后续再视改造成本决定是否重命名枚举值，避免大面积重命名掩盖本次实质改动。
- 新增面板统一称为 Context Sidebar，仅在 `ScreenKind::Interactive` 会话工作区出现。管理屏、欢迎态、历史 overlay、搜索 palette 均不出现该面板。
- 主视图层级为中央 transcript 加底部 composer 加右侧 context sidebar，均为同一 screen 内的区域划分，不新增 screen，不新增顶层路由，不占用数字快捷键。

## 3. 功能规格

- 归属与可见性：sidebar 状态归会话控制器所有，随会话切换而切换，随退出而丢弃，不进入管理屏数据缓存。默认隐藏或显示由配置文件决定，运行时切换仅改内存状态，不自动写回文件。
- 开关方式：会话内单一快捷键切换显隐，关闭时 transcript 占满全宽，打开时横向分栏。窄终端低于阈值宽度时强制隐藏并给出提示，恢复宽度后回到切换前的显隐状态。
- 只读无焦点：面板内无光标，`j`、`k`、翻页等键继续作用于 transcript；面板不参与焦点轮转，不拦截输入法与组合键。未来如需分组折叠或跳转，另行设计，不在首版引入可聚焦列表。
- 分组模型：固定五个分组，顺序默认为 Files、Todos、Context、MCP、Git，空分组自动隐藏，全部为空时面板显示一行弱化空态而非空白边框。
- 截断规则：每组最多显示限定行数，超出显示省略行并提示总数；单行按显示宽度截断并保留省略符，不换行撑高面板。
- 刷新时机：Todos 与 Files 随工具事件到达即更新；Context 随用量事件到达即更新；MCP 在会话启动与手动刷新时更新；Git 复用管理屏缓存，到达时更新，失败时保留旧值并标记过期，不清空面板。
- 层叠关系：搜索 palette、历史 overlay、审批与问题浮层、文件与 diff 查看器均盖在 sidebar 之上；sidebar 打开时不改变这些 overlay 的几何计算。

## 4. UI 与 UX 设计

### 4.1 几何与响应式

- 右置抽屉，宽度取终端宽度的固定比例并钳制在最小与最大列数之间，保证 transcript 至少保留可读的最小文本宽度。宽度计算发生在纵向三段布局之前，滚动区、底部区与输入行共享扣除后的中央列。
- 滚动条、跳转徽标与底部状态继续锚定在中央文本区，不进入侧栏列；侧栏有独立边框，与中央区视觉分离。
- 当终端宽度低于可分栏阈值时，sidebar 自动让位并在通知区给出弱化提示；宽度恢复后自动恢复，不需要用户重新切换。

### 4.2 视觉语言

- 全部颜色经 `tui-style` 主题角色获取，不在绘制侧硬编码颜色；边框、标题、空态、错误态分别使用强调、默认与弱化角色。
- 分组标题为短英文名词加计数后缀，计数来自该组实际条目数；条目前缀使用少量语义符号区分状态，避免大段彩色块。
- 各组渲染约定：Files 显示短路径加单字母状态；Todos 显示状态符加首行文本，未开始、进行中与已完成可区分；Context 显示输入输出拆分、缓存命中率、推理量（仅当 provider 上报）、窗口百分比条与用量总量（窗口未知时仅绝对值加 `window unknown` 行）、 cost、迭代轮次与执行实例短标识；MCP 显示连接名加点状态，异常连接置顶；Git 显示单字母状态加短路径，数量多时仅显示前若干行加省略行。
- 空态使用弱化单行说明该组尚无数据，不显示骨架屏；加载态仅出现在 MCP 与 Git 首次获取阶段；错误态保留旧数据并在分组尾部追加弱化失败原因，不用弹窗打断会话。

### 4.3 交互细节

- 切换快捷键需经键位表下发，默认键在实现前做冲突排查，避开已占用的导航、历史、搜索、锚点跳转与中断键。帮助浮层与底部提示从键位表反查生成，不手写副本。
- 面板不提供鼠标点击与框选复制的特殊处理，复制策略沿用现有会话复制通道。
- 与性能的配合：用量与工具事件的高频更新合并到帧节拍内消化，Git 与 MCP 的后台轮询沿用已有的侧栏刷新间隔配置做节流，避免每事件一次重排。

## 5. 显示信息是否应可配置

结论是应当可配置，但范围收敛。前端已有侧边栏折叠与宽度记忆，TUI 已有会话滚动条显式开关，键位已有全局加项目两级覆盖，配置分离文档已明确展示偏好跟人跟机器、只读全局的归属原则。sidebar 沿用同一套规则即可，不发明新机制。

### 5.1 可配置项

- 总开关与默认显隐：是否启用该面板，启动时默认打开还是关闭。
- 宽度：固定列数或比例上限，超出钳制区间回退到内置默认。
- 分组可见性：五个分组各自的显示开关，关闭的分组不派生数据也不占行。
- 分组顺序：五个分组的排列顺序，非法名或重复名回退到默认顺序。
- 快捷键：切换显隐的绑定走现有键位覆盖文件，不进入展示配置文件。
- 刷新节流：Git 与 MCP 后台刷新的最小间隔，沿用既有刷新间隔语义。

### 5.2 不做项

- 不做任意自定义分组与任意数据源表达式，不做分组内字段模板。
- 不做项目级展示覆盖：显隐、宽度、分组可见性与顺序只读全局展示文件，与鼠标捕获、滚动条开关保持一致；键位覆盖保留全局加项目两级，与现有键位规则一致。
- 不做服务端同步与跨设备漫游：面板偏好属于本地终端偏好，不进入服务端偏好文档；浏览器侧备份不包含终端文件，终端备份命令不包含键位与主题文件，职责边界保持现状。
- 不做屏内编辑：设置屏沿用只读快照风格，仅展示当前 sidebar 配置摘要，修改指引指向编辑文件与备份命令，与现有设置屏定位一致。

### 5.3 存储与默认值

- 新增展示文件分组承载上述六项中的前四项与第六项，全部字段可选，缺键逐项回退，坏文件整体回默认，加载永不使会话启动失败。导出导入沿用现有展示文件的整体备份通道，不为 sidebar 单设通道。
- 默认值取保守可用：面板默认关闭或仅在宽终端默认关闭由实现时根据实测选择其一并在文档中写明；分组默认全开，顺序为 Files、Todos、Context、MCP、Git；宽度默认取适中比例并钳制；刷新间隔默认沿用现有侧栏间隔。

## 6. 数据接入方案

- Files：会话控制器新增已触文件集合。首版从工具结束事件的结果与展示负载中提取路径线索，结合 Git 变更文件做补齐与去重，按最近触达排序并截断。提取失败时该组保持空态，不阻塞其他组。 replay 重建时从滚动历史的工具行做同规则回放，保证恢复会话与实时会话一致。
- Todos：会话控制器新增待办快照。监听 `update_todo_list` 调用结束事件，解析其结构化结果为条目列表并整体替换快照；解析失败时保留上一次快照并记录弱化提示。快照随滚动裁剪保留，不随历史裁剪丢弃。
- Context：会话控制器已持有经 reducer 到达的 `UsageMeta` 快照（末次请求口径，对齐 opencode 取末条 assistant 消息的语义；引擎保留累计预算决策权，TUI 不做客户端累加）。footer 显示紧凑拆分（输入输出加缓存标注加 cost，常驻 ≥120 列摘要区）；sidebar Context 节显示完整拆分：输入输出与已用总量、推理行、缓存命中行（含命中率与写量）、窗口百分比条、 cost 行、迭代轮次与执行实例身份行。已用量取 provider 总量（无则取输入输出和）；百分比为已用除以窗口，不做基线归一化；窗口经画像列表按模型匹配解析（正向匹配无窗口视为未知，不借用他画像窗口；无匹配时回退默认画像），未知时只显示绝对值。缓存命中率为缓存读量除以输入量，无上报或输入为零时整行隐藏，不补零。
- MCP：外壳在会话启动时复用统一目录的工具列表获取做一次聚合，按连接来源分组为名称加可用状态；失败时该组显示弱化失败行并支持随 Git 手动刷新一起重试。会话内不做高频轮询。
- Git：直接复用 Git screen 的数据缓存与获取函数，sidebar 仅做摘要投影。显示变更总数与前若干行，完整列表指引用户前往 Git screen，面板内不提供树形展开与 hunk 浏览。

## 7. 接线点

- `tui-components` 的 context sidebar 模块负责分组数据结构与纯行排版，结构化程度从字符串行小幅增强为带状态与计数的行，不新建包。
- `tui-core` 不新增管理屏数据模型，sidebar 状态归会话控制器所有，与会话流式状态同生命周期。
- `wf-tui` 的会话控制器新增文件集合、待办快照与累计用量三个轻量状态；绘制入口在纵向布局前先做横向分栏；键路由新增经键位表下发的切换动作；导航 overlay 标题与帮助文案统一为 Navigation。
- `wf-cli-shared` 的展示配置新增 sidebar 分组，设置屏快照扩展对应只读行，备份命令沿用现有整体通道。
- `wf-mini` 不复制该面板，仅复用风格与 token。

## 8. 实施阶段

- 第一阶段：术语统一、横向分栏骨架、展示配置分组、切换快捷键与空态面板，数据全部留空以验证几何与重绘。
- 第二阶段：接入 Todos 快照与 Git 摘要，两组数据源最确定，同步补齐设置屏快照行。
- 第三阶段：接入 Context 累计用量与 Files 提取器，补齐窄终端降级与截断规则。
- 第四阶段：接入 MCP 聚合、刷新节流、帮助反查与全量单测收尾。

## 9. 验证

- 单测覆盖分组显隐与顺序、空分组隐藏、截断与省略行、待办解析成功与失败保留、用累计加、配置缺键回退与坏文件回默认、键位冲突校验。
- 集成验证使用现有管理屏示例与头部复现路径，覆盖宽终端分栏、窄终端自动隐藏、切换前后 transcript 宽度一致、overlay 盖压顺序。
- 验证集中在一次全特性编译检查与受影响包的单测，不分散多次构建；快照测试沿用现有 `tui-components`、`tui-render`、`wf-tui` 组合。
