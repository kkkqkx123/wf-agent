# CLI 前端总览

> 范围：`crates/app/cli/` 下五个 crate（`wf-cli-shared`、`wf-headless`、`wf-mini`、`wf-tui`、`wf-cli-demo`）
> 状态：基于当前代码的静态分析

`crates/app/cli/` 收拢全部命令行前端。所有形态均为 `wf-server` 的纯 HTTP 客户端，经由 `wf-client` 访问服务能力，自身不内嵌执行引擎、存储或 LLM 调用。管理类子命令与单次会话在各形态间行为一致，差异仅在交互外壳。

## 形态划分

| 形态 | crate | 二进制 | 进入条件 | 适用场景 |
|------|-------|--------|----------|----------|
| 无头单次会话与管理命令 | `wf-cli-shared`（逻辑）＋ `wf-headless`（薄二进制） | `wf-headless` | 显式子命令，或非 TTY，或 `--no-tui` | 脚本、CI、管道、自动化调用 |
| 轻量行式会话 | `wf-mini` | `wf-mini` | TTY 下无子命令（默认行式形态） | 日常快速问答，追加式输出 |
| 全屏 TUI | `wf-tui` | `wf` | `--tui` 且 stdout 为 TTY | 常驻交互、检视、审批、多会话管理 |
| 演示 | `wf-cli-demo` | 示例目标（非产品） | 手动运行示例 | 开发期检视各形态实现 |

形态解析的优先级统一为：`--tui` 优先，其次为子命令（强制无头），再次为 `--no-tui`，然后是 stdout 非 TTY 回落无头，最后 TTY 默认进入交互形态。该规则由共享的模式解析器集中实现，各二进制只做分发，不各自重复判定。

## 共同约束

- 纯客户端：所有命令与会话先解析连接（远端地址与凭证），经健康检查确认服务可达后再执行业务，失败时给出可操作的启动提示。
- 输出纪律：业务输出经由输出槽走标准输出，诊断信息（工具生命周期、审批拒绝、中断提示）走标准错误，保证 `wf run | jq` 类管道可用。
- 格式与目标正交：内容渲染（文本、单 JSON、按行 JSON、静默）与投递目标（标准输出、文件、内存、扇出）解耦，交互形态复用内存槽。
- 共享库零 TUI 依赖：`wf-cli-shared` 不依赖全屏渲染栈，使轻量目标编译时不引入全屏依赖树；全屏所需的底层能力下沉到 `app/tui/` 系列底层 crate，由 `wf-tui` 门面重导出。

## 依赖关系

上层只依赖门面，不跨层直连内部实现。轻量会话可直接依赖个别底层终端能力 crate，但不依赖全屏门面。演示 crate 只依赖各形态的真实实现，不复制产品逻辑。
