# 关键词与向量存储契约对称调整

> 背景：向量后端实现位于 `vector-contracts` 内，关键词后端实现位于 `wf-rag` 内；向量查询用完整过滤器，关键词查询用原生作用域；向量有集合规约与能力声明，关键词缺少对等形态。本篇把不对称逐项收敛。
> 范围：`vector-contracts`、`keyword-contracts`、`wf-rag` 中的关键词后端、分词核心、打开器与特性门。插件注册形态与调用抽象见《RAG 抽象与插件扩展点复核》。
> 方式：只改原模块，不建替代模块；按职责拆分，不按优劣重建；不做旧索引兼容，格式变化以显式重建恢复。

## 0. 结论速览

* 目标形态是两类存储契约各自纯粹、两类后端布局镜像、打开器与特性门同形、适配职责明确归属门面。
* 关键词三后端上移至契约包并按特性门控，分词核心随之下移，门面只保留文本分析器桥接与点模型适配。
* 集合生命周期、能力声明、计数语义三处补齐对等形态；确无对等语义之处以文档明确意图，不强行统一。
* 特性门、打开器、默认后端选择三处同步对称，避免一侧可配另一侧不可配。

## 1. 现状与不对称清单

* 后端位置不对称。向量侧内存、内嵌向量引擎、远端向量服务实现与契约同包；关键词侧文件型、内嵌倒排、远端全文实现全部位于门面内，导致门面同时承担契约消费与存储实现两类职责。
* 分词归属不对称。内嵌倒排与文件型后端依赖门面的共享分词与自定义分析器注册，契约包自身无法独立表达文本分析语义。
* 打开器位置不对称。关键词侧内存、文件、远端打开器位于门面入口，特性未编译时给出可读错误；向量侧无对等打开器形态，宿主直接构造后端。
* 特性门不对称。向量侧内嵌引擎与远端服务以包特性门控，关键词侧内嵌倒排与远端全文以门面特性门控，同一宿主需理解两套门位置。
* 集合生命周期不对称。向量契约要求按规约建集合与删集合，关键词契约无集合规约，原因是关键词后端以单表承载全集合，但契约未把该意图写明。
* 查询作用域不对称。向量查询携带完整元数据过滤器，关键词查询只携带命名空间与作用域原生字段，通用条件由门面适配层在命中上复核。该分离正确，但能力边界未在契约层显式声明。
* 文档与点模型不对称。向量点携带向量载荷加透传元数据，关键词文档携带显式文本加透传元数据，搜索结果共用带分点。该分工正确，但分词、格式戳、只读降级策略只在关键词侧存在，向量侧无对等说明。
* 维护操作不对称。向量契约含按页滚动、单点载荷改写与合并、载荷键删除；关键词契约无对等操作，原因是关键词载荷为向量载荷的派生镜像，不接受独立写。该意图同样未写明。

## 2. 目标形态

* 契约包只描述操作、值类型、错误与能力声明，不描述门面的分块、引用、合成与重排语义。
* 两类后端与契约同层布局：同包内按特性门控，或按职责拆为对等后端包，两者选其一并执行到底。
* 门面只做双向适配：向量点与关键词文档互转、通用条件复核、命名空间作用域构造、候选放大。
* 分词核心下沉为存储语义，插件桥接上浮为门面语义，两者经注册实例衔接，不经全局状态衔接。

## 3. 修改方案

### 3.1 后端位置与分词下移

* 将文件型、内嵌倒排、远端全文三后端上移至关键词契约侧，与内存、内嵌向量引擎、远端向量服务的布局镜像。首选同包内按特性门控，以最小搬迁达成对称；如包体积或依赖引发实质问题，再按后端拆为对等后端包。
* 将共享分词核心随之后移，包括英文与混合分词、自定义分析器注册、查询词项化与字符截断约束。门面仅保留插件分析器到分词注册的薄桥接。
* 后端内部不再引用门面模块，查询词项化只经下移后的分词核心，分析器缺失按未知名字早失败，已注册分析器执行失败则按空词项降级并记录诊断。
* 关键词打开器随后端一并下移，保持特性未编译时的可读错误语义；门面入口保留为薄转发，待宿主切换完成后移除。

### 3.2 集合生命周期与能力声明

* 为关键词契约补齐集合生命周期形态：按规约确保集合存在、删除集合及全部分片。因现有实现为单表承载全集合，首次实现可以单表加集合列的方式兑现语义，但必须提供与向量侧相同的调用形状，不再以无规约为由缺省。
* 为关键词契约补齐能力声明：支持的分词选择、是否支持自定义分析器、是否支持原生作用域之外的条件。向量侧已有种类与命名空间能力声明，两侧在建集合前均可做快速门禁。
* 为向量侧补齐格式说明：关键词侧已有格式戳与只读降级策略，向量侧明确编码指纹变化即需重建的规则归属，不新增格式机制，只把现有重建规则写入契约说明。

### 3.3 查询、计数与维护语义

* 查询语义保持现有分离：关键词后端只执行原生作用域，通用元数据条件由门面适配层在命中载荷上复核；候选放大只发生在门面适配层，后端按查询上限返回。
* 计数语义两 s侧对齐表述：远端实现允许按配置返回近似计数，调用方不得将其用作精确不变量；该说明同时写入两类契约。
* 维护语义明确意图：向量侧保留按页滚动与单点载荷维护；关键词侧不新增对等写操作，载荷以向量侧为准，关键词载荷通过重建恢复。意图写入契约说明，避免后人误补对称方法。

### 3.4 特性门与默认选择

* 关键词侧文件型能力保持常驻，内嵌倒排与远端全文按特性门控，与向量侧常驻内存、按特性门控内嵌引擎与远端服务的形态对齐。
* 门面特性透出改为转发契约侧特性，不再各自维护一套同名开关；特性关闭时的打开器错误文案保持可读。
* 默认后端选择写入宿主装配说明：本地单文件优先文件型关键词加内存或内嵌向量，高性能本地倒排按特性选用内嵌倒排，远端全文与远端向量分别按服务选用。

## 4. 验证范围

* 搬迁后运行工作区完整编译检查，重点覆盖特性全开与全关两组形态，确认关闭形态的打开器仍给出可读错误。
* 定向运行向量契约、关键词契约与门面测试，重点覆盖建集合语义、原生作用域、通用条件复核、候选放大归属、格式戳拒绝与只读降级、分词与分析器桥接。
* 远端全文与远端向量在线测试保持环境变量门控，无环境时跳过但不视为通过。

## 5. 不做事项

* 不合并向量与关键词为统一超特征，两类排序语义不可互换，融合仍归门面。
* 不新增图谱、多模态、摄取缓存与后台任务。
* 不做旧索引与旧打开路径兼容，存量索引以显式重建恢复。
* 不改变融合算法、重排适配、引用渲染与评测语义。
