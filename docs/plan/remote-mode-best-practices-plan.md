# 远端模式最佳实践对齐修改方案

依据 `docs/archive/remote-mode-architecture-review.md` 的评审结论，把“远端专用执行节点 + 本地管理面”的目标形态落到现有模块。目标不是把远端压成只有工具调用的端点，而是按数据归属切分职责，并补齐版本、连接、信任与同步链路上的缺口。

## 一、修改原则

* 只改现有 crate 与模块，不新增并行实现，不新增版本化模块。
* 默认产品功能集合保持不变；远端档位通过显式 feature 选择。
* 缺位功能不注册、不启动、不占位；不兼容大声失败，不静默降级。
* 不触碰关键词索引加固的未提交改动。
* 代码注释只用英文，文档用中文。

## 二、任务与顺序

### 任务一：API 版本单一来源与连接握手

把 `API_VERSION` 常量收到 `wf-types`，服务端 `/api/v1/info` 与客户端期望值共用同一常量，避免两端各自维护字面量。

CLI 在健康检查通过后读取服务端的 `apiVersion`，与客户端常量不一致时以配置错误终止，提示升级客户端或服务端。服务端后端探测同样校验远端 `apiVersion`，版本不一致的条目记为不可达，避免本地管理面把不兼容的远端当成可用节点。

### 任务二：远端执行档位预设

`wf-server` 新增 `remote-node` feature，显式包含执行节点所需能力：插件与三种后端、文件检查点、关键词与向量检索、PTY、MCP、Git/FS、SQLite 存储；显式不包含后端管理域、指标、OpenAPI 文档、PostgreSQL 存储与静态托管。

在服务启动时拒绝 `remote-node` 与 `backends` 同时启用并给出明确错误，从根上杜绝远端再管理一层远端的递归管理面。启动期检查而非编译期互斥，是为了让全量 feature 的编译与测试检查仍然可用。

### 任务三：SSH 隧道连接复用

在 `wf-types` 提供确定性的 ControlMaster socket 路径计算，由主机与本地端口推导，保证服务端监管进程与客户端打印的启动/停止命令得到同一路径。

服务端监管的 `ssh -N` 作为 master 连接；客户端打印的远端启动与停止命令以 slave 方式复用该 socket。没有 master 时 slave 连接直接失败，不静默退回新连接，让“先建隧道再执行命令”的顺序成为硬约束。

### 任务四：按项目的信任分级

在目录白名单之上增加显式信任根配置：文件层 `trusted_roots` 与环境 `WF_TRUSTED_DIRECTORY_ROOTS`。未配置时保持现有行为；配置后，只有列出的根具备执行与写入能力，其余允许目录只能做只读查询。

拦截集中在目录中间件：请求解析出目录作用域后标记是否受信任，未受信任目录对执行、脚本、工具、PTY、Git 写入、文件系统写入等路径的非只读请求直接拒绝。只读请求不受影响，与受限模式只阻止项目设置拉起能力的思路一致。

### 任务五：备份专用同步端点

在现有观测导出模块中新增一次请求即可取回执行包与检查点链的同步端点，复用已有的导出与链查询函数，不改变两者的数据形态。

本地管理端的定时备份改为调用该端点，不再分别请求通用执行包接口和通用检查点接口，降低备份链路与业务 API 形态的耦合。

## 三、验证

* `cargo fmt`。
* `cargo check --locked -p wf-server` 默认档、`--no-default-features`、`--no-default-features --features remote-node`、`--all-features` 四组。
* `cargo clippy --locked --all-targets --all-features`。
* 版本不匹配、未信任目录写入、ControlMaster 参数生成、同步端点响应的针对性测试。
* 需要 release 构建时在 devs 完成，不回传产物。

## 四、实施状态

五项任务均已落地：

| 任务 | 状态 | 说明 |
|---|---|---|
| API 版本单一来源与握手 | 已落地 | 常量收进 `wf-types`；CLI 连接与服务端探测都校验 `apiVersion`，不一致分别报配置错误或标记不可达。顺带修正了探测读取字段名与服务端输出不一致的问题 |
| 远端执行档位预设 | 已落地 | `remote-node` 显式包含执行域、不含管理面与 UI 面；启动时拒绝与 `backends` 同开 |
| SSH 连接复用 | 已落地 | socket 路径由 `wf-types` 按主机与本地端口生成；服务端监管的转发作为 master，打印的启动/停止命令作为 slave |
| 工作区信任分级 | 已落地 | `trusted_roots` 与 `WF_TRUSTED_DIRECTORY_ROOTS`；未受信任目录的执行与写入路径由目录中间件统一拒绝，只读不受影响；未配置时保持原行为 |
| 备份专用同步端点 | 已落地 | 一次请求取回执行包与检查点链，服务端复用既有导出函数，备份链路不再依赖两个通用业务接口 |

验证结果：四组 `cargo check` 通过，`cargo clippy --locked --all-targets --all-features` 通过。新增测试覆盖版本常量匹配、信任根判定、受限路径判定与 ControlMaster 参数生成。

## 五、不做的事

* 不改插件权限模型、LLM 调用语义、鉴权逻辑与配置优先级。
* 不做跨档位运行时热切换。
* 不在远端提供后端注册、隧道监管、备份调度等本地管理职责。
* 不引入中继服务或新的认证体系。
