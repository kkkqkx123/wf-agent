# 前端模板编辑、配置编辑与可视化现状分析及改造方案

> 目标：复盘 `apps/web-app` 中模板编辑、配置编辑、工作流与 Agent 可视化三块的实现现状，评估设计合理性，并给出分阶段改造方案。只描述做什么、为什么、做到什么算完成，不粘贴完整代码实现。

## 1. 分析范围与依据

- 模板编辑：`src/routes/templates/+page.svelte`（列表加抽屉单页）、`src/lib/services/templates.ts`（网络加归一加校验加保存）、`src/lib/types/models.ts` 中模板类型、`src/lib/api/client.ts` 与 `envelope.ts`。
- 配置编辑：`src/routes/settings/+page.svelte`、`src/routes/resources/+page.svelte`、`src/routes/triggers/+page.svelte`，以及 `src/lib/services/preferences.ts、resources.ts、triggers.ts` 与 `src/lib/stores/preferences.svelte.ts、behavior.svelte.ts`。
- 可视化：`src/lib/components/domain/` 下 `GraphCanvas.svelte、GraphExplorer.svelte、WorkflowGraph.svelte、Timeline.svelte、TimelineOutline.svelte、ExecutionInspector.svelte`，`src/lib/graph/display-model.ts`，`src/lib/services/graph.ts、workflows.ts、agent-loops.ts、executions.ts`，以及 `workflows/[id]、agent-loops/[id]、executions/[id]` 三个详情路由。
- 后端对照：`crates/app/wf-server/src/api/template/library.rs` 与 `templates.rs`（模板更新通道是否存在，是本次关键核验点）。

## 2. 模板编辑现状

单页收敛形态。路由页独占约六百行，列表、详情抽屉、新建表单、导入对话框全部收敛在一个文件内，无子路由、无子组件拆分。

数据分流合并。模板库接口只覆盖工作流与 Agent 两类，节点与触发器走注册表分页接口。列表加载时三路合并，再经归一函数统一字段（标识回退、用量计数、标签数组、精选标记默认）。详情按四种类型分别请求不同端点，取出定义体并序列化为 JSON 文本供预览与回填编辑。

校验不对称。工作流与 Agent 类型调后端校验端点；节点与触发器类型无后端试运行端点，只在前端检查必填字段。校验结果以有效或无效徽标加错误列表呈现，校验不通过时阻断保存。

保存不对称。节点与触发器有原生更新通道，真更新。后端注册表类型只有查询、注册、删除，没有更新通道（已逐行核验 `library.rs` 路由注册：列表与注册、详情与删除，仅此四组）。前端因此用快照删除再重注册模拟更新，失败时尽力用旧快照回滚。克隆、导出逻辑同样按类型分流，导入仅支持节点与触发器两类。

编辑载体为裸多行文本框。预览是格式化 JSON 的预排文本，无语法高亮、无行号、无错误定位，无字段化表单，无图形化预览。

状态管理为页内局部状态。模板列表、抽屉开关、编辑文本、校验状态、删除二次确认等全部是页面级响应式变量，无全局模板存储。筛选条件经地址栏参数持久化，每次保存、克隆、导入、删除后手动整表重载加详情重载，无乐观更新。

## 3. 配置编辑现状

两套机制并存，无统一配置编辑器。

外观类偏好存本地。主题、密度、侧栏折叠与宽度、检查器固定等经偏好存储直写浏览器本地存储，即改即存，无后端参与。

行为类偏好走服务端。分页大小、自动刷新、流跟随、动效缩减等启动时从偏好接口加载，编辑只改内存，经保存按钮整文档替换写回，另有恢复默认值入口。

资源页本质只读加开关。模型档案、供应商、脚本三段为纯表格展示，新建按钮禁用。工具与技能卡片带启用停用开关，采用乐观切换、失败回滚加全局提示。工具调试经对话框输入 JSON 参数文本，先本地解析检查，再调参数校验端点展示错误，最后调执行端点。技能提示词只读查看。

触发器页为记录查看加试发。触发记录表格只读，附带清理旧记录的两步确认。钩子试发为名称输入加负载文本框，仅做本地 JSON 解析后发送。钩子列表当前为空桩，无真实列表来源。

看板与洞察不可配。看板数据为前端多接口聚合计数。洞察的即席查询输入仅为本地草稿，执行动作为虚假成功提示，查询结果、错误分析、审计报告等服务为桩返回。

交互原语统一。多行文本框加对话框加抽屉加分段控件加开关，配合地址栏标签同步、懒加载一次标记、全局提示反馈。

## 4. 工作流与 Agent 可视化现状

三类图中分层最清晰的一块。数据链路为后端纯拓扑经领域服务转换为统一图模型，再派生为展示节点与边，经资源管理器外壳进入画布，全程单向。坐标与视觉编码只在前端展示模型模块内计算，后端不参与排版，该职责划分在模块头注释中明确声明。

渲染技术。图形部分唯一依赖为画布渲染的图库，懒加载引入，节点固定尺寸，边为贝塞尔曲线加三角箭头，样式经数据映射器生成。时间线为纯页面结构加样式实现，不经过图库。工作流图组件只是固定预设与布局的薄适配。

布局策略。工作流与执行默认分层布局；Agent 决策默认按迭代分列排布，横轴为迭代轮次；另有自由力导与规整网格两种可切换布局。

路由装配。工作流详情以图分段为主，叠加环路、不可达、死端分析覆盖层。Agent 回路详情以决策预设加迭代列表呈现，步骤、工具频率、迭代走副链路。执行详情经检查器按标签懒加载，图标签在拓扑基础上并行拉取失败节点与关键路径做高亮，其余慢节点、决策点、效率指标只供分析标签。

交互设计。工具条提供缩放、适配、重排、导出图片。单击节点选中并在右侧展示类型、状态、迭代、出入度；短时间内双击触发邻居扩展，经邻居接口拉取并以临时覆盖层加提示呈现数量。高亮集合驱动强调与弱化样式。过滤支持按标识与标签搜索加类型复选，超限截断并提示可见数量。图例随预设切换。

状态映射双通道。图节点边框色与徽标时间线色共用同一套语义归一：完成类、失败类、运行类、等待类、中性类各归一档，未知值回退中性。形状编码区分起止、决策分支、工具调用。虚线边表示条件、错误路由、分支与未采用路径。

## 5. 设计合理性评估

合理之处。

- 可视化分层优秀。展示模型收敛形状颜色图例，画布与资源管理器复用于三类图，后端解耦为纯拓扑，避免三套重复实现。这是三块中架构质量最高的部分，应予保留并作为后续扩展的底座。
- 数据层约定统一。信封拆包、分页提取、类型逃逸收敛点、地址栏标签同步、骨架加空态加错误态、懒加载守卫，全站一致，维护成本低。
- 模板校验阻断保存、内外层区分保留注册表类型外层元数据，思路正确。

主要问题，按严重程度排序。

- 模板更新存在正确性风险。注册表类型无后端更新通道，前端删除加重注册模拟更新是非原子的，会丢失标识连续性与外部引用，并发更新会互相覆盖，回滚只是尽力而为。这是后端缺口传导到前端的真实风险，不是前端写法问题。
- 模板编辑器可用性不足。裸文本框编辑大 JSON 不可用，无高亮、无定位、无结构校验提示。导入导出按类型残缺，用户无法预测哪类支持哪种操作。
- 无工作流与 Agent 创建编辑器。工作流详情只有查看加版本回滚加草稿提升，草稿不可视化编辑。模板与实例编辑割裂：模板在模板页用 JSON 编辑，实例没有编辑入口。
- 配置语义混乱。资源与触发器页大量只读表格加禁用按钮加空桩，用户无法区分功能未实现与功能无权限。工具参数只有 JSON 文本模式，无结构化表单。洞察的虚假执行提示会误导用户以为查询已运行。
- 可视化只读且复杂图可读性有限。无拖拽建模、无框选、无小地图，分层布局在复杂有向无环图下可读性不如专业排版算法。执行状态需多次串行请求拼装，延迟偏高。超限截断无聚合，下钻能力止于单跳邻居。

## 6. 改造方案

总原则：原模块内改造，不另起替代模块；无历史兼容负担，接口与交互可直接改为目标形态；文档与注释使用中文写文档、英文写代码，设计文档不粘贴完整实现。

### 阶段一：消除模板更新的正确性风险

- 后端补注册表更新通道。在模板库路由注册中为工作流模板与 Agent 模板各增加更新处理，与现有注册、删除并列。语义为按标识整体替换并返回标识，校验逻辑复用注册通道。完成后前端删除模拟更新的分支整体删除，保存函数按类型直调原生更新。
- 前端统一导入导出。导入能力扩展到四类模板，超出后端能力的类型由后端补对应导入端点，而非前端抛错。导出统一走附件下载语义，取消前端本地组装与原生请求混用两套路径。
- 验收：四类模板更新不再经过删除；并发更新后数据一致；导入导出矩阵四类齐备；保存失败不再触发回滚重注册。

### 阶段二：模板编辑器可用性

- 文本编辑能力升级。在原抽屉模块内把裸文本框替换为带行号、高亮、错误行定位的代码编辑能力，语法错误定位到行并与校验错误列表联动。仍保留 JSON 为高级模式，不自研编辑器内核，选用已有轻量编辑依赖。
- 按类型补结构化表单。在抽屉内新增表单与 JSON 双模式切换：表单模式按类型的必填字段与常用字段渲染受控输入，切换到 JSON 模式时双向同步并以校验结果为准。字段定义集中收敛一处，避免四类各自为政。
- 预览升级。详情非编辑态在 JSON 预排之外，按类型增加语义摘要：工作流显示节点数、边数、起止点；Agent 显示步骤数与工具分布；节点与触发器显示关键字段表。摘要数据由已加载的定义体前端派生，不新增接口。
- 验收：千行级定义可定位错误行；表单与 JSON 双向同步一致；四类模板均有语义摘要；禁用按钮全部给出原因文案而非静默禁用。

### 阶段三：配置编辑语义收敛

- 桩与虚假交互清零。钩子真实列表缺失则试发区明确标注来源缺失并保留手动输入；洞察查询在后端聚合器就绪前，执行按钮明确为不可用并说明原因，删除虚假成功提示；审计报告、错误分析的空列表配空态说明，不再伪装成有数据。
- 工具参数结构化。在现有调试对话框内，按工具参数结构渲染表单，JSON 保留为高级模式。参数校验与执行复用现有两段式流程，交互不变，只替换输入载体。
- 偏好读写统一语义。外观类继续本地即改即存，行为类继续整文档显式提交，但两类在设置页内用分区标题与保存提示明确区分，避免用户误以为全部即时生效。
- 验收：全站无静默禁用、无虚假成功提示；工具调试支持表单与 JSON 双模式；设置页分区语义明确。

### 阶段四：可视化在只读基础上的纵深

- 本阶段不做可视化拖拽建模。先补只读纵深：边标签碰撞避让、复杂图按子图折叠展开、超限截断改为按类型聚合而非简单截断、小地图与框选只读导航。
- 执行状态一次成型。新增聚合接口或复用现有批量通道，把拓扑、失败节点、关键路径合并为一次加载，取消前端多请求串行拼装。前端加载守卫与懒加载结构不变，只替换数据源。
- 草稿可视化只读先行。工作流草稿在现有详情页内复用资源管理器做只读渲染加节点属性查看，节点属性编辑作为下一步，不在本阶段引入可编辑画布。
- 验收：复杂图可折叠导航；执行图加载请求次数收敛；草稿可见可查；交互仍为只读语义，无编辑态残留。

## 7. 任务顺序与依赖

- 第一序：阶段一。后端更新通道是正确性前提，其余阶段都依赖它，优先落地。
- 第二序：阶段二与阶段三可并行，分别触模板页与资源触发器洞察页，无文件重叠。
- 第三序：阶段四。可视化改动面独立，但聚合接口需后端配合，排在模板风险消除之后。
- 正式应用变更后按既有同步脚本更新预览工程，样例目录与模拟客户端为预览独有，不被覆盖。

## 8. 验收与风险

- 全量验收：类型检查、构建、 lint、单元测试四项全绿；模板四类更新、导入导出矩阵逐项走查；复杂图折叠与执行图加载时延对比。
- 风险一：后端更新语义与重注册语义差异导致旧数据迁移问题。应对：无历史兼容要求，直接采用替换语义，失败即报错不回滚。
- 风险二：编辑器依赖引入体积与主题适配成本。应对：懒加载引入，只在抽屉进入编辑态时加载；颜色经现有语义 Token 映射，不引入自有主题。
- 非目标：拖拽建模画布、多会话并发流自动重连、全局错误聚合、文件内容编辑、触发器定时启停、技能安装、模板评分评论。本方案不为上述事项预留接口或开关。
