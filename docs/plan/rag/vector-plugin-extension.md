# 向量高级能力插件扩展点预留方案

中文撰写，自然语言为主，不贴完整实现。范围是 `vector-qdrant-followup` 第三批剩余算子与第四批至第六批作为可选高级功能时的插件侧预留。本方案只预留标识与纯函数形状，不接执行线，默认链路零变化。所有预留项均为触发式，无触发时不启用。

## 背景与范围

向量契约已覆盖创建、写入、稠密检索、滚动列举、按标识取数、按标识与按来源删除、计数、载荷局部更新，以及必含、可选分支、最小满足数、标识集合与相等、区间、前缀、子串、长度、空与 null 过滤。剩余项包括第三批延后算子（全文、分词、地理半径包络多边形、嵌套对象、时间区间、向量存在性、切片），以及第四批（分组、推荐与发现输入、预取融合排序）、第五批（稀疏多向量、命名向量、向量增删）、第六批（快照、分片别名集合更新、传输增强、gRPC、多类型索引）。

插件侧现状是无检索一等公民：贡献种别只有节点工具、LLM 编解码认证镜像、事件、中间件、声明式资源与压缩建议；中间件相位只有工作流节点、LLM 工具、错误检查点；权限只细分到 LLM 编解码认证发现。检索相关需求目前只能走通用中间件补丁，容易命名冲突，也容易滑向透传原生请求的旁路。

## 设计原则

- 契约优先：三后端行为一致才进契约，插件只贡献纯函数与描述符，翻译权归主机，不引入透传原生过滤或原生请求的逃生舱。
- 只加可选：新增贡献种别、权限、中间件相位一律可选，缺省行为不变，旧清单可照常解析。
- 纯函数隔离：分词融合排序编码建议保持同步无副作用，输入输出走 JSON，引擎校验每条建议，非法建议直接丢弃并回退内置逻辑。
- 网络约束沿用既有先例：纯计算可跑沙箱，联网实现只许原生后端。
- 运维面不出契约：快照分片别名传输增强保持主机专有，插件只读观察，不直接操作。

## 第三批预留：过滤侧

触发条件为检索管线提出新的过滤需求，每加一个算子仍需三端同步落地，插件预留不替代该流程。

- 文本分词器：新增文本分析器贡献，插件提供分词与归一化纯函数，主机用同一口径驱动内存扫描、端内扫描与服务端文本索引配置。立项前必须先定分词器口径，定不出一致口径宁可继续延后。
- 地理时间嵌套：以声明式策略预留为主，包括坐标校验、米制半径、闭合多边形约定、跨半球与边界口径、时间格式与边界语义、嵌套递归语义与空过滤定义。端内已有半径与包络求值，多边形求值随触发立项。
- 向量存在性与切片：不给插件口，随命名向量与滚动并行扫描一并考虑，属主机内部能力。

## 第四批预留：检索整形侧

触发条件为出现多路召回或分组展示需求，引入前调用方在客户端侧做多路合并。

- 检索建议器：新增检索建议贡献，覆盖分组、推荐与发现输入、预取融合、排序整形。输入为候选命中的只读快照，输出为重排融合分组后的建议，引擎校验标识与分数合法性后才采用，空建议回退内置逻辑。
- 中间件相位：新增检索前、检索后、融合前、重排后四个已知相位，插件可注册改写上下文，引擎触发前不分发。

## 第五批预留：向量形态侧

触发条件为出现混合稀疏需求或多向量建模需求，缺省稠密路径零变化。

- 向量编码器：新增向量编码贡献，插件提供稀疏与多向量编码纯函数，主机拥有存储契约与维度校验。命名向量与向量增删随命名向量一同引入，不单独提前。

## 第六批预留：运维侧

触发条件为分布式运维需求或压测证明传输为瓶颈，日常检索不依赖。

- 快照策略：新增快照策略声明式贡献，插件只声明备份恢复期望，执行权归主机专有扩展。
- 集群观察：复用事件处理器，订阅向量集群只读事件，不新增写入口。分片别名集合更新、传输调参与后端切换保持运维配置，不进插件。

## 插件模型映射

- 贡献种别新增文本分析器、检索建议器、向量编码器、快照策略四种串标识，注册冲突语义与既有种别一致。
- 权限新增检索、向量编码、快照策略三项细分，文本分析器复用向量编码权限，缺声明时仅做准入提示，不改变现有行为。
- 中间件新增四个检索相关已知相位，未知串仍走透传分支。
- 管理器新增四个同名注册表，注册查询注销与贡献归属口径与既有注册表一致，桥接同步随触发立项，当前不接线。

## 测试与文档

- 每种预留补注册往返用例：注册可见、归属正确、注销清空、冲突口径一致。
- 权限串与相位串补往返用例，旧清单照常解析。
- 文档补齐触发条件、隔离约束、校验回退语义。验收为新接入者只读文档即可正确声明，不误用预留口做透传。

## 回归约束

改动只修改原模块，不新增替代模块。日志与错误信息英文，注释只描述意图。无旧数据兼容，不更新版本号。每步通过受影响包的编译检查与单测，编译输出先重定向到文件再阅读，集中为最少次数的验证。
