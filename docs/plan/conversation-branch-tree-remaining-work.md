# 对话分支树剩余修改方案

> 对象：`docs/plan/conversation-branch-tree-design.md` 的落地实现。本文只描述剩余工作，不重复设计原文。
>
> 状态：以下第一至五项已完成；只读工具轮仍按设计文档的第 7 步保留为后续工作，本次未改动 `ChatSession` 的工具边界。

## 目标

保持现有分层与数据模型不变，在不引入“v2”替代模块的前提下，把已落地代码从一个可用的后端骨架补成行为自洽、可恢复、可观测、可被客户端调用的实现。

## 一、执行与并发正确性

1. **在飞槽先于写树**：提交轮与步进作业都在拿到会话写锁后、写任何树文档前检查并占用在飞槽。步进作业整体占一个槽，步骤之间不释放，避免与提交轮交错。
2. **生成基准不可被收敛覆盖**：准备请求时记录节点当前 `base`；生成结束时把该基准写回回复。树在生成期间发生变化时，回复自然保持脏，而不是被误标成新鲜。
3. **崩溃恢复**：加载树时把没有匹配在飞驱动的 `Pending` 回复收敛为 `Interrupted`，并写回树文档。
4. **任务登记**：提交的驱动与步进作业都登记到进程内任务注册表，服务关闭时统一取消。
5. **空闲回收**：运行时表记录最近使用时间与订阅者数量；无订阅、无在飞且超时的实例从内存淘汰，树仍在存储中。

## 二、树手术与嫁接

1. `detach(carry_prefix=true)` 物化前缀时跳过软删祖先，与摘要折叠保持一致。
2. `reparent` / `attach` 允许把子树挂到虚拟根。
3. `attach` 的 HTTP 默认 `carry_prefix` 语义与设计一致（嫁接默认携带前缀）。
4. 允许跨会话嫁接；嫁接成功后删除被消费的 Graft 文档，并清理来源会话的池条目与版本。
5. `detach` / `attach` 的多文档写入按“先写从文档、再写主树、最后清理已消费文档”的顺序执行；失败时主树不留下悬空指针。
6. 手术响应中的 `restale` 使用编辑器真实结果，不再返回空列表。

## 三、脏状态与步进接口

1. `acknowledge` 写入的确认摘要参与脏判定：确认当前基准后 `dirty=false`，上游再次变更则重新变脏；快照暴露 `acknowledged` 与 `modelDrift`。
2. 步进请求支持 `node_id` 与 `policy=keep_human`；人工改写的正文不会被默认策略覆盖。
3. 步进取消按 `jobId` 生效；`step.*` 帧区分进度、完成与停止。

## 四、事件与订阅

1. 订阅先用总线建立实时接收者，再查询持久化事件历史，按事件 id 去重后回放，消除回放/订阅窗口。
2. 回放窗口从进程内环形缓存切换到统一事件存储（总线窗口 + 持久化事件合并）。
3. 所有会话端点先校验执行类型必须是 `Chat`。

## 五、集成

1. 新增树会话端点写入 OpenAPI 注解与中央路径清单，刷新 `openapi.json`。
2. 重新生成 `apps/web-app/src/lib/api/schema.d.ts`，同步 `docs/app/server/11-chat.md`。
3. `wf-client` 增加树会话端点常量。
4. web-app 增加订阅/提交拆分与最小可用的树快照、脏徽标、单步/顺序重算入口。
5. TUI 的 `session_tree` 去掉“没有消息级分支”的旧前提，加入树会话只读装配入口。

## 六、清理

移除未被调用的纯函数与状态残留：`ReplyState::Superseded`、`is_graft`、`can_answer`、`root_id`、`project_active`、`project_ids`、`stop_index`、`is_acknowledged`（若被脏判定使用则保留）、`kind_filter`。修正实现说明文档与实际口径冲突的段落。

## 实施顺序

按“一 → 二 → 三 → 四 → 五 → 六”推进。每一步修改后集中做一次静态检查，不逐文件重复编译。
