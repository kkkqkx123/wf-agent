# 01-注册与调用

> 范围：`registry.rs`、`tool_call.rs`、`handlers.rs`、`callback.rs`、`error.rs`、`failure_protection.rs`
> 定位：工具的注册中心与调用编排层，执行器与预定义工具都挂载于此

## 注册中心

`ToolRegistry` 是全部工具的唯一注册表，内部按工具类型（无状态/有状态/内置/MCP/REST）持有执行器工厂，按工具 id 持有工具定义，另有三套并行的处理器表：同步处理器、异步处理器、有状态实例工厂，以及内置处理器表。附属注入项（执行回调、技能加载器、MCP 连接管理、指标收集器）以锁保护的可选项形式存放，执行器工厂在每次获取执行器时读取当前快照，因此装配顺序不影响已注册工具。

核心行为：按类型查工厂并构造执行器；执行时依次做存在性检查、禁用检查、执行器获取、带超时的执行与指标记录；指标按成功/失败分别记录调用开始、完成（含耗时与参数/结果体量）与错误分类。错误分类把每种工具错误映射为低基数标签供指标聚合。另提供按名搜索、按类型列举、持久化存储 trait（`ToolStorage` 的加载/保存/删除）与 `wf-core` 通用注册表 trait 的适配。

## 调用器

`ToolCallExecutor` 是注册表之上的编排器，持有注册表与可选的事件通道。单次执行按开始/完成/失败三事件上报；重试执行走执行器的重试扩展；批量执行分顺序与并行两种，并行经异步汇聚实现，不做并发限流（限流由上层引擎负责）。

## 默认装配

`handlers.rs` 是开箱即用的装配入口：`create_default_tool_registry` 给出默认配置的注册表，`register_builtin_handlers` 按配置把各类别处理器接入注册表。文件系统处理器可叠加写保护控制器，终端处理器携带终端配置，代码上下文与检索处理器在未配置后端时报告服务不可用而非静默失败。内置处理器（智能体/工作流/技能）的默认实现在此处统一注册，保证经注册表构造的执行器与直接构造的执行器行为一致。

## 回调契约

`callback.rs` 定义引擎回注的 `ExecutionCallback`：同步/异步两态的智能体循环执行、同步/异步两态的工作流执行、执行状态查询与执行取消。另有父链路结构（执行 id、层级管理器、取消信号、父文件作用域、外层工具调用 id、子智能体事件通道），内置调度工具在转发时携带它，使子执行挂到调用时刻存活的父节点下，而非事后按 id 重查。全局回调存取点供未显式注入执行器的路径兜底。

## 错误与失败保护

`error.rs` 以单一枚举覆盖全部工具失败：未找到、执行失败、校验失败、超时、取消、重试耗尽、MCP/传输/连接/REST/HTTP、序列化、IO、回调缺失、内部错误、执行错误、作用域违规。其中作用域违规与缺文件各有机器可读标签（人类与测试信号）与布尔元数据标记（引擎计数信号），避免按文案猜测。`failure_protection.rs` 在调用器之外提供按工具的连续失败计数与冷却：超过阈值后拒绝执行并返回剩余冷却时间，配置可整体开关。
