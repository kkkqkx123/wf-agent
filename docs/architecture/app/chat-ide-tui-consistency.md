# 对话优先形态下 Web 与 TUI 的一致性分析

> 定位：应用层架构记录。结论：`wf-tui` 已是对话优先形态，与 Web 聊天 IDE 方案（见 `docs/plan/web/chat-ide-primary-design.md`）在原则层一致；差异来自终端与浏览器媒介不同，以及双方各自超前的细节。本文只记录结论与分工，不粘贴代码实现。

## 1. 判定结论

`wf-tui` 符合对话作为主界面的设计。导航栈默认落在会话屏，其他界面经浮层进入；绘制路径在会话控制器存在时永远绘制会话；执行列表支持回放进会话。工作台类界面均为附加页。

Web 端翻转完成后，两端在“对话为主、工作台为辅”上一致，无需为一致性做额外改造。

## 2. 一致点

- 默认界面均为对话，会话切换、中断、恢复语义一致。
- 工作台均为附加页：Web 是中心列模式加附加路由，TUI 是导航栈中的执行屏加回放进会话。
- 追问队列与停止语义一致：串行先进先出，提交即排队，取消走安全点。
- 提及与命令方向一致：文件、技能、工作流提及加斜杠命令面板加模型选择。
- 窄屏策略一致：优先保住对话列，侧面板在空间不足时拒绝或转浮层。
- 主题跟随与动效降级原则一致。

## 3. 差异点

### 3.1 会话模型

Web 是多会话管理（星标、最近、草稿、归档四视图加会话搜索），TUI 是单会话模型（会话持有与挂载释放加恢复最近会话）。终端单会话是合理取舍，不要求 TUI 补多会话侧栏。

### 3.2 右侧面板

Web 规划七个归属当前会话的边面板标签（图、迭代、变量、检查点、工具、时间线、分析）。TUI 的图解侧格目前只是占位，管理数据散落在各独立界面，不附着于会话。若补齐则单独立项。

### 3.3 输入框形态

TUI 输入框为单行缓冲加历史环加草稿暂存，属终端约束。Web 不学单行，做多行组合器。

### 3.4 提及种类

TUI 有文件、技能、工作流三种提及；Web 另要模型与工具提及。以 TUI 语义为基扩展。

## 4. 双向借鉴分工

- Web 向 TUI 借鉴：流式管线语义（双缓冲、限速合并、流式尾行、尾部跟随）、队列语义、提及解析规则、审批记忆与提问交互、执行回放进会话。
- TUI 向 Web 借鉴：多会话分组呈现、边面板标签组织、Markdown 富渲染（公式、图表、产物卡片）。
- 两端不共享代码，各自按媒介实现，只对齐语义。
