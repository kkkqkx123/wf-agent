# 落地进展

三阶段改造均已完成并通过回归验证。

## 阶段一：概念收敛与安全补齐

* 统一命名：新增规范名并保留旧名为兼容别名。工作区写入为恢复，编辑指针移动为撤销与重做，历史追加为合并与恢复提交。旧有恢复类入口标注为遗留别名，文档指向规范入口。
* 收敛工作区恢复入口：新增统一恢复目标与统一恢复入口，覆盖全量提交、范围提交、路径精选三个规范核心，旧有仅差参数组合的入口收敛为文档别名。
* 多特性合入新增预演入口：逐特性预测冲突与不可合入原因，不移动引用、不创建提交；合入新增显式选项，支持原子预校验与顺序确认。
* 统一两阶段协议：精选恢复与区间恢复均补齐预览与执行两阶段，预览与执行走同一目标集合，不透明项在预览中显式标出。
* 状态与文件联动新增显式策略：宽松策略保持历史行为，严格策略对缺失关联直接报错，杜绝静默缺席。

## 阶段二：合并与回滚语义加固

* 多特性合入支持全有或全无：原子模式下预演失败则主线不动；执行中遭遇并发导致的半合状态以部分合入错误返回，携带已完成清单。
* 特性回滚新增稳定寻址：主线合入提交写入特性名与合入标识，支持按特性名恢复最近一次合入，不再要求调用方持有精确提交标识。
* 分组回滚非头部改为可报告的业务结果：新增头部状态查询，拒绝信息携带当前头部，调用方可重试或转人工。
* 冲突状态统一口径：提交注释中的状态标记为唯一权威来源，字节标记仅作展示校验；审批、合入、查询三处共用同一判定入口。
* 主线与特性健康检查统一：阻塞判定与冲突列表同源。

## 阶段三：清理与体验优化

* 水位可观测：新增存储水位与回收报告入口，区分可达与可回收层级；清理报告复用既有完成事件，调用方无需二次遍历即可掌握存储压力。
* 数据交换正名：同步模块文档明确其非恢复属性，与恢复命名空间划清界限。
* 恢复演练：新增八项集成演练，覆盖全量恢复、范围恢复、精选恢复、原子合入预演、冲突解决、稳定回滚、严格关联、水位报告。
