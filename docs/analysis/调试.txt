# Ratatui TUI调试方案 + Example示例工程设计
> 目标：调试 TUI 组件、状态流转、流式动画、多模式（Full‑TUI / Mini / Headless）；把每个场景拆独立 example；动画循环播放做预览。
> 结论：**分 example 文件 + 循环动画预览是合理的开发手段，但只用于调试示例，不要带到产品主程序**。同时还要配套日志、离线快照、单元测试、文本快照测试，不只靠肉眼预览。

## 一、整体思路与合理性分析
### 1）每个场景独立 example 文件
合理。ratatui 官方本身就是这么组织示例的。
- `examples/` 目录，每个文件对应一个单一场景：
  - `examples/tui_chat.rs`：完整对话界面（消息、流式输出、滚动）
  - `examples/tui_mini.rs`：mini模式（print+底部输入框）
  - `examples/tui_animation.rs`：动画/流式token模拟循环播放
  - `examples/tui_scroll.rs`：长文本、滚动、resize场景
  - `examples/tui_sink.rs`：OutputSink / TeeSink多路输出演示
  - `examples/headless.rs`：无头模式演示
- 每个 example 可以独立运行：`cargo run --example tui_animation`
- 好处：隔离问题，复现bug不需要跑完整agent业务；新人可以逐个看；CI可以编译检查所有example能否编译通过。

> 约束：examples 只做UI层演示，**尽量mock业务，不要引入真实LLM网络调用**；全部使用模拟数据。

### 2）example中动画循环播放预览是否合理
✅适合**UI调试、演示动画/流式效果**，**仅限example，禁止复制到主产品代码**。
- 例如模拟 LLM token 流式输出：循环不断生成模拟chunk，追加消息，触发重绘，观察滚动、渲染节流、diff表现。
- 问题点：
  1. 循环动画示例必须提供退出条件（按 q/Esc 退出），不能死循环只能杀进程。
  2. 要可控：可配置循环次数，或者按键暂停/重置。
  3. 不要把“无限循环模拟流”的逻辑混入真实业务AppState。

> example 的动画实现思路：
> 使用一个模拟生成器，在事件循环中，用定时器间隔产生模拟token，而不是真实网络IO。
> example内部构造假的`ChatMessage`，调用`sink.write_chunk()`，复用产品的Sink+渲染路径。
> → 这样example跑的渲染逻辑和真实产品完全一致，调试价值很高。

## 二、example工程具体设计
### 目录结构参考
```
src/

  app.rs           # AppState

  tui/             # tui渲染模块
    mod.rs
    chat_ui.rs

examples/
  tui_chat.rs      # 完整聊天TUI，mock流式输出（可开关循环动画）
  tui_mini.rs      # mini模式 print + ratatui底部输入框
  tui_scroll.rs    # 超长文本、resize、滚动边界测试
  tui_animation.rs # 独立动画演示：思考指示器、流式token循环模拟
  tui_sink.rs      # OutputSink / TeeSink，输出到内存/文件/TUI同时输出
```

### example 内部统一模式（以 `tui_animation.rs`为例）
关键点：**复用库内的真实渲染代码，不复制粘贴一套独立UI**。
example 只做：mock数据、驱动模拟事件、启动事件循环。业务/渲染逻辑全部复用`src`下模块。

```rust
// examples/tui_animation.rs
use my_agent::app::AppState;
use my_agent::sink::{OutputSink, TuiSink};
use crossterm::event::{self, Event, KeyCode};
use ratatui::{Terminal, backend::CrosstermBackend};
use std::time::Duration;

fn main() -> anyhow::Result<()> {
    // 初始化终端 alternate screen
    let mut terminal = ratatui::init();
    let mut app = AppState::default();
    let mut sink = TuiSink { app_state: &mut app };

    let mut animate = true;
    let mut tick = 0;

    loop {
        // poll带timeout，用于动画tick
        let timeout = if animate { Duration::from_millis(80) } else { Duration::MAX };
        if event::poll(timeout)? {
            if let Event::Key(key) = event::read()? {
                match key.code {
                    KeyCode::Char('q') | KeyCode::Esc => break,
                    KeyCode::Char(' ') => animate = !animate, //空格暂停/播放动画
                    _ => {}
                }
            }
        }

        // 模拟流式token循环，example专属mock逻辑
        if animate {
            let mock_tokens = ["Hello ", "world ", "this ", "is ", "animation "];
            let chunk = mock_tokens[tick % mock_tokens.len()];
            sink.write_chunk(chunk)?;
            tick +=1;
            // 循环重置：模拟一轮消息结束，新开一条消息
            if tick % 30 ==0 {
                sink.write_message(&my_agent::app::ChatMessage::new_assistant(""))?;
            }
        }

        terminal.draw(|f| my_agent::tui::chat_ui::render(f, &app))?;
    }

    ratatui::restore();
    Ok(())
}
```

> 要点：
> 1. `render` 直接调用src库里面真实渲染函数，example不重复写渲染代码。
> 2. 提供按键：`q/esc`退出，空格暂停动画。
> 3. mock数据完全放在example，不污染主程序。

### mini example 特殊注意
`examples/tui_mini.rs`：演示mini模式（main screen、不alternate screen，容忍resize错乱）
- example也要模拟消息产生，调用`MiniInteractiveSink`；ratatui仅渲染底部输入框。
- 文档注释写明：本示例故意不修复resize历史错乱，用于演示mini模式行为。

## 三、TUI调试的全套手段（除运行example肉眼预览之外）
### 1. 日志调试（最重要，开发日常用）
TUI程序不能随便println，会污染屏幕。
方案：把所有调试日志输出到**独立日志文件**，不要stderr/stdout。

使用 `tracing + tracing‑appender`：
- Full‑TUI / Mini交互模式：日志写入 `./tui_debug.log`；**不在终端输出任何日志**。
- headless模式：可选择输出日志到stderr。

在example和主程序统一使用同一套日志配置。
> 可以打印：滚动偏移、消息数量、重绘标记need_redraw、resize事件、每个tick状态，排查卡顿、不刷新、滚动异常。

### 2. Ratatui 离屏快照（Snapshot 测试，无需终端）
ratatui支持**不打开真实终端，直接渲染到内存Buffer**，做离线快照。
不需要启动终端，单元测试就可以拿到渲染后的cell缓冲区。

示例骨架（放在`tests/tui_snapshot.rs`）
```rust
use ratatui::{buffer::Buffer, layout::Rect};
use my_agent::{app::AppState, tui::chat_ui::render};

#[test]
fn test_chat_render_snapshot() {
    let mut app = AppState::mock_conversation();
    let area = Rect::new(0,0,80,24);
    let mut buffer = Buffer::empty(area);

    // 直接渲染到内存buffer，不碰真实终端
    render(&mut ratatui::Frame::new(&mut buffer), &app);

    // 把buffer转成纯文本字符串，做快照对比
    let rendered_text = buffer.to_string();
    insta::assert_snapshot!(rendered_text);
}
```
搭配 `insta` crate：
- 运行测试生成快照；修改UI后检查快照diff，可以看到渲染输出变化。
- 可以测试长消息、滚动、不同状态（thinking、tool调用），**不需要人手动运行example看屏幕**，CI也可以跑。

> 局限：无法测试crossterm键盘事件、resize交互逻辑；适合静态渲染输出校验。

### 3. 录制渲染diff输出，调试性能问题
ratatui `Terminal` 的backend可以封装一层，拦截每次diff输出的字节，写入文件。
可以看到每一帧到底输出了多少ANSI字节，定位：
- 哪一帧输出量巨大，造成SSH卡顿；
- 是否本应不变的区域却在大量重绘。

适合调试长文本、流式输出时的IO开销。

### 4. 重放录制事件脚本
把交互事件（按键、resize、模拟token）序列序列化保存到文件；example读取事件脚本重放。
- 复现偶发UI bug：录制一套按键+resize+流式序列，反复重放。
> 适合复现：resize错乱、滚动边界、输入框异常。

### 5. 专门的调试后端：ratatui‑tester
`ratatui‑tester` crate：专门做TUI组件集成测试，模拟键盘输入、resize，得到渲染结果。
不需要真实终端，在测试代码驱动按键、改变窗口大小，断言屏幕输出内容。

```rust
// pseudo‑code
let tester = Tester::new(80,24, app);
tester.send_key(KeyCode::PageUp);
tester.resize(40,20);
assert!(tester.screen_contains("Assistant:"));
```
适合测试滚动、resize、按键交互逻辑。

### 6. 真实终端调试技巧
1. **双终端窗口**：一个跑TUI程序；另一个 `tail -f tui_debug.log` 看实时日志。
2. SSH远程调试：用example复现SSH下卡顿，可调整节流参数。
3. 观察滚动条、diff输出，确认是否只有变化区域刷新。

## 四、不同调试场景对应最佳手段汇总表

|调试场景|优先手段|补充手段|
|---|---|---|
|肉眼看动画/流式输出效果、交互手感|独立 example 文件，循环模拟动画（空格暂停 q退出）|日志文件 tail|
|UI组件静态渲染输出是否正确（文本、颜色、布局）|insta快照测试 / ratatui‑tester|example预览确认观感|
|长文本、滚动边界、resize渲染重排逻辑|ratatui‑tester（模拟resize）+ example真实终端验证|日志打印scroll_offset、消息数量|
|性能问题：CPU高、SSH IO大卡顿|拦截diff输出统计字节数，日志统计每帧耗时|example中模拟大量消息压测|
|Mini模式行为（resize错乱、输入框错位）|专门 example/tui_mini.rs，真实终端拖拽窗口测试|日志打印终端size、输入框rect|
|Headless输出正确性|example headless.rs + 单元测试，断言输出文本/json|重定向输出文件比对|
|复现偶发交互bug|事件录制重放脚本 + ratatui‑tester|日志完整记录事件序列|

## 五、重要避坑点
1. **example不要复制渲染代码，复用src模块**。否则example和产品代码会分叉，example正常而主程序出bug。
2. example的无限循环动画仅用于调试演示，**不能移植到产品代码**。产品流式由真实LLM/channels驱动。
3. TUI代码严禁`println!`调试；全部走文件日志。一旦在alternate screen中println，屏幕直接乱掉。
4. 快照测试只能测渲染输出；真实终端交互、crossterm行为，**仍然需要example人工确认**，快照不能100%替代肉眼。
5. example 要注意资源清理：无论正常退出还是panic，调用 `ratatui::restore()` 恢复终端；最好加panic‑hook。

## 六、推荐的工作流
1. 修改UI渲染逻辑 → 先写/更新insta快照测试，跑单元测试；
2. 运行对应example，人工预览动画、交互、resize；
3. tail日志文件，观察状态变量、重绘标记；
4. 性能异常时，开启diff字节统计定位哪一帧输出量大；
5. CI编译全部examples，运行快照测试，防止UI回归。
