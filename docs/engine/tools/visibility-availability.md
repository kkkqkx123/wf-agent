# 可见性与可用性变化

> 范围：`tool_exposure.rs`、`visibility.rs`、`tool_snapshot.rs`、`entity.rs`、`agent_request.rs`、`coordinator/lifecycle/entity.rs`、`handler/agent_loop*.rs`、`handler/tool_visibility.rs`、`agent_prompt.rs`、`general_history.rs`
> 定位：执行实例持有的是可见性意图，完整工具定义永远以注册表为准；可用性变化走冻结快照加显式通告，不做静默改阵

## 完整定义与可见性意图的归属

完整工具定义只存放在注册表：名称、描述、参数结构、类型、元数据默认暴露形态与启用开关。执行实例不复制注册表，只持有五类名单加少量状态：可用池、初始可见、可发现、隐藏、已激活，外加按轮覆盖与可用池是否未设置标记。另有一份循环入口时刻冻结的快照，保存当时各桶排序后的完整声明与稳定指纹。

两者关系是意图对能力的投影：每轮决议读取活注册表，按名单过滤出当前四桶，再与入口快照比对。快照存的是声明内容而非名单字符串，包含描述与参数结构的变化，因此同名改描述也算漂移。渲染时冻结期内直接重放快照中的声明，不回活注册表取新定义，保证声明数组字节稳定。

可用池分未设置与显式两种：未设置继承全部注册工具，显式名单为闭世界白名单，显式空即纯问答。初始名单为空表示可用池全部直接可见，非空时未列入初始的直接工具先入待激活桶。隐藏名单最强，按轮覆盖次之，可发现名单再次之，最后才是工具元数据的默认形态。

## 三类可见性的分工

模型可见分三层，互不越位。声明数组只放直接可见工具加满足条件时的通用代理，是模型决定调用的唯一结构化依据。可发现工具只出现在元数据块中，经占位替换或尾部追加注入首条系统消息，调用必须经通用代理中转，不直接进声明数组。隐藏工具两处都不出现。

可执行性另由运行时门控判定，与声明数组解耦：可见工具可直接调用，可发现工具经代理调用，待激活工具需形式激活后才放行，隐藏工具永不可执行，拦截工具在执行期拒绝，池外工具直接拒绝。拦截只做执行期拒绝，不改声明数组，因此命中缓存的前缀得以保留，代价由入口合并通告中的显式重试禁止行来补偿。

通用代理的归属特殊：它由可发现集合是否非空驱动注入，但作为声明数组一员同样受闭世界约束。显式可用池未包含它，或注册表中根本没有它时，代理保持关闭，可发现工具转为暂时不可达通告，而非静默悬空。

## 模型感知通道

模型经四个位置感知能力：每轮声明数组、稳定系统头、可发现元数据块、用户角色尾通告。稳定头在入口组装一次，含环境、技能、工作流与技能及模型上下文富化，其中技能与模型上下文相关段按可用池判定是否注入，未设置时按注册表是否存在判定，避免与实际决议矛盾。易变尾独立为用户消息，存放时间、待办、钉选与工作区等易变数据。工具变化通告统一为用户角色尾消息，不参与系统合并，存储尾即传输尾，不搅动系统前缀字节。

## 可用性变化的处理

入口只做一次冻结：解析名单、校验子集与互斥、做一轮决议并存快照、做一次边界历史归一、清理旧通告后追加新鲜合并通告、最后追加本轮用户任务。合并通告按固定行序组织已激活、被拦截与不可达信息，无变化则不产生。

轮内走冻结渲染：每轮重新决议并与快照求差，有差则仍按快照渲染声明数组，差异只追加在按轮克隆的请求尾部，注明待下一循环边界采纳，不落盘，不改写存储历史。采纳只发生在新实例入口，本轮长循环不受中途注册表增删或同名改描述的影响。

历史形状只在边界改写一次：上游存档的上游桶形状经纯函数转为本轮目标形状，调用与结果标识一并重映，存档本身不动。轮内投影默认关闭，避免无变化时搅动前缀；显式纯问答直接跳过决议与归一，按无工具渲染。校验分两档：有注册表时含存在性与禁用检查，无注册表时仍保留空名去重、互斥、池外子集与纯问答矛盾检查，工作流与直接入口共用同一校验入口。
