# 维度一：执行过程可视化（Execution Visualization）

> 关注点：工作流**运行/执行**之后，结果、过程、节点状态如何在界面上被呈现与回溯。

---

## 1. Dify 的执行过程可视化

Dify 的执行可视化是**"以一次运行为中心、以节点追踪树为粒度"**的 LLM/ Agent 工作流视角，主要由「画布运行时态着色」+「运行详情面板（三 Tab）」+「节点级追踪卡片」三层组成。

### 1.1 画布运行时态：边与节点的着色

- **边（连线）按节点运行状态着色**。`custom-edge.tsx:90-102` 用 `getEdgeColor(_sourceRunningStatus/_targetRunningStatus)` 计算 `stroke`：
  - 选中态 → `Running` 色；两端都结束时 → 引用线性渐变 `url(#id)`；悬停关联节点 → `Running` 色；默认 → 普通色。
- 颜色映射集中在 `utils/edge.ts:3-20`：
  - `Succeeded` → `var(--color-workflow-link-line-success-handle)`
  - `Failed` → `var(--color-workflow-link-line-error-handle)`
  - `Exception` → `var(--color-workflow-link-line-failure-handle)`
  - `Running` → `var(--color-workflow-link-line-handle)`（失败分支 `failBranch` 时降级为 failure 色）
  - 默认 → `var(--color-workflow-link-line-normal)`
- **两端都结束时的渐变连线**：`custom-edge.tsx:54-66` 当源/目标均为 Succeeded/Failed/Exception/Running 时，注入 `CustomEdgeLinearGradientRender`，起点/终点色分别取两端状态色（`custom-edge.tsx:106-118`）。
- **节点状态边框**：`nodes/_base/node.tsx:34,132` 通过 `getNodeStatusBorders(data._runningStatus, …)` 给基础节点绘制运行中/成功/失败的状态描边。

### 1.2 运行详情面板：RESULT / DETAIL / TRACING 三 Tab

`run/index.tsx` 的 `RunPanel` 是核心（`:104-140`）：

| Tab | 内容 | 数据来源 |
| --- | --- | --- |
| **RESULT** | 工作流最终输出 `OutputPanel` | `fetchRunDetail`（`:49,153`） |
| **DETAIL** | 输入/输出/耗时/Token/状态/步数 `ResultPanel`；监听态显示 `StatusPanel` | `fetchRunDetail`（`:158-179`） |
| **TRACING** | 逐节点追踪列表 `TracingPanel`（底色 `bg-background-section-burn`） | `fetchTracingList`（`:59,182`） |

- 数据获取：`getResult`/`getTracingList`（`run/index.tsx:47-66`）分别调 `fetchRunDetail`/`fetchTracingList`。
- **实时监听自动切 Tab**：当 `isListening` 为真，自动切到 `DETAIL`（`run/index.tsx:84`），契合流式执行体验。
- 面板容器 `bg-components-panel-bg`、`rounded-b-xl`，Tab 头用 `system-sm-semibold-uppercase!` 原子类（`run/index.tsx:110-139`）。

### 1.3 节点级追踪卡片

`run/node.tsx` 的 `NodePanel`（360 行）呈现单个节点的执行细节：

- **状态图标**：成功 `RiCheckboxCircleFill`（`:185`）、错误 `RiErrorWarningFill`（`:191`）、运行中 `RiLoader2Line` 带 `animate-spin`（`:226`）。
- **结构化数据**：输入/过程/输出均用 `CodeEditor` 以 JSON 展示（`:303,319,331`）。
- **子过程嵌套**：迭代（iteration）/循环（loop）/重试（retry）/Agent 等子日志可展开。
- 时间、Token 消耗等做格式化展示。

### 1.4 画布辅助视觉

- 选区矩形：`style.css` 中 `border: 1px solid #528bff; background: rgba(21,94,239,0.05)`。
- 评论/协作光标叠层（`collaboration/components/user-cursors`、`comment/*`）属协作态而非执行态，但同样叠加在画布上。

> **小结**：Dify 把"执行"表达为**一次 RUN 的追踪树**，强调 LLM 链路的可解释性（每个节点的 inputs/process/outputs JSON + 迭代/重试/agent 子日志），画布用连线渐变与节点边框即时反馈进度。

## 2. n8n 的执行过程可视化

n8n 的执行可视化是**"以一次 Execution 为实体、列表+详情为一等公民"**的通用自动化视角，强调跨工作流的记录、检索与重跑。

### 2.1 画布节点执行态类

`CanvasNode.vue:109-118` 根据 `props.data.execution` 计算节点类：

```ts
running:  props.data.execution.running || props.data.execution.waitingForNext,
waiting:  props.data.execution.waiting || props.data.execution.status === 'waiting',
selected / hovered / highlighted
```

这些类驱动节点在运行/等待时的视觉差异（如脉冲、描边）。

### 2.2 画布边的执行态着色

`CanvasEdge.vue:110-117` 对边着色：

- `success` → `var(--color--success)`
- `pinned` → `var(--color--secondary)`
- 非主连接（如 AI 分支）用虚线：`strokeDasharray: '5,6'`（`CanvasEdge.vue:67-70`）。
- 带色状态边不响应 hover 提亮（`CanvasEdge.vue:119-121`）。

### 2.3 执行列表与详情（Executions 功能）

- **按工作流视图** `WorkflowExecutionsView.vue`：
  - `onMounted` 调 `executionsStore.initialize(workflowId)` + `fetchExecution`；通过 `visibilitychange` 启停 `startAutoRefreshInterval`（`:88-97,130-136`）。
  - 结构为「左侧列表 + 右侧预览」：`WorkflowExecutionsList`（`:331-348`）。
- **列表布局** `WorkflowExecutionsList.vue:84-107`：
  - `flex` 容器 = `WorkflowExecutionsSidebar`（左）+ `RouterView name="executionPreview"`（右）。
  - 响应式：`sm-and-down` 时改为纵向列（`WorkflowExecutionsList` SCSS `:123-131`）。
- **全局跨工作流视图** `ExecutionsView.vue:137-182`：在无工作流/概览场景用 `GlobalExecutionsList` + `ProjectHeader` + `InsightsSummary`。

### 2.4 单条执行卡片（状态色编码）

`WorkflowExecutionsCard.vue` 用**左边框颜色**表达状态（`:200-305`）：

| 状态类 | 左边框变量 | 语义色 |
| --- | --- | --- |
| `running` / `new` | `--execution-card--border-color--running` / `--waiting` | `--color--warning` |
| `success` | `--execution-card--border-color--success` | 成功绿 |
| `error` | `--execution-card--border-color--error` | `--color--danger` |
| `waiting` | `--execution-card--border-color--waiting` | `--color--secondary` |
| `unknown` | `--execution-card--border-color--unknown` | 灰 |

- 运行中显示 `N8nSpinner`（`WorkflowExecutionsCard.vue:109-113`）。
- 操作：`redo-2` 重试下拉（`retryExecutionActions`：`current-workflow` / `original-workflow`）、`thumbs-up/down` 标注投票、标签 `N8nTags`、模式图标 `flask-conical`（manual）/ `check-check`（evaluation）。
- 状态文案由 `useExecutionHelpers.getUIDetails` 派生（`:59-61`）。

### 2.5 画布日志面板

`WorkflowLayout.vue:100-102` 在 `layoutProps.logs` 为真时，于 `#footer` 渲染 `LogsPanel`，提供画布下方的执行日志浮层。

> **小结**：n8n 把"执行"建模为**可持久化、可检索、可重跑的 Execution 实体**，通过列表+详情+卡片状态色+画布节点 running/waiting 类+日志面板多通道反馈，偏重运维与审计。

## 3. 横向对比

| 对比项 | Dify | n8n |
| --- | --- | --- |
| 可视化单位 | 一次 RUN 的节点追踪树 | 一条 Execution 实体（可列表/检索/重跑） |
| 画布反馈 | 连线按状态着色+渐变、节点状态边框 | 节点 `running/waiting` 类、边 `success/pinned` 着色、日志面板 |
| 详情呈现 | 三 Tab 面板（RESULT/DETAIL/TRACING） | 列表 + 详情预览（RouterView） |
| 节点级细节 | 每节点 inputs/process/outputs JSON + 迭代/重试/agent 子日志 | 通过 NDV（节点详情视图）查看运行数据 |
| 状态编码 | 语义 CSS 变量（success/error/failure/handle/normal） | 左边框色 + 设计令牌（warning/success/danger/secondary） |
| 适用场景 | LLM/Agent 链路可解释性 | 通用自动化运维/审计/重跑 |
| 实时性 | `isListening` 时自动切到 DETAIL，适配流式 | 自动刷新间隔 + 可见性感知 |

## 4. 设计启示

- **状态色要可组合**：两者都用"语义变量 → 具体色值"的分层（Dify `--color-workflow-link-line-*`、n8n `--color--*`），便于主题切换与暗色模式。
- **画布即时反馈 vs 持久化回顾**：Dify 重"跑的时候就能看懂"，n8n 重"跑完能查、能重跑"——选择取决于产品定位（AI 编排 vs 自动化平台）。
- **节点粒度的数据呈现**：Dify 直接把 JSON 嵌进追踪卡片；n8n 把运行数据收到 NDV 里按参数展示。前者更"摊开看"，后者更"按需钻取"。
