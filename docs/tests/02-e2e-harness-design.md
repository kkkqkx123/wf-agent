# 02 验证线束设计

## 目录划分

`e2e` 按构建产物、输入、输出、编排四类划分。`bin` 只放同步脚本复制来的可执行文件，不入库二进制。`fixtures` 放版本化的输入数据，包括工作流定义、执行输入与手工会话用的提示词。`outputs` 放可检视的输出，其中黄金目录入库，实际运行目录忽略。编排脚本放在 `e2e` 根目录，公共辅助放在 `lib` 子目录。

该划分参照离线调试器与演示集的习惯：输入示例集中存放，输出按形态或用例存放并可重新生成，编排只做搬运与调用，不复制产品逻辑。

## 构建产物同步

同步脚本负责把工作区构建产物复制到 `e2e/bin`，并确认两者版本一致。构建命令限定服务端与无头客户端两个产物，复制前创建目标目录，复制后赋予执行权限并打印版本。同步脚本不做清理之外的删除，不改版本号，不处理全屏与行式形态。

日常顺序为先构建再同步最后验证，验证脚本在启动前检查产物是否存在，缺失时指引先运行同步脚本而非自动触发构建。

## 服务端生命周期

每次验证启动一个独立服务端实例，监听回环地址上的临时端口，存储使用内存模式，业务目录指向本次运行的隔离工作区，日志落到实际输出目录。启动后以健康端点为就绪门限轮询等待，超时即失败并保留日志。验证全程串行执行，结束时无论成功失败都终止服务端并保留日志供排查。

端口选择优先使用系统分配的空闲端口，确有需要时回退到探测式选取。服务端配置全部经命令行显式传入，不依赖项目与用户目录下的配置文件，避免本机状态污染验证结果。

## 客户端调用约定

所有客户端调用均显式传入远端地址与业务目录，输出格式固定为结构化档位并关闭颜色，保证机器可解析。标准输出承载业务包络，标准错误承载诊断，两者分别重定向到实际输出目录下的对应文件。环境变量中的远端与凭证在运行时显式隔离，默认不继承开发机配置。

会话类调用限定为工作流执行形态，智能体会话形态仅在手工层使用。破坏性操作依赖非终端下的默认免确认行为，无需额外确认标志。

## 断言与清理

断言以退出码为第一判据：展示类与只读类命令期望成功退出，错误路径期望非零退出并在包络中给出可识别的错误信息。结构化断言经 JSON 查询提取包络字段，文本断言仅用于诊断通道的存在性检查。含时间戳与随机标识的字段在比较前归一化，黄金文件只保留归一化后的稳定投影。

有状态用例遵循建后即清：创建的工作流定义在用例结束时删除，执行记录保留在内存服务端中随进程退出而消失。清理失败不掩盖用例本身的失败，两者分别报告。
